01 / LANDSCAPE

先看清，系统究竟在改什么

“自改进”覆盖多种不同机制。权重更新、持久记忆、程序搜索和改进器自修改，需要分别检查证据。

工作定义：系统利用自身运行产生的经验或结果，持久更新自己的能力；更强的递归闭环还使这些更新改善下一轮产生、选择或执行改进的机制。这是本文用于比较工作的分析口径，不是统一行业标准。理论中的固定效用自修改、现实中的有限轮次 harness 演化，以及自主研发后继模型，讨论的层级不同。参考：Gödel Machine、Generalized Agent Iteration。
01 / Self-modification

代码与改进器

让系统修改自身代理程序、搜索策略或元层改进程序。重点观察：新版本是否参与产生下一代，以及“改进能力”是否同步提升。

STOP → DGM → Hyperagents

02 / Agent systems

提示、工作流与记忆

更新提示、工具、技能、执行图和持久记忆，常保持基础模型权重不变。区分外部优化器优化 agent，与 agent 改写自身改进机制。

Reflexion · DSPy · GEPA · ACE

03 / Learning loops

训练与自生成数据

生成解答、反馈或学习材料，经筛选、蒸馏、RL 更新权重。检查教师、标签、奖励、数据准入与训练规则的来源。

STaR · ReST · SCoRe · SEAL

04 / Self-play

自博弈与课程演化

提问者、解题者、环境或群体共同产生学习信号。任务可验证性、难度控制和多样性决定学习循环能否持续。

Absolute Zero · R-Zero · SPADE

05 / Automated R&D

自动科研与算法发现

将假设、代码、实验、分析串成研究流程，也可用程序搜索改善 AI 的算法和系统。进一步检验研究成果如何回流到研究者。

FunSearch · AlphaEvolve · AI Scientist

06 / Evidence

评价与闭环边界

检验隐藏测试、资源预算、跨任务迁移与评价器可靠性。高分、发表论文或工程提效，分别只支持相应范围的结论。

RE-Bench · PaperBench · PostTrainBench

四种容易混在一起的“改进”

观察对象变化保存在哪里能够支持的判断还需要什么证据
单次推理修正当前回答或上下文反馈帮助本次任务完成跨任务持久增益，以及后续改进能力
持续学习 / 系统优化权重、记忆、提示或工作流在给定任务分布上变强新系统能否产生更好的后继版本
受限递归自改进改进器、代理代码或元策略在固定环境和预算下，改进结果回流多代泛化、成本收益与独立评价
开放式自主研发研究流程及后继系统需追踪完整研发链跨领域持续创新、扩展预算下稳定闭环

上表为本文的比较框架。“直接 RSI 相关”表示研究问题或机制直接涉及递归，不表示已实现开放式自主研发。固定外部目标不自动排除 RSI，修改评价器也不自动证明 RSI 有效。

六个值得细读的机制

1. 自引用：修改产生修改的程序

STOP把代码改进程序本身纳入优化对象；Hyperagents进一步将任务代理与可修改二者的元代理置于同一程序中。这条线最需要区分“任务解得更好”和“能产生更好的下一代”。

2. 归档搜索：保存有潜力的父节点

DGM保存多条谱系，允许从不同父节点继续演化。HGM用后代表现估计元生产力，提示当前任务成绩与未来改进潜力可能不一致。

3. 内外两层学习：学会如何学习

SEAL先生成自我编辑材料与更新指令，再用实际适应后的任务结果训练生成策略。其工具集合与外层训练仍固定；有限任务上的适应收益需要与长期遗忘和成本一起看。

4. 课程共演化：反馈从哪里来

Absolute Zero利用可执行任务构造训练信号；SPADE继续探索可演化环境。所谓“零数据”只适用于特定训练阶段；预训练先验、执行器、文档或种子任务依然可能存在。

5. 层级递归：哪些层真的可变

Metaⁿ在固定元操作下增长策略层链；MetaRSI尝试调度数据、harness 和权重更新。它们具有不同可修改范围，不能只按名称中的“递归”强弱排序。

6. 研究闭环：产物如何反哺研究者

ScienceBuddy研究框架内层优化与外层 RL 的嵌套；DataFoundry针对数据准备过程演化。应分别测试研究产物、执行流程与研究者能力，而非仅评估最终论文或模型。

03 / READING PATHS

按问题组织的阅读路线

先建立机制与证据的判断标准，再选择模型训练、Agent 系统或自动研究方向。

04 / IMPLEMENTATION

把论文转成可验证的改进循环

仓库可访问与代码可复现是两项不同检查。先明确可改范围、反馈契约与预算，再启动搜索。

最小闭环需要记录什么

  1. 版本化可修改对象：提示、代码、记忆、样本、权重或改进器，保存父子关系。
  2. 可复现反馈：任务、环境、随机种子、评分版本、耗时与调用量。
  3. 候选生成和选择：两部分单独核算成本，保留失败候选。
  4. 迁移检验：候选用新任务验证；最终测试结果不再参与挑选。
  5. 递归对照：新版本参与下一轮，与固定改进器进行等预算比较。

选择实现入口

只有 API 访问：从提示、工作流、记忆或代码优化入手，注明底座模型保持固定。

具备训练资源：考察自生成数据、蒸馏、自博弈或 RL，预算包含生成、筛选与评估。

目标是自动科研：限定数据、脚本、算力与评分接口，先复现可核验的实验循环，再测试研究成果是否反哺研究者。

本节为跨论文抽象的工程建议；具体配置需回查原始仓库。

机制骨架

保存初始系统 S₀、改进器 I₀ 和任务划分
每一代 t：
  Iₜ 根据执行轨迹提出多个候选修改
  固定预算运行候选；记录成本、失败与版本谱系
  用选择任务挑选 Sₜ₊₁；用新鲜验证任务做阶段性检查
  若研究递归：让 Sₜ₊₁ 的变化影响下一轮 Iₜ₊₁
  并行运行固定 I₀、随机搜索 / 多次采样等预算基线
结束后：
  仅一次最终隐藏测试
  报告多代增益、成本、方差、最佳与最后版本、旧能力保持

反复使用验证集仍会泄露信息。预先区分训练、选择、阶段验证与最终测试，并控制使用次数；冻结外部测量协议与研究可变化的内部评价器可以并存。

如何证明改进真的发生

看见分数上涨，还需要解释：是否使用了更多搜索、是否接触了测试任务，以及提升能否保留并迁移。

阅读结论：已有受限系统显示自修改、反馈学习与研究自动化可以产生实测收益。是否形成持续、开放式、可泛化的自主研发闭环，需要额外证据。本文不从有限轮次实验推导智能爆炸或 AGI 时间表。
要回答的问题需要观察的证据常见混淆
系统真的变强了吗？隐藏任务、方差、同预算基线、旧能力保持更长推理、更多候选或更强外部教师
更会改进自己了吗？新旧版本作为改进器，各自产生后继系统的质量与效率把任务得分和元层改进能力视作同一个量
循环能持续吗？多代曲线、停滞与退化、多样性与累计成本单轮收益外推无限增长，隐藏失败代次
有多自主？人工设定和介入、可改文件、环境与模型依赖自动执行实验等同于自主选研究方向
泛化到哪里？跨任务族、跨模型、跨预算与新环境迁移反复调同一基准，使用测试反馈选择版本

评价器与优化器可能共同犯错

自反馈依赖模型能否识别错误；测试通过率、模型打分和真实正确性也可能分离。LLMs Cannot Self-Correct Reasoning Yet讨论缺少外部反馈时的推理修正限制；参考自由评审的奖励投机研究展示“更有说服力”与“更正确”可能脱钩。

合成数据的递归有条件

递归生成数据与模型坍缩揭示特定合成训练设定的退化；累积真实和合成数据及合成数据验证说明数据保留和验证会改变结论。不能推出所有自训练都坍缩，也不能忽略课程多样性与错误累积。

单项基准不代表完整科研

RE-Bench 的研究工程、PaperBench 的论文复现、MLE-bench 的机器学习竞赛与 PostTrainBench 的后训练，分别测量不同组件。需要单独评估选题、实验设计、执行、结论真实性和后继研究者。

RE-Bench · PaperBench · PostTrainBench

预算不只等于 GPU 时间

模型调用、采样、编译、失败实验、评价和人类审查也属于成本。比较硬件数量、墙钟、token、美元或 FLOP，是不同控制条件。最佳检查点与最终检查点也应分别报告。

AIRA₂ · RSIBench-Data

产业自述的证据范围：Anthropic · When AI builds itself描述 AI 参与研发的内部观测，并讨论研究判断与人类介入的瓶颈。可以据此理解实践形态；企业自述、主观生产率与代码量都不能单独证明全面 RSI 已实现。

几项应保留原样的边界

  • HELIX的当前实验只完成一轮 harness 演化与训练数据导出，不能写成已验证多轮模型—harness 共演化。
  • AI Scientist-v2的生成论文通过 workshop 评审，与系统研究本身的正式发表是两件事；workshop 不等于主会。
  • Frontis-MA1的单卡任务沙箱限制不包含大模型代理的推理成本，不能作为完整系统本地显存门槛。
  • Redwood的 FPGA 部署和先进工艺性能投影属于不同证据层级，不能混成已制造芯片的实测结果。
