今日主线： 这轮最值得研究的两个方向是「把测试时的额外计算放在模型内部」和「让 Agent 的训练、判分、推理服务都能接受更严格的成本与可靠性审计」。Looped Transformer、Skill-guided SFT、动态稀疏注意力都展示了效率潜力，但应区分论文宣称、可取得的开源工件和可迁移的系统级收益。

归档日期： 2026-11-22（北京时间，周日）。主观察窗口： 2026-11-21 07:09—2026-11-22 07:09（Asia/Shanghai）；周末论文新增稀疏，研究筛选扩展到过去 72 小时（最早 11 月 19 日），X 讨论另检查过去 7 日的持续发酵。日期约定： 以下各项分别注明首次发表或开放日期，不把本期归档日当成成果发布日期。实验数字均系作者或机构报告，未由本轮独立复现。

一、论文与系统进展｜按实用价值排序

1. Inkling 2 Mini：固定三次中间层循环，把计算留在 token 内部

发生了什么。 Thinking Machines Lab 在 11 月 20 日发布 Inkling 2 Mini 官方技术说明及模型卡。它是 26.4B 总参数、约 3.4B 激活参数的 MoE；24 层中间 12 层重复执行三次，单 token 有约 5.4B 权重激活量。模型大量采用 NVFP4，官方称权重运行内存约 20GB，并公开用于研究的可变循环版本。官方报告 DeepSWE v1.1 为 48.2%、Vals Index v2.2 为 46.5%；跨模型评测设置可能不同，不能视作严格等算力排名。

为什么重要。 通常的推理增强依赖生成更多 CoT token；Looped Transformer 把一部分推理深度移到隐藏状态，可能减少输出 token 与 KV 增长。对 Tool Agent 需要分别测量「每 token 的重复层 FLOPs」「总生成 token」「真实墙钟延迟」，不应仅凭参数量判断部署性价比。

可信度与局限。 官方模型卡、权重入口和技术报告可直接查证；性能和监控性仍是团队自报。研究版本增加循环数时，无显式 CoT 的可解题时长从 16 秒升至 37 秒，同时官方观察到 CoT 变短但保持可读，未发现所测 Agent 破坏行为随循环单调增加。这不构成通用安全保证。需核验不同硬件的量化兼容性、Batch 并发和长上下文性能。

下一步追踪。 同一任务、同一硬件测 success / wall time / generated tokens / actual FLOPs / peak RAM；用变量循环模型画算力—准确率曲线，并做工具调用格式错误与拒判率审计。

2. AutoMaster / Skill-FT：成功轨迹也可能是坏教师

发生了什么。 AutoMaster（11 月 19 日提交）提出先分析教师 Agent 轨迹，自动生成自然语言 Skill 约束教师行为，再选择轨迹给 4B/9B 学生做 SFT。与「只筛选成功教师轨迹」基线相比，作者在 Terminal、Search、SWE 场景报告平均提升 1.42—8.99 个百分点，控制了教师、任务池、训练集规模和 SFT 方案。官方代码。

为什么重要。 success=1 的工具轨迹可能包含无效搜索、未经验证的跳步和重复操作。训练数据质量应同时描述终局正确性与过程策略；对购物 Agent，教师的违规尝试即使最终修正，也不适合作为无条件模仿目标。

可信度与局限。 控制变量设计比简单扩充数据更有说服力，但 Skill 自动搜索会产生额外计算，且可能对既定测试任务过拟合。论文发现保留训练示例中的 Skill 指令比删除更好，但跨教师、跨任务分布的因果解释仍需独立复验。

下一步追踪。 固定成功率相同的教师轨迹池，对照「仅成功筛选／行为 Skill 引导／Skill 引导+去除训练指令／Skill 引导+保留指令」，同时评估分布外约束违规率。

3. LightningMoBA：动态 Top-k 与 KV-centric Kernel 联合优化

发生了什么。 LightningMoBA（11 月 19 日）针对 Mixture of Block Attention 的固定 Top-k、重复加载 KV Block 和不规则 GPU 执行，联合使用自适应阈值路由、按 KV Block 聚合工作任务以及 Hopper 流水化。作者在五个模型上、与 Top-16 平均保留预算匹配时，报告端到端生成 1.20—1.60 倍提速，平均 RULER 由 74.42 提升到 75.28。官方实现。

为什么重要。 动态稀疏注意力的收益取决于选哪些块和GPU 如何执行被选块两部分。KV-centric 调度改善数据复用；可变块数提高检索灵活性，为长上下文 Agent 的动态证据定位提供实现路径。

可信度与局限。 论文提供了路由和内核的分拆比较以及 4K—128K 情境；但基准主要在 Hopper，动态形状对 CUDA Graph、连续批处理及 P99 可能不利。摘要中的端到端加速不能外推为多轮工具工作流整体加速。

下一步追踪。 在固定 GPU 利用率及 P99 SLO 下回放混合长度请求，比较 FlashMoBA、LightningMoBA 的 prefill/decode、KV 命中、内存碎片和吞吐。

4. AltRA-Test：LLM Judge 能替换人工标注吗？先做统计非劣效检验

发生了什么。 AltRA-Test（11 月 19 日）处理「不同样本由不同人工标注员打分」的稀疏标注情境：Bootstrap 重采样样本和人工评分，在混合 Panel 中用一份 LLM 评分替换人工评分，检验混合 Panel 的标注者间一致性是否相对全人工 Panel 非劣。论文在 20 个跨模态数据集、18 个 LLM 与 5 种 Prompt 上实验；作者报告约 100 个样本在很多情境下可做判断，而 LLM 仅在约一半的真实设置通过。

为什么重要。 搜索相关性、推荐质量与 Agent 成功判分经常大量依赖 LLM-as-a-Judge。高相关系数不等于可替换人工标注员；「非劣效边界」「Bootstrap 置信度」与独立 Gold 集能约束过早自动化。

可信度与局限。 有统计理论与仿真，但标注员之间高度一致也可能共同偏离事实，IAA 非劣效无法自动证明评测准确率或公平性。任务定义、边界和抽样机制决定结论外推范围。

下一步追踪。 在推荐相关性标注中预注册可接受的非劣效 margin，按 Query、热门/长尾、语言和高风险错误分层再做替代检验。

5. Hy4：大体量多模态开源权重与原生投机解码

发生了什么。 腾讯混元在 11 月 20 日开放 Hy4 正式版、FP8 与 Base 权重，见官方仓库及部署说明和模型卡。其语言主干 770B 总参数、每 token 激活 49B，支持最长 1M token、图文视频理解；Gated DSA、IndexCache 及 DFly2 原生草稿器复用部分 KV/索引，旨在抑制长上下文投机解码开销。

为什么重要。 对多模态搜索和金融 Agent，模型开放意味着可以测试检索时效性、来源综合及 GUI 工具使用；原生 Speculative Draft 与稀疏索引共享适合研究超长上下文下「草稿验证成本」如何变化。

可信度与局限。 官方仓库提供权重入口和 vLLM/SGLang 部署配方，可信度高；金融任务等 Benchmark 主要是内部评估，未获独立复验。腾讯 Hy License 需逐项审阅，不能按 Apache 2.0 推定商用权利；770B 总权重的存储与多 GPU 内存需求不能用 49B 激活参数代替。

下一步追踪。 评估 FP8 在目标硬件的显存占用、并发、TTFT、验收率、Speculative Speedup 与工具调用格式正确率；和较小模型做单位成功任务成本对比。

6. Posterior Matching Distillation：扩散模型少步蒸馏转向覆盖条件分布

发生了什么。 NVIDIA 等作者在 11 月 19 日提交 Posterior Matching Distillation，通过一组指数倾斜的条件均值约束学习教师完整后验，理论上避免单纯 reverse-KL 的 mode-seeking，支持训练时间网格内任意步数采样；作者声称在 SDXL 和 FLUX.2 klein 4B 的 4-step 图像生成上取得较优 FID。项目说明。

为什么重要。 少步生成的高吞吐并不自动意味着覆盖面好；对广告创意和商品图生成，稀有外观、布局多样性与条件忠实度应共同测量。

可信度与局限。 理论结论依赖其均值匹配和训练覆盖假设。社区对论文两张表的 FLUX FID 数字是否一致提出了公开问题，因此复现前不宜强调绝对 FID 胜出结论。

下一步追踪。 核对指标表格与评测脚本，固定 Prompt 与随机种子测 FID、CLIP/T2I 一致性、多样性和每图 GPU 秒数。

7. AI 推理供应链安全：可追踪 Canary 发现多层转发数据风险

发生了什么。 Dragos 研究者 HD Moore 在 11 月 19 日发表原始调查：据作者称，在数月内向 AI 供应链发送近 200 万个带唯一 URL/诱饵凭证的请求，观察到被用于访问受控 AWS 账号、尝试读取秘密及超出数据保留政策的访问。11 月 20—21 日关于 Zero Data Retention、推理 Marketplace 子供应商可见性的讨论继续扩散。

为什么重要。 Agent 常发送源码、检索内容、工具结果和业务数据，路由器到上游的每个跳点都可能看到完整 Prompt。「ZDR」是特定提供商的声明，不能单独证明整个链路满足企业数据治理要求。

可信度与局限。 研究方法、Canary 行为与案例来自研究团队第一手记录，但本文没有独立审计全量原始网络日志；不同提供商遭遇的问题、违约行为和第三方攻击应分开讨论，不能据此断言所有模型网关均泄漏。

下一步追踪。 在自有代理链路建立供应商路径清单、实际路由留痕、Canary 测试与最小权限审查；商业敏感场景在核实合同和技术控制前避免隐式转售路径。

二、跨研究判断：三条可以检验的假设

假设建议对照应观察的失败信号
Token 内循环可降低任务总成本同等 GPU、同等成功率下比较 Loop / 标准 CoT生成 token 少但每 token FLOPs 与 P99 大幅升高
自动发现的好 Skill 会改善 SFT固定教师、任务、样本量、训练超参仅训练内任务升分、分布外规则违规率变高
动态注意力保留更多有用信息固定平均 KV 预算与吞吐 SLO单请求增益在连续批处理和长尾时延下消失

对于推荐算法，以上论文共同提示：单指标优化很容易把计算、错误或数据泄漏成本挪到未观测的环节。需要任务效用、可靠性、延迟和资源消耗的联合前沿。

今日最值得花 30 分钟阅读的一项

Inkling 2 Mini 官方技术报告：Architecture、Looping Design 与 Monitorability。10 分钟研究 24 层中间 12 层循环 3 次的 FLOPs 结构；10 分钟读可变循环实验里 No-CoT 能力和 CoT 可读性的分离；最后 10 分钟用自己常用的 4B—30B 模型的推理预算、输出 token、CPU/GPU 显存推算哪些负载可能真正受益。关键问题是：多一次隐藏计算，能否比多生成几个可观察的推理 token 更有价值？

今日可立即实践的一件事

给 ShoppingAgentLab 增加「隐藏算力 vs 输出推理」的成本—质量评测模板。 从历史任务抽取 30 条，按简单商品过滤、复杂多约束、长链比较三组，每条冻结候选商品与价格/库存。对同一模型建立短 CoT、中 CoT、长 CoT 三个预算基线，并把 Inkling 2 Mini 作为另一个架构点（如果硬件资源允许）；全部报告 Task Success、硬约束违规、Tool-call Error、TTFT、P95、生成 token、GPU 秒和每 100 次成功任务成本。不要把不同架构当成单变量因果试验：相同权重上可控制的循环次数研究，需要使用单独开放的 Variable-loop 研究模型。
