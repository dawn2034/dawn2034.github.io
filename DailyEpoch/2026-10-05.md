> **今日主线：** Model-native SFT · Multi-Teacher OPD · Looped Contrastive Decoding · RLVR Language Drift · Agent-Web Recommendation · Multilingual Semantic IDs

今天是周一早间，arXiv 最新可见的常规公告批次仍是 **2026 年 10 月 2 日**：cs.AI 381 条、cs.CL 184 条、cs.LG 430 条、cs.IR 21 条。分类之间存在大量交叉收录，不能直接相加。

今天最值得连起来看的变化，是 Post-training 的讨论正从“SFT 还是 RL”推进到更细的层级：**数据分布是否适合当前 Learner、Teacher Signal 如何被隐式加权、训练是否会改变模型内部语言的可读性**。推理侧，Looped Transformer 的中间循环开始被当作免费 weak model 使用；推荐系统侧，两条值得警惕的线同时出现：个人 Agent 网络让推荐进入“有限证据预算”的分布式场景，而多语言 Semantic ID 暴露出一个常被忽略的问题——多语言 Encoder 并不自动带来跨语言稳定的离散商品标识。

## 今日核心判断

1. **SFT 的弱点有一部分来自数据分布，而不只是 Loss。** [Finetuning with Sampling](https://arxiv.org/abs/2610.02140) 不修改 SFT 目标，而是用 MCMC 把 off-policy expert trace 逐步变成“对当前 Base Model 更高概率、但语义等价”的轨迹。Qwen2.5-7B-Instruct 的 Chemistry 任务中，Sampling SFT 相对 Base 提升 31.7%，比 OPSD 的增益再高 4.20%；但把为 Olmo 优化的数据拿去训练 Qwen，Chemistry 反而只有 57.33%，低于 Vanilla SFT 的 61.8%。**数据必须对 Learner 原生，而非抽象意义上的“高质量”。**

2. **MOPD 里的 averaging、optimizer、precision 都是目标函数的一部分。** [From Gradients to Capabilities](https://arxiv.org/abs/2610.02179) 发现，token averaging 会隐式偏向长回答；Adam 一阶矩把不同 Teacher Update 的余弦相似度从约 0.83 压到 0.96；97% 的 FP32 master weight 已改变，但只有 7%–11% 的 BF16 weight 体现出差异。更关键的是，同一个 top-64 KL 近似在 response averaging 下数学成绩比 sampled-token PG 高 2.6 points，在 global token averaging 下却低 2.1 points。**“同一个 distillation loss”并不存在脱离实现细节的唯一含义。**

3. **Looped Transformer 自带一组 aligned weak/strong predictions。** [LoopCD](https://arxiv.org/abs/2610.02185) 把早期 recurrence 当作 weak predictor，与最终 loop 做 contrastive decoding；Ouro-2.6B-Thinking 的 AIME 2024 pass@1 从 61.88% 提到 73.33%，Huginn 的 HumanEval 从 22.56% 提到 31.71%。更重要的是，部分设置可以把 recurrent depth 减半仍匹配或超过完整深度 Baseline，forward FLOPs 降低 22.5%–48.2%。

4. **RLVR 提升新能力时，可能同时支付“语言可读性税”。** [On Language Drift during RLVR Post-Training](https://arxiv.org/abs/2610.02015) 的理论结果是：在其形式化下，RLVR 优化允许无界的 language drift，而 SFT 不会；经验上，漂移主要出现在模型需要学习 Base Policy 原本无法直接抽出的 novel reasoning behavior 时。论文进一步证明，在其假设下，约束 drift 会约束可达到的 expected reward。这个结论不能被简化成“CoT 监控必然失效”，但它说明性能、语言稳定性与可监控性之间可能存在真正的 Pareto 冲突。

5. **个人 Agent 普及后，推荐问题会从集中式特征聚合变成 task-time evidence acquisition。** [AgentWebRec](https://arxiv.org/abs/2610.01705) 假设用户 Agent 持有本地长期语义和偏好，平台只能在有限查询预算内向目标用户 Agent、必要时向邻近 Agent 获取证据，再做融合。四个 InstructRec 数据集上都优于比较基线。它把推荐系统的新接口说得很清楚：**不是把所有 Memory 汇总到平台，而是在决策时决定“问谁、问什么、保留什么”。**

6. **多语言 Semantic ID 的主要脆弱点可能首先来自表示空间，而非量化器。** [Do Multilingual Encoders Produce Language-Consistent Semantic IDs?](https://arxiv.org/abs/2610.01139) 在 Amazon ESCI 上发现，Multilingual E5 的日文翻译与英文源商品只有 7.7% 保持相同第一段 SID code，而英文改写是 89.0%；将 codebook fitting 做得更“语言均衡”后，西语 first-code consistency 反而从 28.3% 降到 6.6%。distance-matched control 没发现 quantizer 特别放大语言方向，说明**均衡 codebook 使用率不能替代跨语言表示对齐**。

## 1. Finetuning with Sampling：别急着换掉 SFT，先让 Expert Data 变得“像这个模型会说的话”

[论文原文](https://arxiv.org/abs/2610.02140)

### 发生了什么

传统 SFT 可以学习完全 off-policy 的专家轨迹，但如果这些轨迹离 Base Model 的生成分布很远，模型就需要通过有限参数更新“跨很远”去拟合；RL / OPD 的优势则来自训练状态更贴近 Student 自己会访问的区域。

这篇工作反过来处理数据。作者把每条 Expert Trace 放进一个保持任务语义／正确性的 equivalence class，并用 MCMC 在其中搜索 Base Model 更高概率的表达。目标可以理解为把 Base Distribution 投影到“仍然正确”的轨迹集合：

$$
p_C(x)\propto p_{\text{base}}(x)\mathbf{1}[x\in C].
$$

训练目标仍是普通 next-token SFT；改变的是训练样本分布。

### 关键结果

| 结果 | 数值 |
|---|---:|
| Qwen2.5-7B-Instruct · Chemistry，Sampling SFT 相对 Base | **+31.7%** |
| 相对 OPSD 的增益优势 | **+4.20%** |
| Qwen2.5-3B · MATH500 相对 Base | **+33.7%** |
| Chemistry prior-capability average loss | **约 -1.10%** |
| 用 Olmo-boosted data 训练 Qwen 的 Chemistry | **57.33%** |
| 同设置 Vanilla SFT | **61.8%** |

作者还报告 Sampling SFT 的高-$k$ pass 曲线没有简单收敛回 Base Model，说明它并不只是把 Base 中已有的正确模式“磨尖”。

### 为什么重要

Post-training 常被粗略写成“off-policy data → SFT；on-policy data → RL / distillation”。这项工作提出另一条轴：**Data Distribution Engineering**。如果 Expert Trajectory 含有 Student 自己几乎不会采用的推理语言、组织方式或局部策略，先把它投影到 Learner 可吸收的区域，可能比直接修改 Loss 更有效。

它尤其适合“模型自己采不到成功轨迹，但外部专家确实知道怎么做”的任务：Scientific Skill、专有流程、少量高质量专家数据。

### 可信度与局限

MCMC 不是免费的。完整采样每一步可能需要候选生成、反向 proposal probability 和语义等价验证；论文实际也采用近似规则来降低开销。语义等价的 Judge 如果失误，数据会在“更像模型”时悄悄丢掉专家信息。

最需要警惕的是模型依赖性。Olmo 优化后的轨迹拿给 Qwen 反而显著退化，说明它不是一个“一次生成，全模型通用”的数据清洗器。

### 最值得继续追踪

看 Projection Sampling 能否用于 Tool-Agent Trajectory：保留相同 Tool Outcome 和最终 Artifact，只改写 Plan、Reasoning 与 Action Packaging，并测它是否能降低低成功率任务的 SFT 样本复杂度。

## 2. Multi-Teacher OPD：很多“算法差异”最后被 averaging 和 optimizer 重写了

[论文原文](https://arxiv.org/abs/2610.02179)

### 发生了什么

MOPD 希望一个 Student 同时吸收多个 RL Specialist。论文用从同一初始化出发的四个 Domain Teacher 分析 Qwen3-1.7B，并额外用 SmolLM3-3B 做诊断，沿着 **raw gradient → optimizer update → BF16 weight → task capability** 一层层跟踪信号。

最关键的观察是：你在公式中写下的 Teacher Weight，并不是最终真正作用在 Capability 上的权重。

### 关键结果

- global token averaging 会给长 Response 更高总权重；
- 不同 Teacher 的 update cosine similarity 约 **0.83**，换不同 averaging rule 后经过 Adam 一阶矩可升到约 **0.96**；
- 约 **97%** FP32 master weights 相对初始化发生变化，但只有 **7%–11%** BF16 weights 在存储精度下可见变化；
- top-64 intersection KL 的梯度已经很接近 full-vocab KL；
- 但数学任务上，同一近似在 response averaging 下比 sampled-token PG **+2.6 points**，在 global token averaging 下却 **-2.1 points**。

### 为什么重要

对大规模 OPD / MOPD Pipeline，loss 归一方式、batch 中不同 domain 的长度分布、Adam / momentum、master weight 与部署 precision、vocab KL 截断方式，都应被视为算法的一部分。

因此，复现 MOPD 工作时只复制 loss equation 并不够。实现层的 aggregation policy 可能已经改变了实际训练目标。

### 可信度与局限

研究规模仍集中在 1.7B / 3B，Teacher 还共享相同起点，现实生产的异构 Teacher 可能具有更大的表示差异。余弦相似度高也不代表 Capability Transfer 等价，因为少量关键方向足以决定特定技能。

### 最值得继续追踪

建立 **effective teacher contribution dashboard**：不只记录输入数据比例，还记录每个 domain / response 在归一化后占 Loss、Gradient Norm、Optimizer Update 和实际 Evaluation Gain 的比例。

## 3. LoopCD：把早期循环当作免费的“弱模型”

[论文原文](https://arxiv.org/abs/2610.02185)

### 发生了什么

Looped Transformer 重复运行同一个共享 Block。标准推理只使用最终 loop 的输出，但每个中间 loop 都已经对同一个 next token 产生一份较弱表示。

LoopCD 利用这个天然对齐关系：最终预测作为 strong view，早期 loop 作为 weak view，做 contrastive decoding。Logits 版本只多一次 output-head pass；Hidden 版本直接在 hidden space 构造对比信号，没有额外输出头成本。

### 关键结果

| 模型 / Benchmark | Baseline | LoopCD |
|---|---:|---:|
| Ouro-2.6B-Thinking · AIME 2024 pass@1 | 61.88% | **73.33%** |
| Huginn · HumanEval pass@1 | 22.56% | **31.71%** |

在四个 Looped Transformer Family 上，作者报告 full-depth 的 pass@1 普遍提升；进一步减少 recurrence 后，仍可匹配或超过 unguided full-depth Baseline，forward FLOPs 降低 **22.5%–48.2%**。

### 为什么重要

普通 Contrastive Decoding 往往需要额外弱模型、Draft Model 或双模型参数。Recurrence 天然产生一组从浅到深、共享参数且 prefix 对齐的 prediction。早期状态因此是非常便宜的“反例参照”。

更一般地说，循环架构不仅提供更多 Test-time Compute，也提供**同一 Token 在不同计算深度上的自监督信号**。

### 可信度与局限

这是 Looped Architecture 特有的红利，不能直接搬到普通 Transformer。headline 结果集中在相对小规模模型；forward FLOPs 减少也不保证 Wall-clock 同比例下降，循环带来的 kernel launch、batching 与 memory traffic 仍需要实际 Serving 验证。

### 最值得继续追踪

把 LoopCD 与 adaptive recurrence 合并：先用 early-vs-late disagreement 判断某个 Token 是否值得继续循环，再只对高分歧 Token 分配额外 depth。

## 4. RLVR Language Drift：推理能力上升时，CoT 可能变得更不像人类语言

[论文原文](https://arxiv.org/abs/2610.02015)

### 发生了什么

Reasoning Model 在 RLVR 后常出现奇怪缩写、非标准句式、半结构化符号或人类难以理解的“内部语言”。论文把这种现象形式化为训练后 CoT 分布相对自然语言／Base Policy 的 language drift。

作者证明，在其设定下，RLVR 的 reward maximization 允许 drift 无界增长，而 SFT 的训练形式不会具有同样性质；经验上，漂移主要发生在**模型确实需要学到原 Policy 无法直接采出的新 reasoning behavior**时。

### 为什么重要

如果 CoT 同时承担两种职责——模型的工作空间，以及人类／监控器的可观察接口——这两种目标可能并不完全一致。

模型为了最大化可验证 Reward，可能发现更短、更怪、但对自己有效的内部编码。此时“要求它继续使用人类可读推理”并非免费的可解释性约束，而可能直接限制可达到的 Policy。

### 可信度与局限

这里最容易被过度解读。论文的“不可能同时约束 drift 和不损失 reward”成立于作者的形式化假设，并不意味着所有现实系统都存在同样强的冲突，也不意味着可读 CoT 已经完全失去监控价值。

此外，可见 CoT 只是生成文本，不等同于模型真实的隐藏计算。观察到语言漂移，也不能反向证明它发现了更先进的“思维语言”。

### 最值得继续追踪

未来 RLVR 评估最好加入独立的 **capability–monitorability frontier**：任务 Reward、CoT linguistic drift、过程 Judge 可检测率、隐藏错误率同时报告，而不是把语言可读性当作“顺带拥有”的副产品。

## 5. AgentWebRec：推荐系统进入“Agent 间有限证据预算”时代

[论文原文](https://arxiv.org/abs/2610.01705)

### 发生了什么

AgentWebRec 假设用户拥有长期运行的个人 Agent，它保存比平台用户向量更丰富的私有语义。平台在一次推荐决策中不能无限读取这些 Agent Memory，只能做有限次数查询。

系统先使用平台提供的 item semantics，再读取目标用户 Agent 中与当前候选相关的证据；如果本地信息不足，才条件式查询邻近用户 Agent，以获得补充偏好模式。底层 Memory 保持在各 Agent 本地，平台只消费按任务返回的证据。

### 关键结果

论文在四个 InstructRec 数据集上都超过比较 Baseline，Ablation 显示 target-user private evidence 与 neighbor evidence 提供互补增益。摘要没有提供一个适合跨数据集复述的统一 headline effect size，因此这里不人为拼一个平均提升数字。

### 为什么重要

当 Personal Agent 真正持有大量私有状态时，推荐接口会从集中式用户特征输入，变成 platform evidence 与 budgeted agent queries 的动态融合。它与 RAG 的本质越来越接近：关键不是“是否拥有所有信息”，而是当前决策预算下应该去哪里取证。

### 可信度与局限

“Memory stays local”不自动等于隐私问题解决。Neighbor Agent 仍可能通过回答泄露敏感偏好，恶意 Agent 也可能投毒证据；现实系统还需要权限、匿名化、信誉、可撤回授权和 Evidence Provenance。

实验目前是公开推荐数据集，没有真实多 Agent 生态与线上 A/B，因此更适合作为一种系统抽象，而不是已证实的生产架构。

### 最值得继续追踪

把 Agent Query 变成显式成本，并评估 **recommendation gain per evidence token / agent call**。真正有价值的系统应能证明“多问一个 Agent”在哪些 Query 上值得付出隐私和延迟成本。

## 6. Multilingual Semantic IDs：同一个商品，换一种语言就可能换了一整条 ID

[论文原文](https://arxiv.org/abs/2610.01139)

### 发生了什么

Generative Retrieval 用 Residual Quantization 将 Item Embedding 变成离散 Semantic ID。直觉上，如果 Encoder 是 multilingual，同一商品的英文、西语、日文表达应该落在近似位置，并共享相似 SID。

论文在 Amazon ESCI 上测试 Multilingual E5 后发现，这个假设远没有那么稳。

### 关键结果

| 设置 | First-code consistency |
|---|---:|
| 英文 source vs 英文 rewording | **89.0%** |
| 英文 source vs 日文 translation | **7.7%** |
| 西语 translation · English-heavy fit | **28.3%** |
| 西语 translation · language-balanced fit | **6.6%** |
| 西语 translation · English-only fit | **67.6%** |

作者又构造 distance-matched product-directed control：当移动距离与 translation-induced shift 相当时，full-SID mismatch 也相近，没有证据表明 quantizer 特别会放大“语言方向”。

### 为什么重要

Generative Recommendation 常把 Semantic ID 稳定性当作 Quantizer 问题：增大 Codebook、均衡使用率、降低 collision。但跨语言场景中，第一层问题可能已经发生在 Encoder Geometry。

一个危险的指标错觉是：**codebook utilization 更均衡，但同一商品在不同语言里反而更不一致。** 这说明“离散空间看起来健康”不等于 Item Identity 稳定。

### 可信度与局限

这是一篇短论文，实验集中在一个 Multilingual Encoder 和 Amazon ESCI；它没有直接报告跨语言 SID 不一致对 end-to-end recommendation / retrieval 的最终损失。

因此当前最稳妥的结论是：上线 multilingual generative retrieval 前必须显式做 identity-consistency audit，不能仅凭 multilingual pretraining 或均衡 codebook 推断一致性。

### 最值得继续追踪

训练目标中加入 **translation-invariant SID constraint**，同时监控它是否牺牲语义区分度。最重要的指标应同时看 cross-language prefix consistency、collision rate、retrieval recall 和语言内 relevance。

## 今日值得收藏的代码 / 学习资源

### Strata：把 125B MoE 的 Expert Paging 做成普通 PC 上可运行的本地 Runtime

[GitHub：Niko1221/Strata](https://github.com/Niko1221/Strata)

Strata 面向 Qwen3.8-Flash-Next 125B 这类大量小 Expert 的 MoE。官方 README 的硬件下限是 **12 GB+ VRAM**、32 GB+ RAM，而不是一些二手讨论里的“8GB 显存”；核心思路是 GPU 常驻热 Expert、RAM 保留完整 Expert、CPU 并行处理冷 Expert，SSD 保存大型查找结构。

官方 RTX 5070 12GB + Ryzen 5 7600 + 64GB RAM 的 Q2_0 数据约为 94 tok/s generation、2650 tok/s 32K prompt processing。最近社区里也出现 RTX 3090 + 128GB RAM 的独立实测，但样本很少、配置差异很大，不能把一两个帖子当成统一性能保证。

真正值得看的不是单一 tok/s，而是 **expert hot-set prediction + GPU/RAM/SSD tiering** 如何把稀疏模型的参数容量问题转换成可调的 memory hierarchy 问题。

### Looped Models Part II：到达 Fixed Point 后，训练与 Serving 可以少做很多重复工作

[项目仓库](https://github.com/ifm-ai/xllm-loop)  
[论文页面](https://www.alphaxiv.org/abs/2610.looped-models-fixed-points)

这项工作把 recurrent state 的“逐渐收敛”当成系统资源：截断 BPTT、terminal KV sharing、Student Prefill Distillation，以及直接从 rollout state 做 RL backward。作者报告 terminal KV 可以从 12 个 bank 缩到 4 个；训练得当时 1.6B 模型 terminal-sharing 配置的 downstream average 可保持约 60%，而 naïve sharing 会在部分任务严重掉分。

最重要的工程教训是：**Fixed-point reuse 需要训练时适配。** 直接把一个按 full recurrent cache 训练的模型硬改成 terminal sharing，GSM8K 这类任务可能发生灾难性退化。

### Request-vs-Label Audit：Synthetic Simulator 的“下一步行为”不等于用户明确想要的东西

[论文](https://arxiv.org/abs/2609.39696)  
[代码](https://github.com/Sanjeev-S/recsys2026-request-audit)

作者审计 RecSys 对话数据后发现，在明确提出具体歌曲的开发集 turn 中，官方 target 有约一半与用户请求冲突：label 更像 simulator policy 选择的“下一首歌”，而不是当前请求的 ground truth。

只加入很小规模、catalog-resolved 的补充训练，在 43 个 conflict turns 上 nDCG@20 相对提高 53.3%，同时没有明显伤害官方指标。对所有 Synthetic User / LLM Simulator 数据都值得问同一个问题：**你训练的究竟是用户意图，还是模拟器自身的策略偏好？**

### AI Agents Need an Undo Button：长期 Agent 需要补偿语义，而不只是日志

[CACM 原文](https://cacm.acm.org/blogcacm/ai-agents-need-an-undo-button/)

这篇工程文章的关键点是：Audit Trail 只能告诉你 Agent 做过什么，不能让现实世界恢复。对文件修改可以 snapshot rollback；对数据库、订单、邮件、权限和外部 API，需要显式 compensation / idempotency / checkpoint 设计。

很多动作不存在真正的“撤销”——邮件已经被人读到、订单可能已经发货。因此生产 Agent 的安全接口应区分 **reversible state mutation、compensatable action、irreversible side effect**，再决定自治级别。

### FineSID：Semantic ID 的 Codebook 不一定需要硬分配才能训练

[论文](https://arxiv.org/abs/2609.36670)

FineSID 用 soft global-local quantization 让梯度传播到全部 codeword，同时 forward 仍保持 hard assignment。三个约 2.5 万商品的 Amazon 数据集上，作者报告相对 CAR 的 Recall@10 从 0.0624→0.0703、0.0455→0.0514、0.0947→0.1031，并展示更高 codeword utilization。

它适合与今天的 multilingual SID 工作一起读：FineSID 解决的是**量化器训练与 codebook 使用**，跨语言论文暴露的是**输入表示几何的一致性**。两层问题不要混成一个“SID quality”指标。

## 今日最值得花 30 分钟阅读的一项

**首选 [Finetuning with Sampling: SFT Learns Better Than You Think](https://arxiv.org/abs/2610.02140)。**

这篇值得读的原因不是“又一种 SFT trick”，而是它重新划分了 Post-training 的问题边界。过去我们习惯在 objective 空间里比较 SFT、RL、OPD；它展示了另一种可能：**先改造数据分布，使 privileged expert behavior 落到 Student 自己更容易学习的区域，再用最普通的 SFT。**

30 分钟重点看四处：information projection 的定义；MCMC proposal 如何保持语义等价；为什么简单 zero-shot rewrite 不够；以及 Olmo-boosted data → Qwen 的失败实验。最后这个负结果最重要，因为它说明“高质量数据”不是脱离 Learner 的绝对属性。

> **一条 Expert Trace 的训练价值，取决于它既包含新信息，又离当前 Learner 的行为分布足够近。**

## 今日可立即实践的一件事

给现有 SFT / Distillation 数据做一次 **Model-Native Data Audit**，先不训练新模型。

从 50–100 条高价值 Expert Trace 中，对当前 Base / Student 计算 length-normalized NLL；再让同一个模型生成 3–5 个**保持最终答案、Tool Outcome 或关键约束完全相同**的等价改写，并重新计算 NLL。把样本分成三组：

| 组别 | 特征 | 处理建议 |
|---|---|---|
| High expert quality + high model likelihood | 已接近 Learner 分布 | 直接 SFT |
| High expert quality + low model likelihood | 有知识但太 off-policy | 优先做 model-native projection |
| Low quality / semantic unstable | 改写后结果不稳 | 不应靠“更像模型”掩盖数据问题 |

随后只对第二组做一个很小的 A/B：原 Expert SFT vs 低 NLL 且经过 verifier 验证的 projected trace SFT。记录新技能 gain、旧能力 retention、pass@$k$、平均 trace likelihood 和 sampling / grading 成本。

真正需要回答的是：

> **你的 SFT 学不进去，究竟因为监督目标不对，还是因为专家演示离这个 Learner 自己能稳定访问的分布太远？**
