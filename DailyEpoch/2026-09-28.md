# 每日 AI 技术简报｜2026-09-28

> **今日主线：** Environment Evolution · Policy Composition · RAG Action Value · Agent Simulation · Evolvable Search Evaluation · Decision-Model Serving

本期重点关注环境成为自我改进对象、从已有策略预测新 RL 结果、RAG 动作价值、Agent 上线前模拟、持续变化的搜索评价标准，以及面向固定候选的低延迟评分服务。

## 今日核心判断

1. **环境准备本身影响 Agent 的能力表现。** Env-Rethink 将嘈杂工作空间重新建立 Collection Map 和 Event Log，并用学习式准备暴露有效证据。
2. **新 Reward 不总是需要新一轮 RL。** PoEM 利用已有 Policy 在 Log-policy 空间构成的低维 Basis 估计新策略变化，Coverage 可以判断哪些目标超出已有策略集合。
3. **当前答案的置信度与修改答案的收益不同。** Return or Revise 发现 Revision 既能修复错误，也会破坏原本正确的 Draft。
4. **On-policy Simulation 是上线前重要的中间门槛。** Nubank Snowglobe 用模拟用户和工具反馈让 Agent 真正经历自己造成的环境状态。
5. **搜索评价规则可外化成 Skill。** 快手 SEEK 通过动态 Skill Routing 降低每次业务标准变化都重新训练 Judge 的成本。
6. **固定候选决策值得专用 Score Serving。** SGLang 通过 Score API 与 Multi-item Scoring 复用共享 Query 前缀。

## 1. Env-Rethink：环境也应该成为可进化对象

[原始论文](https://arxiv.org/abs/2609.29773)

### 发生了什么

作者对比干净工作空间与存在碎片文件、旧版本和冲突证据的真实环境，发现同一个 Agent 在不同环境结构下差异显著。Env-Rethink 使用 Collection Map 和 Event Log 恢复文件与事件关系，再让模型验证证据、准备材料；Environment Evolver 还能生成新的版本冲突和虚拟事件。

### 关键结果

| 环境 | Evaluation-check pass rate |
|---|---:|
| Clean environment | 83.9% |
| Noisy environment | 57.6% |
| Qwen3.8-27B 环境准备 | 59.4% |
| Env-Rethink | **72.7%** |

另外，55 个已配对的 Terminal-Bench 任务中，有 32 个演化环境让至少三种模型成功率下降。

### 为什么重要

Agent 训练的可学习对象可以扩展到 Policy、Harness、Memory、Environment；有结构的环境减少搜索噪声，环境演化又可防止固定题库饱和。

### 可信度与局限

72.7% 是 check pass rate，不是完整任务成功率。环境变难也可能只是增加歧义或 Verifier 漏洞，因此必须同步维护 Reference Solution 和可执行检查。

### 最值得继续追踪

为每次环境变异保存 Seed、Event Mutation、生成文件、Reference、Verifier Version 与下游 Rollout 的可追踪谱系。

## 2. PoEM：预测一次 RL 更新会产生怎样的策略

[原始论文](https://arxiv.org/abs/2609.30226)

### 发生了什么

PoEM 基于已有 Reward 训练好的多个 Policy，在 Log-probability Ratio 空间拟合新 Reward 的方向。作者观察到不同 Post-training Policy 的变化经常落在近似低维子空间中，因此可用有限 Calibration Samples 估计组合 Policy，并用 Coverage 衡量新目标是否被已有 Basis 表达。

### 关键结果

| 方法 | 平均 Reward Error |
|---|---:|
| 实际进行第二次 RL | 0.12 |
| Top expert | 0.23 |
| PoEM | 0.28 |
| Best-of-16 Sampling | 0.37 |

在组合 Reward 实验中，经校正的 Basis 恢复目标 RL Reward Gain 的约 0.83–1.00。

### 为什么重要

多目标推荐、广告和 Alignment 会大量扫描 Reward Weight。如果新 Reward 只要求在已有行为间选择折中，完整新 RL 可能浪费训练成本。

### 可信度与局限

0.28 仍比真实 RL 的 0.12 更差；Coverage 低说明新目标可能需要新的行为能力，已有 Policy Basis 无法可靠外推。多完整模型组合还可能增加推理成本。

### 最值得继续追踪

同一 Backbone 的 Adapter / LoRA Basis：便宜扫大量 Reward，再只训练少量 Pareto Candidate。

## 3. Return or Revise：RAG 应预测动作的增量价值

[原始论文](https://arxiv.org/abs/2609.30087)

### 发生了什么

RAG 系统常基于 Draft Confidence 选择要不要 Revision。但“当前答案可能错”和“修改后会变好”不是同一个概率。论文对每个样本真实执行 Return 和指定 Revision，观察 Repair、Harm 和 Unchanged。

### 关键结果

25,870 个 held-out QA 样本中，Revision 修复约 9.32%–13.42% 的 Draft，同时破坏约 3.05%–3.33% 的正确答案。学习的 Return/Revise Policy 比 Always Revise 提高约 1.10–1.33pp，但仍执行了 38%–46% 的有害修改。

加入 Standard-RAG Answer 作为另一个 Action 后，Return-vs-RAG 在 Llama 系列比 Return-vs-Revision 高约 1.95–2.10pp。

### 为什么重要

错误检测和动作选择应被分离。Retrieval、Revision、Verification、Escalation 都应根据“执行后预计改善多少”分配成本。

### 可信度与局限

开放域 QA 的短期结果较容易评估，长程 Tool Agent 中一次动作会影响大量未来状态，其反事实价值更难预测。

### 最值得继续追踪

把 RAG Router 从 Retrieve/No-retrieve 拓展到 Return、Retrieve、Revise、Verify、Ask User、Escalate Model 的多动作决策。

## 4. Screen Before You Serve：多轮模拟比固定 Transcript 更接近线上

[原始论文](https://arxiv.org/abs/2609.30137)

### 发生了什么

Nubank Snowglobe 提供合成 Customer 和 Mock Tool Layer，让候选 Agent 真实选择动作并经历相应后续状态，先在安全环境中对完整多轮轨迹评估。

### 关键结果

四个已部署版本的模拟得分与线上版本级表现具有高度相关。团队报告平均迭代周期由 21.2 天降低到 4.4 天。Card Management A/B 中 Self-service Rate +4.90pp、tNPS +36.69 points；16,000+ 模拟对话筛选 Open-weight Model 后，实际 SSR +8.82pp、p95 Latency -25%，tNPS 变化不显著。

### 为什么重要

Agent 应先通过 Unit Tests、Static Benchmark、On-policy Simulation，再进入受控 Live A/B。模拟的关键是保留 Agent 自己造成的状态分布。

### 可信度与局限

Offline→Online 相关性仅基于四个部署版本，不能推导通用统计规律。模拟器若长期不吸收真实失效案例，也会逐渐被优化到饱和。

### 最值得继续追踪

将线上事故和新用户行为反向注入 Simulator，维持与实际环境同步的 Scenario Distribution。

## 5. SEEK：评估规则可以作为可版本化的 Skill

[原始论文](https://arxiv.org/abs/2609.29803)

### 发生了什么

SEEK 将 Relevance、Quality、Diversity、Authority 等搜索评价标准外化为 Skill Bank，根据当前 Query 与整页结果动态路由，再让 Listwise Evaluator 输出评判及失败归因。

### 关键结果

| 方法 | Binary Macro-F1 | 3-class Macro-F1 |
|---|---:|---:|
| Qwen3-8B | 0.4345 | 0.3988 |
| Qwen3-8B SFT+GRPO | 0.7206 | 0.6418 |
| SEEK | **0.7374** | **0.6555** |

持续反馈更新中，参数更新方案 Binary F1 为 0.7957，Skill-only 为 0.7921，后者在历史回放上的遗忘更小。

### 为什么重要

稳定能力保留在 Judge Backbone，频繁变更的业务规则放在可读、可审计、可回滚的 Skill 层。

### 可信度与局限

数据来自建设方，缺乏统一线上业务效应。错误 Skill 可能迅速影响大量判断，因此 Skill Store 需要 Provenance、Scope 和 Replay Gate。

### 最值得继续追踪

面向工业 Judge 的 Rule Versioning、适用范围及回滚机制。

## 6. SGLang Decision Models：有限候选不一定需要生成文本

[技术文章](https://www.lmsys.org/blog/2026-09-25-sglang-decision-models)

### 发生了什么

SGLang 通过 `/v1/score` 对固定候选输出 Label Score；Multi-item Scoring 复用 Query Context，限制候选之间的信息泄露，减少为每个选项重复 Prefill 的成本。

### 关键结果

| 模型（H200，16 候选） | Generate | MIS |
|---|---:|---:|
| Qwen3-0.6B | 39.6ms | **18.7ms** |
| Qwen3-8B | 54.1ms | **20.6ms** |
| Qwen3.5-4B | 84.8ms | **55.7ms** |

### 为什么重要

Tool Selection、Memory Ranking、Skill Routing 等高频决策可以使用低延迟评分 Fleet，开放式推理留给更强生成模型。

### 可信度与局限

不同 Prompt 形式不必然产生相同答案质量，Score 也并非天然校准后的 Correctness Probability。性能数据来自官方特定硬件及配置。

### 最值得继续追踪

联合对比 Decision Accuracy、P95 Latency、Cost 和模型升级后的 Calibration Drift。

## 今日最值得花 30 分钟阅读的一项

[PoEM: Predicting RL Outcomes from Existing Policies](https://arxiv.org/abs/2609.30226)。

重点理解 Reward 到 Log-policy 的线性关系、不同 Policy 变化为何可能近似低秩、Coverage 的校准方法，以及 Coverage 很低时为何应该运行新的 RL。它为多目标训练提供了一个“下一轮实验是否真正有新信息”的诊断视角。

## 今日可立即实践的一件事

对从同一 Base 出发的 3–5 个不同 Reward Checkpoint / LoRA 做 **Policy-space Coverage Audit**。在共同 Calibration Prompt 上采样 Response，记录各 Expert 与 Base 的 Log-probability Ratio，并拟合：

$$
r_{\mathrm{new}}(x,y)\approx
\sum_i\alpha_i[\log\pi_i(y\mid x)-\log\pi_{\mathrm{base}}(y\mid x)].
$$

记录 Held-out $R^2$、Combined Policy Reward、KL to Base、推理成本以及随后真实 RL 的 Gain。Coverage 低时不要以组合方法代替训练；Coverage 高时，可以先扫描目标权重并筛选少量完整 RL 候选。
