## 一、前沿论文与技术进展

### 1. OneTrans-GSR｜以单一自回归策略统一重排与混排（生成式推荐）

**发生了什么：** 将商品、短视频、直播、广告等异质内容的 reranking 和 mix-ranking 统一为 Decoder-only Slate 生成策略；完整页面列表由奖励模型评估，使用 RL 优化长期与全局目标，解码时显式满足业务约束。**关键结果：** 作者报告工业线上 A/B：GMV/u **+2.63%**、广告主价值 **+2.06%**、复购率 **+2.03%**，两阶段总延迟 **-13%**。

**为什么重要：** 从 Pointwise CTR/CVR 到 Listwise Slate Policy，优化对象变为有顺序、位置外部性和内容配额的完整曝光集合，能直接编码多目标权衡。**可信度与局限：** 有线上实验是亮点，但收益来自整体系统，无法把提升单独归于自回归结构或 RL；还需核对实验持续时间、流量分层、探索安全和成本。**最值得继续追踪：** Reward Model 的离线—线上相关性、强约束解码吞吐、策略分布偏移与长周期留存。原文：[arXiv:2611.04720](https://arxiv.org/abs/2611.04720)。

### 2. ReuseGR｜大模型离线规划 SID 前缀，小模型在线个性化补全（生成式检索）

**发生了什么：** 7B Planner 离线预生成共享 Query 的 Semantic ID 前缀，0.5B 在线模型依据用户历史选择前缀并补全后缀；ReuseCut 自适应控制缓存深度，Path KD 和基于 OPD/GRPO 的 BudgetCut 选择有限预算下的分支。**关键结果：** 论文报告相对全在线 0.5B 基线，HR@100 **+3.83 个百分点**、平均线上延迟 **-38.9%**；14 天用户级 A/B 的 CTR **+0.93%**、千次请求收入 **+1.05%**。

**为什么重要：** 把共享 Query 计算和用户个性化计算分离，是 Agentic Search 与电商生成式召回可以实用化的部署结构。**可信度与局限：** 包含工业数据和线上 A/B，但前缀命中率、热点 Query 分布、缓存更新/失效成本与新颖查询泛化仍影响实际收益。**追踪：** Query 长尾覆盖、Prefix Staleness、不同缓存深度的 Recall–P95 Pareto。原文：[arXiv:2611.04259](https://arxiv.org/abs/2611.04259)。

### 3. HARP｜用户与物品“双 Profile”的无训练推荐增强

**发生了什么：** 在冻结的 LLM 推荐主干外添加物品 Profile、可在召回阶段使用的 Profile 同质性评分，以及随新交互进行反思更新的用户 Profile，弥补只有用户画像且长期冻结的问题。**关键结果：** 作者报告在 Yelp、Books、MovieTV、Goodreads 四个公开数据集上，Hit@1 比最强已发表基线提升 **6.9%—24.0%**，并做多重比较校正。

**为什么重要：** 个人偏好/物品属性不一定应该全塞进 Reranker Prompt，画像信号先用于 Retrieval Gate 往往更便宜。**可信度与局限：** 代码已公开，离线数据集结果较完整；但没有证明生产流量中画像漂移、实时成本和群体偏差得到控制。**追踪：** Profile 召回门控与普通 Dense Retrieval 的增益拆分、Reflective Update 的污染风险、时序泄漏检查。来源：[论文](https://arxiv.org/abs/2611.05319) · [官方代码](https://github.com/Jove-Zhen/HARP)。

### 4. You don't need long context｜频繁压缩是否足以替代大窗口？

**发生了什么：** 研究在长周期 Agent 和长输入任务中频繁进行 Context Compaction，作者观察到在多个设置下维持较短上下文并未显著损伤成功率；报告部分前沿开源权重模型长位置 Token 的生成成本可高至早期位置的约 **7 倍**，并提出 Semantic State Space Models 的概念方向。

**为什么重要：** 对多轮 Agent，维护可恢复、可验证的语义状态可能比盲目扩展 KV Cache 更有性价比。**可信度与局限：** “不需要长上下文”是带特定任务、压缩器和预算前提的实验结论，不能推广到需要逐字证据、跨段精确引用或超长代码依赖的任务。**追踪：** Compaction 的信息丢失、任务成功率、累计 Token、首次/后续恢复时间及引用精确率。来源：[arXiv:2611.05306](https://arxiv.org/abs/2611.05306)。

### 5. LoopVQ｜Looped Transformer 的跨循环 KV Cache 亚 1-bit 量化

**发生了什么：** 利用 Looped Transformer 各循环步 KV 的冗余和不同量化敏感度，跨循环共同编码并微调 Codebook。**关键结果：** 作者在 Ouro/Huginn 上报告 **0.5 bit/element** 的表现，并在与 TaSQ 组合下测试到 **0.25 bit/element**；SGLang 实现于 32K Context 的 Decode Latency 近乎减半，1.4B/2.6B Ouro 峰值吞吐分别最多 **4.3×/6.1×**。

**为什么重要：** 循环模型参数省显存但 Cache 按 Loop 累加；其压缩维度与传统 KV Quantization 不同。**可信度与局限：** 数值针对特定循环架构，不能外推至常规 Transformer；峰值吞吐还强依赖 Batch、硬件、Kernel 与 Cache 长度。**追踪：** FP16/BF16 精度损失分布、长推理准确率、真实 QPS 下的 TTFT/TPOT、代码复现。来源：[arXiv:2611.05304](https://arxiv.org/abs/2611.05304)。

### 6. FourSight｜FP4 作为 RL Rollout 精度时，如何解决训练—推理错配

**发生了什么：** NVFP4 W4A4 Rollout 可能制造少量严重漂移序列，且部分激活通道量化误差特别大；FourSight 对失配轨迹进行序列过滤，并保留少量高方差通道 BF16，其他仍为 FP4，同时配套 SpliceGEMM。**关键结果：** 作者报告在最高 120B 规模测试中，达到近 BF16 质量、Step-to-Accuracy **1.76—2.60×** 改善，单步耗时相对 FP4 增幅在 **2.3% 以内**。

**为什么重要：** RL 系统不是仅追求 Kernel FLOPS；Rollout 政策分布与 Trainer 不一致会造成错误更新。**可信度与局限：** 论文结果未独立复现；“过滤坏序列”也可能改变采样分布、产生选择偏差。**追踪：** KL/Importance Ratio 尾部、有效样本占比、不同模型/硬件上的可复现性。来源：[arXiv:2611.04887](https://arxiv.org/abs/2611.04887)。

### 7. Stabilizing On-Policy Targeted Guidance｜把文本反馈用于失败步自蒸馏

**发生了什么：** 在多轮软件工程 Agent RL 中，针对策略失败的 Turn，把文本反馈变为 On-policy Self-distillation 信号，同时保留逐准则 RL Reward。作者强调仅在失败步启用指导，以维持熵的稳定并降低策略震荡。

**为什么重要：** 稀疏终局 Reward 难以纠正“哪一步错”，而逐轮语言反馈提供可操作的局部方向。**可信度与局限：** 目前证据集中于特定软件工程环境，Feedback Judge 偏差与 Teacher Leakage 未必可控。**追踪：** On-policy 覆盖、不同反馈密度的收益曲线、无教师终局评估及 Reward Hacking。来源：[arXiv:2611.05266](https://arxiv.org/abs/2611.05266)。

### 8. Meta²｜先离线学习“如何进化 Harness”，再在线选择 KEEP/EVOLVE

**发生了什么：** Offline 对照无 Evolver、普通 Evolver 与训练期可见特权 Verifier 的 Evolver 轨迹，提炼 Meta-Skill；在线只依据当次运行的可观察轨迹在 KEEP 和局部 EVOLVE 之间决策，不重置任务进度。

**为什么重要：** 自进化的瓶颈可能并非缺少编辑能力，而是不知道何时改、何时不改；把跨任务知识迁移到 Harness 修改策略比共享固定 Prompt 更灵活。**可信度与局限：** 训练期用特权 Verifier 产生的规则，部署时可能依赖不可见证据的替身信号；还应关注多次在线改写引入的可靠性与维护成本。**追踪：** 与固定 Harness、Always-Evolve 的等预算比较，回滚、安全隔离和操作数。来源：[arXiv:2611.05139](https://arxiv.org/abs/2611.05139)。

### 9. Continual AutoResearch｜跨任务记忆提高研究效率，但未必提高最终最好成绩

**发生了什么：** 让 5 类前沿研究 Agent 在 9 类任务上比较 Persistent 与 Reset 实例，控制任务序列、数据和时间预算，另外进行保留信息的消融。作者观察到持续状态让所有测试 Agent **更快找到强解**，但最终最优解没有一致显著提升。

**为什么重要：** “Agent 记住了过去”与“Agent 学会了迁移”不是同一个指标；评估自进化需要同时看 First-solution、AUC-over-budget、最终 Held-out。**可信度与局限：** 严格匹配的比较设计有价值，但任务族仍可能小于真实数据科学的分布转移。**追踪：** 显式策略摘要、原始 Trace Replay 与无记忆三者的效率和泛化差异。来源：[arXiv:2611.05108](https://arxiv.org/abs/2611.05108)。

### 10. QueryFlow｜多跳 RAG 让 Query State 随证据图演化

**发生了什么：** 在图检索迭代中，把当前 Query 与已获得的证据图上下文递归融合，再控制后续传播和邻接证据扩展，不再始终使用原始问题向量。**关键结果：** 作者在四个多跳 QA 数据集上报告相对代表性基线，平均 R@10 **+4.98pp**、Full Recall@10 **+8.40pp**、LLM Accuracy **+8.0pp**。

**为什么重要：** 对多跳问题，第二个证据片段可能只与第一个片段相关；静态 Query 很容易漏召回。**可信度与局限：** 对比受图构建质量和预定义边影响，未证明 Web 实时开放域可靠。**追踪：** Full Evidence Recall、图噪声、跳数与成本、在线停止策略。来源：[arXiv:2611.04625](https://arxiv.org/abs/2611.04625)。

### 11. Scaling Laws for Data-Constrained Dense Retrieval｜小样本微调的缩放规律

**发生了什么：** 基于 MS MARCO 子集训练 35 个 BERT 系双塔检索器，研究固定唯一训练样本数、模型规模与最小可达验证损失 MAEL 的关系，提出乘法幂律拟合，并探讨最优正则化时间尺度。**关键结果：** 在作者观察范围内，增大预训练模型规模在降低 MAEL 的微调算力效率上约为增加唯一领域数据的 **1.46 倍**。

**为什么重要：** 小数据场景下重复多轮训练不能视为获得更多独立样本。**可信度与局限：** 这是 BERT 系、特定数据量范围下的经验规律；对 Modern Embedding、跨语言、多模态/工业负反馈场景不宜直接套用。**追踪：** MAEL 与 NDCG、Recall 的关系及 OOD 外推。来源：[arXiv:2611.04979](https://arxiv.org/abs/2611.04979)。

### 12. When Category Means Move｜推荐日志中类别均值不等于类别因果效果

**发生了什么：** 基于 KuaiRand 随机插入曝光，同一批 **12,472 用户、5,486 视频**审计生产分发下的类别均值；部分校准能降低误差，但排序和 Top-k 策略遗憾值不稳定。研究明确指出大多数分解是描述性而非类别自身的因果效果。

**为什么重要：** 类别偏好看板往往混入曝光策略、用户选择、Item Mix 与位置偏差；直接用类别 CTR 高低决定后续分配可能强化反馈回路。**可信度与局限：** 具有随机支持对照值得重视，但只针对重叠用户、内容与日历，且家族校正后的若干比较区间包含零。**追踪：** Propensity 重叠、类别层校准、全局与分人群 Policy Value 的一致性。来源：[arXiv:2611.05006](https://arxiv.org/abs/2611.05006)。

## 今日可立即实践的一件事

**在现有 ShoppingAgentLab 或推荐候选排序模块中做一个受约束 Slate 生成小实验。** 选 100 条含商品相关性、类别、价格及广告标志的固定候选集合（可用合成商品数据）；分别实现 (A) Pointwise Score+Rule、(B) 贪心顺序生成+硬约束、(C) 带简化 Listwise Reward 的 Beam Search。每次在相同候选与相同约束下输出 10 个物品，记录 NDCG@10、类别覆盖、广告配额违例率、平均/ P95 推理时间、重排计算量。不要用模拟 Reward 的改善宣称线上 GMV 提升；若只有离线代理标签，结论应限定为“离线策略与工程性能”。
