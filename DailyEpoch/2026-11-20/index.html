今日主线： Agent 的竞争正在从“让模型完成一次任务”转向“让评测、任务生成、Harness 与推理系统形成可靠闭环”。本期优先看可复现的指标与失败边界：可执行检索评委、自演化软件工程 Agent、真实基础设施优化、长上下文注意力改造，以及开源扩散语言模型。

归档日期： 2026-11-20（Asia/Shanghai）。开始观察时刻： 2026-11-20 07:39 +08:00。优先报道窗口： 北京时间 11 月 19 日 07:39—11 月 20 日 07:39；因部分重要论文首次提交于 11 月 18 日 UTC，扩展研究观察至过去 72 小时（11 月 17 日 07:39 起）。文中明确区分“论文首次提交时间”和“今日关注时间”；这不是宣称所有成果于 11 月 20 日首发。

二、重点论文与技术进展

1. ExecJudges：让 LLM 为每个 Query 写一次可执行相关性评委

发生了什么： Can Programs Replace LLM Judges?（首次提交 11 月 18 日 UTC）不再为每个候选文档调用一次高价 LLM，而是让模型按照 TREC relevance guidelines，为每个主题生成几个可读的 Python 判分程序。程序仅使用词法、解析器、BM25/候选池统计等受限工具，最终由固定 rubric 转为等级；多个程序取平均后向下取整。

关键结果： 论文在 7 个 TREC collection 上评测；与 NIST 人工判断的吻合度在部分 TREC DL 数据上达到 Claude Sonnet 5.5 Judge 量级，官方系统排名 Kendall τ 为 0.87—0.94；每个主题一次性程序生成成本约 0.17—0.49 美元，后续判分无需模型 API 调用。详细方法见原始 HTML 全文。

为什么重要： 这不只是降成本，而是把“Judge 判分标准”变成可审查、可版本化的代码。搜索、RAG 与购物助手的离线评测，都能将稳定约束（价格、品牌、容量、日期）交给程序，语义匹配与主观偏好留给模型。

可信度与局限： 数据、对照和 system-ranking 证据较完整，但语义改写、跨语言、隐含意图以及 program 被优化目标反向利用仍是风险。作者也讨论 evaluation gaming；不能把“程序与 Judge 一致”自动当成“程序等于用户满意”。

最值得继续追踪： 对不同 query 的程序可否泛化；在中文商品检索、多条件过滤中，负控（反事实价格/单位）能否稳定抓到错误；独立人工样本上是否仍维持系统排序。

2. AHE-Beta：Harness 的进化目标从 Benchmark 变成可验证需求

发生了什么： Agentic Harness Engineering Beta（11 月 18 日 UTC）使用三段闭环：模拟用户在多轮使用中提出真实需求形式的 issue；多角色团队修改 Harness；只有解决已验证需求且通过审查才选择变更。它针对以往自修改容易堆积 benchmark 专用补丁的问题。

关键结果： held-out pass@1 从 21.9% 到 33.3%，tokens 少 40.8%；真人盲测 48 个有效配对中有 31 个偏好 AHE-Beta；未经进一步进化迁移到其他模型仍报告收益。

为什么重要： Agent 能力取决于模型、Prompt、工具、权限、状态机和回滚策略的组合。单独优化模型分数可能掩盖 Harness 的真实工程缺陷。该工作提供了“需求—修改—回归测试—批准”的可治理闭环。

可信度与局限： 实验包含 held-out 与真人对照，证据好于只在训练 benchmark 上报告胜率；但模拟用户可能偏向熟悉的任务分布，持续上线后的技能退化与维护成本未充分覆盖。

最值得继续追踪： 需求是否来自真实失败轨迹；规则变更是否有不可变审计；如何防止进化 Agent 修改测试本身而假性涨分。

3. SWE-Growth：学生全失败的样本也可以用于训练

发生了什么： SWE-Growth（11 月 18 日 UTC）指出二元修复奖励下，同一组 rollout 全失败时组内无优势信号。它让 Teacher 提供经过验证、学生尚未掌握的修复，在 SFT 阶段利用全失败但教师成功的任务；之后再把可区分成功/失败的任务送入 RL，并反过来调整后续任务注入器。

关键结果： 从 101 个初始 issue 出发，Qwen3-Coder-30B-A3B-Instruct 的 SWE-bench Pro 从 27.7% 到 31.7%，held-out TerminalBench 2.1 从 11.0% 到 17.2%；与学生自博弈及教师增强自博弈相比有增量。

为什么重要： 在 Agent RL 中，不应把“当前策略不会做”误判成“任务没有训练价值”。Teacher 成功与 Student 失败之间的差异可用于主动课程选择。

可信度与局限： 论文给出了预算相近的对照，但教师成本、验证器误判、泄漏和长尾 issue 分布仍影响生产化。增益是作者设定上的结果，不等于所有 Agent 工作都能复制。

最值得继续追踪： 训练任务的去重和可达性；教师出错时是否放大噪声；随学生能力提升，任务生成器能否真正保持新颖度。

4. RSIBench-Infra：别再只凭 kernel 微基准证明 Agent 会优化系统

发生了什么： RSIBench-Infra（11 月 18 日 UTC）提供 20 个训练/推理真实任务，覆盖 NVIDIA GPU 与 Ascend NPU，最多 32 个加速器。Agent 可修改引擎、kernel、指令等层次；OCI image-layer 保存变更，独立执行端到端验证，并带任务质量约束。

关键结果： 全部任务结果中有 66.2% 超过 1.10× 经验证的速度提升，但论文也明确指出把局部优化转成稳定端到端收益仍困难。

为什么重要： 自动优化的真正 KPI 是固定正确性/SLO 约束下的吞吐、时延及美元成本，而不是仅靠单一算子快多少。尤其 Agent 生成 kernel 时必须防止数值精度回退。

可信度与局限： 跨硬件和整体执行评测强于纯 microbenchmark；任务集 20 个、硬件配置与预算可迁移性仍有限。

最值得继续追踪： 是否公开可运行 OCI 镜像和完整日志；当优化跨越 KV-cache、调度、量化三层时收益是否可归因。

5. FlashMorph2：混合注意力层选择应在实际执行分布中优化

发生了什么： On-Policy Morphing into Hybrid Attention Models（11 月 18 日 UTC）分析把 full attention 逐层替换成 linear attention 时的两种错配：连续插值/teacher-forced hidden state 不等于部署时的离散混合模型；冻结权重选择层也没有考虑恢复训练后的适应。

关键结果： FlashMorph2 对离散架构端到端评分，并与恢复训练联合优化。作者报告对 FlashMorph 的 RULER 平均 +2.42、LongBench +1.08、recall-intensive tasks +0.76；0.6B—8B 模型层选择耗时 0.72—3.57 GPU 小时。

为什么重要： 它是一个普遍的训练/部署一致性问题：筛选阶段评估的模型必须尽可能等同真正运行的模型。对于长上下文检索，少量 recall-intensive layer 错置就可能掩盖平均分提升背后的 needle retrieval 崩溃。

可信度与局限： 结果是已公开论文的作者测量；仍需给出实际 KV/HBM、TPOT、prefill、恢复训练总计算预算对比。选层快不等于服务便宜。

最值得继续追踪： 32K/128K/256K 下的精确检索与多跳保真；训练时和不同硬件推理时是否仍成立。

6. Clover-35B-A3B：扩散语言模型向可运行 Agent 工作负载靠拢

发生了什么： Clover 技术报告（11 月 18 日 UTC）发布 35B 总参数、约 3B 激活参数的块扩散 MoE，结合 Gated Delta Network 的历史记忆和块内双向 softmax attention。官方提供 GitHub 代码 和 Hugging Face 权重与模型卡，Apache-2.0。

关键结果： 报告声称 SWE-bench Verified 73.6、Terminal-Bench 2.1 51.7，在单 GB300、BF16、batch=1 的内部 Agent 任务上实现 680 tokens/s。官方 README 说明基于 Qwen3.6-35B-A3B，128K 上下文；部分后端和 SFT 代码仍标注后续提供。

为什么重要： 扩散/多 token 并行生成是否能在工具调用与高约束代码任务里取得优势，终于有可下载的具体模型可验证。

可信度与局限： 权重及仓库存在是真实证据，性能数字目前主要来自发布方。680 tokens/s 不能脱离输出长度、验证次数、GPU、成功率直接对比 autoregressive 吞吐；官方也提醒不同后端的数值差异会改变生成文本。

最值得继续追踪： 同显存预算的成功任务/秒、工具调用格式正确率、长上下文回忆、量化后准确率和跨后端一致性。

7. Piccolo：共同进化数据与决策模型，loss 下降未必代表决策更好

发生了什么： Piccolo（11 月 18 日 UTC）提供 0.8B—27B 多模态候选决策模型，把 Agent 驱动的数据筛选、语义切片、实验结果和研究记忆接入迭代；目标不是单次回答文本，而是对候选答案/动作作判断。

关键结果： 作者报告 Piccolo-27B 在 Decision Index Vision Full 得分 75.59；另有两个结论值得注意：小模型可用目标数据在专项流程逼近大模型，训练 loss 持续下降也可能与离散决策准确率脱钩。项目页面提供进一步细节。

为什么重要： 推荐/排序、Judge、技能选择都关心候选间决策；“连续概率更好”并不保证 Top-1 选择正确。这是模型和数据选择联合优化的一个可测试假设。

可信度与局限： 权重和工具开放增强可检验性；仍需第三方固定候选池、成本、数据重叠和负控测试，不能直接套用官方排行榜名次。

最值得继续追踪： 错误决策切片能否触发定向数据生成，同时不伤害别的切片；不同候选数 K 下的 ECE 与 Top-1 accuracy。

8. QDA：让 Agent 搜量化配方，但先解决便宜可靠的代理指标

发生了什么： QDA（11 月 17 日 UTC，属 72 小时观察）使 Agent 循环选择 PTQ 方法、构建候选、估计质量；以未向 Agent 暴露的推理轨迹上的输出 KL divergence 做快速代理评估，并用长生成测试拦截循环重复等失败。

关键结果： 作者报告相对最佳公开配方，W4A16/W4A8/W3A16 平均准确率分别 +0.9/+1.4/+2.2 个百分点，每次搜索 64 GPU 小时；在指定 320B MoE 的 NVFP4 W4A4 上恢复 FP8 准确率的 98.3%。代码库、评价器与 Harness 在报告中属于“将发布”，不能当作已可立即复现。

为什么重要： 量化搜索最贵的不是提出配方，而是验证每个配方；如果能找到与最终推理任务相关的廉价代理，可把人工调参转为实验搜索。

可信度与局限： 量化收益依赖模型、校准数据、任务和内核；KL 小不保证工具 JSON 结构、rare tokens、长 CoT 都保真，且搜索总 GPU 账不可忽略。

最值得继续追踪： 独立复现与开源时间；3/4-bit 下的排序一致性、长链重复率和量化校准的时点泄漏。

9. AWS KV-aware routing：Prefix Cache 命中不仅是模型内核问题

发生了什么： AWS 于 11 月 16 日推出 SageMaker 实时端点 KV-aware routing；与固定前缀哈希不同，它从 vLLM 获取缓存区块存储/淘汰事件，将请求送往实际持有最长匹配前缀且负载可接受的实例。官方公告及工程博客提供配置与实验。

关键结果： AWS 在 Llama 3.1 70B、7 台 p5.48xlarge、多轮长上下文负载下，对随机路由报告 p50 TTFT 最多降低 97%，吞吐最多增加 234%，cache hit 从 3%—48% 提升到 80%—93%。支持 vLLM 指定容器、至少 2 个实例/组件副本。

为什么重要： Agent 多轮执行和 RAG 共享系统提示特别容易浪费 prefill，调度层若不知道 KV 实际淘汰情况，就可能把所谓“缓存亲和”变成重复计算。

可信度与局限： 官方可复现实验优于纯宣传数字，但收益是随机路由基线及指定长提示负载下的上界，短提示、低负载、跨租户隔离会改变结论；发布于 11 月 16 日，不是今天的新功能。

最值得继续追踪： 与 PREFIX_AWARE、负载最少路由、真实 Prompt Cache 的多租户隔离和 p95/P99 比较。

三、工程判断｜将上述进展转成实验设计

  • 评测先于改进。 ExecJudges、AHE-Beta、SWE-Growth 三条线共同提醒：优化者与评价者不能共用完全相同、可被轻易迎合的信号。建议固定人工评测小集、保留负控、禁止修改基准任务。
  • 总成本先于单点速度。 RSIBench-Infra、QDA、KV-aware routing 不能只报道峰值。应同时报告 $\mathrm{cost/success}$、P95、峰值显存和任务质量；优化搜索本身花掉的 GPU 小时要摊销。
  • 模型决策应按业务约束分层。 对购物/推荐任务，价格、库存、可售范围等 hard constraints 用确定性执行器；LLM/小型决策模型负责语义偏好与排序；最终判断用独立样本校验，而非仅看模型 loss。

  1. Agent Harness 的需求驱动演化：论文与工程社区均出现 Harness 进化讨论，但缺少符合时间窗口且能阅读技术正文的两位独立 X 作者原帖；不计入热议。

今日最值得花 30 分钟阅读的一项

ExecJudges：Can Programs Replace LLM Judges?。建议用 10 分钟读 §3 的程序生成与三评委合成，再用 10 分钟看 §5 的相关性/系统排序结果，最后 10 分钟读 §6 的失败案例和 evaluation gaming。核心研究问题不是“规则能否取代语义模型”，而是哪些高频、可验证的判定应该从模型调用迁移到可审计程序。

今日可立即实践的一件事

给 ShoppingAgentLab 加一个“可执行评委 + 反事实负控”小实验。 从现有购物 Query 中抽取 30 条、按商品快照冻结结果池；将价格区间、规格、品牌禁用、库存等解析成 Python 断言；同时保留一个独立 LLM relevance judge 与人工复核样本。对每个 Query 生成 2—3 条反事实候选（例如 128GB→64GB、价格超预算 1 元、缺少库存），观察规则误放率、LLM 误放率、人工 disagreement、NDCG@10 和每 1,000 个候选的评测成本。只有在真实候选与负控上同时通过，才让程序判分替代高成本模型调用。
