今日主线： 这一轮值得关注的不是又一个 Agent 演示，而是三种可以独立测量的能力：让不同 Harness 的救援经验迁移到策略参数、将工具观察压缩为行动充分的隐状态、让检索与长期记忆拥有可验证的状态边界。在评测侧，Benchmark 子集的尾部风险和多模态视觉检索的证据遗漏，值得直接纳入工程指标。

归档日期： 2026-11-08（Asia/Shanghai）。执行起始时间： 2026-11-08 07:26:18 +08:00。优先观察窗口： 2026-11-07 07:26 至 11-08 07:26（北京时间）。周末新论文召回较少，依据内容规范扩展至 72 小时（11-05 07:26 起），并对 10-31 至 11-04 首次公开、但 11-06 仍获新讨论或资源更新的研究采用 7 天持续观察窗口。下文将论文首次提交日期与本期关注日期分开，不把早期论文称作“今日新论文”。数字均为作者或项目报告，尚非独立复现结论。

二、重点精读：训练、推理与 Agent

1. Harness-S：通过“兄弟 Harness 救援”训练出更强的基础 Agent

发生了什么。 上海交通大学等作者提出 Directional Harness Evolution，沿不同失败方向创建专门的 sibling harness；基准执行环境的初始尝试全部失败时，才让同一策略在辅助 Harness 中重新采样 Rollout，并用成功的救援轨迹替换失败组进入 RL 训练。Router 依靠 Harness 行为画像选候选，并随着模型变化重新校准。论文首次提交于 11 月 3 日，11 月 6 日进入 Hugging Face Daily Papers 的活跃讨论。

关键结果。 作者在 AppWorld、SWE-Gym、DBBench 上报告：训练完成后，把模型放回最初的基础 Harness，表现仍优于仅训练策略的基线。这一点比“推理时切换到更好的 Harness 获得高分”更有说服力，因为它检验了能力是否迁移到参数，而不是把额外工具脚手架当成模型能力。

为什么重要。 对 Coding / Browser / Shopping Agent，可以把 Harness 当作探索环境的一个维度，训练目标则是：在不改变生产 Harness 的情况下提高真实任务成功率。这同时提示，应将模型权重、工具 Schema、重试策略、观察格式分别版本化。

可信度与局限。 有论文和代码，但三类 Benchmark 不等于开放环境长期鲁棒性。失败组替换可能引入选择偏差，训练成本也包括生成和评估 sibling harness 的费用。需排除“额外 Rollout 数量”本身带来的收益。

最值得继续追踪。 固定总 Tool Calls / GPU-hours，比对 rescue 频率、未见 Harness 的泛化、工具异常与测试不可访问时的回退行为。原始来源：论文 · 代码。

2. Coca-Cola：工具输出不一定要先翻译成文字再让 Agent 消费

发生了什么。 清华大学团队将搜索工具返回的长观察压缩成连续 Latent Tokens，直接进入 Agent 输入嵌入空间。关键训练目标是 Action-Preserving Training：让完整观察和压缩观察下的下一步行动分布尽可能一致，而非只追求文本摘要可读性。

关键结果。 在四个 QA Benchmark、两个模型系列的 Web Search Agent 实验中，作者报告 Token 消耗减少 70.01%～89.24%，端到端时长减少 24.45%～55.97%，同时任务表现改善。仓库公开了 Vanilla、文本摘要、LLMLingua 与 Latent 方法的运行入口。

为什么重要。 传统 RAG 通常优化文档检索与摘要；这项工作把问题改写为什么信息足以维持后续决策。对于高频 Search Agent，Token Budget 可以从“可读证据量”转向“决策信息量”优化。

可信度与局限。 测试集中在搜索问答，无法直接外推到有严格可追溯性、金融解释义务或需要原文逐字引用的任务；连续状态也更难做人工审计和跨模型迁移。Token 节省不等于同幅度真实费用节省，还需计算压缩器本身的时间和显存。

最值得继续追踪。 把回答正确率、行动一致率、关键数字保真率、引用可追踪性与成本一起评估；在 ShoppingAgentLab 的商品规格、可售区域和价格工具结果上做 Hard Constraint Test。原始来源：论文 · 代码。

3. Muir：线性注意力从“状态大小”走向“操作敏感性分配”

发生了什么。 Muir 分析 Gated Delta 类状态更新，发现擦除（erase）与写入（write）对不同通道和最终性能的敏感性不同，因此对擦除采用较低秩参数化，并使用 Matched-Filter Readout 重新平衡状态行贡献，再把节省的参数用于 FFN；训练端采用更稳定的并行更新。

关键结果。 在 166M～1.34B 模型规模上，作者报告相对 GDN-2 更低的困惑度。1.34B 实验中，从 4K 训练长度外推到 10M token 流，1M token Passkey 近乎全部找回；32K 训练吞吐相对 Transformer 达 2.7×。这些是特定模型与任务的作者实验，不是所有长文推理都能无损处理 10M token 的证据。

为什么重要。 长上下文不只有 KV Cache 压缩这一条路线。固定状态模型能避免标准全注意力随上下文增长的缓存成本，但受制于状态写入覆盖与读出干扰，门控设计本身就是系统效率问题。

可信度与局限。 规模上限 1.34B，与最先进大规模 MoE、复杂多跳 Agent Workflow 的可比性有限；Passkey 是必要但不足的长期推理指标。需控制训练 Token、数据、宽度及真正的在线 Decode 吞吐。

最值得继续追踪。 4K/32K/128K/1M 下的事实更新冲突、跨文档多跳与长程顺序事件恢复，以及模型训练和推理总成本。原始来源：论文。

4. SAE Interprets MoE：从路由频率改为语义特征贡献审计

发生了什么。 字节跳动 Seed 研究者在 MoE Block 输出上训练 Sparse Autoencoder。由于 SAE Encoder 仿射结构，单个 Latent 的 Pre-activation 能按 Expert 输出分解，由此估计哪个 Expert 实际驱动哪个语义特征，而不是仅统计 Router 选中次数。

关键结果。 在 Qwen3-30B-A3B 第 4、30、46 层的作者分析中，多数 Latent 主要由一到两个 Expert 驱动；一些 Expert 的细粒度分工体现为 Java、前端、几何、算术等。已公开 SAE 权重、贡献统计和复现实验脚本。

为什么重要。 对 MoE 路由优化、Expert Pruning、异常分布检测、量化精度分配，贡献矩阵比粗粒度“专家所属领域”更接近因果诊断的起点。

可信度与局限。 特征解释仍包含自动命名和阈值选择；SAE 的线性贡献分解不自动证明干预某 Expert 会引起特定行为变化。完整追踪环境资源重：项目说明使用两张 80GB GPU。

最值得继续追踪。 对 Dominant Expert 做干预与重路由，检验 Latent 功能变化及 Token 级 Loss；比较贡献大小与 Expert 量化敏感性的相关性。原始来源：论文 · 代码及权重入口。

5. VFlash：结构化计划的并行预测替代逐坐标自回归

发生了什么。 NVIDIA 等作者面向点、框和轨迹等视觉原语，使用轻量 Drafter 一次预测完整结构，并根据原语类型处理不同长度、维度与约束。训练和接受规则不强求与自回归模型逐 Token 完全一致，而关注几何结构是否合法和任务结果。

关键结果。 论文报告 3D 点运动预测单次 Rollout 的初步生成速度约 25×，下游 World Action Model 在四套 MolmoSpaces Task Suite 上平均成功率 70.2%，对照 62.6%。

为什么重要。 对 Agent 的计划表示不必是自然语言，结构化动作可以通过并行 Head 显著减轻序列解码瓶颈。这与 Semantic ID、结构化 JSON 和 Action Token 的解码约束设计有方法层面的联系，但不能直接照搬性能结论。

可信度与局限。 “约 25×”来自初步单 Rollout 测试，不能当作端到端机器人系统提速；安全约束、异常动作和分布外物体仍需单独验证。

最值得继续追踪。 结构化计划接入成本、真实推理延迟分位数、错误轨迹的物理可执行性及控制频率。原始来源：论文。

三、推荐、检索、记忆与评测

6. Trainable [DUMP] Tokens：为检索向量中的无用残留提供出口

发生了什么。 CIKM 2026 工作在 Embedding Encoder 输入前添加可学习的 [DUMP] 前缀 Token，不改 Pooling、架构和 Contrastive Loss，让无信息 Token 的干扰在训练中重新分配。作者报告对 Encoder 与 Decoder Embedding、常规检索和长上下文检索均有改善。

为什么重要。 在商品、文档和多轮检索中，最终向量要压缩“主语义”同时避开冗余模板、格式与 Attention Sink。相较重做整个 Retriever，训练前缀的实验成本低，更适合 A/B Ablation。

可信度与局限。 论文没有证明该机制在所有 Backbone、所有 Pooling 策略或 OOD Query 上都有效；需警惕仅通过额外可训练参数受益。最值得继续追踪： 与 Learnable CLS、普通软提示、Pooling 改造比较，另测商品属性硬约束召回和 Query Drift。原始来源：论文。

7. VisSearch-Bench：视觉检索需要验证证据链，而非单张图识别

发生了什么。 蚂蚁集团等作者发布 204 条人工撰写任务，涵盖集合式、序列式、宽深结合、竞争消歧和结构引导五类视觉搜索，提供可追踪证据与 Process Score。在 16 个多模态模型中，作者报告最优完整任务成功率仅 26.47%。

为什么重要。 对图文购物助手，“识别图里的鞋”远远不够；真正困难的是跨多张图、规格参数、商品页面和先前问题连接证据。最终答案准确率与证据链完整度应当分开。

可信度与局限。 204 题规模较小，样本构成和 Tool Access 控制可能影响排序；Process Score 的判定一致性需要复核。最值得继续追踪： 对照 Query-only、视觉召回、图文联动搜索，检查多跳完成率、证据覆盖率与预算。原始来源：论文。

8. EvoMemState：长期记忆不是越来越长的事实列表

发生了什么。 工作把记忆拆为 Persistent Facts、描述事实关系及有效范围的 Relational State，以及服务于当前请求的 Reasoning State；再以 RL 学习“如何使用记忆”。开源实现包含 GRPO Policy Training，关系中显式区分 SUPERSEDES 和 CONFLICTS_WITH。

为什么重要。 多轮推荐最常见的错误并非完全忘记偏好，而是把过时偏好、互相矛盾的偏好、仅适用于某场景的偏好混用。将事实、版本和使用判断分层，可对 Memory Retrieval 与 Decision Policy 分别做回归测试。

可信度与局限。 作者在多种记忆基准上报告改善，但 Memory Ontology 的维护成本、隐私删除与偏好快速反复变化是开放问题；训练后未必能迁移到真实长期使用。最值得继续追踪： 以时间戳和来源区分撤销与条件偏好，测错用记忆率、记忆遗漏率、回滚和删除一致性。原始来源：论文 · 代码。

9. BestRand：压缩 Benchmark 也必须压缩最坏抽样风险

发生了什么。 BestRand 发现随机选一小部分测试题，平均分通常能代表完整 Benchmark，但极少数抽样会制造大幅偏差。通过少量 Probe Models 评估多个随机候选子集，选择误差更稳定的子集。作者在 70+ 文本、多模态和 Agent Benchmark 报告高误差风险降低 50.2%、平均误差降低 16.4%，构造成本约为对照方法的 51.3%。

为什么重要。 Agent 迭代常常只有 30～100 条回归测试；只看平均 Spearman 容易让模型在少量“幸运样本”上错误晋级。需要单列不同种子和新模型家族下的 Tail Risk。

可信度与局限。 这是 10 月 31 日预印本，本期关注其 11 月 6 日公开的可运行仓库；“相对风险下降”来自作者所定义的阈值和比较集。最值得继续追踪： 时间分布漂移、模型家族 OOD、候选子集过拟合，以及与 Stratified Random 的比较。原始来源：论文 · 代码/数据（CPU 可运行）。

四、开源模型与基础设施观察

模型卡观察，不作为当日新发布： Kimi-K3.1-Pro 模型卡列出了图文输入、Safetensors 与压缩权重标识，并注明专用 License；Hugging Face 11 月 7 日榜单记录了其活跃度。应核验模型文件、许可证、服务引擎支持与准确的显存要求，不能从网页自动生成的 vllm serve 示例推断任何单机即可部署，更不能把 Trending 排名当作 Benchmark 质量结论。

值得读的生产工程复盘： X 工程团队 11 月 4 日的 Rebuilding the global town square from scratch，说明通过 Edge 流量切换、路由发现与分阶段回滚替换 Web 服务。团队在文中报告其受控测试下 First Post Time 从 23.9 秒变为 2.7 秒，并提到使用 Coding Agents 辅助开发。这里的证据是特定网络/测试环境的工程案例，不能外推出“AI Coding 使研发效率提高多少倍”；真正值得复制的是可回滚迁移和端到端指标设计。

今日最值得花 30 分钟阅读的一项

Harness-S：Learning from Sibling Harnesses for Generalizable Agent Training。建议按四段阅读：前 7 分钟明确 Base Harness 与 Rescue Harness 的区别；接着 8 分钟看“所有基础尝试失败后才救援”怎样构成样本选择；再花 10 分钟检查返回 Base Harness 的指标、Rollout 额外开销与分组消融；最后 5 分钟思考自己的 Agent 是否存在“工具升级后分数变好，但模型策略没有进步”的假阳性。不要先读演示页面，先读实验控制变量。

今日可立即实践的一件事

在 ShoppingAgentLab 做一个无需重新训练的大约 30～60 分钟 Harness 救援审计。 固定 30 条含库存变动、规格冲突、检索结果为空和工具超时的购物任务，建立 H0（现有工具链）与 H1（增加重试、约束校验、证据补查）两个 Harness。分别记录：

组别测量对象最低记录字段
AH0 单独完成任务成功、Constraint Violation、Tool Calls、Token、P95
BH0 失败后才用 H1 救援救援成功率、额外成本、失败类型
C固定预算下始终使用 H1同样五个指标，检查是否只是“工具更强”

仅在总调用量和成本可比时比较 A/B/C。B 的救援成功不等于 Harness-S 所说的“能力已迁移到参数”，因为这一最小实验未训练策略；真正验证迁移仍须训练后再回到 H0 测试。保存三组原始轨迹，后续可直接变成 Tool-Agent RL 的训练和回归样本。
