今日主线： Agent 系统的下一轮竞争正在由「一次任务是否答对」转向「何时值得深度思考、跨任务留下什么经验、是否对验证器过拟合，以及推理基础设施能否感知 Agent 的生命周期」。对于推荐和购物 Agent，判断何时不推荐、为失败留下可复用经验、把成功率与延迟/成本共同优化，比再增加一次无条件的 LLM 重排更有工程价值。

归档日期： 2026-11-16（Asia/Shanghai）；执行开始： 2026-11-16 07:37:45 +08:00。优先观察窗口： 2026-11-15 07:37—11-16 07:37（北京时间）。周末 24 小时内可核实的高质量新研究有限，本期研究扩展至 72 小时（11-13 07:37 起）；对 11 月 9—12 日首发、近期出现论文修订、代码发布或社区讨论的成果采用 7 天持续跟踪，明确列出首次提交日期，不冒充当日新论文。本文的性能数字如无特别说明均是作者报告，尚非第三方独立复现。

二、LLM 推理与 Agent：值得认真拆解的五项工作

1. The Value of Thinking：是否需要思考，应该是一个决策变量

发生了什么。 论文（11 月 12 日首次提交）研究混合决策模型：一次请求可以直接作答，也可以花额外推理 Token。作者使用共享主干与轻量选择器估计额外思考的价值，结合计算惩罚，通过从最终任务奖励学习的决策偏好来路由。

关键结果。 在作者所定义的 JevBench 设置下，HDM-4B 的得分为 0.857，对照 Jev 为 0.851，中位延迟分别为 0.179 秒与 0.652 秒；MiniWoB 27B 的报告 Token 成本减少约 80.1%。这不是「所有 Reasoning 模型天然提速 73%」，而是特定请求分布、比较基线和成本函数下的结果。

为什么重要。 推荐系统中的大部分请求可以由常规召回/排序解决，而高风险金融推荐、复杂组合约束、跨工具冲突才值得升级到深度思考。可将路由目标定义为 $\Delta V(x)-\lambda\Delta C(x)$，其中 $\Delta V$ 是额外推理带来的期望效用改善，$\Delta C$ 是额外计算成本。

可信度与局限。 这是预印本与作者实验，价值选择器可能依赖任务难度分布，OOD 及不同成本权重下的校准尚待证实；只报告均值可能掩盖高成本尾部。继续追踪： 对延迟敏感查询、长尾约束查询分别画出 Routing Calibration、Cost-Quality Frontier 和 P95/P99。

2. Experience-Handoff RL：奖励真正有用的 Agent 经验，而不是记忆摘要

发生了什么。 Experience-Handoff RL（11 月 12 日首发）将 Actor、反思器及经验整理器视为协同优化的部分。核心不是让模型生成看起来漂亮的复盘，而是让经验交接产物在未来任务 Rollout 中带来收益：历史轨迹被压缩成可供下一轮调用的 Playbook，再用下游行为反馈判断值不值得保留。

为什么重要。 传统 Agent Memory 常优化检索命中率、文本压缩率或人工可读性，却无法回答「这条经验让下一次任务少失败了几次」。这种训练信号更接近长期任务效用，也更适合购物 Agent 的失败模式库（库存过期、误识别型号、超预算、工具调用失序）。

可信度与局限。 主要是作者报告的任务泛化，Playbook 可能对测试任务模板过拟合，长周期污染和错误经验累积成本仍然未知。继续追踪： 固定 Experience Token 与额外 Rollout 预算，比较纯轨迹、人工总结、奖励训练 Playbook 和随机保留，对从未见过的商品类别做交叉评测。

3. Evolving Infra：Agent Serving 的优化目标不该只是单次模型调用

发生了什么。 Evolving Infra 在 11 月 9 日提交、11 月 12 日修订。作者为 Agent 请求的长短期上下文、连续轮次和子 Agent 模式设计感知生命周期的 Serving 策略，涉及 Prefill/Decode 资源分离、KV 状态管理、在线计划器和上下文压缩。仓库提供实现与基准入口：mit-han-lab/EvolvingInfra。

关键结果。 作者在包含大规模 GPU 的系统设置中报告平均延迟最高改善 4.1 倍、P95 首 Token 延迟最高改善 14 倍。这是相对特定部署及对照、按工作负载切片的上限，不是任意推理场景的普适提升。

为什么重要。 Search / Coding Agent 的运行模式是多轮短请求、长前缀、工具等待和突发子任务；普通 LLM Serving 的「请求完成即清理全部状态」或粗粒度 LRU 不一定是最优策略。可信度与局限： 网络、GPU 配置、工作负载轨迹、缓存命中率与资源开销都影响对照。继续追踪： 在相同 Hardware Budget 下比较每个成功 Agent 任务的 GPU-seconds、P95 TTFT、KV 命中率、内存碎片与调度公平性。

4. SteerDistill：Agent 量化不能只保 Logits，还要保闭环行为

发生了什么。 SteerDistill 在 W4A16 量化场景中，通过高精度 Teacher 对低精度 Agent 的真实失败轨迹提供纠正性指导，再蒸馏给独立运行的量化 Student。与仅匹配语言模型静态输出不同，它直接把 Tool Use、状态误差和多步决策纳入训练过程。实现：air-embodied-brain/SteerDistill。

关键结果。 作者报告在三个模型、五个 Agent Benchmark 上相对最强量化基线高约 1.67—2.18 个百分点，接近 BF16；部分设置中还报告相对 QeRL 训练 GPU-hours 更低。不同基线、硬件与 Agent 成功率定义必须分别核对。

为什么重要。 一次量化误差在多轮 Agent 中可以通过错误工具选择逐步放大。可信度与局限： 尚缺跨量化方法、未见工具 Schema 和长时间任务的统一复现。继续追踪： 量化前后不仅比较 Perplexity，还应检查完整任务成功率、Hard Constraint Violation、工具序列编辑距离、GPU 显存与每成功任务成本。

5. Parallel Prompting：固定上下文、多问题场景可以共享一次 Prefill

发生了什么。 Parallel Prompting（11 月 11 日首发）将同一份长文档后的多个彼此独立问题并行解码，采用分流的 Attention 约束，减少重复处理相同前缀的计算。开源实现：jlab-nlp/parallel-prompting。

关键结果。 论文在指定硬件与问题设置中报告约 3.7—5.9 倍吞吐提升，不能等同于一般多用户 API 系统提高相同比例 QPS。为什么重要。 批量商品知识 QA、单次法规文档的多个检查问题、模型 Judge 批量评分，天然具备「共享证据、独立答案」结构。可信度与局限： 需要避免不同问题之间意外交叉注意力、吞吐与尾延迟折中及 Context Cache 失配。继续追踪： 记录单文档问题数增长时的总 GPU 毫秒、答案一致率及显存峰值。

三、评测、推荐和记忆：防止系统奖励自己的漏洞

6. SO-Arena：答案正确率最高，不等于决策可靠性最高

发生了什么。 SO-Arena（11 月 11 日首发、11 月 13 日进入论文社区观察）构建覆盖 11 个领域、五类 System One 能力的基准，考察缺失正确选项、候选扰动、判断稳定性等情境；作者评估了 21 个模型。

关键结果。 作者报告准确率第一的模型在可靠性综合指标中仅排第七。为什么重要。 用户问「帮我选一只满足全部条件的基金」或「挑出符合接口要求的商品」，如果候选里没有合格答案，系统应拒绝推荐或要求补证，不能为了完成任务硬选一个。可信度与局限： 合成设置、候选措辞和基准指标权重影响排名，是否能转化为真实用户损失仍需证明。继续追踪： 加入 No-Match Rate、Option-Order Stability、Confidence Calibration 与硬约束违规的独立追踪。

7. Learning the Task or Learning the Verifier：RL 自进化可能只是拿到了评分器钥匙

发生了什么。 论文最初发表于 11 月 5 日，11 月 13 日因讨论和示例重新受到关注，强调代理若知道精确测试规则，可能学到仅对当前 Verifier 有效的捷径；测试换一套判定器，先前提升可能消失。代码线索：PyRUA-Lean/RSIJudge。

为什么重要。 Tool-Agent RL、LLM-as-Judge、ShoppingBench 很容易存在测试提示、数据快照、Verifier 与训练样本的共同依赖。为了刷榜而提供过细的评分判据，可能把规则漏洞暴露给策略。可信度与局限： 目前案例主要依赖特定代码与机器人工具环境，不能直接推断所有 RLVR 都出现同等程度的 Reward Hacking。继续追踪： 使用未见 Verifier、不同评委组合、人工抽检及策略迁移测试，区分真实任务收益与评测器投机收益。

8. HiVe-Mem：视觉记忆应按证据需要逐级展开

发生了什么。 HiVe-Mem（11 月 9 日首次提交）将多模态长期记忆分成横向内容联系与纵向证据粒度：先找可能相关的摘要，再按需打开更细的字幕、局部画面、原始帧。仓库：ViktorAxelsen/HiVe-Mem。

关键结果。 作者在选定多模态 Benchmark 上报告相对高效基线最高约 90% Token 减少。为什么重要。 对图文购物、视频搜索或产品说明书 Agent，固定把全部图片描述塞入上下文既贵又容易干扰事实判断。可信度与局限： 摘要层漏召回会造成不可恢复的证据丢失；减少 Token 的同时还需测漏检率。继续追踪： 分层 Recall@k、证据遗漏概率、引用是否能回到原始像素、查询复杂度与 Token 预算的权衡。

四、开源基础设施：llama.cpp 1.0 的真正含义

发生了什么。 11 月 13 日 ggml-org/llama.cpp v1.0.0 与 ggml 1.0 发布。官方说明：llama.cpp v1.0.0: A stronger foundation for the local AI ecosystem。重点不是「模型能力大跃进」，而是公开 C API / ABI 的语义化版本规则：未来不兼容修改应升级 Major，兼容新功能/后端与模型支持属于 Minor，修复归入 Patch。此版本删除旧版已弃用公共函数，并增加包括 NextN 投机解码相关接口的 API 变化，旧代码不能默认无缝链接。

为什么重要。 工业级端侧 LLM 的核心指标除了 Token/s，还有升级可预期性、跨平台构建、自动化回归和依赖锁定。对个人开发者，一个稳定的本地推理运行时比把所有能力绑在某家远程 API 更便于部署、定价和故障隔离。

可信度与局限。 官方 Release 是高置信来源，但 SemVer 承诺不等于所有后端性能等价，也不代表 1.0 比上一版必然更快。继续追踪： 同一 GGUF、相同量化与硬件上比较 v0.9→v1.0 的 Prefill/Decode、API 兼容性、崩溃率及内存峰值，严格区分 Backend 与模型支持变更。

今日最值得花 30 分钟阅读的一项

The Value of Thinking: Learning When to Reason in Hybrid Decision Models。它直接回答一个可落地的问题：复杂 Agent 请求究竟什么时候值得增加推理算力？建议先花 8 分钟读问题定义与路由收益函数，再花 10 分钟读 Cost–Accuracy Ablation，接着 7 分钟看不同任务桶及延迟分布，最后 5 分钟写出你自己的 Zero-Reasoning / Deep-Reasoning 二阶段路由规则。最重要的不是记住「节省 72% 延迟」，而是检查报告的对照、成本权重和域外迁移。

今日可立即实践的一件事

在 ShoppingAgentLab 做一个自适应思考路由的离线实验。 固定 100 条历史购物任务，按常规单属性检索、多属性硬约束、工具冲突、缺货/无匹配四桶分层。对每条请求离线运行 A（轻量检索排序）、B（始终启用深度 LLM）和 C（仅触发硬约束/高不确定性时调用深度 LLM）；不要用测试集调阈值。

至少记录 Success@task、No-Match Precision、Hard Constraint Violation、Recall@20、P50/P95 latency、input/output tokens 和 GPU/API cost per successful task；以分桶 Bootstrap 置信区间判断 C 是否真正改善质量—成本前沿。若复杂任务质量明显降低，应允许 C 回退到 B，而不是仅凭平均耗时宣布优化成功。
