今日主线： Agent 研究的共同方向正在从「能否完成单次任务」转向「评价信号是否可信、经验是否值得保存、有限推理预算应该花在哪里」。对推荐和搜索工程而言，事后动作评价、单侧可验证奖励、反事实引文审计比追逐一项未复现的榜单提升更值得优先落地。

二、Agent RL：用事后判断修正长期信用分配

1. Actor, Judge, or Teacher?：做得不好不等于教得不好

发生了什么与关键结果。 作者比较三类 Decision Model 和三种通用 LLM 在长程环境中的 Actor、Judge 与 Teacher 角色。直接决策时，模型容易先做简单但不应优先的子目标；给出完整轨迹后，按「该动作是否有帮助」打分却能奖励早期必要步骤。JEV 作为教师引导 Qwen2.5-1.5B 的 GRPO，在 WebShop 上从 56.8% 升至 71.4%，ALFWorld 从 72.8% 升至 82.9%。

为什么重要。 电商 Agent 中常见「先查库存/可售范围，再比较价格」这样的前置约束。只看最终成功可能把前置验证步骤的 Advantage 估得过低；事后 Judge 能看到后续后果，可能更适合训练 Action Credit，而不适合直接选下一步 Action。

可信度与局限。 有公开 代码 和两个环境结果，但 JEV 分数是否校准、额外 Judge 计算成本、OOD 产品与工具故障均未由摘要证明。下一步： 对同一批轨迹比较 Final Outcome、逐步 Progress Judge、未来成功概率三种奖励，并按工具预算对齐。来源：论文 · 官方仓库。

2. NOPO：Verifier 只会识别错误时，停止奖励「未被抓到」

发生了什么。 NOPO 形式化 One-Sided Verifiability：单元测试、约束检查或 LLM 自检识别到的失败可信，但通过检查不一定真正确。它不强化「未检出错误」的轨迹，而是相对参考策略压制确认的负例，再用组内未证伪比例调节更新。

为什么重要。 推荐解释、网页购买、代码测试等场景经常没有完备 Oracle；用 tests_passed=1 直接做正奖励会诱导 Reward Hacking。NOPO 给出偏保守的训练方向。可信度与局限： 作者报告在多类 Benchmark 有收益，NeurIPS 2026 Spotlight 为论文所列信息；只压制负例可能牺牲探索，对负例覆盖率和误报率敏感。下一步： 分层记录 Verified Negative / Unknown / Gold Positive 的混淆矩阵及 pass@k，比较 GRPO、DPO、NOPO 的校准与多样性。来源：论文。

3. Experience-Handoff RL：优化经验本身的下游价值

发生了什么。 Experience-Handoff Reinforcement Learning 在固定 Agentic Context Engineering Harness 下联合训练动作执行、反思与 Playbook 整理，并根据整理出的经验对后续 Rollout 的影响来评估，而不是直接奖励长篇「经验总结」。为什么重要： Agent 自我进化应优化可迁移、可验证的经验制品，而非重复 Self-Reflection。可信度与局限： 作者表示 Held-out 任务优于对照，摘要未给足独立成本、迁移和长期污染数据；与 Harness 改造的贡献必须分离。下一步： 固定未来任务采样和 Token 预算，对经验条目逐项做删除消融，计算每条净收益。来源：论文。

三、RAG、长期记忆与安全边界

4. CoReMem：为「下一项未知代码任务」选择记忆

发生了什么。 CoReMem 在持续变化的代码仓库里，对轨迹片段执行「下一任务带/不带此片段」的对照评估，优先保存仓库定位点、可执行测试等 Anchor；Actor 训练只给真正使用记忆 Anchor 的步骤附加记忆价值信用。作者报告 ChainSWE 27B Resolve Rate 21.0%→25.7%，步骤 -17%，总 Cache-aware Token -11%（含记忆模块）。

为什么重要。 与其把所有任务日志塞入 Context，不如保存「遇到相似失败时可直接定位文件/断言」的最小记忆。局限： 单一演进代码库的相邻任务受时间、重复文件与测评构造影响；未来任务不可预知。下一步： 时间切分评测并检查记忆陈旧率、误导率及长期写入成本。来源：论文。

5. Cited but Unused：RAG 引用正确不代表来源可信

发生了什么。 Cited but Unused 把检索段落里的关键值替换为虚构值，再观察回答是否随之改变。作者在多个模型大小上报告 1.2%—15.7% 的可引用声明更可能来自参数记忆而非当前上下文，且常规 NLI 验证区分能力差；比较有无 Context 的分布更有效，却仍不足以作为可靠自动修复器。

为什么重要。 金融产品事实、库存与价格可能随时间变化；答得对并给正确引用，也可能恰好引用了与旧记忆一致的网页。局限： Counterfactual 替换引入分布外假值，不能简单等同真实世界的逐 Token 因果归属。下一步： 通过受控商品快照变更，测答案更新率、错误引用率、对比不同检索器的来源敏感性。来源：论文。

6. CapLite：外来网页不能为 Agent 添加新收件人或支付对象

发生了什么。 CapLite 不让小模型自己撰写安全规则，而从 Tool Schema 推导授权检查，并在读入不可信工具结果之前确定写操作许可；被执行的关键对象（收件人、金额、目标、路径）必须来自用户原始要求。作者在 13,935 次受攻击 AgentDojo Episode 上报告零成功攻击，受攻击条件下 Utility 29.0%，与 CaMeL 的 27.2% 可比。

为什么重要。 将「写入前授权」放到模型之外，是 Agent 安全边界中比提示词更可审计的工程设计。局限： 零成功不等于真实系统无风险；用户未指定具体对象时，该规则可能降低自动化能力。下一步： 专测间接对象解析、带时效授权、批量写入与受污染读取链。来源：论文。

四、推理预算、架构与基础设施

7. The Value of Thinking：按预期收益收费的零或完整思考

发生了什么。 HDM 在冻结骨干上增加轻量 Self-Router：先用单次 Forward 的隐式判断预测慢推理的边际收益，只在超过每请求阈值 $\lambda$ 时生成完整 CoT。作者报告 JevBench 中位时延减少 72.5%，MiniWoB Token 成本减少 80.1%。为什么重要： 推荐重排中简单请求不必全面调用推理模型，复杂意图、冲突约束或高风险操作才升级。局限： 不同评测使用不同尺寸模型与代价分布，不能把这些数字直接带入线上 SLA。下一步： 画成功率—延迟—成本 Pareto 曲线，测路由误判损失。来源：论文。

8. Ballad 与 Metal Sandbox：决策路由和工具调度分别省钱

Ballad 通过非平稳 Bandit、候选启发式的 DAG 祖先信用传播和旧观察衰减，在五种 NP-hard 优化问题与四种 LLM 池中，作者报告比始终用最贵模型最多节省 65.6% API 成本而保持或超过最好单模型表现。工程价值是用真实搜索收益而非静态模型排名做路由；但组合优化不等于通用对话。论文。

Metal Sandbox 则把多个 Coding Agent 的 GPU/命令执行交给跨 Mac 的调度器，隔离每个 Workspace；四台 M4 Mac mini 上命令吞吐提升 1.68—2.05 倍，动态调度追踪回放下等待时间 -18.8%。这证明工具执行队列也是 Agent 端到端成本来源，但指标包含静态 Trace 的模拟假设，不能直接当成生产集群收益。论文 · Metal Sandbox 代码 · Harbor 集成。

9. ArchSpace 与 CRAM：避免拿不对等 Benchmark 宣传新架构

ArchSpace 提议把新架构的完整训练过程、Scaling Law、失败实验和等规模比较放到可审计社区平台，提供 Qwen3.5/OLMo3 参考和计划中的分层训练；其开源流程已经可查看，但平台的长期开源审计价值尚待真实实验积累。官方仓库。

CRAM 将经典能量函数学习用于 Sudoku/Maze，报告比相关 Looped Model 在这些任务上训练快至少 1000 倍，Sudoku 相同准确率推理 FLOPs 少至少 282 倍。其最大贡献是反例提醒：简单 Puzzle 可能让复杂架构看起来必要，其实能量优化已足够。绝不能外推为通用 LLM 的 1000 倍加速。 下一步看可组合语言推理任务和相同训练预算的 OOD 迁移。

今日最值得花 30 分钟阅读的一项

Actor, Judge, or Teacher? Understanding Decision Models in Long-Horizon Agents。建议 8 分钟读「前置子目标为何被短期诱惑打败」，10 分钟读 Actor/Judge/Teacher 的实验设计，7 分钟读 WebShop GRPO 提升和消融，最后 5 分钟检查 Judge 用了多少额外计算、是否看到了模型在决策时不可见的未来信息。核心不在再训练一个高分 Actor，而在判断哪一类评分信号能真正改进长期策略。

今日可立即实践的一件事

在 ShoppingAgentLab 做一个轨迹级「前置约束信用」离线实验。 抽取 30 条多轮商品选购样本（库存、地区可售、规格匹配、价格比较各覆盖），固定候选商品快照和 Tool Budget。建立三个 Judge：A=只看最终成功，B=逐步预测剩余成功概率，C=完整轨迹后判断每个动作是否帮助最终任务。为同一轨迹记录：required_subgoal_completed、constraint_violation、step_credit、task_success、judge_tokens。先人工复核 10 条含「先查约束再排序」的失败案例，再比较三组 Step Credit 的排序一致性和额外成本。这只是奖励质量审计，不是训练收益证据；若审计有效再以固定总 Token/样本预算开展 GRPO 消融。
