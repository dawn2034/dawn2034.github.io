> **今日主线：** 推荐排序中的除法特征交叉、百万上下文的分层索引、按请求适配的量化，以及强化学习训练和推理的资源共享。共同的问题是：怎样在固定成本预算下，把计算资源用到真正有价值的信息上？

## 一、研究与技术进展

### 1. DCDN：让推荐模型直接学习比值关系

**发生了什么：** DCDN（11 月 20 日提交，23 日公开列表）在 DCNv2 的交叉层加入倒数分支，使特征组合同时包含正、负幂次；理论上可表达 Laurent 多项式。实验采用一阶倒数展开，并用掩码及 epsilon=0.01 处理不稳定分母。作者报告线上特征输入减少 40.1%，点赞增加 3.25%，分享增加 16.26%，总观看时长增加 0.33%，全屏点击增加 0.38%，展示视频数减少 0.24%。

**为什么重要：** 转化率、完播比例、单位曝光收益等比值往往依赖人工特征工程。普通乘法交叉层不天然具有这种归纳偏置；倒数分支可能降低对人工比例特征的依赖，减少特征服务负担。

**可信度与局限：** 论文含四个公开数据集的实验及线上 A/B，证据强于纯离线架构论文，但线上结果仍是单一业务环境的作者报告；分享的大幅变化不能直接外推至收入或留存。近零分母、低频用户和分布漂移尤其值得关注。

**下一步：** 控制参数、训练预算与特征集合，比较 DCNv2、人工比值特征及 DCDN；分桶检查分母大小、长尾用户与推理成本。

来源：[论文](https://arxiv.org/html/2611.27514v1) · [代码](https://github.com/rw404/DCDN)。

### 2. LRSA：百万 token 稀疏注意力的索引成本

**发生了什么：** 美团研究者提出分层检索式稀疏注意力 LRSA（20 日提交）。它将 key 按页组织，用多个细粒度中心表示页内方向，再粗筛页、细选 key；保留 sink、滑动窗口及未建立索引的候选。SGLang 实现支持异步建索引和前缀复用。1024K 上 key selector 相对 DSA 加速 4.70 倍，注意力与选择合计相对全注意力加速 35.60 倍；相对 DSA 的端到端收益约 1.87—1.98 倍，64K 约 1.13—1.14 倍。

**为什么重要：** 稀疏注意力若每步仍扫描全部历史 key，就会将注意力成本转移给索引器。LRSA 尝试改变这一瓶颈，尤其适合长上下文和重复前缀服务。

**可信度与局限：** kernel 加速、端到端加速和任务正确率不可混用。注意力质量的历史权重召回并不能保证稀有证据被保留；索引构建、额外显存、并发及短上下文场景可能抵消收益。

**下一步：** 在 64K、256K、1M 上联合测量 TTFT、TPOT、显存、索引复用率与多跳证据召回，而不只测 attention kernel。

来源：[论文](https://arxiv.org/html/2611.27233v1) · [SGLang](https://github.com/sgl-project/sglang)。

### 3. PLoQ：每个请求自己的低秩量化补偿

**发生了什么：** PLoQ（20 日提交）在 prefill 根据当前 prompt 学习高方差低秩方向，decode 复用该方向，以分离主导分量和量化残差，并通过融合 GEMM 控制额外开销。作者在六种 1B—70B 模型上比较平均约 4.2 bit 的权重、激活和 KV 混合精度，最高追回量化相对高精度基线的剩余困惑度差距的 46%。Llama-3.1-8B 的 8K 场景报告 prefill 额外耗时约 4%、decode 约 8%。

**为什么重要：** 全局校准集难以覆盖请求级离群方向；低秩补偿将量化误差控制从模型级扩展至请求级。

**可信度与局限：** 46% 是差距追回比例，不能解释为绝对困惑度降低 46%。当前评估上下文主要在 8K，少量至 16K。多轮对话的方向变化、批处理形状和额外缓存可能影响生产价值。

**下一步：** 用相同平均 bit 数比较静态量化与请求级补偿，在长程工具调用上记录结构化输出错误率、P95 延迟和每请求补偿状态内存。

来源：[论文](https://arxiv.org/html/2611.27092v1)。

### 4. ERA：不重建全量向量索引的检索模型升级

**发生了什么：** Google 的 ERA（20 日提交）用少量 anchor 对齐两个 embedding 空间，使新 encoder 的查询能复用现有语料索引，并对困难查询有条件地升级。核心包括余弦最远点采样、流形对齐和正交正则。五个 BEIR 数据集上，ArguAna 的 nDCG@10 相对比较基线最高提升约 35%；在名义升级比例 20% 的设置下，作者报告约 160 ms 的基线降到 38—86 ms。

**为什么重要：** 十亿级商品或文档重编码的计算、双索引存储和在线迁移成本很高。对齐层可作为编码器升级的过渡方案。

**可信度与局限：** 特定数据集的相对增益不代表全业务收益，延迟高度依赖 encoder 服务。对齐无法凭空恢复旧空间已经丢失的信息，且不同领域或语料版本可能改变几何关系。

**下一步：** 对真实 query 按头尾、类目、新品、长文本分桶，测量 Recall@K、nDCG、旧新索引重叠率及升级路由的校准曲线。

来源：[论文](https://arxiv.org/html/2611.26919v1) · [BEIR](https://github.com/beir-cellar/beir)。

### 5. CTRL：让 RL rollout 与训练共享 GPU

**发生了什么：** CTRL（20 日提交）使用 CUDA MPS 使训练与 rollout 共驻 GPU，借助 CPU optimizer states 和受控权重传输减少显存竞争，并对策略版本发布设置 staleness gate。论文在 Qwen3、H100、A800、4090 等 24 个配置上报告，相对更强的 verl 异步基线吞吐提升 1.11—2.24 倍；8 张 H100 上相对 colocate_async 为 1.23 倍。

**为什么重要：** Agent RL 的 rollout 长度波动很大，训练和生成分割 GPU 容易造成两侧利用率不平衡。共享资源的价值在于缩短有效训练周期，而非单纯增大生成 tokens/s。

**可信度与局限：** 吞吐不能证明相同 wall-clock 下的最终模型质量。CPU 内存、PCIe 带宽、长尾 rollout、策略滞后及生产任务的异质性会影响收益。

**下一步：** 同时记录 GPU busy、队列等待、policy version lag、每小时有效奖励样本和固定计算预算下的验证集成功率。

来源：[论文](https://arxiv.org/html/2611.27119v1) · [verl](https://github.com/verl-project/verl)。

### 6. RL 能否修复错误的 SFT 推理轨迹？

**发生了什么：** 11 月 19 日提交的研究在 OLMo-2-1B 与 GSM8K 上构造 361 种推理污染配置。随污染加重，聚合 SFT-only 成绩从 43.61% 降至 13.80%，后续 GRPO 仍约 60%。一个仅使用八条极简、答案错误的格式示范的设置，RL 后为 69.30%，对照金标准 SFT 后 RL 为 60.71%，无 SFT 为 35.00%。

**为什么重要：** SFT 的价值可能部分来自输出格式、行为启动和可探索性，而非所有推理步骤的知识灌输。这为低成本 cold start 和可验证任务的数据选择提供了可实验假设。

**可信度与局限：** 小模型、单一数学数据集、可验证终局奖励；不能推论错误轨迹普遍有益，更不能推广到开放式任务或弱 verifier。格式模板的贡献与知识贡献尚需分离。

**下一步：** 在工具调用任务对比无 SFT、正确轨迹、只保留结构的模板及受控错误轨迹，独立评估格式、任务成功和奖励漏洞。

来源：[论文](https://arxiv.org/html/2611.26756v1)。

### 7. Know Your Context Bank：Agent 的经验库也需要数据治理

**发生了什么：** Google 研究者（19 日提交）研究 SQL Agent 经验库中的规则冲突，以比较器定位冲突约定并清理 context bank。在 BIRD 训练数据上的修复相对等量随机删减平均增加 2.6 个百分点；独立专家审查中，92.4% 的被删条目得到认可，对照审查条目为 45.6%。一致规则相对相反规则的差距达到 13.3 个百分点。

**为什么重要：** RAG 与 Agent memory 的瓶颈可能来自互相矛盾的经验，而非上下文长度不足。经验库应包含版本、适用范围、证据与冲突关系。

**可信度与局限：** 结果来自 SQL 场景及特定规则分布；大量新逻辑会降低历史经验的作用。自动清理还可能误删少数业务的有效例外。

**下一步：** 对商品规则、财务指标定义或企业知识库建立按生效时间的冲突检测，用独立案例测试清理前后正确率及例外召回。

来源：[论文](https://arxiv.org/html/2611.26775v1) · [BIRD](https://bird-bench.github.io/)。

### 8. SkillPrivus：从恶意代码检测走向数据用途审计

**发生了什么：** SkillPrivus（19 日提交）联合分析 Agent Skill 的说明和代码，关注敏感数据是否被用于授权目的及传给适当接收者。726 个公开 Skills 中，563 个涉及相关数据，其中 307 个被标记为潜在用途问题，占 54.5%。可判定数据流的评审一致率 83.2%，kappa 约 0.346。

**为什么重要：** 一个 Skill 即使没有明显恶意代码，也可能将合法读取的数据用于不适当的后续操作。权限授予需要考虑用途和数据流。

**可信度与局限：** 潜在问题不等同于已证实泄露；静态推断缺少运行时环境信息，kappa 提示评审稳定性仍有限。

**下一步：** 将静态用途标签与运行时工具权限、接收者 allowlist、敏感字段脱敏及实际访问日志结合，测试误报和漏报。

来源：[论文](https://arxiv.org/html/2611.26747v1)。

### 9. DISCO：自适应探索模型行为时，怎样控制假发现？

**发生了什么：** Google DeepMind 的 DISCO（20 日提交）使用经过粗粒化的 e-process 和 e-BH，将统计假发现率控制引入自适应模型行为发现。论文包含模拟实验和 LLM 行为探索，并提供 agent、bandit、统计与验证模块的代码。

**为什么重要：** 当 Agent 自动生成并测试大量行为假设时，偶然的高分很容易被当成能力或漏洞。将发现与验证区分、控制多重检验，是自进化评测的重要基础。

**可信度与局限：** FDR 保证依赖统计检验有效性与相应假设，不能证明模型整体安全，也不保证没有漏掉重要行为。共享样本、重复选择和评委漂移需要专门审计。

**下一步：** 在 Agent failure mining 中使用独立验证样本，比较未校正、固定阈值与 FDR 控制的发现集合，并报告检验功效。

来源：[论文](https://arxiv.org/html/2611.27104v1) · [代码](https://github.com/google-deepmind/disco)。

## 今日最值得花 30 分钟阅读的一项

[DCDN](https://arxiv.org/html/2611.27514v1)。建议前 10 分钟理解 Laurent 特征交叉和倒数分支，接下来 10 分钟检查公开数据集的时间切分、特征消融与数值稳定性，最后 10 分钟阅读线上 A/B 及代码中的实际交叉层。关键问题：在去掉手工比值特征后，DCDN 的收益究竟来自更合适的归纳偏置，还是额外容量与特征组合变化？

## 今日可立即实践的一件事

搭建一个最小推荐排序对照实验：A 为 DCNv2 + 全量特征，B 为 DCNv2 + 删除人工比值特征，C 为 DCDN + 同 B 的特征。严格按时间切分，所有计数特征仅使用请求前数据，尽量控制参数量、训练步数和随机种子。另设分母为零、近零和低曝光用户的负控。

记录 AUC、log loss、nDCG@10、长尾分桶表现、特征 RPC 数量、P95 和峰值显存。对相同样本做配对 bootstrap，检验 C 相对 B 的差异，并检验 C 相对 A 的非劣效性；预先定义非劣效界限。如果只改善离线指标却增加延迟或数值异常，不应直接进入线上全量实验。若结果可靠，再开展小流量 A/B，独立观察观看、分享与长期留存。
