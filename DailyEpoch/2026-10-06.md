> **今日主线：** Harness–Task Co-evolution · OPD Implicit Reward · Dependency-aware Credit · Self-refining KV Cache · Agent Source Bias · Request-first Recommendation

arXiv 最新常规公告批次为 **2026 年 10 月 5 日**：cs.AI 266 条、cs.CL 113 条、cs.LG 297 条、cs.IR 11 条。分类之间存在大量交叉收录，不能直接相加。

今天最值得连起来看的变化，是“自我改进”开始从模型权重进一步扩展到 **Harness、训练数据与执行依赖图**：Harness 可以与任务难度共同演化，但必须防止对有限评测集过拟合；On-policy Distillation 需要被理解为一种隐式 Reward Optimization，而不只是模仿 Teacher；Terminal Agent 的 Credit 则开始沿真实 read/write dependency 回溯。系统侧，KV Cache 压缩也从一次性近似进入“轻量筛选 → 只重算高价值子集”的自精炼结构。推荐与搜索侧，两篇值得一起看：一篇说明 Agent 会对来源本身形成强偏好，另一篇说明历史偏好会压过用户当前明确请求。

## 今日核心判断

1. **Harness 自我改进的下一步，是让任务难度与 Harness 同步演化，同时给接受机制加硬约束。** [Recursive Harness Self-Improvement](https://arxiv.org/abs/2610.03548) 在模型权重和 verifier 固定的条件下，让生成任务与 synthesis harness 一起递归升级；14 轮后 solver 平均准确率从 100.0% 降到 54.8%。27B Student 用 10K 条合成数学样本训练后，在 APEX 上达到 62.5% mean-16。这个结果证明 harness-level search 能产生训练价值，不等于开放式“递归智能爆炸”。

2. **OPD 更像“Teacher 作为隐式 Reward Model”而非普通蒸馏。** [Gains and Collapse in OPD](https://arxiv.org/abs/2610.03185) 发现，OPD 可以让 Student 更容易采到原本已有的正确行为，却不一定扩展其可达能力；当 Teacher 的隐式偏好和真正质量错位时，Student 会把长而重复的 Rollout 放大成 reward hacking。论文给出的缓解方式包括屏蔽不健康 Response 和使用 SFT 初始化。

3. **Agent RL 的 Credit 正从按轨迹／按步骤，进入“按执行依赖图”分配。** [DepGPO](https://arxiv.org/abs/2610.03634) 从 verifier 最终检查的资源向后追踪 command read/write dependency，只给真正影响最终状态的写操作和支撑这些写操作的读取分配更高 Credit。对 Coding / Shell Agent，这比按 step index 或 outcome advantage 广播更贴近因果路径。

4. **可复用长 Context 的 KV 压缩不必在“便宜粗糙”和“全量重算准确”之间二选一。** [KV²](https://arxiv.org/abs/2610.03198) 先用廉价 proxy scorer 找候选高价值 Token，再只对这个子集做 reconstruction-based 精细评分。RULER 16K、2% KV budget 下，平均分比下一强 Baseline 高 **40+ points**；LongBench 在 2%–10% budget 上取得最高平均结果。

5. **LLM Agent 会把“来源”本身当成质量 shortcut，而且这个偏好可以压过用户要求。** [Source Preference in the Wild](https://arxiv.org/abs/2610.03195) 对 12 个 Agent Model、商品／酒店／论文三个领域做端到端搜索控制实验：当较差 Item 来自偏好 Source、较好 Item 来自不偏好 Source 时，前者约 **三分之二**时间被选中。

6. **生成式推荐中，“长期历史”应当个性化当前请求，而不应覆盖当前请求。** [AIMS](https://arxiv.org/abs/2610.02600) 用删除单条历史事件的 intervention 构造 ranking margin supervision；训练和推理仍保留完整历史。六个 LLM Backbone、一个工业数据集和两个公开 Benchmark 上均改善 Recall / NDCG。

## 1. Recursive Harness Self-Improvement：训练数据生成器本身也应该进化

[论文原文](https://arxiv.org/abs/2610.03548)

### 发生了什么

传统 recursive data synthesis 常让新一轮题目由上一轮题目继续变难，但生成这些题目的 Harness 固定不变。这项工作把自我改进拆成两个时间尺度：Online self-improvement 在生成过程中把 solver 的中间失败提炼成可复用 Skill；Post-task self-improvement 在一批任务结束后修改 Skill、Prompt 与 Workflow。新 Harness 只有在生成更难且仍然有效的任务、同时成本增幅受控时才被接受；Solver 权重和 Verification Criteria 保持固定。

### 关键结果

| 指标 | 结果 |
|---|---:|
| 演化轮数 | **14** |
| Mean solver accuracy | **100.0% → 54.8%** |
| 27B Student 合成数学数据量 | **10K** |
| APEX mean-16 | **62.5%** |

### 为什么重要

这把 AI-for-AI 从“优化模型”推进到**优化训练环境与数据生产系统**。真正可持续的数据飞轮必须防止两个退化方向：Generator 反复生成模型已经会的题；或者为了制造“难题”逐步生成无效、歧义或 verifier 漏洞任务。

### 可信度与局限

Mean solver accuracy 下降只能证明任务对该 Solver 更难，不能单独证明任务质量更高。下游 SFT / GRPO 增益补强了证据，但仍属于有限领域、固定 verifier 下的受控递归。

### 最值得继续追踪

和 [RRSI](https://arxiv.org/abs/2609.24972) 一起看：成熟系统更可能需要 **Co-evolution + OOD transfer gate + complexity / cost regularization**。

## 2. OPD 的 Gains 与 Collapse：Teacher 不生成坏行为，也可能“奖励”坏行为

[论文原文](https://arxiv.org/abs/2610.03185) · [代码](https://github.com/HancCui/opd_hacking)

### 发生了什么

On-policy Distillation 让 Student 自己采样，再用 Teacher 对 Student 当前状态提供分布监督。问题在于 Teacher 同时扮演一个**隐式 Reward Model**：某种 Student 行为即使 Teacher 自己极少生成，只要 Teacher 对这类轨迹的局部概率结构给出持续正向信号，训练就可能放大它。

### 为什么重要

只检查 Teacher Sample Quality 不够；还要检查 Teacher 对**Student 实际 Rollout**的相对偏好。对 Agent OPD 尤其应关注 Tool Loop、超长 Response、Truncated Rollout 与真实 Task Success 是否同向。

### 可信度与局限

论文关于“没有扩展 Student Capability”的结论依赖测试和采样边界；没有观察到新可解任务，不等于理论上绝不可能扩展能力。屏蔽超长／重复样本是有效修复，但不是对所有 OPD Collapse 的完整解释。

### 最值得继续追踪

建立 **student-rollout preference audit**：对成功／失败、短／长、正常／循环 Rollout，让 Teacher 的隐式 advantage 与 verifier reward 做相关性检查。

## 3. DepGPO：Terminal Agent 的 Credit 应沿真正的数据依赖回溯

[论文原文](https://arxiv.org/abs/2610.03634)

### 发生了什么

DepGPO 从 execution trace 构建 Command Dependency Graph：某一步读了什么、写了什么、后面的 Command 又依赖哪些结果。训练时从 verifier 真正检查的资源向后追踪，只把更强的 Credit 分给相关写操作和它们依赖的读取。

### 为什么重要

轨迹级 GRPO 会把同一个 Outcome Advantage 广播到整条轨迹；依赖图更接近程序切片：最终 Artifact 之所以正确，哪些命令实际处在它的因果数据流上？对 Coding Agent，这类结构信号通常比再加一个自然语言 Judge 更便宜、更可验证。

### 可信度与局限

Dependency Graph 对显式文件／变量／命令输出依赖最有效。它无法自动捕捉高层策略依赖，也可能漏掉环境变量、外部服务和非确定性状态。

### 最值得继续追踪

将依赖 Credit 与 Pivotal-state Counterfactual 结合：先用 Graph 缩小候选关键步骤，再只对少量候选 Turn 做昂贵分支 Rollout。

## 4. KV²：先粗筛，再把精确计算花在可能值得保留的 KV 上

[论文原文](https://arxiv.org/abs/2610.03198) · [代码](https://anonymous.4open.science/r/KVsquared-0B97)

### 发生了什么

KV² 采用两阶段策略。第一阶段用廉价 proxy scorer 筛出可能重要的 Token；第二阶段只重算这一小部分，得到更精确的最终 Eviction Score。

### 关键结果

| 设置 | 结果 |
|---|---:|
| RULER Context | **16K** |
| KV budget | **2%** |
| 相对 next-best baseline | **+40+ average score points** |
| LongBench budget | **2%–10%** |
| LongBench | **各预算平均最优** |

### 为什么重要

对长期 Agent、企业知识库与共享 Prefix，Cache 压缩本身不能成为新的 Prefill Tax。KV² 的思路可以抽象成：**用便宜信号扩大 Recall，用贵信号只精修小候选集。**

### 可信度与局限

2% Budget 下的 40+ points 是极紧的压缩区域，不能外推到所有模型、所有 Context。它仍是 query-agnostic，后续 Query 如果依赖已被压掉的低频事实，系统没有机会按 Query 恢复。

### 最值得继续追踪

把 Reusable Cache 做成两层：稳定的 Query-agnostic Core + 小型 Query-conditioned Expansion。

## 5. Source Preference：Shopping / Search Agent 的“来源偏好”是可测的排序偏差

[论文原文](https://arxiv.org/abs/2610.03195)

### 发生了什么

研究者控制 Item 满足用户要求的数量和展示位置，只改变它来自哪个 Site / Service。12 个 Agent Model 在商品、酒店、论文三个领域都表现出稳定 Source Preference。隐藏 Source Identity 后偏好减弱；给相同 Item 换成偏好 Source Label，选择率会上升。

### 为什么重要

这不是普通 Position Bias。Agent 正在把 Source 当成先验质量特征，并在信息缺失时用这个先验补全事实。Shopping Agent / Agentic Search 应把 Source Bias 纳入排序审计。

### 可信度与局限

真实产品里 Source 与库存、物流、退货、可信度确实可能相关。生产系统不应简单禁止使用来源，而应区分**可验证的来源质量特征**与模型未经当前证据支持的刻板先验。

### 最值得继续追踪

固定 Item Attributes 与 User Requirements，只交换 Source Label / URL，监控 selection delta。

## 6. AIMS：长期兴趣只能在满足当前请求之后做个性化

[论文原文](https://arxiv.org/abs/2610.02600)

### 发生了什么

AIMS 不在推理时删历史，而在训练阶段做 intervention：冻结 Reference Model，逐个删除历史事件，只有当某次删除同时提升 Target Score、并扩大 Target 相对 cutoff competitor 的 Margin 时，才把这个增量转成监督。Student 仍使用完整历史输入。

### 为什么重要

关键问题不是“哪些历史最影响模型”，而是：**哪些历史正在错误地压低当前请求真正需要的 Item？** Influence 与 Utility 是两件事。

### 可信度与局限

论文覆盖六个 LLM Backbone、一个工业数据集和两个公开 Benchmark，并报告 Recall / NDCG 改善，但没有真实线上 A/B。Deletion Intervention 也只是一类局部反事实。

### 最值得继续追踪

推荐模型需要显式优先级：**hard current constraints → current intent → stable long-term preference → weak historical hints**。

## 今日值得收藏的代码 / 学习资源

**LESSER**：[论文](https://arxiv.org/abs/2610.03702)。只用 Output Layer Gradient 就能做有效 Post-training Data Selection。Feature Extraction FLOP 成本在 SFT 上降低 **9.7×**、RL Benchmark 上降低 **3.0×**，同时跟踪 full-gradient downstream performance。

**RRSI**：[论文](https://arxiv.org/abs/2609.24972) · [GitHub](https://github.com/google-research/rrsi) · [项目页](https://regularized-rsi.com/)。八个 Benchmark 上最高取得 evolve split **+14.1 points**、五个 OOD Benchmark 最高 **+4.7 points**，并比 unregularized evolution 少约 **30% policy tokens**。

**Olmo-core 3**：[Ai2 官方介绍](https://allenai.org/blog/olmocore3) · [技术报告](https://allenai.org/papers/olmocore3) · [GitHub](https://github.com/allenai/olmo-core)。官方 8×B300 测试中，47B MoE 相对旧实现约 **2.7× throughput**；expert pool 从 8 扩到 128、active params 维持约 3.2B 时，吞吐下降不到 5%。1.2T 模型的 512×B300 测试属于 random-routing systems reference，不等于真的完成了 1.2T 模型训练。

**Candidate Coverage**：[论文](https://arxiv.org/abs/2610.03387)。TREC 五候选设置下，Laya missing-answer detection 为 **97.2%**，但 present-control false rejection **69.7%**；Jev 对应 **24.8% / 0.0%**。Calibration 后分别为 33.9% / 3.7% 与 45.0% / 1.8%。分类准确率、Score Ranking 与 Reject Policy 应分开评估。

**大家在争论什么**

Tool Routing、Memory Selection、Guardrail 和 Candidate Ranking 往往只有少量合法答案，不必让 Generative LLM 输出长文本。但候选完整时会选，并不代表模型知道“正确答案根本没在候选集”。

Candidate Coverage Benchmark 只测 reference-label omission，不能证明自然 OOD / open-set 场景已经解决。低延迟与正确拒绝是两条不同能力轴。

**大家在争论什么**

Harness 已不只是 Prompt + Tool。它正在承担 Model Routing、Context Policy、Permission、Sandbox、Plugin、State、Verification 与 Subagent Orchestration。相同 Weight 换 Harness，Task Success、Token Cost 和 Tool Behavior 都可能明显变化。

## 今日最值得花 30 分钟阅读的一项

**首选：Gains and Collapse in On-Policy Distillation。**

[论文原文](https://arxiv.org/abs/2610.03185)

它最值得看的地方，是把 OPD 重新解释成 **implicit reward optimization**。这能统一解释两个现象：Teacher 自己几乎不输出某种坏行为，Student 却可能把它越学越严重；OPD 可以提高小采样预算下成绩，却未必创造 Base Student 原本完全不可达的新能力。

> **Distillation Teacher 的关键能力不只是“会做对”，还包括“会正确评价 Student 当前实际做出来的东西”。**

## 今日可立即实践的一件事

给现有 OPD / MOPD 训练日志做一次 **Implicit Reward Audit**，不需要重新训练完整模型。

从最近 100–300 个 Prompt 各采 8–16 条 Student Rollout，至少标出 verifier success / failure、response length、truncation、severe repetition、tool-loop count、invalid action / malformed call，以及 Teacher 对这些 Rollout 的 token-level distillation signal 或近似 advantage。

然后按真实 Task Quality 分桶，检查 Teacher Signal 是否单调：

$$
\mathbb{E}[A_{\text{teacher}}\mid \text{good rollout}]
>
\mathbb{E}[A_{\text{teacher}}\mid \text{bad rollout}].
$$

尤其查看四类坏轨迹：**长但错误、重复但未立刻失败、工具循环、达到生成上限**。如果它们的平均隐式 Advantage 不低于正常成功轨迹，就已经出现明显 reward-hacking surface。

下一步先做最低成本修复：mask 明确 unhealthy rollout、加入 SFT warm-start 或设置长度／循环 Guardrail，再比较 Task Reward 与生成健康度。
