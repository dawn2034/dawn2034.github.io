## 今日核心判断

1. **多轮 Agent 的 OPD 不能只教正确动作，还要显式教错误状态下的恢复。** PivotOPD 在 Qwen3 8B–235B 的预实验中发现，超过一半失败轨迹存在较早出现的 pivotal mistake，而且很多只需后续几步定向指导就能恢复。Qwen3-1.7B 在 ALFWorld 相对最强基线 +5.5%，Nemotron-3.5 Student 在 SWE-bench Verified Resolve Rate +3.2%。

2. **Harness Evolution 正从“根据失败修 Patch”升级成“持续阅读研究文献后主动搜索策略”。** ScholarEvolve 将 Harness 拆成功能模块，从论文中抽取互异策略再实现、组合和验证；Qwen3.5-27B 在 AppWorld Challenge 从 49.6% 提到 63.6%，GPT-5.4-mini 在 τ²-Bench Telecom 从 72.7% 提到 81.9%。

3. **RLVR 的 Token Credit 可以用“答案不变的反事实扰动”过滤脆弱依赖。** SCAPO 对语义等价的 semifactual prompt 测 token 概率漂移，高漂移 token 在训练早期获得更低 Advantage。Qwen3-4B / 1.7B 在 AIME 2024–2026 相对 GRPO 分别 +5.63 / +4.17pp。

4. **Recurrence 与 MoE Sparsity 开始进入统一 Scaling Law。** 新工作报告 sparsity 在 reasoning 上约带来 3× active-parameter efficiency，recurrence 约带来 2× total-parameter efficiency；trillion-token 规模、训练计算匹配时，law-derived looped MoE 可匹配约 2× 更大的 non-looped MoE，同时保留 test-time recurrence scaling。

5. **AutoResearch 的执行正确性正在成为比“想法数量”更硬的瓶颈。** RankEvolve 用可执行状态机约束实验阶段，并让 Claude Code、Codex 等完整 Coding Agent 产品互审互修。预算匹配实验中 all-oracle execution accuracy 从 45.8% 提到 62.5%（+16.7pp，95% CI [6.6, 26.7]），但仍有 10.4% silent critical-defect rate。

6. **推荐 Reranking 多了一个介于专用模型与生成式 LLM 之间的工作区间。** Jev 实证研究显示，decision-oriented model 在多个 Amazon Domain 上保持较强推荐效果，延迟随候选规模增长比 pointwise Qwen 更平缓；但绝对延迟仍显著高于推荐专用模型。更准确的结论是“多了一个 Pareto 点”，而非“Decision Model 取代 RecSys Model”。

## 1. PivotOPD：同时学“预防关键错误”和“从错误状态恢复”

[论文原文](https://arxiv.org/abs/2609.40285)

### 发生了什么

Multi-turn Agent 中，一次错误 Action 会改变后续 Observation 与状态分布。PivotOPD 先定位 **pivotal mistake**：某个动作让任务明显离完成状态更远；Teacher 在该 Turn 给 Gold Action，并在接下来几步给 Recovery Action。Preventive Distillation 用 reverse KL 避免关键错误；Recovery Distillation 用 forward KL 学 Student 原 Policy 很少采到的恢复行为。

### 关键结果

| 设置 | 结果 |
|---|---:|
| Qwen3-1.7B · ALFWorld | 相对最强基线 **+5.5%** |
| Qwen3-1.7B / 8B · ALFWorld、WebShop、Search QA | 13 个基线中平均表现最强 |
| Nemotron-3.5 Student · SWE-bench Verified | Resolve Rate **+3.2%** |
| 失败 Rollout 中含 pivotal mistake | **超过一半** |

### 为什么重要

真实 Browser、Shopping、Coding Agent 不可能保证每一步都正确。更合理的目标是：

$$
\text{robust agent}
=
\text{avoid pivotal errors}
+
\text{recover after pivotal errors}.
$$

只优化“首次就选对”会让 Policy 在 off-nominal state 上很脆，而线上失败经常发生在已经偏离最佳路径之后。

### 可信度与局限

Pivotal mistake 的定位依赖任务反馈和 Teacher 判断；如果失败后果延迟数轮才出现，或环境存在不可逆副作用，第一处关键错误并不容易识别。Recovery Teacher 还需要访问 Student 已经制造出的错误状态，训练成本高于单纯模仿成功轨迹。

### 最值得继续追踪

自动化 **pivotal-state discovery**：用 counterfactual branch、状态价值差异和执行验证，找出“替换这一动作后，后续成功概率显著改变”的 Turn。

## 2. ScholarEvolve：Harness 不只从失败学，还可以持续从论文里学

[论文原文](https://arxiv.org/abs/2609.40169)

### 发生了什么

常见 Harness Self-improvement 是“运行 → 失败 → Meta-agent 修改代码 → 再运行”，高度 reactive。ScholarEvolve 额外引入 Research Literature：先把 Harness Evolution 分成功能模块，再从相关论文中抽取候选机制，用 Topic Modeling 保留互异策略，随后实现、组合和验证。新论文可以持续加入 Search Space。

### 关键结果

| Benchmark | Base | ScholarEvolve |
|---|---:|---:|
| AppWorld Challenge · Qwen3.5-27B Goal Completion | 49.6% | **63.6%** |
| τ²-Bench Telecom · GPT-5.4-mini pass@1 | 72.7% | **81.9%** |

### 为什么重要

长期 Agent Evolution 可以同时利用执行反馈、历史 Harness Change 和外部研究进展。Memory、Tool Routing、Context Management、Verifier、Sandbox 等领域更新很快，只靠模型参数里冻结的既有知识做 Harness Search 很容易过时。

### 可信度与局限

两项 Benchmark 的正结果不能证明系统运行数月后仍稳定。论文技巧常依赖隐藏实现细节、特定模型和特定数据分布；自动组合越多，回归测试与 Scope Control 越重要。

### 最值得继续追踪

给 Harness Skill 加上 **provenance + applicability scope + regression evidence**：来源论文、验证任务族、失败模型和撤销条件都应成为可查询元数据。

## 3. SCAPO：用 Semifactual Intervention 清理 GRPO 的错误 Credit

[论文原文](https://arxiv.org/abs/2609.40360)

### 发生了什么

GRPO 把 outcome-derived Advantage 广播给整条 Response，但正确轨迹里也可能包含依赖 Prompt 表面形式的脆弱 Token。SCAPO 构造不改变底层问题与答案的 semifactual prompt，观察固定 Response 中每个 Token 的概率漂移；高漂移 Token 在训练早期被降权，稳定 Token 只是不受折扣，并不会额外加分。

### 关键结果

| Backbone | 相对 GRPO 的 AIME 2024–2026 提升 |
|---|---:|
| Qwen3-4B-Base | **+5.63pp** |
| Qwen3-1.7B-Base | **+4.17pp** |

作者还报告两种模型在多数数学 Benchmark 和全部 OOD Benchmark 上取得比较方法中的最好结果。

### 为什么重要

$$
\text{correct answer}
\not\Rightarrow
\text{every token dependency is useful}.
$$

统一 Advantage 可能把偶然格式、措辞和顺序依赖一起强化。Semifactual Stability 提供了无需人工过程标签的细粒度 Credit 信号。

### 可信度与局限

当前最强证据仍是数学推理。Agent Tool Use 中“任务无关但语义保持”的 Intervention 更难定义；改变网页、日志或 API Schema 很可能真的改变正确动作。稳定也不等于因果重要，因此 SCAPO 只做折扣而不奖励稳定是必要限制。

### 最值得继续追踪

把同样思路迁移到 Agent Observation：改变字段顺序、无关日志、命名方式和页面噪声，测 Tool Choice / Argument Token 是否保持稳定。

## 4. Scaling Laws for Looped MoE：Recurrence × Sparsity 进入统一设计空间

[论文原文](https://arxiv.org/abs/2609.40316)

### 发生了什么

MoE 用稀疏激活扩展总参数，Looped Transformer 用共享参数重复计算增加深度。新工作首次把 model size、data、sparsity 与 recurrence 放进同一个 scaling-law 框架，用 sparsity-conditional recurrence mapping 描述“循环带来的有效参数增益”如何随稀疏度变化。

### 关键结果

| 结果 | 论文报告 |
|---|---:|
| Sparsity 的 reasoning active-parameter efficiency | 约 **3×** |
| Recurrence 的 reasoning total-parameter efficiency | 约 **2×** |
| trillion-token、训练计算匹配 | 匹配约 **2× 更大**的 non-looped MoE |
| Test-time scaling | 可继续增加 recurrence |

### 为什么重要

未来模型可以联合选择 $(N_{\text{total}},N_{\text{active}},R,D)$，把参数容量、每 Token 激活量、循环深度和数据量分开优化。对内存受限部署和按请求动态分配 Test-time Compute，这比单纯扩大模型更灵活。

### 可信度与局限

Scaling Law 最大风险是越界外推。Router、Expert 共享、数据混合、Tokenizer 和循环层稳定性都可能改变拟合关系；“匹配 2× 更大模型”只针对论文所测 reasoning benchmark 与计算条件，不等于整体能力全面等价。

### 最值得继续追踪

**latency-aware recurrence scaling**：FLOPs 匹配不代表真实延迟匹配，循环是否破坏 batching、并行度和 speculative decoding 会决定系统价值。

## 5. RankEvolve：AutoResearch 先把“实验真的执行对了吗”变成硬约束

[论文原文](https://arxiv.org/abs/2609.39551)

### 发生了什么

AutoResearch 最危险的失败并非报错，而是实验顺利跑完但结论无效：数据泄漏、Normalization 漏掉、Gradient 断开、Train/Eval Flag 未生效都可能生成漂亮的假结果。RankEvolve 用 Executable Operating Protocol（EOP）声明 Phase、Gate、Branch、Loop，再由 Runtime 执行编译后的 State Machine；同时把 Claude Code、Codex 等完整 Coding Agent 产品作为黑盒节点互相 Review / Repair。

### 关键结果

| 指标 | 结果 |
|---|---:|
| 最佳单一 Coding Agent all-oracle execution accuracy | 45.8% |
| Heterogeneous composition | **62.5%** |
| 配对提升 | **+16.7pp**，95% CI [6.6, 26.7] |
| Silent critical-defect rate | **10.4%** |
| HSTU · MovieLens-20M LARGE NDCG@10 | **0.2192**，较 published anchor +4.48% |
| LitGPT transfer composition effect | **+12.5pp**，95% CI [3.0, 22.0] |

### 为什么重要

当“生成研究想法”越来越便宜，真正稀缺的会变成 **execution integrity**。EOP 类似实验系统里的 CI/CD Contract：Agent 可以在允许的状态转移里探索，但不能把实验协议一起随意改写。

### 可信度与局限

62.5% 仍意味着大量执行不完整，10.4% silent critical defect 对自动研究也不低。多 Agent 互审会增加成本，而且 Reviewer 共享盲区时并不构成真正独立验证。HSTU 的 NDCG 提升也来自完整系统，不能单独归因给 EOP。

### 最值得继续追踪

把核心 KPI 改成 **verified useful experiments per dollar**，并联合报告 silent defect、invalid comparison、reproduction rate 和 lineage completeness。

## 6. Decision-Oriented Reranking：推荐系统多了一个 System-1 工作点

[论文原文](https://arxiv.org/abs/2609.40241)

### 发生了什么

Reranking 本质上是有限候选间的结构化选择。该研究把 Jev 这类 decision-oriented model 放进推荐场景，与专用 RecSys Model、pointwise / listwise Qwen 在多个 Amazon Reviews Domain 和不同 Candidate Size 上比较效果与延迟。

### 关键结果

论文没有给一个 headline 数字，而给出更有工程价值的 Pareto 结论：Jev 保持了较强 recommendation effectiveness，候选集扩大时延迟增长比 pointwise Qwen 更平缓；但绝对延迟仍显著高于推荐专用模型。

### 为什么重要

一个更现实的 Serving 分层是：

```text
专用 RecSys Model
→ 高频低延迟基础排序

Decision Model
→ 候选有限、语义更复杂的选择

Generative LLM
→ 少量高价值开放式推理
```

Tool Routing、Memory Selection、Candidate Filtering 也有同样结构。大量今天由 LLM 完成的“选择题”可能会迁移到专门 Decision Model。

### 可信度与局限

Amazon Reviews 离真实大规模推荐的特征复杂度与延迟预算仍有距离。结果没有证明 Decision Model 比同等工程优化的专用 Ranker 更经济，也没有覆盖百万级候选检索。

### 最值得继续追踪

做置信度路由的 Cascade：cheap scorer → decision model → 仅对罕见高价值案例调用 generative model，并共同评估质量、P95 延迟与成本。

## 今日值得收藏的代码 / 学习资源

### Strands Decider 2B：开源 Decision Model 进入 Agent 工具链

[官方发布](https://strandsagents.com/blog/introducing-strands-decider/)

Strands 在 **10 月 1 日**发布 Decider 2B：基于 Qwen3.5-2B torso，替换传统 LM Head，使用约 100 万参数的 pointer-style head 给固定候选打分，并用 rank-16 LoRA 适配 torso。官方定位包括 Tool / Model Routing、Guardrail、Memory / Context Selection、Policy Classification 和 Evaluation。

它的边界也很明确：复杂推理能力明显弱于 Reasoning Model，不能用于 Coding、Chat、Summarization。官方约 115 ms RTX 3090 / 153 ms M3 的小任务中位延迟属于建设方测试，值得复现，不应直接当作跨硬件 SLA。

### Claude-shaped science / BootLoops：科研 Agent 的稀缺环节可能是“问题是否值得做”

[Anthropic 原文](https://www.anthropic.com/research/claude-shaped-science)

Matthew Schwartz 总结 BootLoops 之后约三个月的科研工作流：36 份 manuscript、18 个领域、19 位共同作者，来自约 400 个候选问题。流程强调主协调器、后台 Subagent、持久中间工件、独立验证和 adversarial referee session。

最重要的负面观察是：Claude 跨领域时经常“技术上正确”，但结果在专家看来并不重要，直到领域专家重新定义问题。计算、代码和文献搜索能力正在变便宜，scientific taste 与 problem selection 仍是稀缺环节。

### GEAR：Generative Retrieval 同时处理表示坍缩与 Item Collision

[论文原文](https://arxiv.org/abs/2609.39327)

抖音广告的 GEAR 指出两个问题相互耦合：扩大 Codebook 可减少 Item Collision，却更容易造成 Representation Collapse。BasisVQ 用 orthogonal-basis reparameterization 改善 Codeword 更新，再用 Prefix-aware BasisRQ 与 Context-conditioned Reranking 处理生成和碰撞歧义。系统已部署到抖音广告数亿 DAU 流量；摘要只说线上 A/B 有 substantial improvements，没有统一 Effect Size，因此更适合作为工业架构案例，而非用模糊 headline 做定量比较。

### The KV Cache Is the New Memory Wall：长上下文 Serving 的系统地图

[论文原文](https://arxiv.org/abs/2609.30854)

这篇 SoK 把 KV 优化按瓶颈分区。以 128K Llama-3-70B BF16 为例，单 Session KV 约 42 GB；Quantization / Eviction 主要缓解带宽，Paging / Prefix Cache 解决容量与复用，Tiering 会把压力转移到 Host / SSD / Network。做长 Context Agent Serving 时，先判断自己是 Capacity、Bandwidth 还是 Recompute 主导，再选优化方法，通常比只追“最高压缩率”更有效。

### Vera Rubin × Cognition：Agentic 基准开始从 tok/s 转向完整轨迹吞吐

[CoreWeave 基准](https://www.coreweave.com/blog/cognition-becomes-first-customer-for-nvidia-vera-rubin-nvl72-on-coreweave-cloud)

CoreWeave 与 Cognition 在 SWE-2 上报告 Vera Rubin NVL72 相对 GB200 NVL72 **最高 4.8× total-token throughput**，RL 场景 output-token throughput **3.8×**。这是厂商与客户的第一方早期 Benchmark，不能直接外推到普通 LLM Serving。更值得追踪的是指标变化：Agentic Coding 的系统性能开始按长 Context、高并发、连续 Tool Loop 下能完成多少真实工作来衡量，而不是只比 isolated decode tok/s。

## 今日最值得花 30 分钟阅读的一项

**首选 PivotOPD。**

[论文原文](https://arxiv.org/abs/2609.40285)

这篇值得读，不只因为它给 OPD 加了一个 Loss，而是它抓住了 Multi-turn Agent 的分布问题：错误 Action 会生成新的未来状态，因此“纠正错误之前的 Policy”与“训练错误之后的 Recovery Policy”是两件不同的事。

30 分钟建议重点看 pivotal mistake 的定义、为什么超过一半失败 Rollout 可以追溯到较早关键动作、reverse-KL preventive distillation 与 forward-KL recovery distillation 为什么方向不同，以及为什么只指导少数后续 Turn 就能恢复很多任务。

> **强 Agent 不只需要更低的 first-error rate，还需要在进入错误状态以后仍然拥有足够厚的 recovery support。**

## 今日可立即实践的一件事

给现有 Tool-Agent / Search-Agent 的失败轨迹做一次 **Pivotal Mistake + Recoverability Audit**。从最近 50–100 条失败轨迹中，对每个 Turn $t$ 保存环境快照 $s_t$；让当前模型或强 Teacher 为候选 Turn 生成替代动作 $a'_t$，再从替代状态独立 Rollout 2–4 次。

可以先定义：

$$
\Delta_t
=
P(\text{success}\mid s_t,a'_t)
-
P(\text{success}\mid s_t,a_t).
$$

若某个较早 Turn 的 $\Delta_t$ 很大，就标成候选 pivotal mistake。随后比较两个分支：

```text
A. 只替换 pivotal turn，然后完全交回 Student
B. 替换 pivotal turn，并额外指导后续 2–4 个 recovery turns
```

至少记录 `first pivotal position`、`one-step repair success`、`k-step recovery success`、`irreversible failure rate` 和 `teacher tokens per recovered task`。

如果 A 已足够，主要问题是 **prevention**；如果 A 不行、B 明显恢复，说明缺的是 **recovery behavior**；如果 B 仍无改善，错误可能已造成不可逆后果，继续投入 recovery distillation 的价值较低。

真正要回答的是：

> **你的 Agent 失败，是因为总在关键一步做错，还是因为一旦做错就完全不会把任务拉回来？**
