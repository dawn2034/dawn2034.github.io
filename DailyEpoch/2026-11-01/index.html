1. DeepSeek dsh-superagent：让 Coding Agent 主动接活时，谁控制发起权？

原始资料： 官方研究原型仓库 · 授权设计文档 · 架构文档。仓库于 10 月 31 日公开更新。

发生了什么

DeepSeek 团队公布面向一个 GitHub 仓库的主动式 Coding Agent 原型，作为 DeepSeek Harness Bundle 运行。系统接收 GitHub 或可选的飞书消息，把已授权需求建为 Work Item，在独立 Agent 会话和目录中执行，并在原对话回复结果或 PR；Web Panel 展示需要人处理的事项。设计重点是明确谁能委派任务、何时需要人工响应，以及任务间的上下文与执行隔离。

为什么重要

多 Agent 并发真正的约束不只是 Token 和 GPU，还包括审核负担、任务相互干扰、权限升级与写操作副作用。按 Work Item 隔离、为触发入口设置权限门槛、只在需要决策时通知人，比“始终在线自动提 PR”更适合作为生产基线。

可信度与局限

代码仓库及文档可以直接审阅；README 明确标注 research prototype / not production-ready，且公开代码与文章内部版本不完全相同，部分设计仍是未来方向。未提供独立的长期任务成功率或每人工审核小时收益，不能推断已经是成熟产品。

最值得继续追踪

运行授权白名单、恶意 GitHub Comment、取消任务、重复 Webhook、主分支变化与并行写入的故障注入；检查是否具有幂等队列、审计日志和失败后补偿路径。

2. Factory Droid 1.0：Programmatic Tool Calling 的收益边界

原始资料： Factory Research：Droid 1.0（10 月 29 日） · Droid CLI 文档。

发生了什么

Droid 1.0 把工具调用组织成沙箱内执行的 JavaScript Script。多次读取、查询、过滤与校验在一个程序中完成，模型只接收经过筛选的输出，从而减少大量工具 Schema 和原始日志反复进入 Prompt。厂商同时调整工具按需加载、Prompt 缓存和跨模型 Harness 评测。

为什么重要

对存在大量确定性子步骤的 Agent，保留原始中间结果在执行层可以明显减少模型轮次；安全边界则应继续落实在每个 Tool 的授权与执行端，不能因为 Script 会批量调用就放宽写权限。Script 也把可审计性从逐轮自然语言转移到程序日志与代码审查。

可信度与局限

Factory 一例把移动和核对 151 个 Linear Issue 的 312 次工具调用合并为 2 次模型请求、约 61K Input Token；直接调用的 36 次请求和约 3.1M Token 是按每轮 10 次调用建模的估计。厂商报告 Claude Opus 5.5 场景 Script Mode 成本下降 15%。这些数字不能当作控制变量充分的通用提速或任务成功率保证。

最值得继续追踪

固定相同工具、权限、任务和完成条件，比较 Direct Tool Calls 与 Script 的 P50/P95、Token/成功任务、重试率、异常可恢复性；尤其要测试半数写操作成功后的中途失败。

3. PFA：生成式推荐的 Attention 重要性可能跨解码步稳定

原始资料： PFA 论文 · HTML 全文，v1 首次提交 10 月 29 日。

发生了什么

Progressively Focused Attention（PFA）利用 Semantic ID 自回归解码时注意力逐渐集中，以及候选历史 Token 排名跨步相对稳定的现象。第一步使用全量 Attention 探索历史，随后聚合 Beam 的重要性排序、重排选中的 KV 为连续存储，并逐步缩小后续 Attention Budget。

为什么重要

长用户行为序列的 GR Serving 需要兼顾召回与延迟。静态历史压缩损失信息，逐步动态 Top-k 可能因重复排序和非连续显存访问拖慢推理；PFA 用“一次排序、多次复用”重构计算图，是值得与 FlashAttention / Paged KV 对照的实现路线。

可信度与局限

论文给出两个公共数据集、工业数据和 7 天在线 A/B 结果，但摘要未给可统一复述的业务增益百分比。稳定性依赖 SID 步长、Beam 结构及行为序列分布；应检查稀有兴趣和临时改意图用户。

最值得继续追踪

测 Attention 覆盖率、KV 重排耗时、Kernel 利用率、Top-k Recall、Beam 多样性及 P95，并按兴趣突变/长尾商品分桶。

4. Merge & Branch：让一条长历史监督多个推荐目标

原始资料： Merge and Branch · HTML 全文，v1 10 月 27 日。

发生了什么

生成式推荐通常读取长历史，只监督一个短 SID。M&B 将历史中各商品文本与 SID 压缩为少数学习 Token，再把同一历史编码分成浅而宽的分支预测多个目标 SID，使用 Tree FlashAttention 和共享 KV 减少重复编码；训练梯度从各分支传回共享主干。

为什么重要

从系统角度看，优化对象变成“每次 Prefill 历史带来多少有效监督”。多目标分支为长历史训练提供吞吐收益，也为多意图推荐提供一种显式表示。

可信度与局限

作者报告公共基准优于强比较方法并改进训练/解码效率；不同分支目标的独立性和样本权重会影响真实收益。缺少统一线上时延与转化数据，不能将训练吞吐直接等同线上 GMV。

最值得继续追踪

控制模型参数、历史长度、总训练 Token，比较独立训练与多分支共享的 NDCG@10、SID 碰撞、短尾与长尾商品命中、GPU-hours。

5. ThinkJev：同一个推理轨迹可支持多个停止预算

原始资料： ThinkJev 论文 · HTML 全文，v1 10 月 27 日。

发生了什么

针对有封闭选项、需要概率输出的 Typed Decision，ThinkJev 用同一个混合思考模型提供直接分类 System 1 和推理后分类 System 2。对每个推理中间位置读取相同候选字母的概率，既能在统计校准后的简单题立即作答，也能在推理过程中按置信度早停。

为什么重要

可验证的结构化决策（意图分类、工具选择、规则检查）没有必要每次都跑完整 CoT；更关键的是以实际错误率约束校准阈值，避免一味根据模型自信程度节省计算。

可信度与局限

在 8,359 道测试决策上，Qwen3.5-27B 于目标错误率 5% 的设置中直接回答 24.5% 的题，实际错误率 3.9%；其余题采用动态停止后整体准确率 81.6%，对照 Always Think 为 82.7%，消耗 72% 的思考 Token。该结论基于封闭选项与开发集统计校准，开放式工具任务可能失效。

最值得继续追踪

区分易题、难题与分布外题；对每个置信区间做 Reliability Diagram，测错误高置信停止、P95、升级思考后的净纠错收益。

6. CASH：把模型可靠范围做成广告补贴决策的能力许可证

原始资料： CASH 论文，v1 10 月 29 日。

发生了什么

Advertiser Subsidy Allocation 需要在总补贴率约束下，为账户选择不同补贴折扣。CASH 让知识引导的 LLM 与数值响应模型并行，根据历史结果判断两者在哪些账户、补贴档位可信，形成 Capability License；EPCG 选择最能扩展可靠覆盖面的反馈样本。

为什么重要

这是 Agent 工具治理与经典因果/响应建模结合的工业案例：何时让 LLM 给建议，何时必须交给数值模型，以及何时应该弃权，都由可追溯证据决定。比单纯把业务策略交给 LLM 生成更便于离线校验。

可信度与局限

作者报告单月线上实验覆盖 60% 流量，收入/账户 +15.35%、ADVV +19.86%，整体补贴率基本不变。没有独立的流量随机化、异质性与长期竞争效应复核，不能推断普遍收益或完全由 LLM 贡献。

最值得继续追踪

核对单位经济性、长期增量价值、冷启动广告主、公平性、Policy Coverage 和错误许可证导致的损失；比较纯数值模型及统一策略模型的相同预算结果。

7. RRC：利用相关性标签校准 Dense Embedding 谱压缩

原始资料： RRC 论文 · 作者匿名代码，v1 10 月 26 日。

发生了什么

低维 Embedding 的 PCA/Whitening/SpecTemp 通常依据语料的协方差谱保留方向，却未考虑每个维度对相关文档与负样本区分的贡献。RRC 根据正负样本得分边际的均值和方差估计校正权重，把相关性残差合并到线性变换；不额外引入在线推理阶段。

为什么重要

压缩检索向量时，目标应是同存储成本下的 Retrieval Quality，而不只是重建 Embedding 的平方误差。相关性引导能改善训练分布中重要但方差较低的判别维度。

可信度与局限

论文在五个 BRIGHT 数据集、768 维设置下，相对 SpecTemp 平均提升 2.34 nDCG@10 点，还报告标量/乘积量化后的持续收益。但正负样本标签规模、域迁移及变换更新带来的索引重建成本需要单独检查。

最值得继续追踪

固定 128/256/384 维及索引字节预算，用 BM25、Dense、PCA、SpecTemp、RRC 做 Zero-shot 与 In-domain 对照，记录 nDCG@10、召回率、P95 和量化误差。

8. Top-1 LLM 推荐：候选顺序是隐藏的实验变量

原始资料： 位置偏差论文 · HTML 全文及统计检验，v1 10 月 27 日。

发生了什么

作者针对 LLM 直接从候选商品列表给出 Top-1 推荐的场景，设计 Contingency Matrix 卡方检验与 Permutation-based Null Model。将同一用户查询与相同候选商品做多次位置重排，检验被推荐的商品是否与其在 Prompt 中的顺序独立。

为什么重要

LLM Reranker 的线下成绩可能受传入候选集的固定排序影响。即使检索结果、用户需求不变，顺序也可能改变结论；这对选品、公平曝光和 A/B 解释都有直接影响。

可信度与局限

研究使用 2,000 条模板化用户查询、每条 20 种顺序，共 40,000 个实例，在测试模型中检出显著位置依赖；但单轮 Top-1、固定 Prompt 的外推范围有限。统计显著性不等于严重业务损失，需要报告 Strong Positional Bias。

最值得继续追踪

在同一 Candidate Set 上做随机排列与重复抽样，区分低质量替换和等质量商品之间的顺序敏感，给出置信区间与最终转化差异。

9. FedRecAgent：共享推理知识而保留用户原始历史

原始资料： Federated Recommender Agents，v1 10 月 29 日。

发生了什么

FedRecAgent 不聚合原始交互历史或更新共享大模型权重，而把本地推荐经验写成 Condition–Transition–Reasoning（C-T-R）单元，按照条件和决策转移组织可复用经验。每个客户端保留个人语义与决策记忆，再按当前请求选择合适的共享推理。

为什么重要

它提供一种将推荐系统的跨用户知识迁移从参数聚合转向可检索经验库的路线，适合个体偏好冲突、局部稀疏数据和低成本持续迭代。

可信度与局限

作者在三个领域报告优于联邦与 LLM 推荐基线，但将推理文本共享不自动构成差分隐私保证；例子可能泄漏独有行为、位置和属性。也没有证明真实多租户安全部署已经可行。

最值得继续追踪

在用户隔离的时间留出集比较本地-only、共享未经结构化推理和 C-T-R，加入 Membership Inference、罕见特征泄漏、冷启动与推荐多样性测试。

10. CERN chATLAS：垂直领域 RAG 的真实部署证据

原始资料： chATLAS 论文 · HTML 全文，v1 10 月 24 日，属于七天回顾。

发生了什么

ATLAS 实验的内网 RAG 助手覆盖 30,000 多份内部文档，采用稀疏与稠密混合检索、领域 Embedding 微调和 Contextual Retrieval，并配有意图路由、安全处理、Mattermost 接入与 MCP 服务接口。

为什么重要

它说明在专业术语密集且资料权威性各异的环境下，检索器领域适配、证据溯源及实际用户工具接口往往比仅更换更大的生成模型更可控。

可信度与局限

作者称在最困难的文档来源上，领域微调加上下文检索使正确文档 Top-1 命中频率增加超过一倍；但评测问答部分自动生成，可能高估典型真实用户的收益。内部文档无法完全公开，独立复现受限。

最值得继续追踪

分析原始关键词检索的长尾失败、权威来源分级、更新延迟、人工复核与误引用率；比较 Hybrid、Contextual Retrieval 和领域微调的增益贡献。

候选主题 1：Droid 1.0 的程序化工具调用能否显著改善成本

候选主题 2：DeepSeek Super-agent 的授权边界与被动/主动工作流

Factory Research：Droid 1.0 — Building a Frontier Harness。

今日可立即实践的一件事

在已有 Agent Trace 上做程序化工具调用的离线回放。 选择 30—50 条包含多个查询和校验步骤的工具工作流，分别实现 A 版逐步 Model→Tool 调用和 B 版一次性生成受限 Script。两版使用完全相同的 Tool API、授权、数据快照和终局校验器；B 版将原始 Tool Result 留在执行层，只把必要汇总与异常交给模型。

记录 model_requests、input_tokens、tool_calls、P50/P95、task_success、partial_write_recovery 与 unauthorized_tool_rejection，按工具次数 1—3、4—10、10+ 分桶。额外注入“第 N 次写入成功后网络断线”“工具返回字段缺失”“权限中途撤销”三种故障，检查 Script 是否引入跨步骤批量失败或不可撤销副作用。

上线判定： 在成功率不降低且权限拦截完整的前提下，才根据每成功任务成本和恢复时延选择程序化工具调用；不允许只根据总 Token 节省下结论。
