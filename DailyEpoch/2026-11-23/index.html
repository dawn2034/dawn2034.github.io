今日主线： Agent 能力进步正在从“换一个更强的基础模型”转向三条可验证的工程路径：训练模型适应真实 Harness；为长期运行设计可追溯、可检索的记忆；把评测从容易给分的短任务扩展到有延迟反馈、需要专家判断的真实工作。推理基础设施则开始按不同层的缓存特征决定显存驻留和数据搬运。本期优先分析可复现方法、测量口径与失效边界。

归档日期： 2026-11-23（Asia/Shanghai）。研究观察窗口： 优先 2026-11-22 07:21—11-23 07:21（北京时间，最近 24 小时）。由于周末 arXiv 常规提交节奏较慢，主要研究窗口扩展到 11-20 07:21—11-23 07:21（72 小时）；另以 7 天窗口追踪 11 月 18—20 日首次公开但仍有工程增量的研究。每项标注原始发布日期；“本期关注”不代表当天首发。 本期没有将 11 月 19 日缺失归档冒充 11 月 23 日稿件。

一、研究与技术进展：按工程影响排序

1. METR：任务时间跨度上升，不意味着所有真实工作已接近自动化

发生了什么（2026-11-20，研究机构原文）： METR 更新了 AI 研发相关任务的评测，包括更长和更开放的任务。对于结果可客观验证的 TH2 子集，其报告的前沿模型 50% 成功时间跨度最高约为 27 小时，拟合倍增时间约 3.61 个月。与此同时，遇到专家判断、慢反馈、较高环境构建成本的任务，模型依然明显弱于在相同约束下的人类专家。METR 原始报告

关键结果与方法： 把“人类完成需多长时间”“模型完成比例”“是否容易准确判分”拆成独立变量；不同任务族与阈值分别建模。它也指出模型与人类的相对优势受到环境中可利用自动反馈的程度影响。27 小时是特定可验证任务分布上的统计时间跨度，不能解读为 Agent 能独立可靠工作 27 小时。

为什么重要： 推荐、搜索与交易 Agent 如果只用单轮 QA、短链路购物成功率评价，容易高估真正的长期能力。将测试集拆成规则能直接验收的硬约束任务和需要专家评价的策略任务，通常比增加一个总分更有诊断价值。

可信度与局限： 原始研究包含方法、数据和鲁棒性讨论，证据级别高于公司产品发布；但任务采样、基线人类招募、分数阈值及评判成本都可能带来外推偏差。对未来能力时间线的外推是条件预测，不能作为确定事实。

最值得追踪： 同等推理预算下，模型在“必须询问用户是否允许资金转移”“商品描述不完整”“最终答案需要商业判断”等难评分任务上的相对表现；以及判分成本与性能增长斜率的关系。

2. Hugging Face：把 RL LoRA 训练在真实 Agent Harness 内，减少工具调用

发生了什么（2026-11-20，新技术总结；11-17 前后已出现模型）： Hugging Face harness-hub 针对同一个 Qwen3.8-27B 基座，分别在 pi、OpenCode、Hermes 等真实 Agent Harness 中训练轻量 RL Adapter。11 月 20 日技术文章报告：pi / Terminal-Bench 2.1 的 pass@1 由约 39% 提升到 55%，平均输出 token 从约 2.9K 降至 1.5K。独立模型卡进一步报告 pi / SWE-bench Pro hard-51 子集 39.2%→64.7%（关闭 thinking、同 Harness 的成对比较）。新技术总结｜训练设计｜模型卡

关键机制： 固定基座模型；每个 Harness 单独训练 LoRA；让被训练的模型走该 Harness 原生的规划、工具调用、上下文管理和停止逻辑；使用可验证任务奖励和工具效率奖励，并通过 safeagents 在执行前拦截越权和污染评测的工具调用。模型卡列出 AsyncGRPO、8 个 rollout/任务、LoRA rank 32、部分数据与配套权重。

为什么重要： 相同模型在不同 Harness 的 tool schema、系统提示词、上下文压缩规则、终止策略下会有明显的策略分布差异；可以尝试 Harness-specific policy adaptation，而非每次对话调用更大模型。对于商品 Agent，这提示把库存检查、参数校验、价格比较等实际工具轨迹转换成可验证训练环境。

可信度与局限： 模型卡、训练方法和权重可查；核心数值仍为作者自报，SWE-bench 子集小，指标与其他 Harness 评测不可横向拼接。网页早期宣传数字和更新后模型卡基线曾变化；本期使用模型卡当前口径。GGUF 低比特版本未获相同强度的复测，不能直接套用 BF16 成绩。

最值得追踪： 切换工具 API 版本后 Adapter 的退化、跨 Harness 迁移、被拦截轨迹比例以及在真正未见过的业务环境中的样本效率。

3. IBM Agent 自蒸馏记忆：更多 Guidelines 并不一定更好

发生了什么（论文 2026-11-19，7 天跟踪）： How Much Should an Agent Remember? 将历史 Agent 轨迹提炼为 lesson，再合并成 guideline，比较向当前任务提供全部规则或只检索一部分规则。作者报告 AppWorld 上，较强模型 DeepSeek-V3.2 使用完整规则集的 task completion 提高约 9.5 个百分点；较弱模型 gpt-oss-120b 从 39.9% 基线升至完整规则集 51.2%，而选择约 29 条规则可达 55.4%（两次运行均值）。ALTK-Evolve 仓库

关键结果： 最佳记忆量受模型处理能力、规则长度、冲突程度和上下文干扰共同影响。论文披露了高支持度规则反而害人、合并时来源丢失、工具错误被静默吞掉、基线设置混淆等负面案例。

为什么重要： 自进化 Agent 的关键产出应是通过 holdout 验证的可迁移经验。盲目把所有历史总结注入 system prompt，可能同时增加成本、冲突和过拟合。

可信度与局限： 有开源实现与应用型研究细节；增益依赖 AppWorld 任务分布和具体模型；两次运行不足以判定小幅提升必然稳健。部署声称不等于公开生产 A/B 收益。

最值得追踪： 记忆选择器的误召回与灾难性干扰率；按模型规模和上下文负载寻找 memory budget 的响应曲线，而非统一设一个最大条数。

4. GrepMem：无索引、保留完整日志的极简长期记忆基线

发生了什么（论文 2026-11-18，7 天跟踪）： Forget Freely, Grep Later 用只追加的完整文本日志和正则检索工具，替代先摘要再存储的有损记忆方案。作者在五种上下文管理策略下训练 Qwen3.5-9B，报告 ContextBench 上 95%—97% 准确率，而有损基线最高约 21%；在 BCP-Multi 上比 SUPO 摘要高 8.8 个百分点。

关键机制： 把所有旧交互持久化，短上下文里只保留“如何搜索旧日志”的能力。查询触发时使用 grep 式精确匹配，而不是要求模型预先猜未来需要保留哪些信息。

为什么重要： 对有大量订单 ID、SKU、时间戳、日志行号、工具原始回执的 Agent，逐条原始记录是很强的 audit baseline。与向量记忆系统比较时，应固定 token 成本、测试集和可见性权限。

可信度与局限： 公开的是作者训练加评测结果，优于空泛概念设计；正则匹配对同义改写、模糊实体匹配和跨文档语义关联有固有弱点。还需测量长日志检索耗时、隐私泄漏和权限撤回。

最值得追踪： 混合检索（regex + BM25 + embedding）是否超过纯 grep，在相同成本下的额外贡献；日志压缩后是否能保留可验证证据链。

5. MemFolder：减少“记忆条数”和“召回后的上下文长度”两个独立成本

发生了什么（论文 2026-11-19；仓库更新 11-20）： MemFolder 先通过 RecordFolder 以实体、时间链和互补锚点合并记录，再由 ContextFolder 生成更短表述并检验关键事实是否可恢复。作者报告在 Mem0 上，把记录数量减半可保留文本评测平均性能的 99.0%；仓库另报告 ContextFolder 对部分基准进一步减少每条记录约 38%—40% token。官方代码及实验说明

为什么重要： RAG 记忆并非单一压缩比问题：记录数量主要决定检索与索引开销，检索文本长度主要决定 prefill 与 attention 成本。两种预算需要独立测量。

可信度与局限： 论文和代码可核验；“保留 99% 性能”是相对指标，不能当作 99% 回忆准确率。模型和数据规模可能影响压缩损失，长期更新中的冲突、遗忘与权限问题仍待验证。

最值得追踪： 以实体命中率、时序事实恢复率、召回后首 token 延迟三个轴监控结构化压缩，而非只看压缩率。

6. TideCache：混合模型的异构缓存不应简单共用一套驻留策略

发生了什么（论文 2026-11-19，7 天跟踪）： TideCache 面向包含全局注意力层和有界状态层的 Hybrid LLM，把缓存池、前缀流式传输和请求调度组合起来。在 GB300、GH200 的七种模型/平台配置下，与 SGLang + HiCache 基线相比，作者报告最多 2.04 倍的 Agent turn 完成量、P50 每 token 延迟降低 20%—59%、P50 TTFT 改善 1.40—3.05 倍。

关键机制： 缓存池在稳定虚拟地址后重分配物理页；利用有界状态层计算间隙提前拉取下一个全局注意力层的历史前缀，生成中的 KV 继续常驻；调度器按请求大小与队列状态选择 resident/streamed 模式。

为什么重要： 长上下文 Agent 不只是“KV Cache 很大”，还包括 SSM/linear attention 状态和不同层的访存时序。内存驻留策略直接决定并发、TTFT、TPOT 的三角权衡。

可信度与局限： 有真实硬件实验及明确对照，但数字受拓扑、带宽、批量、输入长度与基线配置强烈影响，不能直接移植到消费级 RTX 4080。论文摘要注明 SGLang 实现，未据此推断已有稳定可用的独立开源包。

最值得追踪： 在混合模型上分开绘制 cache residency、PCIe/NVLink 带宽、P95 TPOT 和请求弃置率；关注与 prefix caching、推测解码的互相干扰。

7. TwinLab-Bench：评测 Agent 是否能真正设计实验，而不只执行给定步骤

发生了什么（论文 2026-11-19）： TwinLab-Bench 使用真实实验室记录构建 52 个任务、100 余种实验操作；Agent 自己提实验方案，环境 Agent 通过实验记录和计算器生成回答，然后用隐藏的真实实验结果评分。最强的受测模型 Claude Fable 5.2 平均分 45.0，其余模型更低。任务与代码

为什么重要： 这是对“环境真实性”的一次工程化尝试：固定结果、隐藏验收、复现真实实验约束，比单纯让另一个 LLM 给 Agent 研究报告打分更接近可证伪的评测。类似思想可迁移到推荐策略、金融规划、产品匹配的模拟环境。

可信度与局限： 数据和实验定义有原始材料支撑，但 Twin Agent 仍是代理实验环境，现实世界的隐藏变量、实验误差与长时反馈不完全可复制。45 分不能代表通用科学能力上限。

最值得追踪： Agent 在做了无效实验以后是否有可重复恢复能力；同一实验操作多次采样的一致性、对环境提示泄露的抵抗。

8. dLoop：扩散语言模型在提交 token 前反复细化潜在表示

发生了什么（论文 2026-11-19）： dLoop 将预训练 Diffusion LM 划成 Prelude—Loop—Coda 三段，在相同的部分 mask 状态上循环执行共享中间层，增加 latent compute，但不推进扩散去噪步数。作者在 GSM8K、MATH、MBPP、HumanEval 上报告最高或并列最高准确率，并在按循环计算量调整的 TPF 指标上超过 Fast-dLLM。

为什么重要： “多花计算再决定是否输出”与“输出之后发现不够可靠再补采样”是不同的控制问题。这给 reasoning-aware scheduling 增加了隐式计算深度这一维度。

可信度与局限： 是受控实验下的早期研究；文中 TPF 不能自动替代实际端到端延迟、能耗和生产吞吐。不同模型家族的比较尤其需要归一化硬件与质量目标。

最值得追踪： 何时触发额外循环的策略、按问题难度动态循环次数，以及相同 GPU 秒预算下与自回归思考模型的正面对比。

9. OpenAI：对抗性蒸馏与推理轨迹泄露防护的新实测

发生了什么（官方文章 2026-11-20）： Combatting adversarial distillation 公布关于未经授权能力蒸馏的威胁模型、防御措施和内部红队评估。其一项自适应测试称，提取历史请求中受保护推理轨迹的平均成功率，从旧防护下的 54.0% 降至更新防护下的 0.2%。

为什么重要： Agent RL 与蒸馏往往需要高质量轨迹，但“用于训练的合法轨迹”“可见的工具记录”和“模型内部受保护推理”有不同的数据治理边界。服务端不应假定客户端只会按预期访问模型信息。

可信度与局限： 属于供应商内部测试，攻击者集合、评价条件和产品版本同时变化；不能把该百分比推广为对所有模型或所有攻击的保证，更不能等同于开放可复现第三方评测。

最值得追踪： 公开红队可复现协议、长上下文与多轮 Agent 场景下的防护稳健性，以及不公开内部推理时是否仍能提供可审计外部决策依据。

二、给推荐 / 搜索 / 购物 Agent 的技术合成

在同一离线任务集上，建议把系统拆成 Harness、Memory、Policy、Environment、Verifier、Serving 六个可独立版本化的层。下表是本期研究导出的工程假设，不是已实现的生产收益。

层关键变量最小必要对照主要风险
Harness工具参数 schema、超时、重试、停止规则固定模型换 Harness策略漂移、错误工具调用
Policy基座 vs Harness LoRA、推理预算同任务/相同预算Benchmark 过拟合、reward hacking
Memory原始日志、选取 guidelines、结构压缩no memory / grep / selected guideline来源丢失、错误规则积累
EnvironmentSKU/价格/库存快照、状态转移固定数据集与可重放模拟器时间泄漏、模拟器与真实分布偏差
Verifier硬约束 / 专家判断、任务后验规则验收与盲审分开Judge 偏好与不可验证高分
ServingKV/状态缓存驻留、请求路由同延迟目标与同成本约束平均延迟掩盖 P95 尾部

特别提醒： 不要把 agent success、judge score、tool-call reduction 三个指标混作“模型更聪明”。更少工具调用可以来自更好的决策，也可以来自跳过必要检验；最有价值的是在 硬约束违规不增加 的条件下节省单位成功任务成本。

今日值得收藏的代码 / 学习资源

以下按实践用途排序，区分可直接运行的代码、研究原文和官方变更记录；部分资源早于本期，作为方法依赖收录，不宣称 11 月 23 日新发布。

  1. Hugging Face Harness Adapters（11-20 方法文章）：同一基座多个 RL LoRA、跨 Harness 合并与评估策略；重点读训练数据隔离。
  2. harness-hub/Qwen3.8-27B-pi-adapted（模型卡）：读 benchmark 分母、thinking 配置、训练步数、GGUF 未复测提示。
  3. TRL + Harbor：训练真实 Agent：HarnessRolloutWorker、OpenEnv、Harbor 的黑盒 Harness 集成路径，适合研究 Tool-Agent RL。
  4. AgentToolkit/altk-evolve：从历史轨迹提炼规则并动态召回；与上面的模型专用记忆预算论文配套。
  5. MemFolder 代码与 LoCoMo 实验：RecordFolder、ContextFolder 与压缩恢复测试；有具体安装与 benchmark 配置。
  6. TwinLab-Bench 任务和代码：研究开放式实验设计与可验证环境；可借鉴环境接口。
  7. METR 2026-11 能力评测方法：建议精读人类基线与难评分任务的定义。
  8. Cline SDK v0.2.1（11-21 Release）：session.resume、模型切换后推理字段兼容、文件读取 50K 上限修正；要做“保存—压缩—切换—恢复”验收。
  9. claude-mem v16.0.3（11-21 Release）：针对大记录 / JSONL 解析失败的边界处理；用于检查记忆摄入是否静默截断。
  10. OpenAI 对抗性蒸馏技术说明（11-20）：数据治理和推理可见性安全边界；是自有测试证据，不能当独立行业标准。
  11. GrepMem 论文：无 Embedding 记忆基线的理论与实验描述，可作为所有复杂记忆方案的下限对照。
  12. SGLang 官方仓库：TideCache 论文以 SGLang/HiCache 为对照，适合理解 Prefill / Decode 分离与缓存观测指标；此链接不是 TideCache 独立复现代码的证明。

METR｜AI R&D-relevant model capabilities are improving rapidly and are getting harder to measure（2026-11-20）。

今日可立即实践的一件事

建立一个 Agent Memory × Verifier 的 30 例对照小实验（无需训练新模型）。

先冻结 30 条包含跨轮次约束、商品 SKU、价格区间、库存变动和需澄清条件的任务，以及相应工具返回快照。对固定模型与同一 Harness 运行以下四种配置：A 无持久记忆；B 原始 append-only 日志 + regex 查询；C 从成功/失败轨迹中提取不超过 20 条 Guidelines；D 只检索当前任务最相关的 5 条 Guidelines。所有条件使用相同工具权限、温度、最大预算，至少两个随机种子。

每条样本记录 hard_constraint_pass、final_task_success、evidence_recoverability、错误工具调用、P95 延迟、总 token 和单位成功任务成本；为关键事实构造反事实负控（例如过期价格、同名不同 SKU、库存反转），检查 Agent 是否会照搬旧记忆。若 C/D 提升成功率但增加约束违规，就先停止引入自动更新规则。GrepMem 的目标是提供强基线，不预设必然优于精心选择的 Guideline。
