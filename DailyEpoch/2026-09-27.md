# 每日 AI 技术简报｜2026-09-27

> **今日主线：** Self-Play Pretraining · Scaled Agent RL · Reasoning Compression · Recommendation Auto-Research · Search-Aware Credit · Confidence-Routed Evaluation

今天是周日，arXiv 没有新的常规公告；最新常规批次为 2026 年 9 月 25 日。本期集中讨论训练数据自演化、Agent RL 的环境与奖励扩展、长程 Agent 状态压缩、推荐算法自动研究以及检索组件级的强化学习。

## 今日核心判断

1. **Self-play 开始触及预训练。** 从随机初始化模型出发，让程序生成器探索可预测结构，可以在未将自然数据纳入梯度更新的条件下获得对真实数据的部分泛化。但这不意味着能够凭空恢复世界知识。
2. **Agent RL 的扩展不只依赖模型计算。** MiMo-V2.6 同时扩展 Environment Diversity、Rollout Volume 与 Groupwise Grading；成功率高时，二元奖励缺乏分辨率。
3. **旧推理往往属于临时工作状态。** ICLR 只压历史 Reasoning，保留 Tool Call 和 Observation，在 WorkBuddyBench 上降低成本的同时保持或改善质量。
4. **推荐 AutoResearch 的核心资产是研究谱系。** AgentX-Model 组织 Reproduce、Follow-up、Composition、Diagnose，而不把每次实验看成孤立事件。
5. **搜索中的 Reward 应按组件职责分配。** Roblox 的 Search-Aware RL 用实际搜索结果向 Query Understanding 的不同组件反馈。
6. **低成本 Judge 应优先充当分流器。** Jev-as-a-Judge 在低风险偏好判断中廉价高效，复杂推理及对抗样本应升级给强 Judge。

## 1. Self-Play Pretraining with Zero Data：让数据生成器追踪学习者的能力边界

[原始论文](https://arxiv.org/abs/2609.30063)

### 发生了什么

Generator 搜索可执行程序，将执行结果转成字节序列；Learner 对这些序列做 Next-token Prediction。纯粹追求难度容易产生随机噪声，因此作者用 Learner 最近的真实梯度更新方向奖励生成器，鼓励发现“当前值得学、能够学”的结构。

### 关键结果

训练覆盖约 34.36B 个合成 Token、4096 Context。作者在文本、图像、音乐、语音和代码等未用于梯度更新的自然数据上观察到随 Self-play Compute 改善的 Zero-shot Loss，并观察到 Reverse、Stack、Associative Recall 等 In-context Learning 行为。生成器早期找到了 Fibonacci、Geometric、Quadratic 等结构化程序族。

### 为什么重要

这将合成数据从固定题库采样推进为 Learner-dependent Curriculum。未来可以让自然数据提供世界事实、程序化 Self-play 提供某些可由计算发现的通用结构。

### 可信度与局限

“Zero Data”指自然数据未进入训练梯度；研究过程的超参数选择仍使用自然数据 Validation Loss。当前规模也远低于大型基础模型预训练。可预测结构与偶然世界事实必须严格区分。

### 最值得继续追踪

做 Natural-data Efficiency 实验：先用不同规模 Self-play 预训练，再给相同自然数据预算，比较下游能力的学习曲线。

## 2. MiMo-V2.6：成功轨迹过多时，奖励分辨率成为新瓶颈

[官方模型卡](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL) · [开源蒸馏版本](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Distill-Qwen-9B)

### 发生了什么

MiMo-V2.6 的异步 GRPO 单步使用 1,568 个 Prompt、各 16 条 Rollout，约 25,088 条轨迹。它混合 Coding、General Agent 与 Visual 等环境，并用 Groupwise Agentic Grading 对同组中都成功的轨迹进一步排序。

### 关键结果

| Benchmark | MiMo-V2.6 Pro | V2.5 Pro |
|---|---:|---:|
| DeepSWE v1.1 | 71.9 | 19.0 |
| AutomationBench | 53.1 | 16.0 |
| Terminal-Bench 2.1 | 89.9 | 65.2 |
| Toolathlon-Verified | 76.9 | 49.1 |

### 为什么重要

二元奖励在成功样本比例很高时会趋向饱和。路径效率、冗余调用、产物质量和稳健性构成进一步学习的排序信号。

### 可信度与局限

这些分数来自 Xiaomi 第一方评测；模型和 Harness、采样协议、环境分布的共同变化限制了因果归因。更细的 Judge 也增加训练成本和可被利用的评分边界。

### 最值得继续追踪

在 9B 开源模型上固定 SFT 起点，分离比较 Binary RL、Groupwise Grading 和 MOPD 的每 GPU-hour 边际收益。

## 3. ICLR：为什么 Agent 可以丢弃旧推理？

[原始论文](https://arxiv.org/abs/2609.29875)

### 发生了什么

Interaction-Aware Compression for Long-Horizon Reasoning 仅处理历史 Reasoning Block，将 Action、Tool Call、Observation 原样保留，用冻结 Proxy 的 Entropy 估计旧推理的未来依赖性。

### 关键结果

260 个 WorkBuddyBench 任务中，平均 Reward 从 0.699 到 0.718；Input Tokens 下降 25.5%，Output Tokens 下降 14.4%，Cache-read Tokens 下降 33.3%。

### 为什么重要

Reasoning 是临时计算状态，环境 Observation 是外部事实，代码和文件是持久产物。推理结论外化之后，继续重放历史思考过程的边际价值可能下降。

### 可信度与局限

Proxy Entropy 并不是因果重要性的直接标注；减少某段推理可能改变后续工具选择，因此局部 Token 节省与整体成本关系非线性。

### 最值得继续追踪

使用 Externalization Check：确认约束与结论已有可验证持久表示后，再允许压缩相应 Reasoning。

## 4. AgentX-Model：算法实验需要长久的研究状态

[原始论文](https://arxiv.org/abs/2609.30001)

### 发生了什么

Research Agent 研究论文、历史实验和线上反馈，提出可执行方案；Model Agent 修改训练代码、执行实验并返回效果与未解决问题。四类行动分别是 Reproduce、Follow-up、Composition、Diagnose。

### 关键结果

636 个完成且实际改变模型的实验中有 560 个 AUC Point Estimate 高于业务基线。建设方还报告一组线上 A/B 的 Acquisition Efficiency 提升约 10%–15%、目标人群广告支出提升 15%–20%、Watch Time 提升约 0.3%–0.8%。

### 为什么重要

实验之间具有依赖结构：复现提供 Anchor，Ablation 划清贡献，Follow-up 验证局部机制，Diagnose 定位新失效。Agent 应维护 Research Lineage。

### 可信度与局限

560/636 不能解释成 88% 的实验统计显著成功；线上结果属于第一方报告。更复杂的实验调度在论文部分控制设置中也未能稳定提高效率。

### 最值得继续追踪

为上线模型维护数据、Checkpoint、指标、祖先实验、失败分支和 A/B 的端到端因果证据链。

## 5. Search-Aware RL：组件级 Reward 应与真实搜索后果对齐

[原始论文](https://arxiv.org/abs/2609.30177)

### 发生了什么

Roblox 为 Query Understanding 的 Intent、Expansion、Filter 等组件分别设计与真实 Search Engine Interaction 对应的 Reward，先通过 Distillation + SFT 保证 Schema，再进行 RL。

### 关键结果

论文报告 NDCG@20 相对 SFT Policy 提高 8.9 points，相对统一 End-to-end Reward 的 RL 提高 3.5 points。

### 为什么重要

不同组件对检索系统的贡献路径不同，简单向所有输出 Token 广播同一个 Reward 容易产生错误 Credit。

### 可信度与局限

组件 Reward 高度绑定 Roblox 的 Search Stack；局部改善 Recall 也可能提高 Ranker Noise，必须保留端到端指标护栏。

### 最值得继续追踪

为检索中的 Query Rewrite、Filter 和 Evidence Selection 建立可解释的分层 Reward 与 A/B 归因。

## 6. JEV-as-a-Judge：小 Judge 适合分流，不宜承担全部验收

[原始论文](https://arxiv.org/abs/2609.26550)

### 发生了什么

轻量 Decision Judge 对固定候选的偏好选择可以直接输出分数，避免生成长篇推理。论文研究它在 Preference Judgment、过程核验和对抗性错误中的表现差异。

### 关键结果

常规比较调用成本约为强 Comparator 的 0.36%；在部分普通偏好任务接近强 Judge，但在深层推导链和具有误导性格式的样本上明显退化。

### 为什么重要

Judge Fleet 可以分层：大量低风险样本由廉价评分器处理，不确定及高风险样本调用更强验证器。

### 可信度与局限

Confidence 在不同 Domain 不自动校准；要针对工具轨迹、代码、数学、研究评估分别学习升级阈值。

### 最值得继续追踪

监测不同风险分桶下的错误接受率，而不仅是整体平均判断准确率。

## 今日最值得花 30 分钟阅读的一项

[Self-Play Pretraining with Zero Data](https://arxiv.org/abs/2609.30063)。

重点阅读 Gradient-alignment Reward、随机噪声为何不是有效难度、Uniform Prior 与 Adaptive Self-play 的差异，以及自然数据未参与梯度更新与世界事实无法凭空学习之间的边界。

> 数据生成器是否能持续找到 Learner 当前还缺少、且恰好能够学习的结构，可能成为下一条预训练效率轴。

## 今日可立即实践的一件事

对现有 Agent RL 数据池做 **Groupwise Reward Resolution Audit**：选取 100–300 个 Prompt，每个采样 8–16 条 Rollout。对同组多条成功轨迹记录路径长度、Tool Calls、Verifier Margin、关键约束和 Artifact Quality，比较二元 Reward 与 Groupwise 排序信号。

重点报告成功组比例、同 Reward 下质量分歧、额外 Judge Cost 和 Reward 排序一致性。如果绝大多数 Prompt 只有零或一条成功轨迹，优先增加 Exploration；只有当成功轨迹足够多且质量差异显著时，昂贵的 Groupwise Grading 才值得投入。
