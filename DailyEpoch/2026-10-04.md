> **今日主线：** Scientific Inspiration Retrieval · Belief-State Control · Active Harness Curriculum · Deep Looped MoE · Catalog Context Curation · Decision Models

今天是周日，arXiv 没有新的周末常规公告；最新常规批次仍是 **2026 年 10 月 2 日**：cs.AI 381 条、cs.CL 184 条、cs.LG 430 条、cs.IR 21 条。分类之间存在大量交叉收录，不能直接相加。

今天最值得连起来看的变化，是 Agent 系统开始把“保存更多历史”与“理解当前世界状态”明确拆开：长程执行需要的是经过证据校验的 belief state，而 Harness 自我改进则开始主动决定“下一批最值得训练的失败模式”。科研 Agent 侧，一个不太舒服但重要的结果是：复杂 Agentic Search 并不天然比朴素 Embedding Retrieval 更会找到真正改变研究方向的论文。架构侧，Looped MoE 开始处理深循环时的状态漂移与 Router 塌缩；推荐／搜索侧，完整 Catalog 即使能塞进 Context，也仍需要学习“哪些商品、以什么顺序进入推理”。

## 今日核心判断

1. **科研 Agent 的瓶颈不只在推理，可能首先在高召回的“灵感检索”。** ScholarCatalyst 让近期论文的一作回溯标注：哪些更早的工作真实地影响、或本可推进其项目。复杂 Agentic Search 在 Recall@20 上为 0.42，低于单纯 Embedding Retrieval 的 0.48；Claude Fable 5.1 Agent 也只有 0.51。更多搜索步骤没有自动转化成更好的研究灵感召回。

2. **长程 Agent 的核心状态应从“历史摘要”升级为“可验证的当前信念”。** Beyond Memory 的 PoS 将当前世界建模为 task-conditioned belief state，同时维护 epistemic / achievement gap；Belief Sentinel 对每次更新做证据一致性检查，并在停滞、循环或漂移时诊断 Belief Trapping。论文在 ALFWorld、LOCA-Bench、RCA-100、ClinDiag 上跨三个模型取得最高总体结果，相对最强基线最高提升 22.68% 和 37.89%。

3. **Harness 自我改进也需要课程学习。** ActiveSaddler 把“接下来应该让 Harness 优化器看到哪类失败”建模成非平稳 Bandit，而不是固定顺序消费 Scenario。GAIA2 Test Pass@1 +4.4pp，Terminal-Bench 2.0 +7.5pp。自我进化的瓶颈因此不仅是 Patch Generator，还包括训练经验的选择顺序。

4. **Looped MoE 要扩到深循环，必须同时解决状态稳定性与专家多样性。** LOOM 发现超过两次循环后，Residual Variance 会造成 Representation Drift，同一批 Expert 又会反复被选中。通过 Residual Scaling、Input Reinjection、Per-loop Router 与 Looping Residual，模型可以稳定扩到 9–12 loops；近等 FLOPs 的 700M 设置在 5 loops 时 PPL 18.36→16.54。

5. **“整个 Catalog 已经放进 Context”并不等于 LLM 会正确使用它。** RPTune 用可学习的 encoder-reorganizer 先排序／裁剪产品，再以 downstream feedback 训练；7 个真实商家、每家 100 个复杂对话查询中，Context Curation 最多让搜索准确率 +31.4pp，后续 Post-training 平均再增加 10.3pp。长上下文容量与有效证据编排是两个问题。

6. **Decision Model 的能力边界开始变得清楚：擅长评估已呈现的候选，不擅长替你模拟未发生的未来。** *Code Owns the Simulation, Jev Owns the Evaluation* 中，Jev 类模型能很好地判断给定状态中的选项，但如果正确决策依赖对环境后果的隐式 rollout，就会系统性失误；当代码显式提供 Lookahead / Physics Simulation 后，它又能成为很强的 Controller。这个边界对 Tool Routing、Reranking 和 Agent System-1 层很重要。

## 1. ScholarCatalyst：科研 Agent 先别高估自己的“搜索智慧”

[论文原文](https://arxiv.org/abs/2610.02202)

### 发生了什么

ScholarCatalyst 试图测量一个比“能不能找到主题相关论文”更难的问题：**能不能找到真正会改变研究设计、方法或论证的前置工作**。

数据来自 184 位近期 CS 论文一作，对 207 个项目进行回溯标注。候选文献严格限制在项目开始时已经公开的工作，避免让检索器“偷看未来”。作者还要求研究者写出为什么某篇论文实际影响了项目，或为什么它本可以推进项目。

### 关键结果

| 方法 | Recall@20 |
|---|---:|
| Embedding Retrieval | **0.48** |
| Agentic Search | 0.42 |
| Claude Fable 5.1 Agent | 0.51 |

这里最有信息量的并不是 0.51 这个最高值，而是复杂 Agentic Search 没有超过 Embedding Baseline。

### 为什么重要

科研 Agent 很容易把“搜索次数更多、查询改写更多、浏览链更长”当作更强 Research Ability。但研究灵感检索具有三个额外难点：重要论文可能词面不相似；真正有价值的连接常跨子领域；“相关”与“能改变项目”不是同一个标签。

因此，Research Agent 的检索目标更接近：

$$
P(\text{paper changes research trajectory}\mid q,\text{project state})
$$

而不是普通语义相似度。

### 可信度与局限

作者回溯标注本身会受记忆偏差影响：研究者未必准确记得哪些论文真正改变了项目，也可能遗漏当时没有读到、但事后看来关键的工作。

它还只评估“从初始问题到启发性文献”的检索能力，并不等于完整科研自主性。

### 最值得继续追踪

值得看下一代系统是否会把 Citation Graph、Method Graph、失败实验与研究阶段一起加入 Retriever，而不是继续堆更多自然语言 Search Agent 步骤。更强的目标应该是高召回地覆盖**互补研究路径**，再由 Research Agent 做后续筛选。

## 2. Beyond Memory：历史很多，不代表 Agent 知道“现在到底是什么状态”

[论文原文](https://arxiv.org/abs/2610.01415)

### 发生了什么

大量 Memory 工作优化的是“保存哪些过去”，但长程任务真正需要的是一份一致的**当前世界模型**。PoS 将状态拆成两部分：

- task-conditioned world state：实体、状态、关系；
- gaps：当前还不知道什么，以及距离目标还缺什么。

每次新 Observation 到来后，Belief Sentinel 会检查更新是否与现有信念、外部证据一致。系统还追踪 gap persistence、progress stagnation 和 belief recurrence；如果 Agent 在同一信念附近反复打转，就诊断为 Static / Cycle / Drift，并产生对应恢复约束。

### 关键结果

论文在 ALFWorld、LOCA-Bench、RCA-100、ClinDiag 四个长程任务上、三个 LLM Backbone 中都取得最高总体结果。

作者报告相对最强基线的最大提升包括：

| Benchmark | 最大相对提升 |
|---|---:|
| ALFWorld | **22.68%** |
| RCA-100 joint accuracy | **37.89%** |

### 为什么重要

这与最近大量 Context Compaction / Memory 工作构成一个重要补充：即使所有事实都“还在”，Agent 也可能把旧状态和新状态混在一起，或者一直重复一个已经被证伪的解释。

更适合长程 Agent 的状态栈可能是：

- Raw evidence：可追溯；
- Belief state：当前最可信解释；
- Invariants：必须持续满足的约束；
- Gaps：还缺哪些证据／目标；
- History：只在需要复盘时检索。

### 可信度与局限

Belief State 仍由模型生成，因此它本身也可能写错。Sentinel 只是增加了一层一致性检查，并没有建立形式化正确性。

系统还引入额外 Token 和控制逻辑。对短任务而言，这些开销可能大于收益。

### 最值得继续追踪

把 Belief State 更新进一步做成 **evidence-addressable state transition**：每个状态字段都能指回具体 Tool Observation / File / API Response，并支持撤销。这样 Belief 不只是更漂亮的 Summary，而是可审计的运行状态。

## 3. ActiveSaddler：Self-improvement 还缺一个“今天练什么”的调度器

[论文原文](https://arxiv.org/abs/2610.00906)

### 发生了什么

多数 Harness Optimizer 固定 Scenario 顺序：顺次跑任务、观察失败、修改 Harness。ActiveSaddler 认为这相当于把 Curriculum 当成常量。

它先把失败轨迹抽象成不断变化的 Failure Pattern，再把这些 Pattern 当作 Non-stationary Bandit 的 Arm。Scheduler 估计每类失败当前的 learning progress，在“继续打磨已知薄弱点”和“探索还没充分见过的问题”之间分配优化预算。

### 关键结果

相对使用同一 Harness Optimizer、但固定 Scenario Order 的设置：

| Benchmark | 提升 |
|---|---:|
| GAIA2 Test Pass@1 | **+4.4pp** |
| Terminal-Bench 2.0 | **+7.5pp** |

### 为什么重要

Self-improvement 系统长期运行后，最常见的浪费之一是继续重复已经学会、或当前无法进一步改善的失败模式。真正需要优化的是：

$$
\text{expected capability gain per next training episode}.
$$

这与传统 Active Learning 很像，但对象从样本变成了 Agent Failure / Environment Scenario。

### 可信度与局限

Failure Pattern 是一个高风险抽象层。如果聚类把根因不同的失败合并在一起，Bandit 的 learning-progress 估计就会失真；如果分得过细，又会出现数据稀疏。

另外，Benchmark gain 证明了 curriculum 有价值，不证明该调度策略在数月持续演化、环境不断变化的生产 Agent 上仍然稳定。

### 最值得继续追踪

把 Curriculum Scheduler 与 Experiment Lineage 结合：每种失败模式不仅记录分数，还记录最近一次 Harness Patch、回归影响、覆盖任务族和已投入 Compute。这样才可能优化真正的 **capability gain / experiment cost**。

## 4. LOOM：Looped MoE 深度增加以后，最先坏的是状态和路由

[论文原文](https://arxiv.org/abs/2610.01153)

### 发生了什么

Looped Transformer 通过重复使用同一 Block 增加计算深度；MoE 又希望每次只激活部分 Expert。把两者简单相乘看似自然，但作者发现超过两次 Loop 后会出现两个耦合问题：

1. Residual hidden-state variance 逐轮放大，导致 representation drift；
2. Router 倾向反复选择同一批 Expert，额外 Loop 没有产生足够新的函数组合。

LOOM 加入 Residual Scaling、每轮重新注入 Input Embedding、Per-loop Router，以及 Looping Residual 来保留早期输出。

### 关键结果

模型在 100M–1.7B 参数范围内可稳定扩到 **9–12 loops**。

近似等 FLOPs 的 700M 设置中，5 loops 最优：

| 指标 | Baseline | LOOM 5 loops |
|---|---:|---:|
| Perplexity | 18.36 | **16.54** |
| Zero-shot average | 38.84 | **39.53** |

非 FLOP-matched 的 1.7B / 60B-token 实验在 9 loops 达到 PPL 7.77、zero-shot 47.7，对应 baseline 为 9.62 / 42.4。

### 为什么重要

“多循环”只有在每次循环继续产生新信息时才有意义。对 MoE 来说，深循环需要同时控制**状态稳定性**和**计算路径多样性**。

这也解释了为什么 recurrence 不能简单理解成“把同一层再跑 N 次”。额外计算的价值取决于模型是否能进入新的表示区域、调用新的 Expert 组合。

### 可信度与局限

模型规模仍远小于当前 Frontier MoE。近等 FLOPs 条件下，zero-shot gain 明显小于 non-matched 实验的 headline 数字。

论文也没有证明 9 loops 在真实 Serving 中拥有良好的 latency / batching / kernel efficiency；循环深度和 wall-clock 并非线性可互换。

### 最值得继续追踪

真正值得看的下一步是 **adaptive recurrence + expert diversity**：不同 Token / Request 应该决定是否继续 Loop，同时 Router 需要避免“继续算了很多，但仍在重复同一路径”。

## 5. RPTune：Catalog 全塞进去以后，真正的问题才刚开始

[论文原文](https://arxiv.org/abs/2610.00964)

### 发生了什么

对于中小商家，一个完整商品 Catalog 有时已经能放进长上下文窗口。一个看似自然的方案是：直接把所有商品交给 LLM，让它在对话中自己搜索。

RPTune 的结果说明，Context Capacity 并不是核心瓶颈。作者训练一个 encoder-reorganizer，根据当前查询和 downstream feedback 对 Catalog 进行排序、压缩和重组织，再用 context-relative reward 对 LLM 做 Post-training。

### 关键结果

实验覆盖 7 个真实 Merchant Vertical，每家 100 个复杂 conversational query。

| 阶段 | 报告收益 |
|---|---:|
| Context Curation | Search Accuracy 最高 **+31.4pp** |
| 后续 Post-training | 平均再 **+10.3pp** |

增益在 Proprietary 和 Open LLM 上都出现。

### 为什么重要

长上下文经常把两个问题混在一起：

- 信息能不能放进去；
- 模型能不能在有限注意力与推理预算下有效利用它。

完整 Catalog Prompting 解决的是前者。RPTune 表明后者仍需要专门的 evidence ordering / pruning / training signal。

对 Shopping Agent，一个合理架构可能是“高召回 Catalog Evidence Layer → Context Curator → LLM Reasoner”，而不是把 Retrieval 全部省掉。

### 可信度与局限

总测试规模约 700 个 Query，而且研究的是“Catalog 能整体进入 Context”的 SMB 场景，不代表百万级 SKU 的大型电商可以跳过传统 Retrieval。

论文摘要没有给真实线上 A/B，因此目前最有力的证据仍是离线 Search Accuracy。

### 最值得继续追踪

比较三种系统在相同 Token / latency 预算下的 Pareto Frontier：传统 Retrieval + Rerank、Full-catalog + Curator、以及 Hybrid Retrieval + Curator。真正要优化的是 **end-to-end product discovery per cost**。

## 6. Code Owns the Simulation, Jev Owns the Evaluation：Decision Model 的边界在哪里

[论文原文](https://arxiv.org/abs/2610.01834)

### 发生了什么

Jev 类 Decision Model 不生成长文本，而是对一组明确候选直接输出概率。它们非常适合 Tool Routing、Intent Classification、Memory Selection、Candidate Ranking。

这篇工作专门问：如果一个决策的正确性取决于“接下来会发生什么”，Decision Model 能不能在一次调用里同时完成模拟与评估？

### 关键结果

作者发现了一个稳定边界：

- 对已经描述清楚的候选状态做 evaluation，Jev 很强；
- 如果必须预测未观察到的环境后果，它容易把 simulation 当成已有事实；
- 在 Cognitive Reflection Test 上可达 **99%**；
- 在博弈任务中却表现得像把理性对手当成随机对手；
- ALFWorld 中会出现子目标次序错误；
- 一旦由代码提供 explicit lookahead / physics simulation，Jev 又能成为很强的 Controller。

### 为什么重要

这给 Agent 的 System-1 / System-2 分层一个更清楚的接口：

> **Decision Model 负责比较已经被计算出来的候选；Environment / Code / Planner 负责产生可信的候选后果。**

因此，不能因为一个模型“会给候选打分”，就让它隐式承担规划、物理模拟或多步反事实。

### 可信度与局限

结论来自一个具体 Decision Model 家族和特定任务。未来具有更强 world modeling 的 Decision Model 可能把边界推远。

但从系统工程角度，这个保守边界很有用：如果后果可以廉价地用代码、检索、环境 clone 或 simulator 明确计算，就不该让 Judge 靠语言直觉猜。

### 最值得继续追踪

结合 Confidence Routing：低成本 Decision Model 先评估明确候选；若候选需要反事实 rollout，就升级到 Simulator / Planner；只有在两者都无法可靠判定时，才调用更昂贵的 Generative Reasoner。

## 今日值得收藏的代码 / 学习资源

### DRelay：并行 Speculative Decoding 也需要“全局纠错”

[论文原文](https://arxiv.org/abs/2610.01439)

Parallel Speculative Decoding 的 Candidate Pool 里可能已经包含正确 Token，但前面一次错误选择会让后续候选全部失去价值。DRelay 用全局 Reader 看整个 Draft Block，再由 Causal Selector 在 Target Verification 前有选择地修复候选。8 个 Benchmark、H800 + SGLang 环境下，论文报告相对 DFlash 的端到端 Speedup 再提升 **14.7%–16.8%**，相对 Domino **8.7%–9.3%**。这些是相对已有 Baseline 的增量，不等于通用 1.16× 在线服务收益。

### CANOPY：多模态 RAG 的问题是“证据粒度”，不只是 Top-K

[论文原文](https://arxiv.org/abs/2610.00923)

CANOPY 把 Text / Table / Image / Video 组织成层次结构，用 learned node encoder 选择不同粒度的证据；当当前证据不足时，Critic 再发起定向补充检索。五个 QA Benchmark、3300 万异构 Item 上优于论文中的 Retrieval Baseline。一个值得注意的拆解是：Multi-hop 准确率的主要收益来自**额外检索**，而不是 Compression 本身；Qwen3-VL-8B 的压缩更多体现为 reader-input evidence token **-14.2%～-27.7%**。

### Continuous Process-Level Evaluation：最终答案对了，过程仍可能已经漂移

[论文原文](https://arxiv.org/abs/2610.01833)

在 240 个企业 Agent Trial 中，175 条轨迹通过全部最终数值检查，其中 **162 条（92.6%）**仍存在其他 Evaluator 检出的过程偏差。使用更广的 7-check final-state 后，164 条最终通过轨迹里仍有 151 条违反 trajectory check。它提醒长期 Agent：Skill / API / Spec 演化后，只看 Final State 很容易漏掉“错误方式碰巧得到正确结果”。

### REPAIR：用户画像压缩以后，别忘了 Cache 里还有信息

[论文原文](https://arxiv.org/abs/2610.01270)

REPAIR 针对 Personalization Encoder 的压缩损失：最终 user state 可能已经丢信息，但历史 timestep representation 里仍保留有用信号。它冻结原 Encoder 和 Head，只根据当前 preference state 去挑选需要“补回”的历史表示。MovieLens、PENS、MIND、Amazon Reviews 2023 上 12 个 Host 全部提高 MRR / nDCG@10；Mamba4Rec 在 MovieLens 上 MRR **+3.96 points**，而只调 Head 为 +0.19。工程上需要继续核算 cached representation 的存储成本。

### VISTA：视觉 Agent 的长期记忆也可以保留原始证据

[论文原文](https://arxiv.org/abs/2610.02200)

VISTA 使用直接 Visual Observation + lossless visual memory，并让 Agent 主动检索和重组历史视觉输入。ARC-AGI-3 上，Claude Opus 5.0 的 Relative Human Action Efficiency 从 40.68 提到 100.0，并完成全部 25 个公开 Game。需要注意，这是 10 月 arXiv 版本；作者在 8 月已经发布过早期版本，因此它是近期正式化／扩展信号，并非今天突然出现的新方向。

## X.com｜近期高信号技术讨论

本轮按“动态新词发现 → Alias 扩展 → 原帖召回 → 作者／机构扫描 → Event-driven 补充 → 72 小时 / 7 天回退”执行。今天的 24 小时窗口里没有形成足够强的新簇，因此最终收录的是过去 **72 小时**仍在快速扩散的两个主题。互动数据没有完整核验，不据此做精确热度排名。

**趋势判断：** 10 月 1–2 日连续出现 Jev、Cloudflare Clef / Clef-flash、Strands Decider 等产品与讨论。多个独立作者开始讨论一个共同架构：不要让 Generative LLM 为每个分类／路由问题都生成文字，而是直接对受限候选给概率。

**大家在争论什么**

核心问题是 Agent 的哪些判断值得从大模型生成链中拆出来。Tool Routing、Memory Selection、Intent Classification、Guardrail、Candidate Ranking 都具有“候选有限、输出结构固定、要求低延迟”的共同结构。

Cloudflare 10 月 1 日发布的 Clef / Clef-flash 提供了具体工程实现：Qwen Backbone 做 Prefill，随后并行评分合法 Schema Choice，不生成中间文本。其第一方 43 项 Eval 中，Clef / Clef-flash Median Latency 为 209.3 / 38.8 ms，Jev 为 524.1 ms；但这属于 Cloudflare 自己的模型、硬件和测试设置，不能当成通用倍数。

**为什么现在值得关注**

过去 Agent Serving 的二分法通常是“便宜小 LLM / 贵大 LLM”。Decision Model 引入第三类角色：它不是开放式生成器，而是可泛化的 semantic scorer。

这很可能形成新的 Cascade：

> Cheap rule / classical model → Decision Model → Generative Reasoner / Simulator

**技术判断与局限**

Decision Model 的最大风险是误把“打分”当成“推理”。今天主文提到的 *Code Owns the Simulation* 正好给出了边界：如果候选结果依赖未来环境演化，应先由代码或环境产生后果，再让 Decision Model 评估；直接让它猜未来会发生什么，可靠性明显下降。

**大家在争论什么**

Mods 与传统 Prompt / Skill 不同，它可以运行在 Claude Code 内部事件链上：观察、改写或接管 Prompt、Tool Call、Permission Request 和 UI Event。这意味着 Harness 的一部分运行时行为从厂商固定实现，变成用户可编程的 TypeScript Extension。

更重要的同时是安全边界：官方资料明确说明 Mod **不是 Sandbox**，它拥有和 Claude Code 相同的机器访问能力。因此“可修改 Harness”同时扩大了 Agent Engineering 能力和 Supply-chain / Permission Risk。

**为什么现在值得关注**

近期很多研究都在证明 Harness 可以被优化、学习甚至自我修改。Claude Mods 的意义在于把这种思想从研究 Harness 推进到主流 Coding Agent 的真实扩展接口。

未来实验不必总是 Fork 整个 Agent：Context Policy、Tool Approval、Retry Logic、UI、Telemetry、Verifier 都可能作为 Mod 被独立开发和 A/B。

**技术判断与局限**

把产品变得可编程不自动等于变得更可靠。Mod 越深地进入 Tool / Permission Path，越需要版本固定、代码审查、签名来源、回归测试和企业级 allowlist。安装未知 Mod 应被视为执行具有 Agent 权限的本地代码，而不是“装一个普通 Prompt 插件”。

## 今日最值得花 30 分钟阅读的一项

**首选 Beyond Memory: Explicit Belief States for Long-Horizon Agents。**

[论文原文](https://arxiv.org/abs/2610.01415)

这篇最值得看的地方，是它把最近很热的“Memory / Context Compaction”问题往前推了一层：Agent 真正需要的不是无限保存历史，而是一份**当前有效、证据一致、知道自己还缺什么的世界状态**。

30 分钟建议重点看四处：belief state 与普通 summary 的区别；epistemic / achievement gap 如何进入控制；Belief Sentinel 怎样阻止错误更新；以及 Belief Trapping 如何区分 Static、Cycle、Drift。

最值得带走的判断是：

> **长期记忆解决“过去能不能找回来”；Belief State 解决“现在应该相信什么”。长程 Agent 两者都需要。**

## 今日可立即实践的一件事

给现有 Coding / Search / Research Agent 做一次 **Belief-State A/B**。不需要训练新模型，先验证“明确维护当前状态”本身是否有价值。

从 30–50 个超过 20 Turn 的真实任务中，保留现有 Harness 作为 A 组；B 组额外维护一个结构化状态，至少包含：

| 字段 | 含义 |
|---|---|
| confirmed_facts | 已有直接证据支持的当前事实 |
| invariants | 必须持续满足的用户／系统约束 |
| open_questions | 当前还不知道、但会影响决策的点 |
| goal_gaps | 距离完成还缺什么 |
| invalidated_beliefs | 已被新证据推翻的旧假设 |
| evidence_refs | 每条事实对应的文件、Tool Result 或 Observation |

每次 Tool Call 后只允许做增量更新，并要求所有新增／修改的事实附 Evidence Reference。

至少记录 Task Success、重复 Tool Call、Contradiction Count、Stagnation Turn、错误假设存活时长、额外 Token Cost。若 B 组主要收益来自减少“反复验证同一事实”或“继续沿已被证伪假设行动”，说明当前瓶颈确实是 State Coherence；若收益很小而成本明显增加，则任务 Horizon 可能还没长到需要独立 Belief Layer。

真正要回答的是：

> **你的 Agent 失败时，是忘记了过去，还是过去都还在，但它已经不知道哪些信息现在仍然成立？**
