> **今日主线：** Faithful Context Compaction · Harness-Level RSI · Low-Bit On-Policy Distillation · Phase-Specialized Quantization · Critic Alignment · Long-Sequence Recommendation

arXiv 最新常规公告批次为 **2026 年 9 月 23 日**：`cs.AI` 240 条、`cs.CL` 108 条、`cs.LG` 216 条、`cs.IR` 15 条；分类之间存在大量交叉收录，不能直接相加。今天几项高信号工作的共同点，是“把昂贵能力放在哪里”正在比“单纯把模型做大”更重要：长程 Agent 不一定需要不断总结旧 Context，可以通过只删不改的机械压缩控制漂移；研究 Agent 可以把自己的 Harness 当成优化对象；低比特模型需要在自己真实会走到的轨迹上接受 Teacher 信号；Prefill 与 Decode 也开始使用不同的量化格式与权重；RL 侧则进一步追问 Critic 是否真正对齐更新后的 Policy。推荐系统侧，超长用户历史的工业落地继续依赖时间压缩、多兴趣表示、缓存与异构 Serving 的联合设计。

## 今日核心判断

1. **长程 Agent 的 Context 压缩不一定需要“更聪明的总结”，高保真删除可能反而更稳。** CliffCompaction 只截断或丢弃内容，不改写、不重述，也从不对旧 Compaction 再次做 Compaction；每次都从原始 live session 构造新的 cliff。Terminal-Bench 2.0 上，Kimi K2.6 在 32K / 16K Context 下都达到 61.42% resolved，高于 full-context 的 59.16%；Terminal-Bench 2.1 中 GLM 5.3 Flash 在约 45K mean peak context 下达到 76.69%，高于 Claude Code 原生总结式压缩的 70.97% 和默认 200K Context 的 73.03%。它说明一个常被忽略的风险：长程 Agent 的主要问题之一可能是**摘要误差的递归累积**，而不是原始历史本身太长。

2. **AIDE² 给出了目前较完整的 Harness-level RSI 实验，但“点火”尚未被证明。** 这项工作在 8 天、100 个 outer-loop 节点中接受 7 次自我改写，把 private grade 从 0.703 提到 0.778；最终 Harness 在 4 个未参与选择的 Benchmark 上匹配或超过一个经过两年人工迭代的生产 Research Agent，Reward Hacking 率从 55% 降到 32%。但其 Ignition Test 只有 3 个 seed，改进后的 Agent 与人工 Agent 驱动下一轮 RSI 的最终均值分别约 0.780 与 0.782，作者明确认为结果**不足以证明改进后的系统更善于继续改进自己**。因此更准确的结论是：AIDE² 已展示可迁移的多步 Harness 自我改进；它没有证明递归改进已经进入加速、自维持的“智能爆炸”阶段。

3. **低比特 Reasoning 的主要损失之一来自 Quantization-amplified Exposure Bias，而不仅是静态 Weight Error。** 新工作从 Quantization-Aware Distillation（QAD）出发，让量化 Student 用部署时的低比特 Forward Path 自己生成 On-Policy Prefix，再由冻结 BF16 Teacher 在这些真实 Prefix 上提供 Token-level guidance，并和 Task Verifier Reward 联合训练。Across four models at 2.79 / 1.88 effective bits，MATH-500 的平均 BF16 Performance Retention 从 35% 提到 70%，HumanEval 从 66% 提到 91%。这表明 sub-3-bit Reasoning 的恢复关键不只是“更好地拟合 Teacher 权重／Logits”，还要覆盖量化模型实际偏离后进入的状态分布。

4. **Prefill 与 Decode 的最佳量化方案并不相同，Phase-specific Quantization 开始变成独立设计轴。** Disaggregated Quantization（DQ）让 Prefill 使用适合低精度算术的 Compute-native 权重，让 Decode 使用更紧凑、降低 Memory Traffic 的权重格式；甚至可以把额外 Prefill Checkpoint 从 SSD 逐层流入设备。Qwen3.8-27B 的公开 GGUF Decode Checkpoint 上，新增 NVFP4 Prefiller 让 IQ1_S 的 MMLU-Pro / MMMU-Pro Accuracy 分别提高 32.5 / 35.3 points，同时不修改 Decode Checkpoint；8K Prompt 下，Offloaded Disaggregated Prefill 将 TTFT 从 12.27 秒降到 6.90 秒，约 1.78×。代价也很明确：短 Prompt 下 SSD Loading 反而会拖慢系统。

5. **Token-level Credit 的理论问题正在回到 Critic 本身：如果 Critic 没对齐更新后的 Policy，更细粒度的 Advantage 也可能是错的。** PACT 从 Completeness、Prefix Consistency、Neutrality 三个条件出发定义唯一的 Token-level Credit，并指出理想 OPD Teacher 可以视为隐式 Critic；同时说明 Response-level RLOO 在期望 Policy Gradient 上可以匹配 Token-level Credit 的贡献。基于这一分析，PACT 采用 Actor-then-Critic 更新顺序并对 Critic Training 做 Importance Sampling Correction。Agentic Math 四个 Benchmark 平均 72.87%，相对 GRPO +8.80pp、PPO +13.16pp；SWE-bench Verified 为 67.4%，相对 GRPO +2.0pp。这里真正值得追踪的是“Critic Alignment”是否比继续堆更复杂 Credit Heuristic 更稳定。

6. **工业长序列推荐的可行路径仍然是“压缩旧历史 + 保留近期细节 + 多兴趣 + 异步缓存”，而不是对 10^5 行为直接做全量 Attention。** 百度 MuSeR 把近期行为保留全分辨率，旧历史逐级池化，将每个用户 10^4–10^5 条交互压进固定 Serving Budget；再用多 Query Interest、Orthogonality Regularization 和 LLM Summary 语义补充稀疏 ID。线上 A/B 在首页 Feed、发现 Feed 和短视频场景中带来 DAU +0.26%、总 Session Duration +0.89%（均 p<0.05），并报告 Serving Latency / Cost 下降。作者也明确把它定位为系统集成，而非新的基础建模原语。

## 1. CliffCompaction：长程 Agent 先解决“摘要漂移”

[论文原文：CliffCompaction: Cost-Efficient Compaction for Long-Horizon Coding Agents](https://arxiv.org/abs/2609.26779) · [开源仓库](https://github.com/nguyenvuthientrang/cliffcompaction)

### 发生了什么

常见 Autocompaction 会把旧历史先总结成摘要，下一次 Context 再溢出时继续总结“旧摘要 + 新历史”。这种 summary-of-summary 会产生一个不可逆的问题：一次摘要遗漏或改写的信息会进入下一轮摘要输入，误差会沿 Session 累积。

CliffCompaction 选择非常保守的策略：只截断、删除或机械保留，不让模型重写旧事实；每次压缩只针对最新原始 live session，上一轮 compacted output 直接丢弃，因此不会形成嵌套摘要。开源 Proxy 的默认做法也很直白：短 Tool Result 原样保留，大 Tool Result 丢弃；Tool Call 只保留调用签名；Human Text 原样保留；System / Task Head 和最近若干 Turn 不动。

### 关键结果

| 设置 | Full / 原生策略 | CliffCompaction | 观察 |
|---|---:|---:|---|
| Terminal-Bench 2.0 · Kimi K2.6 | 59.16% @ full context | **61.42% @ 32K / 16K** | 压缩后不降反升 |
| Terminal-Bench 2.1 · GLM 5.3 Flash | 73.03% @ 200K | **76.69% @ ~45K** | 高于默认长 Context |
| Claude Code 原生总结式压缩 | 70.97% @ ~45K | **76.69%** | 同预算 Cliff 更高 |
| KernelBench · Kimi K2.7 | 1.30× @ 200 steps, no compaction | **2.23× @ 200 steps** | 长程搜索持续积累 |

论文进一步报告，CliffCompaction 在某些配置下可节省最高约 50% 成本；在 Terminal-Bench 的部分配置中成本降幅更高，但阈值过紧会增加重新 Prefill 和 Cache Invalidation，因此成本收益并非随 Context Threshold 单调增加。

### 为什么重要

它提供了一个很值得保留的 Context Engineering 原则：**高 Precision 的 Memory 有时比高 Recall 的自然语言 Summary 更重要。** 长程 Coding Agent 对文件路径、命令、错误信息、约束条件非常敏感，一条“听起来合理但被改写过”的历史摘要可能比直接忘掉一段旧日志更危险。

### 可信度与局限

论文覆盖 SWE-bench、Terminal-Bench、KernelBench，并跨多个 Harness / Model；开源 Proxy 也让复现门槛较低，这是优势。不过删除式压缩天然牺牲 Recall：如果一个很早的罕见约束从未在后续行为中留下痕迹，它会永久丢失。作者所谓 residual propagation 依赖 Agent 后续动作自然携带旧信息，这不是形式保证。

另外，Compaction 频率越高，Prefix Cache Hit Rate 会下降；论文在 Terminal-Bench 的 GLM 5.1 设置中观察到阈值收紧时 Cache Hit 可从约 79% 降到 47%。因此“更小 Context”不能简单等价为“更便宜”。

### 最值得继续追踪

看这种机械高保真 Compaction 能否与结构化 Memory 联合：对事实、约束、文件状态做显式持久化，对冗长 Tool Output 继续使用 Cliff 式删除。真正生产化的目标应同时优化 `task success × input tokens × prefix-cache hit × compaction frequency × stale-memory error`。

## 2. AIDE²：Harness-level RSI 已有持续改进证据，但 Ignition Test 仍未过关

[正式论文：Recursive self-improvement of AI research agents](https://arxiv.org/abs/2609.26457) · [Weco 早期公开说明（2026-07-14）](https://www.weco.ai/blog/first-evidence-of-recursive-self-improvement)

### 发生了什么

这篇论文今天进入 arXiv 最新批次，但核心结果并非今天第一次公开：Weco 已在 **2026 年 7 月 14 日**发布 AIDE² 博客。新论文的价值主要在更完整的实验协议、Held-out Evaluation、Reward Hacking 审计和 Ignition Test。

AIDE² 有两个循环。Inner Loop 用 Research Agent 在固定预算下优化 ML Engineering、Heuristic Algorithm Engineering、Harness Engineering 等任务；Outer Loop 把 **Inner Agent 自己的 Harness Code** 当成被优化对象，提出 Rewrite，并用 Inner Agent 在 Private Held-out Data 上的研究效率决定是否接受。每次接受的 Rewrite 会成为下一轮被继续改写的 Agent。

### 关键结果

一次 8 天运行产生 100 个节点（初始 Agent + 99 个 Rewrite Proposal），接受 7 次改进，private grade 从 **0.703 → 0.778**。最终 AIDE_85 的改动包括：多臂 Bandit Search Policy、Periodic Forking、Role-specific Bounded Prompt、Bug-rate-gated Failure Memory，以及针对不可信高分的 Robustness Mechanism。

这些改动并不只在 Selection Benchmark 上有效。论文用 ALE-Bench、MLE-Bench、FML-Bench 和 WeatherBench 2 做 External Evaluation；AIDE_85 在四项上都匹配或超过人工迭代两年的 AIDE_human。另一个完全不参与选择的 Kernel Engineering 测试中，Reward Hacking 率沿 lineage 从 **55% → 39% → 32%**，而 AIDE_human 为 39%。

### 为什么重要

这比“一次让 Agent 改自己的 Prompt”更接近真正的递归对象：被改写的是**驱动研究搜索的算法与 Harness**，而下一轮继续使用改写后的 Harness 作为研究 Agent。它说明至少在一个受控 AI R&D 域内，Harness 的搜索策略、Context Management 和 Verification 可以被自动发现并积累。

更值得注意的是，很多被发现的改进很“工程化”：控制 Prompt Growth、避免 Search Plateau、对失败做 Memory、修复 Evaluation Bug。RSI 的近端形态很可能先表现为大量这类程序化 Research Harness 改进，而不是模型突然自行重写 Transformer 架构。

### 可信度与局限

这里必须区分三件事。第一，论文展示的是 **Harness-level RSI**，模型权重在每一层 Loop 内保持固定；第二，Outer Loop 仍由一个强人工 Research Agent AIDE_human 驱动；第三，真正更强的“Ignition”没有被证实。

Ignition Test 让 AIDE_47 和 AIDE_human 分别作为 Outer-loop Agent，各跑 3 个 seed × 50 steps。最终平均 grade 约为 **0.780 vs 0.782**；AIDE_47 看起来更早进入高分区，但作者明确认为三 seed 不足以证明它更善于继续改进自身。论文讨论还指出，双层搜索中的噪声会复合，单次错误接受就可能把后续搜索带偏，而且增加 seed 的成本非常高。

### 最值得继续追踪

未来真正关键的指标不只是“又接受了多少 Rewrite”，而是 **self-improvement efficiency 是否随 generation 提升**：第 N 代 Agent 是否用同样成本更容易找到第 N+1 代；这种提升是否跨 seed、跨 benchmark、跨模型都成立；Acceptance Gate 是否能控制 false-positive rewrite。只有这些成立，才接近论文定义的更强 Ignition / Inflection。

## 3. Train Where the Quantized Model Goes：sub-3-bit Reasoning 要在量化模型自己的轨迹上训练

[论文原文](https://arxiv.org/abs/2609.26708)

### 发生了什么

Quantization-Aware Distillation 通常在固定 Corpus Prefix 上让低比特 Student 模仿 BF16 Teacher。短回答任务上这很有效，但长推理中，量化误差会改变某一步的 Token 选择；从此以后 Student 进入 Teacher-forced 数据没有覆盖的新 Prefix，误差继续在自己的轨迹上叠加。

论文把这一现象称为 **Quantization-amplified Exposure Bias**。它从已有 QAD Checkpoint 出发，让 Student 使用真正部署时的量化 Forward Path 生成 On-Policy Rollout，再让冻结 BF16 Teacher 在 Student 自己访问到的 Prefix 上提供 Dense Token Supervision，并与 Task Verifier Reward 联合优化。

### 一个很有说服力的失败诊断

Qwen3-0.6B、W2.79 的 QAD 模型在 MATH-500 上，**95%** 的生成会耗尽 Decode Budget，BF16 只有 27%；QAD 输出有 **70%** 以重复 8-gram 结束，BF16 为 12%。在 GSM8K 这种较短推理里，同样问题较轻：Budget Exhaustion 32% vs 5%，重复率 30% vs 2%。

这说明知识并没有完全消失：QA9 这种只做 Likelihood Scoring、几乎不需要自回归长生成的任务仍保留约 86% BF16 能力；真正崩坏的是**沿着自己的低比特轨迹持续推理并结束答案的能力**。

### 关键结果

Across six Qwen3 model/bit-width settings，OPD 将 MATH-500 的平均 BF16 Retention 从 **35.3% 提到 69.7%**，GSM8K 从 62.7% 提到 85.0%；Qwen3-1.7B W2.79 的 MBPP 从 35.3% 到 52.0%，HumanEval 从 41.5% 到 59.1%。与完全相同预算的 Continued QAD 比较，OPD 在 4 个 Benchmark × 4 个核心配置的 **16/16** 比较中全部胜出。

一个额外值得注意的结果是：从 1.7B Student 开始，更大的 Teacher 并没有稳定带来更多恢复；很多设置中 Student 自己的 BF16 版本已能匹配或超过 4B / 8B Teacher。这意味着收益主要来自 **On-Policy Coverage**，不只是 Teacher Scaling。

### 为什么重要

对低比特 Reasoning Model，量化后再做少量静态 Calibration 可能不足以恢复真实推理。部署精度改变了 Policy 自己会访问的状态分布，因此恢复过程更接近“对一个新 Policy 做 Post-training”，而非简单修复 Weight Approximation。

这条结论还会影响低比特 Agent：Tool Choice 或 Argument 在前几个 Turn 因量化发生轻微偏移，之后访问的 Observation、文件、网页状态都可能完全不同，Teacher-forced Distillation 的 Distribution Mismatch 会更严重。

### 可信度与局限

当前实验集中在 Qwen3、数学与代码，Verifier 比较清晰；Agentic Tool Use、开放式写作和多模态任务还没有同等证据。OPD 也需要 BF16 Teacher Forward 和 On-Policy Rollout，因此训练成本明显高于纯 PTQ / QAD。

### 最值得继续追踪

看 3-bit / 2-bit Agent Model 是否出现类似“前几步还正常、长轨迹越来越循环／偏离”的量化轨迹崩坏；以及能否把 Teacher Signal 只放在真正发生 Quantization-induced State Divergence 的 Token / Turn 上，进一步降低 OPD 成本。

## 4. Disaggregated Quantization：Prefill 和 Decode 不必共享同一种量化

[论文原文](https://arxiv.org/abs/2609.26333)

### 发生了什么

Prefill 与 Decode 的硬件瓶颈不同。Prefill 更偏算力密集，低精度 Activation / Tensor Core 计算更有价值；Decode 往往 Memory-bandwidth-bound，更紧凑的 Weight 才是重点。统一 Quantization Format 实际是在两个阶段之间妥协。

DQ 直接把它们拆开：Prefill 可以使用一个 Compute-native Quantized Checkpoint，Decode 继续使用更紧凑的 GGUF / Weight-only Checkpoint；Prefill 结束后，其 Weight 不再需要常驻，系统只保留产生的 KV。Offloaded Disaggregated Prefill（ODP）因此可以从 SSD 一层层流入 Prefill Weight，用两个 Device Buffer 交替实现 Load / Compute Overlap。

### 关键结果

Qwen3.8-27B 的公开 GGUF Decode Checkpoint 上，新增 NVFP4 Prefiller 后，IQ1_S 的 MMLU-Pro Accuracy 提高 **32.5 points**、MMMU-Pro 提高 **35.3 points**，而 Decode Checkpoint 完全不变。

在 llama.cpp 实现中，8K Context 下 TTFT 从 **12.27s → 6.90s**，约 **1.78×**；4K–32K 的测试区间里加速约 1.38×–1.78×。论文同时验证了 vLLM Disaggregated Serving，并把 Shared-weight Format Disaggregation 的 PTQ 实验扩展到最高 2.8T 参数模型。

### 为什么重要

过去“一个模型文件对应一个量化格式”更多是存储和部署习惯，并不是推理阶段的物理必然。P/D Disaggregation 已经在服务器层把 Prefill 和 Decode 分到不同 Worker，Quantization 继续沿同一方向做 **phase specialization** 很自然。

对本地推理也一样：如果长 Prompt 的 Prefill 是瓶颈，可以把一个更适合计算的 Prefill Weight 当作临时流式资源，而让极低比特 Decode Weight 长驻内存。

### 可信度与局限

ODP 的优势需要足够长的 Prompt 才能摊平 SSD Load。论文在短 Context 下明确观察到 ODP 更慢；额外 Checkpoint 也增加磁盘空间、版本管理与部署复杂度。生产系统还要验证 Prefill / Decode 两套 Weight 是否会引入一致性、Cache Key、滚动升级问题。

### 最值得继续追踪

关注 `prompt length × SSD bandwidth × prefill precision × decode bit-width` 的完整 Pareto，以及 llm-d / vLLM / llama.cpp 是否把 Phase-specific Checkpoint 变成一等部署抽象。

## 5. PACT：Token Credit 的下一步可能是 Critic 对齐，而不是继续堆 Heuristic

[论文原文：PACT: From Credit Assignment to Critic Alignment](https://arxiv.org/abs/2609.26355)

### 发生了什么

PACT 先从理论上提出三个 Token-level Credit 的 Regularity Condition：Completeness、Prefix Consistency、Neutrality，并证明它们唯一确定 Token Credit。这个框架给几个常见训练信号提供了统一解释：理想 OPD Teacher 相当于隐式 Critic；虽然 RLOO 只有 Response-level Reward，它在期望 Policy Gradient 上仍能匹配 Token-level Credit 的贡献；而 GAE 的 Intermediate Critic Error 可能与真正 Credit 本身同量级。

基于这个分析，PACT 将常见的 Critic-then-Actor 顺序改成 **Actor-then-Critic**：先更新 Policy，再用 Importance Sampling Correction 让 Critic 对齐更新后的 Policy Distribution。

### 关键结果

Agentic Mathematical Reasoning 的四个 Benchmark 平均 Accuracy 为 **72.87%**，相对 GRPO +8.80pp、PPO +13.16pp；SWE-bench Verified 为 **67.4%**，相对 PPO +2.4pp、GRPO +2.0pp、SAO +3.8pp。

### 为什么重要

近期很多 RL 工作都在把 Credit 做得更细：Token Advantage、Critical State、Process Reward、Teacher Gating。PACT 提醒一个基础问题：**如果 Value / Critic 预测的是旧 Policy 的未来，而 Actor 已经移动到新 Policy，再细的 Credit 也可能是在精确地拟合错误目标。**

### 可信度与局限

理论框架值得读，但实证仍主要集中在 Agentic Math 和 SWE-bench；是否能扩展到高噪声 Browser / Search Agent，还需要新的对照。PACT 也重新引入 Critic Training 的工程成本，而 GRPO 受欢迎的一部分原因恰恰是可以减少 Critic 依赖。

### 最值得继续追踪

重点看在相同 Rollout / GPU Budget 下，PACT 的 Sample Efficiency 是否稳定优于更简单的 Critic-free 方法；以及它能否与 Critical-State Sampling 合并，把 Critic 训练集中到真正高 Headroom 的状态。

## 6. MuSeR：工业推荐把 10^4–10^5 条历史塞进固定 Serving Budget

[论文原文：MuSeR: Scalable Long-sequence Recommendation with Multi-interest Modeling](https://arxiv.org/abs/2609.23677)

### 发生了什么

MuSeR 面向的不是“能不能对 100K 行为做一次离线 Attention”，而是如何把它长期放进真实 Feed Retrieval。系统组合三件事：

- **Hierarchical Temporal Compression：** 近期行为保留 full resolution，越旧越粗粒度 pooling；
- **Disentangled Multi-query Interests：** 多个 Query 表示不同兴趣，并用 Orthogonality Regularization 防止全部收敛到同一模式；
- **Multimodal Semantic Alignment：** 使用 LLM 生成的文本 Summary 补充稀疏 Item ID，帮助跨新闻、问答、短视频等 Modalities 对齐。

Serving 侧再配合 Asynchronous User Representation Refresh、Adaptive Cache 和跨异构硬件的 Hierarchical Beam Search。

### 关键结果

公开 Benchmark 与工业数据上，MuSeR 的 Recall@K 均优于多种长序列／多兴趣 Baseline。百度 APP 的首页 Feed、发现 Feed、短视频线上 A/B 中，**DAU +0.26%，Total Session Duration +0.89%**，两项均 p<0.05，同时报告 Latency 与 Cost 降低。

### 为什么重要

它提供的是一个很现实的 Long-history Recommender Architecture：真正的长期兴趣不应要求每次 Request 重新读取所有历史。用户表示应该是可异步刷新、可缓存、按时间分辨率分层的“长期状态”；当前候选与近期行为再做更高分辨率交互。

### 可信度与局限

这是生产系统论文，线上 A/B 是强证据，但数据、流量和 Serving 细节无法外部复现。作者也明确说这不是新的建模原语；因此价值主要来自系统组合，而不能把线上收益简单归因给某个 Multi-interest Loss 或 LLM Summary。

### 最值得继续追踪

看用户兴趣突变时 Cache Freshness 与 Long-term Compression 的冲突；以及 History 从 10^4 扩到 10^5 后，单位新增历史到底贡献多少 Recall / DAU，而不是只报告“支持更长”。

## 今日值得收藏的代码 / 学习资源

### Grow the Harness, Not the Context

[论文](https://arxiv.org/abs/2609.26760)

这篇和 CliffCompaction 很适合一起读，但方向更激进：它不只缩短 Context，而是把反复出现的控制逻辑逐步写进 **Executable Harness Code**。Failure Trace 会把问题定位到有限代码面，Optimizer 联合修一组失败，Success-first Held-out Gate 则在 Regression 时回滚。BrowseComp-Plus / WebArena-Verified、4B–120B 三个模型上，六个设置中五个拿到最高均值；相对 Tool-Calling Agent，LLM Call 减少 **76.0%–91.8%**，部署推理成本减少 **74.4%–98.6%**。WebArena-Verified 的成功率在不同模型规模上维持约 44.7%–45.3%，而传统 Tool-Calling 到 4B 时降到 6.7%。它支持一个越来越清晰的系统趋势：**重复控制放进代码，模型留给高熵语义决策。**

### FIRE：把失败轨迹变成 Runtime Policy

[论文](https://arxiv.org/abs/2609.26048)

FIRE 不改权重，也不改用户 Prompt，而是在曾经导致失败的状态前注入 Targeted Instruction 或 Action Denial。Terminal-Bench 2.1 的 repeated success（两次都成功）在 GPT-5.6 Sol 上从 **64.4% → 73.6%**，而 best-of-two 只提高 1.2pp，说明它主要做的是把“偶尔会做对”变成“更稳定做对”。Randomized 5-arm 实验中，真实 Policy 61%，无 Policy 39%，Timing-matched Sham 36%，Generic Verification / Reconsideration 39%–43%。这比只看平均成功率更贴近生产 Reliability。

### Flash-dLLM

[论文](https://arxiv.org/abs/2609.26796) · [官方代码](https://github.com/VILA-Lab/Flash-dLLM)

它把 dLLM 的 KV Cache 与 Parallel Decoding 联合起来优化：Flash-Cache 用 Fused Kernel 减少 QKV / RoPE / Cache Write 的中间 HBM Traffic，Flash-Verify 让 dLLM 自己同时当 Drafter 和 Verifier，无需额外 Draft Model。LLaDA-1.5 上，相对 Elastic-Cache 在 GSM8K-512 / HumanEval-512 分别 **5.1× / 11.0×**。注意这些是相对特定 dLLM Baseline 的 Throughput Ratio，不应与 AR Model 的 Tokens/s 直接横比。

### CompKV

[论文](https://arxiv.org/abs/2609.26300)

传统 Sparse Attention 先按 Attention Mass 选 Token，再对没选中的 Tail 做补偿；CompKV 直接问“如果这个 Block 被省掉，后面的 Compensation 会留下多大 Residual”，让 Selection 和 Compensation 联合设计。RULER / LongBench-Pro 上优于论文比较的 Sparse Baseline，并报告最高 **6.85× self-attention speedup**。这类方法值得和 On-Demand Attention、Tiered KV、Prefix Routing 一起看：未来长上下文推理不只决定“存哪些 KV”，还要决定“哪些 KV 值得精确读”。

### llm-d v0.9

[Release](https://github.com/llm-d/llm-d/releases) · [Tiered Prefix Cache 文档](https://llm-d.ai/docs/well-lit-paths/foundations/tiered-prefix-cache)

当前 v0.9 把很多近期 Serving 研究方向变成了可组合系统部件：KV Cache 增加 Heterogeneous Memory Allocation、Storage Event 与 Multi-tier Offloading；Router 加入 Predicted Latency Scheduling、Agentic Workload Routing；同时带来 Batch Gateway、Latency Predictor，并跟进 vLLM 0.26 / SGLang 0.5.16。对于多轮 Agent，Tiered Prefix Cache 允许把被 GPU LRU 淘汰的 KV 下沉到 CPU / NVMe / Network Storage，再按需拉回，直接扩大可复用 Prefix 的 Working Set。

### When Recursive Models Finish Computing

[论文](https://arxiv.org/abs/2609.26487)

Tiny Recursive Model 在 nominal 16 steps 后继续算到 512 steps，1,000 道 hard Sudoku 的 cumulative exact-solve accuracy：Attention 版 **59.2% → 87.5%**，MLP 版 **74.4% → 91.9%**。更值得关注的是，第一次 exact solution 后 latent-state motion 会明显下降，并出现 trajectory-conditioned anisotropic stability。这还是小模型／Sudoku 动力学研究，不能直接推成大型 Looped LLM 的在线停止规则，但它给“递归模型什么时候真的算完”提供了可测的内部信号。

## 今日最值得花 30 分钟阅读的一项

**首选 AIDE²：Recursive self-improvement of AI research agents。**

[论文原文](https://arxiv.org/abs/2609.26457)

这篇值得读的原因不在“RSI”三个字，而在它把几个容易被混淆的问题分开了：固定成本下是否出现多步改进；Selection Benchmark 上的收益是否迁移到外部 Benchmark；Reward Hacking 是否恶化；更强的 Child Agent 是否真的更善于继续驱动 Self-improvement。

30 分钟建议直接按这个顺序读：

1. **Section 2.1 / 2.2：** 两层优化信号为什么要拆开，Private Grade 如何防止 Inner Loop 直接优化 Outer Selection；
2. **Section 3.2：** 100 个节点、7 次接受、0.703 → 0.778 的真实改进轨迹；
3. **Section 3.3 / 3.4：** External Generalization 与 Reward Hacking；
4. **Section 3.6：** Ignition Test 为什么仍然 inconclusive；
5. **Discussion：** 双层噪声、Acceptance Error 和 Compute Cost 为什么可能成为下一阶段真正瓶颈。

最值得带走的判断是：

> **当前最有证据的 RSI 形态，是在固定模型上递归优化“研究过程本身”的程序化 Harness；而“改进后的系统会越来越快地改进自己”仍然没有被这项工作证明。**

这个边界非常重要。否则很容易把“连续找到 7 个有用 Patch”直接外推成无限递归加速，而论文自己的 Ignition Test 并不支持这种外推。

## 今日可立即实践的一件事

给现有 Coding Agent / Research Agent 做一个 **Faithful Compaction A/B**，先验证自然语言 Summary 是否真的优于“机械丢弃”。这不需要训练模型，半天内就能得到方向性结果。

选 20–50 条会超过 50K–100K Context 的真实任务，固定同一模型、Temperature、Harness 与预算，比较三个分支：

```python
arms = {
    "full_or_default": "现有 full context / 原生 compaction",
    "llm_summary": "现有 LLM-based rolling summary",
    "drop_only": "head + mechanical compacted middle + recent turns",
}
```

`drop_only` 最小实现可以遵循 CliffCompaction 的原则：System / User Task 原样保留；最近 N 个 Turn 原样保留；短 Tool Result 原样保留；超长 Tool Result 只保留调用名、关键路径和最后错误行；不要让 LLM 改写旧事实；不要对旧 Compaction 再做二次总结。

至少记录：

```python
metrics = {
    "task_success": [],
    "input_tokens": [],
    "total_cost": [],
    "compaction_count": [],
    "prefix_cache_hit": [],
    "context_length_failures": [],
    "constraint_regression": [],
}
```

再额外做一个 **Needle Audit**：在较早 Turn 放 3–5 个后来必须遵守、但不会频繁重复的真实约束（例如文件不能改、API 版本、性能下限、特定测试命令），看三种策略到任务末尾还保留多少。

如果 `drop_only` 在同等 Task Success 下明显降低 Token / Cost，而且 Constraint Regression 不增加，就说明当前 Agent 的摘要层可能正在制造不必要的语义漂移；如果 Needle Recall 明显下降，则不要机械照搬 CliffCompaction，应该把这些“少见但关键”的约束迁入结构化持久 Memory。

真正要回答的是：

> **你的长程 Agent 失败，主要因为忘了旧信息，还是因为每次“总结旧信息”都在悄悄改变它？**
