## 二、重点精读：推荐系统、Agent 与推理

### 1. 推荐系统 Scaling Law：小规模 A/B 不是看谁赢一次，而是估计全规模胜率

**发生了什么。** Meta 等作者研究不同模型、数据与 Feature 变化下的推荐效果，发现许多改动仍遵循同类幂律曲线、但系数不同。方法在若干小规模点训练后拟合曲线，用统计推断预测全规模 Validation Loss 及不确定区间；覆盖 Wukong、HSTU、基于 LLM 的推荐模型和 40 多种改动。特别重要的反例是：在 MovieLens-20M 的一个电影类型特征实验中，小数据量下变差的方案，到更大训练规模反而变好。

**为什么重要。** 很多推荐团队先跑 10% 数据的模型来淘汰候选，隐含假设是不同 Scale 下改动效果同号。这项工作直接挑战这个假设。文中使用的简化形式为 $L=AN^BD^C$，其中 $N$ 为模型规模、$D$ 为训练数据规模；真正应拿来决策的是目标规模效果的置信区间，而非小规模排名。

**可信度与局限。** 已阅读论文 HTML 的方法、统计建模及失败讨论。作者给出多个模型族和 Feature 案例，但这个规律不能理解成所有架构改动都共享一个精确函数。高 $R^2$ 不能证明远距离外推必然可靠；文中的“全规模 A/B”主要指离线训练配置比较，**不等于线上随机化用户实验**，更无法自动保证 AUM、GMV 或 CTR 的因果收益。

**最值得继续追踪。** 使用 Leave-one-scale-out 校准预测区间覆盖率；加入时间漂移、Feature 交互、冷启动及线上反馈偏差；只有预测显著且成本合理的变更才进入真正的在线 A/B。原始来源：[论文](https://arxiv.org/html/2611.13539v1)。

### 2. Agent 架构成本审计：单 Agent 常是合理基线

**发生了什么。** 研究把模型、任务和工具固定，仅改变架构，在 13 个企业式标准操作流程上测试四类设计共八个实验臂。作者报告，协调型方案相对单 Agent 消耗约 **1.4–4.7 倍 Token、2.6–5.8 倍延迟**，多数额外成功率收益很小或无统计显著性；高质量 Skill 可将成功率从 67.4% 提升至 73.1%，而精心重构的一个多 Agent 实现达到 75.6%。

**为什么重要。** 对真实 Shopping / Search / Coding Agent，Swarm 增加角色和消息往往也增加错误接口与重试成本。正确的目标函数应至少包含成功率、硬约束违例、Token、工具调用次数和 P95，而非只看模型是否“更有分工”。

**可信度与局限。** 固定模型工具的对照设计比跨团队演示有解释力；但只有 13 个 SOP，任务复杂度与 Skill 编写质量会影响结果。聚合结果不显著不能证明任何复杂任务都不需要多 Agent；75.6% 的优势也依赖具体实现。

**最值得继续追踪。** 在相同预算下对单 Agent、Skill Agent 和分工 Agent 做成对 Bootstrap；按 SOP 分支数、失败恢复次数、外部工具不稳定性分桶。原始来源：[论文](https://arxiv.org/abs/2611.12953)。

### 3. ADIndex：稀疏注意力的索引器可能吃掉节省下来的算力

**发生了什么。** DSA 虽然减少被计算的注意力 Token，但 Indexer 仍可能按查询扫描整个因果前缀。ADIndex 观察不同层、不同 Query 的检索重叠程度差异，采用层级校准与 Group-level Distillation，在组内共享 Token Bank、保留 Query 级细化。

**关键结果。** 作者在 DeepSeek-V3.2 与 GLM-5.1 上测试 LongBench、LongBench v2 和 RULER，报告 256K 上 Prefill/Decode Kernel 分别最高 **6.22×/3.40×**，但 128K 时 **E2E Serving 约 1.54×**。这种局部与端到端差距，是理解推理优化收益的关键。

**可信度与局限。** 论文提供了模型与测试环境，但“最高 Kernel 提速”不可用作所有上下文长度、所有并发下的真实吞吐预测；注意力检索近似还需要专门的 Needle、多跳推理与错误传播回归。

**最值得继续追踪。** 在固定准确率下测 Indexer GPU 时间占比、TTFT、TPOT、P95、显存、Batch Size 和 Indexer 训练开销。来源：[论文](https://arxiv.org/html/2611.12956v1)。

### 4. DocFS：把文档处理空间变成 Agent 可以操作的文件系统

**发生了什么。** DocFS 不只是把长文档切片向量化，而是将文档章节映射到目录，文本、表格、图像、公式之间保留可追踪的连接，再为 Agent 暴露导航、查找和读取工具。搭配 Qwen3.5-Plus，在 MMLongBench-Doc、FinRAGBench-V 上，作者报告分别比最强基线高 **2.9、4.3 个百分点**，推理阶段最多 10.3× 更快、Token 最多减少 10.1×。

**为什么重要。** 对财报、合同、产品说明书，错误往往来自跨页关联与工具接口缺失，而不是单个 Chunk Embedding 不够强。文件系统结构为引用追踪、按需展开和层级搜索提供了标准抽象。

**可信度与局限。** 数据集、底座与结构构建成本需要合计；不能把论文中的推理加速直接理解成从 PDF 原始输入到最终答案的端到端加速，也不能跳过表格识别错误和目录错位评测。

**最值得继续追踪。** 同一模型下对比 Flat RAG、层级 RAG 和 DocFS，逐项计入预处理、索引构建、查找、答案质量与证据页码准确率。来源：[论文](https://arxiv.org/html/2611.12957v1)。

### 5. Agent Benchmark：二值成功率可能让排行榜提前失去分辨力

**发生了什么。** 研究重评分八个 Agent Benchmark 的已发布轨迹，包括 MLE-bench、ALE-Bench、SWE-bench Verified、Terminal-Bench 等。作者认为常见 Pass/Fail 评分丢失了任务质量信息，某些任务的成功测试本身有错误区间或过低上限。提出有时间锚点的截断对数比评分，同时把成本作为单独坐标。

**为什么重要。** 推荐算法的 NDCG 高一分通常还需看分桶和置信区间；Agent 的 0/1 Task Success 更粗。两个 Agent 可能都“通过”，但一个代价昂贵、结果质量明显较差，排序完全无法显示。

**可信度与局限。** 重新评分比只发表新 Benchmark 更有诊断意义，但重新定义度量也可能引入偏好的任务权重与参考上限，且无法自动纠正原任务环境中的数据泄漏。

**最值得继续追踪。** 将完成率、连续质量分、硬约束、成本分别公开；比较不同评分规则对模型相对名次、置信区间和线上任务的预测能力。来源：[论文](https://arxiv.org/abs/2611.13541)。

## 三、RAG、知识管理、蒸馏与监控

### 6. 电商评论伪标签蒸馏：学会模仿 Teacher，不等于学会评判信息价值

**发生了什么。** 作者使用 Gemini 3.1 Flash-Lite 给 **534 万条土耳其语电商评论**提供信息量标签，再训练轻量 Encoder；对新 SKU 做时间切分，在一组 1.6 万条评论的时序审计子集上，单独与人工标注对照。一个 H3 类目提示在大测试集上略增 Teacher Fidelity，却在审计子集上降低与教师和人工的一致率。作者报告特定单卡 L4 离线设置下学生流水线约快 **50.2×**。

**为什么重要。** 这是典型的 Teacher Fidelity 与业务目标不一致：如果教师标签有偏见，蒸馏得更像教师不一定能更好地筛选有价值评论。

**可信度与局限。** 仅一位企业标注者、土耳其语市场和简短论文，人工标签可靠性与跨地域泛化未知；50.2× 是所测两套流水线对比，非普适模型比值。**追踪：** 多标注者一致性、困难 SKU 和时间外分布、点击后决策收益。来源：[论文](https://arxiv.org/abs/2611.13797)。

### 7. TIGA：用可执行编辑动作而非自由文本生成商品类目树

**发生了什么。** TIGA 把 Taxonomy Induction 设计为显式树状态上的受约束编辑操作；Agent 可调用结构化工具，维护行动记忆、运行时更新分类策略，并选择是否调用 Global Reviewer。四个 Taxonomy Benchmark、两个底座上，多数组合的结构质量变好。

**为什么重要。** 电商目录分类最关键的是“不漏 SKU、不产生环、不乱挂父子关系”。这种场景下，约束编辑与可审计状态通常比让模型直接输出最终 JSON 树可靠。

**可信度与局限。** 作者明确披露 Token、API 调用和推理时间显著增加，且 Precision 并非全面最好；全局 Reviewer 的价值随数据集和修改预算变化。**追踪：** 完整率、祖先 F1、人工回滚成本和每次正确编辑的 Token。来源：[论文](https://arxiv.org/abs/2611.13966) · [代码](https://github.com/bschaarmann/TIGA)。

### 8. Knowledge Graph 检索：多跳准确率、证据覆盖与成本不可互换

**发生了什么。** 研究在 320 条问题上比较图检索、单向量与合并候选；在其内部配置中，KG 的部分多跳 MRR 更高，合并候选的 Recall@20 更高，但单次平均检索 **20.374 秒（KG）对 0.646 秒（SV）**。作者明确指出结果主要是描述性比较。

**为什么重要。** 在 RAG 中，提升前五条结果的相关性，不代表能提供足够完整的证据，也不代表合理的用户等待时间。

**可信度与局限。** 单领域、320 个问题，其中多跳子集仅 15 条；不能外推成“图 RAG 一定比向量更好”。**追踪：** 固定召回预算和 P95，报告完整证据 Recall、最终答案支持率与单位请求成本。来源：[论文](https://arxiv.org/abs/2611.14050)。

### 9. TopicScope：Prefill 训练轻量 SAE 主题监控器，Decode 时部署

**发生了什么。** TopicScope 在 Prefill 隐状态提取的 SAE Feature 上训练七类 Topic 的因果 Token 级分类器，并在解码阶段逐 Token 判断主题变化。作者用 Gemma-3 1B/4B 的合成多主题对话验证，公布代码、数据和 Checkpoint。

**为什么重要。** 生成过程监控可避免等整段回答生成完毕才做标签判断，并提示一些 SAE Feature 可作为廉价在线读出基础。

**可信度与局限。** 合成七类 Topic 不代表能识别真实工具注入、越权行动或事实错误；逐 Token 检测性能也不自动保证控制能力。**追踪：** 真实分布漂移、误报率与 GPU/CPU 执行开销。来源：[论文](https://arxiv.org/abs/2611.12935) · [代码](https://github.com/Mercity-AI/SAE-Guardrails)。

## 今日最值得花 30 分钟阅读的一项

**[Exploiting Feature-invariant Scaling Laws for Efficient A/B Experimentation in Recommendation Systems](https://arxiv.org/html/2611.13539v1)**。推荐分配：8 分钟读 MovieLens 的“小规模下降、大规模上升”反例；10 分钟读 §5 的 $\log L$ 回归与 Student-t 预测区间；7 分钟看不同 Feature 的拟合及外推失效条件；最后 5 分钟列出自己业务里哪些真实变化可能打破“同类幂律”假设。关键不是记住公式，而是把**筛选实验的错杀率、GPU-hours 与区间覆盖率**做成三项可观测指标。

## 今日可立即实践的一件事

**为现有推荐实验建立一个“小规模预测全规模”的回测表。** 从历史已有全规模结果的 5—10 个 Feature/模型改动中，选每个实验的 3—5 个小 Scale Checkpoint（如果未保存就先从已有训练日志起步），拟合 $\log L=\beta_0+\beta_1\log N+\beta_2\log D$；在完全不使用全规模数据训练拟合器的前提下，输出全规模改善概率与 95% 预测区间，再与真实结果比较。至少测 **方向判断准确率、预测区间覆盖率、误淘汰率、节约的训练算力**。与“只看最大小 Scale 一次结果”做同样预算的比较；若数据少或设计矩阵秩不足，不要假装能稳定估计三个系数。
