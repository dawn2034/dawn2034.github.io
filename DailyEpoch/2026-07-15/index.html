每日 AI 技术简报｜2026-07-15

今日核心判断

今天值得抓住的技术主线有四条：

  1. LLM 强化学习的研究重心继续下沉到细粒度信用分配。最终答案奖励仍然保留，但搜索步骤、证据来源和推理过程开始获得独立信号。
  2. Agent 工程指标正在扩展。Token、延迟和成功率之外，运行日志、快照、检查点的存储膨胀开始进入系统评估。
  3. 长上下文出现一条不同于扩展注意力窗口的路线：将外部历史压缩进可更新的循环记忆。
  4. LLM-as-a-Judge 的偏差可能存在稳定的内部表示结构。这会直接影响模型评估、奖励模型和自动化数据筛选。

1. STAMP：把“找到关键证据的搜索动作”纳入奖励

发生了什么

STAMP 面向 Deep Search Agent 提出一种基于证据溯源的信用分配方法：

  • verifier 判断引用文档能否支持训练时证据图中的实体或关系；
  • 将有效引用追溯到首次发现该文档的搜索步骤；
  • 用 sign-preserving advantage modulation 调整各步骤 advantage，同时保留原始轨迹奖励的正负号和组内排序。

在相同 SFT 初始化、训练数据和搜索工具下，STAMP 相对 GRPO 在 BrowseComp、BrowseComp-ZH 和 xbench-DS 上分别提升 2.0、5.5 和 3.0 个百分点。

为什么重要

搜索 Agent 经常出现一种奖励错配：最后答案正确，但真正暴露关键文档的早期 query 得不到特殊奖励；后续整理和复述反而共享了全部回报。

STAMP 把信用链改成：

事实 → 支撑文档 → 首次发现文档的动作

这比用另一个 LLM 对每一步泛化打分更容易验证，也更适合有明确 evidence graph 的任务。

对推荐系统也有启发：在“曝光模板—进入详情—发起生成—完成创作”的链路中，可尝试记录哪个候选、召回源或排序动作首次暴露了最终被采用的创作意图。这只是方法迁移的合理推断，真实有效性仍需通过反事实或在线实验验证。

局限与追踪点

STAMP 依赖训练期参考证据图和可验证引用。在开放式任务中，完整 evidence graph 的构建成本可能很高。还要观察：

  • 无标准答案的研究任务能否使用弱监督 provenance；
  • verifier 错误是否会系统性放大；
  • 与 CriticSearch、step reward model 相比，训练成本是否真正更低。

2. SCOPE-RL：分别处理“成功之前”和“成功之后”的推理问题

发生了什么

SCOPE-RL 将 RLVR 的过程优化拆成两个阶段：

  • Adaptive Scaffolded RL：对困难问题生成隐藏答案的子问题链，给尚未走到最终答案的有效前缀提供可验证奖励；
  • Quality-Aware Process RL：只在最终答案正确时，对有用步骤密度、局部错误、冗余推理和 token 效率进行进一步优化。

在 Qwen3-8B-Instruct、DAPO-Math 和 Big-Math 实验中，论文报告相对 outcome-only GRPO，平均准确率最高提升 11.2 个百分点，推理 token 最多减少 27.1%；结果也在 GSPO 和 Qwen3-0.6B-Instruct 上进行了验证。代码与数据已经公开。

为什么重要

它明确区分了两种训练停滞：

  • 模型还不会做：需要让“接近成功的局部进展”产生梯度；
  • 模型已经会做：需要压缩绕路、重复和偶然正确的步骤。

这比单纯继续调整 GRPO clipping、采样组大小或 KL 系数更接近问题源头：可学习信号覆盖了哪些 token 和轨迹。

局限与追踪点

目前主要证据来自数学推理。scaffold 本身由模型生成时，可能带入错误分解或训练分布偏置。值得继续看：

  • 在代码、搜索 Agent 和工具调用任务上的结果；
  • scaffold 生成与过程 judge 的额外训练成本；
  • 11.2 个百分点提升由哪些 benchmark 和基线贡献，是否存在挑选最大值的问题。

3. Inside the Unfair Judge：LLM Judge 的偏差存在低维方向

发生了什么

该工作研究了 7 种 Judge、7 类偏差和 9 个 benchmark。作者发现：

  • 正常评测输入的隐藏激活集中在较紧的流形；
  • 带偏差的输入会沿某些低维、偏差类型相关的方向移动；
  • 沿这些方向进行 activation steering，可以诱发或逆转评分偏差；
  • 基于这些方向训练的简单线性预测器，可以提前识别三个未见 benchmark 上的 Judge 失败。

为什么重要

很多评估系统依赖 LLM Judge 生成：

  • pairwise preference；
  • 奖励模型标签；
  • Agent 轨迹质量分；
  • 推荐理由、内容质量和安全标签。

如果偏差具有稳定的内部方向，它就可以成为一种上线前诊断信号，用途比提示词层面的“交换顺序再评一次”更广。

局限与追踪点

这类方法需要访问隐藏状态，对闭源 API Judge 很难直接部署。还需要确认：

  • bias direction 能否跨模型家族迁移；
  • 去除一个偏差方向是否会损害真实质量判断；
  • 多种偏差同时出现时，子空间是否仍然可分。

4. Associative Recurrent Memory：用恒定状态承载超长历史

发生了什么

论文将 Associative Recurrent Memory Transformer 用于现有 LLM 的上下文扩展，并给出一套包含持续预训练、合成长上下文数据、课程学习和选择性插入记忆层的训练方案。

作者报告，ARMT 模型能够：

  • 处理超过原始窗口的输入；
  • 对训练长度之外的上下文保持更好的泛化；
  • 在原始上下文范围内保持基线性能，同时减少约 30% FLOPs；
  • 记忆占用随上下文长度保持恒定。

为什么重要

Agent 的长期记忆目前常见两条路线：

  • 外部检索：向量库、图、日志搜索；
  • 上下文压缩：摘要、截断、重写历史。

ARMT 增加了一条内部状态路线：让模型在分段读取历史时，将信息写入可更新的关联记忆。它更适合重复读取窄领域长文档、长对话或代码仓库。

局限与追踪点

这不是一个可直接挂载到任意模型的推理插件，需要架构调整和继续训练。论文侧重窄领域数据，仍需观察：

  • Needle 类任务以外的真实证据保真度；
  • 长循环后的记忆覆盖与遗忘；
  • FLOPs 降低能否转化成 GPU 实际延迟下降；
  • 与 RAG 混合时，什么信息应进入内部记忆。

5. AgentFootprint：Agent 跑完以后究竟留下了多少数据

发生了什么

AgentFootprint 将 Agent 的持久化存储列为独立评估指标，包括日志、历史快照、checkpoint、调试 trace 和框架数据库。

实验显示：

  • 同一条轨迹在不同持久化框架中的最终存储量相差 6.7 倍；
  • 达到相同 100% 任务准确率的配置，保留字节数可相差 15.7 倍；
  • 部分保存完整历史的配置会随重复观察呈超线性增长；
  • content-addressed store 可减少 4.8 至 32.7 倍存储，同时保留论文测试的历史重建能力。

为什么重要

长运行 Agent 的成本经常被低估。每轮都保存完整 prompt、工具结果和数据库序列化副本，可能造成：

  • 本地 Agent 磁盘持续膨胀；
  • 企业数据保留与删除困难；
  • 日志中重复存储敏感内容；
  • 多 Agent 并行后，存储成本高于最终产物本身。

局限与追踪点

更低存储不必然更优。恢复、审计、重放和故障诊断都需要数据。合理目标是报告一个多目标结果：

成功率 + 推理成本 + 存储量 + 可重建程度

推荐系统补充：RouteRec 反驳了过于简单的“模型路由”

RouteRec 比较了两种异构推荐 Agent 组合方式：

  1. 每个请求只选择一个完整推荐器；
  2. 在 item 层面对多个推荐器结果进行学习融合。

在 MovieLens-1M 的 leakage-free 五折实验中，请求级 hard routing 的 HR@10 低于 BM25：0.223 对 0.254；item-level gated aggregation 达到 0.295，但需要在 70.2% 的请求中调用 LLM。作者因此认为，稀疏固定候选场景中，“每个请求选择一个模型”粒度过粗，item-level aggregation 更值得研究。

与你当前推荐场景最相关的判断：

多路召回、精排模型或 LLM 重排器之间，优先测试 item score fusion / list aggregation。请求级 router 容易丢失互补 item，因为它一次性淘汰了整个候选列表。

局限也很明显：实验基于 MovieLens-1M，没有在线延迟、创作转化、长期留存和大规模候选池验证。

今日深度资源：The Dark Arts of Skill Engineering

Paul Bakaus 最新发布了同名 X 长文，并开放了完整演讲材料、speaker notes、演示和一个可运行的 mini-skill。

材料将 Skill Engineering 分成四组实践：

  1. 让多个 Agent 独立生成、争论和强制产生差异；
  2. 将 skill 当作带路由、状态和动态指令的程序；
  3. 使用 hooks、运行时反馈和多 harness 编译；
  4. 按较弱模型的能力边界设计整个 skill。

仓库中的 starter 采用 Apache 2.0，演讲材料本身保留版权。

价值判断：高工程价值，中等证据强度。 这是实践经验与可运行示例，缺少严格对照实验。适合拿来改造 Codex Skill，不能直接视为普适 Agent 理论。

X.com 近 24 小时技术信号

X 的公开检索无法稳定提供完整的实时互动排行榜。以下按发布时间、重复传播和技术密度筛选，不能视为严格的全站热度排名。

1. Skill Engineering 与 Harness Engineering

Paul Bakaus 的长文在近数小时发布，并附完整 GitHub 材料。核心讨论从“继续堆系统提示词”推进到可验证 hooks、动态路由、持久化上下文和多 Agent 评审。

2. STAMP 的证据溯源信用分配

X 上已经出现针对 STAMP 的技术摘要，讨论集中在如何把引用证据追溯到首次发现它的搜索动作。

3. Requential Coding

Requential Coding 开始在 X 上传播。它用学生自身分布生成的训练样本构造编码，使码长不再直接随参数量和数据熵增长，并用于构造十亿参数模型的 PAC-Bayes 泛化界。这个工作理论味很重，短期内不会直接改变部署压缩，但可能影响我们理解“模型规模、记忆与可泛化信息量”的方式。

今日最值得花 30 分钟阅读的一项

STAMP。

建议阅读顺序：

  • 5 分钟：理解 reward-credit mismatch；
  • 10 分钟：看 evidence graph 与 first-exposure attribution；
  • 10 分钟：看 sign-preserving advantage modulation；
  • 5 分钟：思考如何映射到多阶段推荐或创作转化链路。

今日可立即实践的一件事

在现有推荐离线数据上做一次 RouteRec 风格的无泄漏对照实验：

  1. 选取两个已有信号，例如精排 CVR 分数和内容质量／LLM 分数；
  2. 用五折 out-of-fold 方式产生训练集预测，避免 meta-model 看到基模型的训练内结果；
  3. 比较三组：
    • 最优单模型；
    • 请求级选择一个模型；
    • item-level 线性融合或小型 MLP aggregation；
  4. 同时报告 AUC、GAUC、NDCG、创作转化率 proxy 和 LLM 调用比例。

最关键的检查点：item-level fusion 的提升是否来自真实互补信息，还是训练泄漏和候选池变化。 RouteRec 的结论只有在固定候选集和严格 OOF 条件下才有参考价值。
