# 每日 AI 技术简报｜2026-07-16

## 今日核心判断

今天的信息密度主要集中在两条线上：

1. **推荐系统开始系统性反思“照搬 Transformer/LLM 架构”的成本。**Meta 的 SlimPer、Pinterest 的 MESH、Meituan 的 NONTP 分别从排名架构、异构召回和生成式推荐训练目标切入，而且都有大规模线上数据。
2. **Agent 优化逐渐进入“控制冗余、预测失败、管理未来意图”的阶段。**单纯提高任务成功率已经不够，执行范围、逐步置信度和延迟任务记忆开始成为独立能力维度。

## 1. SlimPer：Meta 重新设计工业级个性化排名架构

### 发生了什么

Meta 提出的 SlimPer 将推荐排名建模为对一个固定大小的 `<user, item>` 知识库进行多轮 **Select–Match–Refine**：

- 每层根据当前 user-item 状态，从完整用户特征和行为序列中选择证据；
- 显式计算候选 item 与不同兴趣侧面的匹配分数；
- 用匹配结果更新固定大小的知识库；
- 用户侧 token 在一个请求中只计算一次，由全部候选 item 共享。

模型通常使用 16–64 个知识槽、堆叠 5–10 层，并已用于 Instagram Reels 和 Feed，可处理超过一万个细粒度历史事件。citeturn199706view0turn143100view0

### 为什么重要

SlimPer 指出了推荐 Transformer 的一个结构性浪费：语言模型需要保存每个 token 的中间表示，因为每个位置都有预测监督；工业精排通常只输出少量 user-item 任务分数，继续让每层传播完整历史序列，会把大量计算用于 user-token 之间的交互。

SlimPer 将大部分容量直接分配给 **user-item relevance interaction**，同时让每层重新读取原始证据，减少一次压缩后信息永久丢失的问题。这条路线和 DIN 的 target-aware attention 有亲缘关系，但增加了多轮迭代、跨模态统一建模和请求级计算共享。citeturn199706view0

### 结果

在相同历史长度下：

- Reels 2k 历史事件：QPS 提升 11%，平均显存降低约 9.3%；
- Feed 1k 历史事件：QPS 提升 12.5%，平均显存降低约 18.1%；
- 增加到 4k–5k 历史后，预测质量继续提升，但 QPS 开始下降，说明长历史依旧有真实成本；
- 论文报告了线上互动指标的统计显著改善，但没有公开完整的线上绝对数值。citeturn143100view0

### 可信度与局限

**可信度：较高的工业证据，中等的可复现性。**

优势是直接对比 Instagram 当前 HSTU+Wukong 精排基线，并完成线上实验。主要问题是全部数据和训练基础设施均为内部资源，论文也没有直接对比 OneTrans、HHFT、RankMixer 等近期统一架构，外部团队很难复现其收益幅度。citeturn143100view1

### 最值得追踪

- 固定知识槽是否会损失弱兴趣、短期兴趣和多峰兴趣；
- 在一次请求只返回 12 个候选的场景中，request-only optimization 的收益有多大；
- SlimPer 与 MMOE/PLE 等多任务结构如何组合；
- attention 权重能否真实解释贡献，还是仅与最终分数相关。

## 2. NONTP：生成式推荐不能只靠 Next-Token Prediction

### 发生了什么

Meituan 的 NONTP 认为，生成式推荐中的 NTP 存在两类信号覆盖不足：

- **时间局部性**：当前位置只监督下一项，没有直接信号要求模型理解更远期的兴趣迁移；
- **空间局部性**：目标 item embedding 的梯度主要来自前一个 hidden state，稀疏领域容易被高频领域的表示支配。

NONTP 增加两个仅训练期使用的目标：

- **TCL**：利用 EMA teacher 和 InfoNCE，让当前状态对齐未来 K 步的行为轨迹；
- **TDL**：汇总其他领域的 hidden states，通过同一个预测头为目标 item 增加一条跨域梯度路径。

两个模块在推理时都被移除，因此没有线上推理开销。citeturn370711view0turn143100view4

### 结果

在 Meituan 四领域全量排序数据上，NONTP 的 HR@10 为 0.0485：

- 相对普通 NTP 提升 34.3%；
- 相对 MBGR 提升 18.3%；
- 线上 A/B：CTR 提升 1.8%，GMV 提升 2.1%。

在 Amazon Movie–Book–CDs 公共数据上，HR@10 提升 2.8%，NDCG@10 提升 3.7%。工业数据提升明显更大，作者将其归因于更长序列、全量排序和更频繁的跨域行为。citeturn370711view0turn143100view5

### 为什么重要

这项工作的核心价值是把生成式推荐的优化问题从“更换模型架构”推进到 **监督信号覆盖范围**。

Semantic ID 本身没有自然语言 token 那样的连续语义邻近关系。只训练下一 token，模型可能学到热门局部跳转，却难以理解用户正在从餐饮转向酒店、从内容浏览转向创作等较长行为迁移。

### 可信度与局限

**可信度：较高，包含公共数据、工业全量排序和线上实验。**

成本并不为零：训练时间增加约 20%–25%，GPU 显存增加约 40%，而且三个目标直接相加会产生梯度冲突。作者发现辅助目标权重超过 0.3 后效果下降。citeturn143100view5

### 最值得追踪

对 AI 创作推荐场景，最有价值的迁移方向是：

- 用未来数步的“查看详情—发起生成—完成生成—取走作品”轨迹监督当前表征；
- 检查不同内容域、创作工具和模板类型之间是否存在稀疏域梯度不足；
- 比较 TCL 与常规 next-action 多任务学习，确认收益来自长程结构，还是简单增加正样本密度。

这是合理迁移假设，尚无证据表明 NONTP 会直接改善 30 天创作留存。

## 3. E3：Agent 在行动前先判断任务到底有多复杂

### 发生了什么

E3 将 Agent 执行拆成三个阶段：

1. **Estimate**：估计任务复杂度和最小必要信息范围；
2. **Execute**：先执行最低成本的可行路径；
3. **Expand**：只有验证失败时才扩大读取文件、工具调用和推理范围。

作者还提出 Agent Cognitive Redundancy Ratio：

\[
ACRR=\frac{C_{actual}-C_{min}}{C_{min}}
\]

其中成本可同时计入延迟、token、工具调用和读取文件数。citeturn878755view2turn678899view0

### 结果

在 121 个可控代码编辑任务中，E3 保持 100% 成功率，同时相对 maximum-context-first 策略：

- 成本降低约 85%；
- token 减少约 91%；
- 完整读取文件数减少约 92%。

与更强的 adaptive retrieval 基线相比，成本仍低约 16%。不过主要实验基于能力受控的模拟环境；真实 GPT-4o 案例只是补充性验证，不能据此断言一般 coding agent 都能获得相同幅度的收益。citeturn878755view2turn678899view0

### 为什么重要

很多 Agent harness 默认执行“先把能读的都读完”。这会产生三个问题：

- 简单任务被长上下文和工具调用淹没；
- 更多无关信息可能降低注意力质量；
- 成本随着代码库或工作区规模增长。

E3 的实用原则很简单：**先走最小路径，验证器负责决定是否扩展。**

### 深度资源

项目仓库包含完整离线 benchmark、成本 ledger、四种策略、ACRR 计算、消融实验和可复现图表，不调用模型 API 也能运行。citeturn678899view0

## 4. Critic Experience Bank：让 Agent 从过去行动的后果中学习置信度

### 发生了什么

Critic Experience Bank 为 Agent 的每一步动作估计“这一步是否会推进任务”的概率。

每条轨迹结束后，一个 hindsight LLM 查看完整环境反馈，为各步骤生成 productive / unproductive 伪标签；这些经验被写入记忆库。未来遇到相似状态和动作时，critic 检索相关成功与失败案例，再预测当前动作置信度。

该方法无需训练，也不依赖人工步骤标签。在三个 Agent benchmark、三个 critic backbone 上，它在校准误差、Brier score 和 AUC 上均优于对比方法，ECE 最大降低 54%。citeturn878755view0

### 为什么重要

普通 LLM confidence 更接近“模型觉得这句话像不像正确答案”。Agent 更需要估计：

> 执行这个动作之后，环境是否会朝目标方向变化？

把动作、环境反馈和最终后果形成经验闭环，方向上比单纯读取 logits 或让模型自报信心更贴近实际执行风险。

### 可信度与局限

**可信度：中等。**

步骤标签仍由 hindsight LLM 生成，critic 和 hindsight model 可能共享偏差。相似经验检索还可能造成确认偏误：历史上常见的动作持续获得高置信度，新策略则被系统性低估。

### 最值得追踪

- 低置信度动作是否真的适合阻断，还是应该触发更强模型或 verifier；
- memory bank 增长后如何清理过时和冲突经验；
- 置信度校准改善能否转化为更高成功率，而不仅是更好地预测失败。

## 5. MESH：推荐模型扩容可能只让头部内容受益

### 发生了什么

Pinterest 在十亿级 Related Pins 系统中发现，扩大统一召回模型时，常青热门内容的效果增长明显，fresh 和 long-tail 内容的增长却很弱。论文将其称为 **Scaling Bias of Heterogeneity**。

MESH 将 user、item、context 等异构信号先放进独立子塔，再进行全局交互，为稀疏内容保留相对独立的梯度路径。citeturn143100view2

### 结果

论文报告：

- flat baseline 中，常青内容的梯度范数约为 fresh 内容的 12.4 倍；
- MESH 将该比例降到 4.7，改善约 62%；
- fresh impressions 提升 5.5%，repins 提升 4.9%；
- long-tail shopping repins 提升 2.33%；
- 总体 repins 仍提升 0.96%，没有观察到明显的头尾流量互相蚕食。citeturn143100view3

### 为什么重要

这对 AIGC 模板推荐尤其关键。直接扩大精排或召回模型，梯度可能继续被高曝光模板、成熟创作者和高频内容类型主导。模型容量增加并不自动带来新模板、长尾风格和新创作意图的改善。

### 最值得追踪

- 分召回源、模板生命周期和内容类型统计 scaling curve；
- 检查 fresh item 的梯度范数、embedding 更新频率和曝光反馈环；
- 将“新内容获得更多曝光”与“新内容真实质量提升”分开评估，避免把探索流量误记成模型能力。

## 补充观察：Agent 的“未来任务记忆”仍然很弱

PM-Bench 模拟连续七天的任务环境，要求 Agent 在处理日常活动的同时，记住“当某个时间、状态或事件出现时再执行”的延迟意图。八种模型和八种 Agent 配置中，最佳 GPT-5.4 Agent 的 F1 也只有 65.1%，且没有一种记忆策略能稳定统治所有模型。该工作已作为 COLM 2026 论文发表。citeturn878755view3

这说明长期 Agent 的问题不只在于能否召回过去，还包括能否在正确时机主动触发已有意图。日历提醒、条件任务、异步工作流和长期研究 Agent 都受这一能力约束。

**判断：**传播标题中的“90% token 都被浪费”过于宽泛。论文的 91% 来自特定模拟 benchmark 相对特定基线，不能外推到所有 Agent。

### MESH：模型规模与长尾公平性

MESH 已被技术论文聚合账号传播，核心关注点是统一召回模型扩容时，fresh/long-tail 内容无法获得同比例收益。citeturn512414search1

**判断：**这比泛泛讨论“推荐要照顾长尾”更有价值，因为论文提供了梯度范数和 scaling exponent 层面的机制证据。

# 今日可立即实践的一件事

对当前“每次请求返回 12 个 item”的精排链路，做一次 **user-side 重复计算审计**：

1. 将精排计算拆成 user-only、item-only、user-item interaction 三部分。
2. 记录一次请求中 user embedding、历史序列编码和公共特征处理是否被按 12 个候选重复执行。
3. 分别统计 GPU time、显存峰值和中间 tensor 大小。
4. 尝试将 user-side token 或中间状态改成 request-level shared representation。
5. 对比 QPS、P99、显存、AUC/GAUC 和各创作任务指标。

关键点：先 profile，再改模型。批量张量在代码层面看似复制 12 份，底层算子未必真的重复完成全部计算；只有 profiler 能确认这一点。SlimPer 提供的是架构方向，是否值得改造取决于现有链路中 user-side 计算的真实占比。
