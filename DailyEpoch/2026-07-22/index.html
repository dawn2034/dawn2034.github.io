每日 AI 技术简报｜2026-07-22

arXiv 最新可见批次为 7月21日，cs.AI 当批共列出 342 项。本期优先筛选 Agent Harness、自我进化、检索、推荐和推理基础设施中具有明确实验或线上证据的工作。

今日核心判断

第一，Agent Skills 的价值边界开始变得清晰。渐进式披露主要解决语料规模和上下文组织问题；当 Harness 已具备强检索与文档导航能力时，额外封装 Skill 的收益可能接近于零。

第二，自我改进系统的关键瓶颈逐渐从“生成更多反馈”转向“反馈是否稳定、是否可验证”。搜索 Agent 的自蒸馏会出现模板化坍缩，Lean Agent 借助形式验证和课程共进化则取得了更强结果。

第三，工业推荐中的 Agent 更适合修改受约束的策略空间。SR-Agent 并未让 LLM 直接改写完整排序模型，而是将其放在诊断、经验归纳和有界后排序策略调整环节。

1. 渐进式披露：一层目录有用，两层路由可能适得其反

发生了什么

《Is Progressive Disclosure All You Need for Long-Context Agents?》对以下方案进行了受控比较：

  • 将整本书直接放入上下文；
  • 给 Agent 原始文档路径，由其自行导航；
  • 将文档制作成按需加载的 Agent Skill；
  • 使用传统混合检索器。

实验覆盖三个 Agent Harness、三个模型家族和 InfiniteBench。单本书任务中，收益高度依赖 Harness：弱导航 Harness 获益较大，强 Harness 本身已经会切分和查找文档，Skill 增量接近零。多本书场景下，原始文档导航迅速退化，一层渐进式披露更稳；增加第二层路由没有带来提升，部分设置还降低了准确率。

为什么重要

这项工作给出了一个很实用的边界：

\[\text{Skill价值} \approx \text{语料导航难度} - \text{Harness已有检索能力}\]

很多团队把文档全部转换成层层嵌套的 Skill，以为结构越精细越好。论文结果显示，过深目录会增加错误路由、额外工具调用和信息遗漏。一层“描述—文件”映射可能已经覆盖大部分价值。

可信度与局限

可信度：中高。它进行了跨 Harness、跨模型的受控实验，且直接比较经典检索方案。

局限在于评测集中于书籍问答和 InfiniteBench。代码仓库、实时业务数据、包含表格和图片的文档，可能需要不同的目录深度与检索策略。论文也没有证明 Skill 自动生成后的内容质量稳定。

继续追踪

  • 目录描述错误对路由的影响；
  • Skill 与向量检索／BM25 联合使用的最佳方式；
  • 多模态文档是否需要单独索引；
  • 强 Harness 下，Skill 的主要收益是否只剩 token 和延迟。

2. 搜索 Agent 自蒸馏失败：轨迹看起来不同，实际在重复模板

发生了什么

FA-SD 使用成功搜索轨迹作为特权信息，让模型充当自己的教师，对检索交错搜索 Agent 进行 on-policy self-distillation。

作者发现，模型会反复生成相似的“思考—搜索—总结”模板。这些轨迹在表面文本上存在变化，内部行为却对具体问题不敏感。作者将其称为 decoding collapse。此时学生与自教师之间的 KL 信号缺乏有效任务信息，自蒸馏难以带来提升。

论文进一步将监督不稳定拆成：

  • 模型不一致性：同一模型不同阶段的分布持续移动；
  • 提示词不一致性：学生和自教师看到的上下文不同，导致概率差异混入大量提示条件噪声。

加入 EMA Teacher 后，监督信号更稳定，但训练初期可能暂时退化。

为什么重要

它指出了一个常被忽略的问题：轨迹多样性不能用字符串差异衡量。

Agent 可能生成很多不同 query，却始终采用同一种缺乏问题针对性的搜索程序。离线评估至少应该增加：

  • query 与问题实体的条件互信息；
  • 不同问题之间的动作序列相似度；
  • 检索结果变化对下一步动作的敏感性；
  • 固定模板占比；
  • 干预关键证据后的策略变化。

可信度与局限

可信度：中等。论文对失败机制进行了拆解，但仍属于新预印本，EMA Teacher 是否能稳定迁移到代码、浏览器和长任务 Agent 尚未建立。

值得警惕的是，稳定的教师也可能稳定地传递错误策略。EMA 解决分布漂移，无法自动解决教师能力上限。

3. SR-Agent：快手将 Agent 用于后排序策略闭环

发生了什么

SR-Agent 面向电商推荐中的后排序策略，例如列表多样性、相似内容抑制、类目曝光和商品重复控制。系统包含三部分：

  1. UserSim Agent：通过分阶段检查发现用户可感知的坏案例；
  2. Analysis Agent：将重复坏案例整理成结构化、可复用的诊断经验；
  3. Strategy Refinement Harness：将诊断映射成类型明确、幅度受限的策略动作，并经过四阶段奖励检查和可逆回滚。

在快手电商一个月线上 A/B 实验中，论文报告订单量提升 0.71%、浏览深度提升 0.34%、点击类目多样性提升 0.48%。

为什么重要

这是一种风险相对可控的“自进化推荐”架构：

\[\text{用户体验坏例} \rightarrow \text{结构化诊断} \rightarrow \text{受约束策略修改} \rightarrow \text{离线与线上验证} \rightarrow \text{保留或回滚}\]

Agent 不直接更新精排模型权重，也不自由生成线上规则。动作空间经过类型化和边界限制，因此更容易审计和回退。

可信度与局限

可信度：较高的工业信号，外部复现性较低。

论文提供了一个月线上结果，但未从摘要中披露流量规模、显著性区间、策略迭代次数及不同组件的线上消融。UserSim 发现的“坏体验”也可能继承模拟器偏好，与真实用户长期行为存在偏差。

对你的推荐场景的启发

在 AI 创作模板推荐中，可以先让 Agent 调整有限的后排序参数：

  • 同类模板连续曝光上限；
  • 新模板最低曝光配额；
  • 图片／视频比例；
  • 相似封面抑制阈值；
  • 用户近期已浏览模板的冷却时间；
  • 探索内容占比。

这些动作容易离线重放，也容易在线回滚。让 Agent 直接生成精排权重或修改核心模型，当前风险远高于潜在收益。

4. Self-Modifying Lean Agent：Agent 与训练任务共同进化

发生了什么

该工作设计了一个小型、固定、可信的运行时，外围工作区则允许 Agent 自行修改：

  • 证明工作流；
  • Prompt；
  • 工具；
  • 证明上下文表示方式。

系统还允许当前最佳 Agent 修改下一代任务分布。只有在当前难度达到一定掌握度后，课程才引入更难的证明任务；每次课程变化后，通过固定锚点重新校准得分。所有成功最终都必须由 Lean 编译器验证。

经过 15 代进化，最佳共进化 Agent 在 held-out miniF2F 子集上的通过率达到 45.1%，初始 Agent 为 12.7%，使用固定 benchmark 进化的最佳 Agent 为 32.0%。

为什么重要

许多“自我进化”实验会逐渐针对固定 benchmark 过拟合。这里同时演化：

\[\text{Agent能力} \leftrightarrow \text{任务难度}\]

形式验证器提供了相对可靠的外部真值，使 Agent 可以修改自己的工作流，同时很难通过语言表述或 Judge 偏好“骗分”。

可信度与局限

可信度：中等偏高。形式验证和 held-out 评估增强了结果可信度。

局限包括：

  • 只运行了 15 代；
  • 测试集规模和领域集中于 Lean 数学证明；
  • benchmark 由 champion 修改，仍可能形成狭窄课程；
  • 工作流改进与底座模型随机波动的贡献需要更细消融。

这条路线更容易在代码测试、SQL 执行、编译器、定理证明等具有强验证器的领域成功。开放式研究、推荐和写作缺少同等可靠的外部判定。

5. Table RAG：语义最相似的表格可能无法回答问题

发生了什么

TCR-Bench 专门构造具有相似 schema、内容存在细微差异的 sibling tables。密集检索器经常能找到正确表格组，却无法识别其中唯一包含完整答案的表格。

在该基准上：

  • 使用 Oracle 表格时，QA 得分为 0.755；
  • 使用检索得到的 Top-5 表格时，降至 0.330；
  • 普通 Top-1 目标表检索率仅 18.2%；
  • 加入 Answerability-Aware Reranking 后提高到 57.4%。

作者将问题归因于语义信息累积、过度依赖 schema 线索，以及较弱的行列绑定能力。

为什么重要

企业 RAG 中，检索目标通常写成“与问题最相关”。表格和结构化数据需要更严格的目标：

当前检索结果是否包含完成计算或逻辑判断所需的全部字段和行？

因此，表格 RAG 可以考虑两阶段打分：

\[\text{语义相关性} \rightarrow \text{答案充分性验证}\]

可信度与局限

可信度：中等。诊断基准和提升幅度明确，但测试属于刻意设计的 sibling-table 场景，真实企业表格的 schema、权限和跨表连接更加复杂。

AAR 的大幅提升也不能证明模型已经理解表格逻辑。它可能只学会了识别 benchmark 中的答案充分性线索。

6. FlowBlock：利用扩散语言模型的自纠错能力并行解码多个块

发生了什么

传统 block-wise diffusion LLM 需要先完成前一个块，才能处理下一个块。FlowBlock 发现，自纠错扩散模型可以修复基于稍旧上游上下文生成的草稿，因此允许多个块进入有限的 wavefront 并行更新。

其主要机制包括：

  • readiness gate 控制新块何时进入并行窗口；
  • 多个活动块一起进行 token-to-token 编辑；
  • 块仍按原始顺序提交，保留冻结前缀的 KV cache；
  • 不同请求拥有独立 wavefront，再被打包成形状稳定的批处理。

论文报告，相对 LLaDA-2.1 和 LLaDA-2.0，吞吐最高提升 2.95 倍和 4.01 倍，延迟最高下降53.6%和77.1%，平均准确率还提高了1.3分。

为什么重要

这说明扩散语言模型的“可修改已生成 token”能力，可能同时用于质量修复和调度并行。它绕开了严格的自回归依赖链，为 dLLM 服务系统提供了新的并行轴。

可信度与局限

可信度：中等。结果幅度很大，且方法无需额外训练；目前仍是预印本和特定 dLLM 架构上的结果。

“最高4倍”高度依赖模型、批大小和请求分布。dLLM 自身尚未成为主流生产推理架构，FlowBlock 的现实价值取决于 LLaDA 类模型能否在质量、生态和硬件利用率上持续缩小与自回归模型的差距。

补充观察：反复修复可能让正确答案越来越差

VRR-Stop 为“验证—修复—再验证”循环建立了噪声模型，分别估计 verifier 的误接收／误拒绝，以及 repairer 的修复与破坏概率。其核心结论是：当修复的真实边际收益转负时应立即停止；若 verifier 区分能力太弱，则使用更保守、无需参数估计的 VRR-Guard。

在作者构造的 GSM8K 压力测试中，相对固定执行5轮修复，VRR-Stop 将最终真实有效率提高60.6个百分点，平均只执行0.72轮修复。该结果来自高度特定的噪声设置，幅度不能直接外推到一般 Agent。

公开 X 索引无法给出完整、可靠的全站热度排序。以下按发布时间可见性、技术密度和与原论文的一致性筛选。

1. Decoding collapse 开始进入 Agent 训练讨论

Sumit 的论文摘要线程重点传播了一个容易被常规指标漏掉的失败模式：搜索轨迹文本看似多样，行为模板却几乎不依赖输入问题；EMA Teacher 可以缓解监督不稳定。该讨论与原论文结论一致。

2. “Traces + Evals”与渐进式披露

Vtrivedy 的讨论将 Agent 改进归结为执行轨迹、评测与上下文工程，并提到 Skills 自带的渐进式披露能力。今天的新论文给出了重要修正：渐进式披露在大语料中有价值，但强 Harness 下可能冗余，目录层级也不宜无限加深。

3. Lean 让模型推理中的隐含假设显式化

John Ennis 发布的长文《My Experiences Using AI for Math》讨论了使用 Lean 时，形式化过程如何暴露自然语言数学推理中的隐藏假设。文章约在近24小时内发布，属于实践经验，缺少受控实验；它与 verifier-grounded self-evolution 的研究方向形成了较好的互补阅读。

今日最值得花30分钟阅读的一项

《Is Progressive Disclosure All You Need for Long-Context Agents?》

建议阅读顺序：

  • 5分钟：明确 raw context、raw navigation、Skill pack 和 hybrid retrieval 的区别；
  • 10分钟：比较三个 Harness，观察收益为什么随 Harness 能力变化；
  • 10分钟：看单本书与多本书结果，以及第二层路由为何失效；
  • 5分钟：把“Skill 增量”与“底层 Harness 增量”分开思考。

配套可查看 Skill Seekers：它能将文档、GitHub 仓库和 PDF 等来源转换为结构化 Skill 或 RAG 资产，并支持多种 Agent 平台。仓库功能较完整，但 README 中的效率和质量宣传属于项目方自报，使用时仍需自行评测。

今日可立即实践的一件事

对同一份长文档知识库执行一个 三臂 Agent Context 实验：

A：原始文档导航

仅提供文件路径和基本读取工具，让 Agent 自行搜索、打开和定位内容。

B：一层渐进式披露

创建一个简短索引，每个条目包含：

  • 文件名；
  • 50—100字用途描述；
  • 主要主题；
  • 原始文件路径。

不再增加二级路由。

C：混合检索

使用 BM25 加 embedding 检索 Top-K chunk，再交给同一模型回答。

使用30—50个真实问题比较：

  • 最终准确率；
  • 引用正确率；
  • 输入 token；
  • 文件打开次数；
  • 无效读取比例；
  • P50／P95 延迟；
  • 每道题成本。

最关键的判断标准：

B 相对 A 的收益有多大，以及 B 相对 C 是否提供了独立价值。

若强 Harness 下 A 已经接近 B，继续批量制作 Skill 的投资回报可能很低；若语料扩展后 A 明显崩溃，一层渐进式披露才值得进入正式链路。
