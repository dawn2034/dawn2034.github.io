今日主线： Agentic RL 单轨迹价值学习 · 状态型长期记忆 · Tool/Skill KV 复用 · AI4AI 自我改进评测 · Sequential RecSys Benchmark 审计 · 可验证机制解释

今日核心判断

  1. Agentic RL 正在重新吸收 actor–critic 的价值学习，但试图去掉独立 critic 与多 rollout 的成本。 SAPO 用一个自回归 backbone 同时承载 policy、state value 与 action value，并把 temporal credit 做到 turn 级；它解决的是“单轨迹也能学 value”的效率问题，不等于已经解决 token-level credit assignment。
  2. Agent Memory 的核心对象不应只是“相关历史”，而应包括“当前仍然有效的状态”。 StateMemBench 表明，当事实、规则和派生量跨 session 被修改时，常见 retrieval / memory 系统容易把已经失效的旧值重新带回答案。
  3. Tool/Skill context 的推理成本正在从 prompt token 问题变成可复用资源状态问题。 ReCache 先让每个 tool/skill schema 的 KV 与资源顺序、组合解耦，再做结构与字段级压缩；这比“每次检索后重新 prefill 全部 schema”更接近长期 Agent serving 的真实瓶颈。
  4. 当前 AI Agent 距离“自动设计更好的训练算法”仍很远。 AI4AI-Bench 的强结果不是证明 RSI 已经接近，而是恰好相反：大多数 Agent 优先调预算、checkpoint 和超参，真正修改 objective / update rule / supervision 的尝试仍是少数。
  5. Sequential Recommendation 的很多常用 benchmark 可能没有真正测到高阶序列建模能力。 在 5 个经典数据集中的 4 个，只有 pairwise transition、没有高阶交互的 capacity probe 就能追平或超过 Transformer baseline。
  6. Mechanistic interpretability 的“看起来解释得通”不等于产生了额外因果证据。 Anthropic 的 CHIVE 用真实 counterfactual intervention 作为可检验标签；在其当前代理任务上，三类 activation-reading 工具都没有超过只读 transcript 的基线。

1. SAPO：一个 Backbone 同时做 Policy、V 与 Q，单 Rollout 做 Agentic RL

一句话结论： SAPO 的关键不是“又一个 GRPO 变体”，而是把 critic 的 value generalization 和 temporal credit 重新带回 Agent RL，同时避免复制一整套 critic 模型和 group sampling。

论文： SAPO: Single-Rollout Autoregressive Policy Optimization for Agentic Reinforcement Learning

发生了什么

当前很多 Agentic RL 方法选择 critic-free、group-relative 路线：同一 prompt 采多条 trajectory，用组内 reward 差异估 advantage。这样省掉 critic，却带来两个结构性代价：需要多 rollout；当组内结果高度一致时，advantage 容易退化；同时缺少显式 value function 去跨状态泛化。

SAPO 反过来保留 actor–critic 思路，但不再维护独立 critic。它利用自回归模型的 causal boundary，在同一个 backbone 中读取 policy、state value 和 action value；policy 仍生成普通 action token，V/Q 则通过保留的 readout token 在不同条件边界上读取。训练同时包含 PPO-style policy objective、value regression 和 on-policy SARSA-style Q target。

它的 temporal credit 以 turn 为单位，通过 trajectory-level GAE 和 batch normalization 估计每一步交互的 advantage。要注意一个边界：SAPO 把 credit 从“整条 trajectory 一个值”细化到了 turn，但一个 turn 内的 token 仍共享该 turn 的 advantage；因此它并没有自动解决前几天 SkillGate / action-local credit 暴露的“少量关键 token 被长文本稀释”问题。

为什么重要

SAPO 说明“critic-free”并不是 Agent RL 唯一的低成本方向。对长程环境，显式 V/Q 的优势在于可以把不同 state 的价值结构学进模型，而不是每次都依赖同 prompt 的多样本比较。

更值得关注的工程问题是：单 rollout 省下的采样预算，能否换成更多不同任务、更多 environment coverage 或更长 horizon。 如果答案是肯定的，它的收益可能不只体现在单 iteration 加速，还会改变固定 GPU-hour 下的数据覆盖率。这是基于论文设计得到的推论，论文当前没有直接验证这一预算再分配收益。

可信度与局限

这是刚发布的预印本，验证环境只有 ALFWorld 与 WebShop，模型规模也停留在 1.5B/7B。value、Q 与 policy 共用 backbone 虽然省内存，但也可能产生表示竞争；当前实验不足以证明这种共享在更复杂 Coding/Web Agent、长 context 或超大模型上仍稳定。

另外，2026 年已经存在另一篇同样缩写为 SAPO 的 Search Agent Policy Optimization。工程实现和文献检索时必须按全名区分，避免把两套算法混在一起。

最值得继续追踪

重点看三件事：更长 horizon 下 V/Q 是否真的改善 early credit；single-rollout 方差是否需要更强 baseline / replay；以及 turn-level advantage 与 action-local / token-local credit 能否组合，而不是互相替代。

2. StateMem：长期记忆真正难的是“旧事实什么时候失效”

一句话结论： Retrieval 能找到历史不等于 Memory 知道世界当前是什么状态；对长期 Agent，supersession、standing rule 和派生值重算应成为显式状态操作。

论文： Can Agent Memory Systems Track Evolving State?

发生了什么

StateMemBench 专门把“回忆过去”与“维护当前状态”拆开。它包含 234 个 multi-session scenario，让同一事实、规则、排序、预算或派生量在后续对话中被修改；closed-pool grader 区分模型输出的是当前值、已经被 supersede 的旧值，还是其他错误。

StateMem 不把所有历史事实平铺存储，而显式表示状态替换与依赖关系。其核心规则包括：后来的显式更新可以 supersede 旧值；standing rule 与单次实例要分层；派生量在上游变化后需要 recompute；只有明确失效、覆盖或到期的状态才退休。

论文还给出一个 StateMemWrapper：不替换现有 memory backend，只在答案阶段增加一次 state treatment。它在六种 memory/retrieval backend 上把 current-state accuracy 提高 32–67 个百分点；length/cost matched control 仍有 15–32 个点可以归因于 state structure，而不是单纯多塞上下文。

可信度与局限

StateMemBench 是作者专门为这类错误设计的 benchmark，方法与 benchmark 的 policy family 有一定同源性；作者自己把部分结果视为上界式诊断。更重要的是，“single-call wrapper”不代表成本很低：它仍读取完整 transcript，StateMemBench 的 median input 约 8.6k tokens，LongMemEval 约 87k tokens。

因此它目前更像证明 state structure 是真实缺失项，还没有证明这种结构能以最低成本部署到所有长期 Agent。

最值得继续追踪

值得看增量式 State Store：能否在每轮只更新受影响的实体与依赖，而不是答案时重新读取完整 transcript；以及如何防止 dependency graph 过度传播，把“该更新的状态”变成“全局错误重写”。

3. ReCache：Tool / Skill Schema 先独立缓存，再按层、Head 与字段压缩

一句话结论： 对动态 Tool Agent，缓存失败往往不是“资源没重复”，而是相同 schema 每次出现的组合和顺序不同；ReCache 通过让资源 KV 对组合不敏感，把这类重复真正变成可复用 cache。

论文： ReCache: Efficient KV Cache Reuse and Compression for Tool-Augmented LLM Agents
代码： EIT-NLP/ReCache

发生了什么

普通 prefix cache 只有在前缀完全相同或高度稳定时才好用。Tool/Skill Agent 的情况更麻烦：同一个 API schema 今天可能和 A/B 一起出现，明天与 C/D 一起出现，而且工具顺序、retrieval set 会改变，导致相同资源被反复 prefill。

ReCache 的第一步不是压缩，而是 resource-wise attention：去掉不同资源 schema 之间的 cross-resource attention，并为每个资源重置局部 position，使同一 tool/skill 的 KV block 与其他资源的组合和顺序解耦。这样每个资源可以预编码一次，后续任意组合复用。

随后它做两层压缩：structural pruning 只让贡献较大的 layer–KV-head-group 访问这些资源；semantic pruning 则只保留调用真正需要的字段和 token。

为什么重要

Agent 系统越来越依赖大规模工具注册表、MCP server、Skill catalog。一个常见但昂贵的架构是：

如果工具 schema 更新频率远低于调用频率，这种“资源状态缓存”会比纯 prompt-cache 更自然。它也和 context engineering 的 deferred tool discovery 并不冲突：前者减少暴露资源数，后者降低已暴露资源的重复编码成本。

可信度与局限

结果主要来自 Qwen3 backbone，端到端实验以 Qwen3-4B 为主；resource-wise attention 改了注意力可见性，需要推理引擎配合，而不是一个完全透明的 cache policy。OOD 结果也明显低于 IND：虽然相对 Dense 保留 91.8%，绝对 Inv-F1 仍只有 60.8。

因此最强结论应是“资源级复用在这类 Tool/Skill workload 上有明显潜力”，而不是“任意 Agent 都能无损减 92% KV”。

最值得继续追踪

看它在真实 MCP / OpenAPI registry 上的 cache invalidation、schema versioning、并发复用和 P95 TTFT；另外需要验证 Tool schema 中跨资源依赖很强时，禁止 cross-resource attention 会不会真正伤害复杂调用规划。

4. AI4AI-Bench：今天的 Agent 更会“调训练”，还不太会“发明训练算法”

一句话结论： AI4AI-Bench 给“Recursive Self-Improvement”降了温：强 Agent 能做有用的 MLE 优化，但多数时间仍停留在 run-side engineering，而不是改变 learning rule 本身。

论文： AI4AI-Bench: Benchmarking LLM Agents in Algorithmic Design for Recursive Self-Improvement

发生了什么

AI4AI-Bench 试图把“AI 帮 AI 研究”里最容易混淆的两种能力拆开：

  • run-side optimization：改训练时长、batch、checkpoint、capacity、超参；
  • learning-side design：改 objective、supervision、update rule 或训练数据机制。

Benchmark 冻结 10 个研究代码库，覆盖 10 种 training algorithm family。每个任务给 Agent 4 小时、1 张 B300 去修改训练算法；随后把代码从头运行最多 12 小时，用对 Agent 隐藏的固定 evaluator 打分。

不同任务指标被映射到统一尺度：$0$ 是无信息模型，$0.1$ 是仓库原始算法，$1.0$ 是任务设定的 optimum。

最值得注意的不是模型排行榜，而是行为层级：更多 reasoning effort 的主要作用，是让 Agent 更愿意深入 objective / update rule / supervision，而不只是继续调外围工程；但即使最强系统平均 0.250，也只越过原始算法 0.1 一小段，离 1.0 的 task optimum 很远。

为什么重要

“AI 能改代码”与“AI 能提高产生下一代模型的学习算法”之间差着一层真正的 research taste。AI4AI-Bench 的设计至少开始要求 Agent 对训练动态做机制诊断，而不是靠扩大预算或调参获得漂亮结果。

这也给 Self-Evolving Agent 一个更严格的定义：如果所谓“自我改进”只是更多采样、更多数据或更贵训练，它提高的是当前 run 的能力；只有能够稳定改善 learning procedure 的 compute–capability exchange rate，才更接近 recursive improvement 的关键环节。

可信度与局限

Benchmark 仍然是 10 个冻结 repo，而且“任务 optimum”与归一化尺度是人为构造的评估框架，不等于真实科研价值。4 小时探索窗口也偏向能快速迭代的改动，可能低估需要更长实验链的算法研究。

另一方面，这个限制恰恰使结果更值得克制解读：当前最强 Agent 尚未在一个专门为 algorithm design 构造、反馈又相对清晰的环境里接近上限。 因此把今天的自动 MLE 直接描述成“已经进入 RSI”缺乏证据。

最值得继续追踪

关注三类变化：Agent 是否开始提出跨 repo 可迁移的 learning principle；算法修改能否在不同 seed / budget 下重复成立；以及通过经验 Memory 或 research-world-model 后，Agent 是更会“调已有算法”，还是确实更频繁地产生新 update rule。

5. Sequential RecSys Capacity Probe：很多 Benchmark 可能只需要 Pairwise Transition

一句话结论： “用了完整序列”不等于“需要高阶序列交互”；在常用小型 Amazon benchmark 上，简单 pairwise transition probe 足以解释甚至超过 Transformer 的大部分收益。

论文： Do Sequential Recommendation Benchmarks Really Require Higher-Order Sequence Modelling?
代码： spotify-research/sequential-capacity-probes
状态： RecSys 2026 接收

发生了什么

作者不是再做一个新 SOTA，而是做 capacity probe。SeqRules 与 PCTM 都会使用多次历史交互，但只聚合 item-to-item 的 pairwise transition，不包含三阶及以上的序列交互；然后在同一数据处理、full-catalogue evaluation 和冻结配置下，与 SASRec / eSASRec 比较。

这回答一个比“模型分数高不高”更基础的问题：benchmark 的预测信号到底真的要求高阶 sequence model，还是一个带 recency weighting 的 transition model 已经足够。

为什么重要

这直接影响 Sequential RecSys 论文的证据标准。如果一个新 Transformer / Generative RecSys 只在 Beauty、Sports、Toys 上超过旧 Transformer，却没有与强 transition probe 比较，那么你不能从这个结果推出“模型学到了更强的高阶用户序列结构”。

尤其值得注意：order-sensitive 与 higher-order 不是同义词。 一个只看 pairwise transition、但按 recency 加权的模型同样对顺序敏感，却没有显式建模复杂的跨步交互。

可信度与局限

论文结论非常克制：它没有说 Transformer 对 Sequential Recommendation 无用；ML-20M 正好提供反例。PCTM 自身也包含平滑、weighted log pooling 等强 inductive bias，需要进一步 ablation 才能知道具体是哪一部分产生收益。

它最强的价值是 benchmark audit：要求新模型先证明数据确实包含它声称建模的结构，再谈“高级序列能力”。

最值得继续追踪

未来 benchmark 应增加可控合成数据和真实高阶依赖诊断，例如让 pairwise transition 统计完全相同、但三阶 pattern 不同；只有在这类任务上仍有稳定增益，才能更直接证明模型学到 higher-order dependency。

6. CHIVE：Interpretability Tool 没有在可验证 Counterfactual 任务上提供额外预测力

一句话结论： Anthropic 的负结果不是“可解释性无用”，而是更窄、更严谨：在 CHIVE 这类可直接验证的自然行为上，activation-reading 工具没有比 transcript 本身提供更多可用于预测因果反事实的证据。

官方文章： Would This Change Your Answer? Evaluating Explanations of LLM Behavior in the Wild with Counterfactual Experiments
论文： CHIVE paper
代码： adamkarvonen/chive

发生了什么

CHIVE（Counterfactual Hypothesis Investigation Via Edits）不把 LLM 自己写出的“行为解释”当 ground truth。它先对每个 prompt 采样 30 个 response，筛出异常行为；investigator agent 再运行 5–15 个 prompt counterfactual，例如改变量名、删除线索、改变上下文条件；最后独立 judge 检查这些实验是否真的支持解释。

真正的标签来自干预后的实测行为变化，而不是解释文字本身。随后作者让 predictor agent 判断某个 counterfactual 是否会改变目标模型行为，并比较三类 activation-reading 工具：activation oracle、natural-language autoencoder、sparse autoencoder。

关键结果

主实验中，没有任何一类工具超过 transcript-only baseline。这个结果跨两个 target model、三个 predictor family、多组超参，以及人工 / 自动 tool-use prompting 都保持。

作者进一步检查失败原因：工具输出经常能读出“某个 feature”和“某个行为”都存在，但很少直接提供二者之间的 causal relation；大量额外输出有时反而会误导 predictor。

另一方面，CHIVE 数据作为训练集却有正结果。作者训练 Qwen3-8B 和 Qwen3.5-397B-A17B 去预测 counterfactual prompt 的行为变化，在 held-out investigation、OOD transcript source，以及训练中没有包含的 hint-setting 上都观察到明显泛化改善。

为什么重要

很多 mechanistic interpretability case study 的证据链是：

1
2
3

activation feature 看起来与行为相关
→ 给 feature 一个自然语言解释
→ 推断模型“因为这个内部概念”做了行为

CHIVE 强迫这条链面对一个更硬的问题：如果解释真抓住了因果机制，它是否能帮助我们预测一个相关干预会不会改变行为？

在当前实验里答案是否定的。这意味着 activation readout 更适合被描述成“相关内部证据 / hypothesis generator”，而不是直接升级为因果解释。

可信度与局限

Anthropic 自己强调这只是 proxy。CHIVE 行为多数比 system card 中的 deception、evaluation awareness 等案例简单，而且 counterfactual 的 ground truth 可以通过直接重跑模型获得；现实安全调查往往恰恰没有这种便宜标签。

所以不能从结果推出“SAE / activation oracle 对高级安全审计无价值”。更准确的结论是：当前工具至少还没有在一个相对简单、可检验的因果预测基准上证明增量价值。

最值得继续追踪

看 interpretability 工具从“读取相关 feature”转向真正 interventional：直接修改 activation、构造更干净的 causal intervention，并明确报告相对于 transcript-only / behavior-only baseline 的增量证据，而不是只展示一个看起来合理的 feature label。

今日值得收藏的代码 / 学习资源

  • EIT-NLP/ReCache：如果在做 Tool Agent serving，最值得看 resource-wise attention、结构剪枝预算和 field-aware pruning 的实现，而不是只看论文的 92.43% KV 数字。
  • spotify-research/sequential-capacity-probes：仓库公开数据重建、hash 校验、eSASRec 固定版本和 Table 1 复现命令，很适合直接拿来给自己的 Sequential RecSys benchmark 加“能力下界”。
  • adamkarvonen/chive：适合学习如何把开放式“为什么模型会这样”转换成可实测的 counterfactual prediction task。
  • EnvHarness: Awakening Static Worlds for Agent Learning：把静态环境外包一层可编程 wrapper，EnvRigger 根据 policy weakness 自动生成并验证环境组件；作者在 5 个 benchmark / 4 个 domain 上报告 held-out 最高 +9.0 个点、execution steps -9.8%。它值得作为“policy 与 environment co-evolution”方向继续跟踪，但目前仍缺更广泛独立复现。
  • Phantom Gains: Auditing Self-Improvement Against a Measured Null：今天另一篇非常重要的 self-improvement 评测论文。它显示单次 greedy decode、batching 和 transition statistic 可以让完全没训练的 frozen control看起来也发生“能力获得/遗忘”；以后做 self-training / self-evolution，null control 应当成为默认实验组。

X.com｜近期高信号技术讨论

本轮独立于论文筛选，完成了过去 24 小时优先、48 小时召回的四路检索：Broad Topic Search；OpenAI、Anthropic、Google DeepMind、Meta、Microsoft Research、NVIDIA、Hugging Face、DeepSeek、Qwen、Moonshot、智谱、ByteDance/Seed、xAI 等研究者 / 机构方向；围绕 SAPO、StateMem、ReCache、AI4AI-Bench、CHIVE 和 Sequential Capacity Probes 的 event-driven 搜索；以及中英文双语检索。

没有发现同时满足“原始 X.com URL、作者身份、真实发布时间、可核验技术正文”四项硬条件，并且技术增量足够高的 24–48 小时帖子。 搜索引擎返回的结果主要是旧帖、X 官方历史文章或无法确认原帖正文 / 时间的索引片段，因此没有为了凑 3–5 条而降低准入标准。

公共 Web Search 对 X.com 的实时索引覆盖有限，因此这表示本轮无法高置信核验，不代表 X.com 当天不存在相关热门讨论。

今日最值得花 30 分钟阅读的一项

首选：AI4AI-Bench。

建议不要先看模型排行榜，而按这条线读：

  1. 先理解它如何把 “run-side change” 与 “learning-side change” 分开；
  2. 再看统一的 $0 / 0.1 / 1.0$ 归一化尺度，否则很容易误读各任务原始指标；
  3. 看 263 个真正做出代码修改的 submission 到底改了什么——尤其是 141 个只动运行侧、122 个触及 learning procedure；
  4. 看 reasoning effort 从低到高时，为什么“敢动算法”的比例从 8% 升到 64%，而最终分数仍离 optimum 很远；
  5. 最后再思考：你想做的 “AI Research Agent” 到底是在自动化 MLE，还是已经能产生可迁移的新学习机制。

这篇最值得带走的不是“某模型是第一”，而是一个更严格的研究问题：

如果 Agent 只能把已有训练 recipe 调得更顺，却很少改变模型学习的机制，我们应该把它叫 autoresearch，还是更准确地叫 automated MLE？

当前证据更支持后者。

其中最关键的是：

\[\mathrm{StaleAnswerRate} = \frac{\#\text{回答采用已被 supersede 的旧状态}} {\#\text{state-update probes}}\]

停止条件：如果普通 QA / retrieval accuracy 很高，但 stale_answer_rate 仍超过 10%，先不要继续调 embedding、top-k 或 reranker；优先给 Memory 增加 active / superseded / expires_at / depends_on 这类显式状态字段，再重新跑相同 probe。若错误主要是 off-pool、而不是旧状态回流，则说明瓶颈更可能在 answerer / retrieval coverage，不应误诊成 supersession 问题。

这个实验的价值是把“Memory 找到相关历史了吗”与“Agent 知道当前世界状态吗”拆成两个指标；StateMemBench 今天最重要的贡献正是这个拆分。
