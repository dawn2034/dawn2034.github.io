## 1. vLLM 双向 KV Transfer：多轮 Agent 为什么还在反复 Prefill？

[10 月 12 日 vLLM 官方文章及复现说明](https://vllm.ai/blog/2026-10-12-bidirectional-kvxfer-multiturn-agentic-workload)

### 发生了什么

传统 Prefill/Decode（P/D）分离一般只将 KV 从 Prefill 节点发送给 Decode 节点。Agent 返回下一轮时，Prefill 侧未必持有上一轮 Decode 新生成 Token 的 KV，可能重复处理不断增长的会话历史。vLLM 新方案让 Decode 暂时保留 KV，下一轮 Prefill 通过 NIXL **反向读取**。带会话标识的 Router 维护 Block 位置元数据，张量仍由节点传输。

### 关键结果

作者在 AWS P5en、H200/EFA 的 1 Prefill + 1 Decode 环境下报告：Qwen3-32B 在最长测试 Prompt 的 TTFT 从 **778ms 降至 460ms**；GLM-5-FP8 从 **2,334ms 降至 702ms**。示例保留 TTL 为 480 秒，远程读取阈值为 64 Token；更短前缀可能重算更便宜。

### 为什么重要

Coding、Research 和 Shopping Agent 每轮携带很长的历史。跨轮重复 Prefill 往往比单次 Token/s Benchmark 更能解释交互延迟。一个部署决策可写成：

$$
\text{Reuse KV if } C_{\mathrm{transfer}}(n)+C_{\mathrm{coordination}} < C_{\mathrm{recompute}}(n).
$$

### 可信度与局限

作者**主动关闭 Prefill 端 Prefix Caching**以模拟缓存驱逐或路由切换，因此测到的是特定 Cache Miss 场景的收益。实现还依赖 KV Metadata 的流式传递、足够的网络带宽和合理的生命周期。不能把 3.3× TTFT 改善换算成所有请求的总体吞吐提升。

### 最值得继续追踪

在真实 Agent Trace 上，按会话轮数、Prefix 长度、轮间隔与缓存命中率分桶，比较普通 P/D、双向 KV 和共享 Prefix Cache 的 TTFT P50/P95、GPU 显存驻留和每次成功任务成本。

## 2. MagicBeanStalk：为什么大部分 RLVR 题目产生不了组内 Advantage？

[原始论文](https://arxiv.org/abs/2610.12659)

### 发生了什么

作者在固定 Policy 与 Rollout Budget 下检查数学 RLVR 题库，约 **88%** 题目在组内呈现全正确或全错误，因而没有组内奖励差异。仅保留现成的“中等难度”题会丢掉困难技能。MagicBeanStalk 将困难种子题拆成推理组件，再递归组合成对当前模型更可学习的新题。

### 关键结果

八个数学 Benchmark、16K 输出预算下，论文报告 gpt-oss-120b 从 **61.2 升至 69.8（+8.6pp）**，DeepSeek v4Flash 从 **72.4 升至 77.9（+5.4pp）**。作者所用的完整 78K 题训练仅改善 1.1pp，最佳过滤子集改善 5.8pp；另报告从 340 条金融问题解答合成超过 14K 个可验证问题。

### 为什么重要

在二值 Reward、同题独立采样的简化情况下：

$$
p_i=\Pr(r=1\mid x_i,\pi,B),\qquad V_i=p_i(1-p_i).
$$

当 $p_i$ 接近 0 或 1，方差趋近零。数据规模增长，并不等于有效策略梯度信号同比增长。

### 可信度与局限

88% 是特定题池、模型和采样配置的观察，训练后应重新估计。合成题可能泄露原题结构、压窄分布或利用不可靠的 Verifier。两种大模型实验的资源成本较高；尚不能推论长期开放式自我改进。

### 最值得继续追踪

按 Policy Snapshot 重新测量题目成功率，把静态过滤、失败驱动合成和递归组合放在同样 **OOD 成功率 / 有效 Rollout Token** 预算下比较，并审计同构题重合。

## 3. EWM：推荐系统的远期奖励该归给哪个旧动作？

[原始论文：Explanatory World Models for Credit Assignment](https://arxiv.org/abs/2610.13504)

### 发生了什么

生成式推荐中，一次曝光或选择的影响可能隔很久才体现为后续行为。常规折扣回报主要沿时间传递奖励，可能遗漏真正相关的动作。EWM 借助语言模型解释当前结果与历史决策的联系，定位候选前因，按分层规则重分配 Reward，同时保持 Episode 的**未折扣总回报不变**。

### 关键结果

论文报告在 Crafter、WordCraft、KuaiRand 顺序推荐数据和一个工业级生成式推荐器上取得积极结果；所列基线包括 PPO、LaRe、SFT 和 A2C。工业模型涉及离线 Recall 和行为 Proxy，但公开摘要没有可以统一引用的绝对百分点，所以不将其写成线上 CTR 或 GMV 增益。

### 为什么重要

“时间接近”与“行为相关”是不同信号。曝光、加购、后续搜索、留存存在长距离链条；结构化解释可能帮助从众多中间步骤筛出少量关键决策。

### 可信度与局限

模型的解释可能只是事后叙事；总奖励守恒无法证明归因的因果正确性。离线回放、语言推断与真正随机化干预间仍有明显证据差距。

### 最值得继续追踪

构建含真实干预或随机化标签的小型归因集，比较 EWM、GAE、TD($\lambda$) 与 LaRe，报告归因偏差、Off-policy 风险和安全约束违反率。

## 4. ReplaySSM：存近期输入，少读写循环状态

[原始论文](https://arxiv.org/abs/2610.13778) · [作者代码](https://github.com/Johnny-Liou/ReplaySSM)

### 发生了什么

Mamba-2、Gated DeltaNet 等状态空间模块在 Decode 每步读写较大的状态。ReplaySSM 把状态表示为“较早的 Checkpoint + 最近输入缓冲”，通过短窗口重放而不必每一步回写完整状态。推测解码失败时可调整缓冲指针回滚，并使低精度输出与高精度状态更新解耦。

### 关键结果

作者在 vLLM 的四类 Hybrid Model、Batch 256 上报告相对调优后的基线，标准 Decode 加速 **1.20—1.47×**；两个 120B 级模型的推测解码吞吐约为对照的 **1.8×**。

### 为什么重要

混合 Attention/SSM 结构下，瓶颈可能从 Attention KV 转向 SSM State I/O。Replay 将部分带宽需求替换为局部计算，同时影响精度与 Speculative Rollback 的实现方式。

### 可信度与局限

重放引入额外 FLOPs，收益受模型、Batch、状态大小、Checkpoint 间隔和内存带宽影响，不能直接迁移到单卡 16GB GPU。

### 最值得继续追踪

扫描 Checkpoint 间隔，联合测量 State Bytes/token、回放 FLOPs、Speculative Acceptance、TTFT/TPOT 与结果一致性，检查并发会话的 Buffer 隔离。

## 5. RATED：工具检索要把“它是否能用”纳入排序

[原始论文（CIKM 2026）](https://arxiv.org/abs/2610.13889) · [EcoAgent 代码与数据](https://github.com/Elliotes/EcoAgent)

### 发生了什么

静态 Tool Retriever 根据工具描述做语义匹配，但无法及时应对超时、限流或服务故障。RATED 在 Dual-encoder 检索后加入 Contextual Bandit Reranker，根据执行反馈调整候选位置，无须每次故障后重新训练整个 Embedding Model。

### 关键结果

EcoAgent 提供 **5,172 个工具、超过 210,000 条 Query–Tool Pair**。论文报告相对 ToolLLM API Retriever 的 MRR **相对提高 52.2%**；模拟 30% API Failure 时，故障工具选择率由 **86.2% 降到 2.9%**，额外排序延迟小于 1ms。

### 为什么重要

Agent 最优工具集合随时间变化。语义相关、预计成功率、延迟与成本应在同一执行上下文中综合决策，尤其对于多工具冗余和服务降级。

### 可信度与局限

严重故障仿真不必然匹配线上故障模式。Bandit 还存在稀疏反馈、曝光偏置、延迟奖励及冷启动问题，短期失败也不应造成永久降权。

### 最值得继续追踪

把指标从 Recall@k 改为**可成功执行的 Top-k**、Task Success 与故障恢复时间。用真实故障窗口重放比较 Bandit、滚动成功率、规则熔断和固定语义排序。

## 6. BSR：测试结果相同时，怎样比较 SWE Agent 的行为质量？

[原始论文：Behavioral Self-Rewarding](https://arxiv.org/abs/2610.12598)

### 发生了什么

SWE Agent 的 Verifiable Reward 通常来自测试是否通过，可靠但粗糙；多条同为失败的轨迹没有区别。BSR 用当前 Policy 对同题、相同 Verifier 结果的 Debugging 轨迹做成对比较，汇总为 Task-local Score，再产生有界辅助 Reward，并**保证辅助奖励不颠倒测试定义的 Pass/Fail 优先级**。

### 关键结果

论文在 SWE-bench Verified / SWE-bench-Live、Qwen3-14B/32B 上报告持续改善；摘要未给出可以跨设置统一引用的绝对数值，所以不编造“平均提升”。

### 为什么重要

两个失败 Rollout 可能截然不同：一个定位到真正故障根因，一个重复无效搜索与盲目改文件。对已有轨迹进行受约束的行为对比，可以在不增加真实工具执行的情况下提供部分训练信号。

### 可信度与局限

Self-Judge 可能偏爱语言风格、长推理或表面合理的操作。即使奖励有界，仍可能诱导模型学习某种评分偏好。需要独立行为标注与真实任务成功率共同检验。

### 最值得继续追踪

和 Outcome-only GRPO、Process Reward、Independent Judge 进行对照，记录 Test Pass、无效修改、重复 Tool Call、Token 成本和 Reward Hacking 案例。

## 7. DualQuant：免校准数据的 W4A4 权重—激活联合量化

[原始论文](https://arxiv.org/abs/2610.13767)

### 发生了什么

真正的 W4A4 推理要同时降低权重与激活的位宽，而激活通常依赖校准数据。DualQuant 通过权重重建误差求解缩放因子，同时导出对激活量化友好的逐通道重标定；优化算法采用变量分裂与 Block Coordinate Descent，适用于多种 MX / NVFP4 格式。

### 关键结果

Llama/Qwen 在 WikiText-2、C4 与零样本任务中的结果多数达到或超过作者选用的 SmoothQuant 设置。RTX 4090 上 Llama-3.1-8B 的真实 Packed W4A4 推理最高报告较 BF16 **显存减少 2.61×、吞吐提高 2.46×**。

### 为什么重要

Weight-only INT4 不一定能充分调用原生低比特计算单元。W4A4 能改变吞吐与成本曲线；免额外校准数据对频繁部署新模型尤其便利。

### 可信度与局限

“免校准数据”不等于任何输入都无质量损失。最高性能与特定 Kernel、Batch、RTX 4090 有关，也未证明长程工具调用或代码生成质量完全保留。

### 最值得继续追踪

在一致质量门槛、Kernel 与 Batch 下，对照 DualQuant、SmoothQuant、AWQ/GPTQ 和 FP8 的 P95 Latency、显存、Coding Agent 成功率和极端激活误差。

## 8. Token-level Memory Retrieval：单向量表示遗漏了哪些关键证据？

[原始论文：Beyond the Final Embedding](https://arxiv.org/abs/2610.13277)

### 发生了什么

一条 Memory 可能同时包含背景、日期、约束、例外等多个事实。单一 Embedding 容易因主题相似而掩盖一个短小但关键的片段。新方法直接利用 Encoder 内部的 Token Representation，让 Query Token 检索匹配的 Memory Token，再聚合为 Memory 级得分。Query Adapter 可在冻结文档表示的情况下训练。

### 关键结果

作者在八个 Benchmark、多类 Encoder 上报告改善；Qwen3-Embedding-4B 加 Query Adapter 时，平均 Recall@10 **+13.3 个百分点**、NDCG@10 **+14.3 个百分点**，并改善长期记忆问答的证据检索。

### 为什么重要

长期 Agent 常要找“某次讨论中已经确认的具体限制”，这与检索相似主题不同。Token-level Evidence 有机会降低重要短证据被大片背景淹没的概率。

### 可信度与局限

Token 级索引增加存储、更新和随机 Lookup 的成本；主要增益配置包含额外 Query Adapter 训练。检索排名改善也不必然成为更高的最终 Agent Task Success。

### 最值得继续追踪

固定 Index Size 与 Latency，对比 Dense Single-vector、Late Interaction、Hybrid BM25+Dense 和 Token-level 方案，特别观察带时间、否定和版本约束的证据召回。

**[CLEAT：何时向用户澄清？](https://arxiv.org/abs/2610.12655)。** 通过对照 Rollout 估计 Clarification 的收益并与策略协同训练。能迁移至购物 Agent，但必须显式加入打扰成本和任务价值。

## 今日可立即实践的一件事

对现有 Agent Rollout 做一次 **Effective Advantage Audit**。选择 100—300 个代表性 Task，在同一 Policy、相同采样温度和 Tool Budget 下，各生成 4—8 个 Rollout。使用一致且可信的 Verifier，估计任务成功率 $p_i$ 和组内差异 $p_i(1-p_i)$，将任务分成「全成功」「全失败」「有成功也有失败」三类，分别统计比例、Token 与费用。

再从全失败但仍可验证的任务中抽样，标记任务定义模糊、工具失败、预算不足和真实推理难题；只针对最后一类尝试拆成子问题并重新组合为中等难度的新题。让冻结的 Policy 重新评估合成题是否产生非零组内差异，只有在独立 Held-out Task 上能稳定改善，才纳入训练。

> 核心问题：今天消耗的 Rollout Compute，有多少产生了真正可学习的策略差异，又有多少耗费在零 Advantage 与重复轨迹上？
