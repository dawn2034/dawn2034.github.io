## 1. vLLM vs DeepInfer：模型特化引擎与通用引擎的工程差距正在缩小

**原始来源：** [vLLM 官方技术复盘（2026-10-23）](https://vllm.ai/blog/2026-10-23-deepseek-v41-flash-pd-wide-ep) · [DeepSeek 官方 DeepInfer 仓库（2026-10-20）](https://github.com/deepseek-ai/DeepInfer) · [vLLM 对应原帖](https://x.com/vllm_project/status/2114054277379641770)。

### 发生了什么

DeepSeek 开源了内部服务用的 DeepInfer 推理框架，但第一版主要提供 **DeepSeek-V4.1-Flash 离线推理**：包含 DeepSelect、DSpark 验证调度、SWA 有界回放、MoE EP/EPLB 和结构化输出。**KV Cache 系统、完整 P/D 解耦服务编排和跨副本负载均衡仍未开源。** 支持设备限定为 NVIDIA SM100 与 Ascend 950，不能拿这套仓库直接在普通消费级 16GB 显卡部署 700B 级模型。

vLLM 随后公布将 DeepSeek Kernel 融入通用 Serving 栈的系统测量：P/D 分离、DEP2 Prefill、Wide-EP Decode 和动态 EPLB。作者在 GB300 NVL72 上报告 AgentX **954K aggregate tokens/s/GPU**，P90 用户速率约 196 tokens/s，单用户专用 Decode 路径约 826 tokens/s。Decode 相对 DeepInfer 官方曲线**差距在 6% 以内**；新 Prefill 优化在 128K 缓存前缀场景的 4K—64K 新 Token 范围内提升 **35.6%—43.9%**。

### 为什么重要

这里最有价值的细节是**瓶颈转移**：V4.1 Flash 的长上下文 KV 约 890 bytes/token，128K 上下文 Decode 里 MoE 计算可占主要时间，而索引与 Attention 不是首要瓶颈；因此应按模型结构分别优化 Prefill、专家负载均衡与 CPU Batch Scheduler。对多轮 Agent，要比较缓存命中之后的 TTFT、P95、成功任务吞吐，而不是只看裸 Decode TPS。

### 可信度与局限

vLLM 的性能来自项目自己的测量，使用 GB200/GB300，不是与 DeepInfer 完全相同的硬件、配置和输入。Prefill 曲线取自不同实验，作者明确**不把两者间的差距视作引擎优劣的因果加速**；`954K` 统计包含缓存和非缓存输入 Token 及输出 Token，不能解读成“每张卡每秒生成 95.4 万输出 Token”。

### 最值得继续追踪

针对同一个模型快照，在可获得相同设备时比较 TTFT、ITL、单用户/总体吞吐、KV 占用、prefix hit、AgentX 任务执行成本，并审查 Wide-EP 的热点专家漂移。尤其观察开源的 DeepInfer 是否补齐完整线上 KV/P/D 服务层。

## 2. Anthropic：什么时候该把 Subagent 折叠回一个 Loop？

**原始来源：** [Anthropic 10 月 22 日技术文章](https://claude.com/en/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop) · [single-agent-loop-kit 官方仓库](https://github.com/anthropics/single-agent-loop-kit)。

### 发生了什么

Anthropic Applied AI 团队建议重新评估“一个 Router + 大量垂直子 Agent”的结构。将主 Agent 保持为单一循环，按需披露 Skill 文档、按需搜索 Tool Schema，能够减少上下文交接时的摘要损耗、额外模型往返和组织结构映射到 Agent 结构的问题。官方公开了含六子 Agent 的客服样例及 `coupling_map.py`、`compare.py` 等诊断脚本。

### 关键证据及为什么重要

官方援引某客户单 Agent Loop 约快 **2 倍**的个案，同时提到渐进披露帮助 Claude Code 的 System Prompt 缩减超过 80%。但官方也记录了明确反例：折叠客服子 Agent 后，主 Agent 跳过了原来的发货日期查询。**评估要看失败任务翻转（task flips）及流程不变量，不能只看平均分与速度。**

### 可信度与局限

公司实践报告与开源样例可核验，但客户结果没有公开统一任务集；Kit README 明确定位为参考实现，**不维护、不接受贡献，实模型演示范围有限**。独立并行搜索、权限隔离、黑盒验证任务仍可能需要子 Agent。更少的 Agent 不是天然更优。

### 最值得继续追踪

每次只折叠一组紧密串联的子 Agent，固定任务集、模型、Token Budget、重复次数，记录 pass@1、P95、每成功任务成本、工具越权、步骤遗漏和新旧失败集差异。

## 3. SARL：Agent 是否真正知道自己“搜到了什么、还缺什么”？

**原始来源：** [Self-Assessment Reinforcement Learning（arXiv:2610.30435，v1 10 月 21 日）](https://arxiv.org/abs/2610.30435) · [HTML 全文](https://arxiv.org/html/2610.30435v1)。

### 发生了什么

Search Agent 常在证据不足时提前停止，或已有证据却继续无效检索。SARL 通过训练时的 Self-Assessment 奖励鼓励模型识别检索状态，奖励纠正信息缺口，同时惩罚额外的评估开销；推理时不需要独立 Assessment Agent。

### 关键结果与意义

作者报告对最强基线的相对提升 **24.3%**，多跳推理和 Deep Research 各基准平均增益为 **35.9%**、**27.9%**（依论文相应比较口径）。它把“是否继续 Search”作为可学习策略，而不只优化 Query 文字。对 Agentic RAG 的直接价值是控制**搜索是否充分**和**继续搜索的边际信息收益**。

### 可信度、局限与追踪

论文为第一方实验。自评奖励依赖训练中的评估信号质量，可能学出套话；不同 Search Budget 影响比较。下一步应做固定搜索次数、固定 Token 和等总耗时对照，独立标注 Evidence Sufficiency、Early Stop Error、Unnecessary Retrieval 和最终答案引用准确率。

## 4. HERD：把 Skill 演化与参数更新组合成可持续学习循环

**原始来源：** [HERD（arXiv:2610.31401，v1 10 月 22 日）](https://arxiv.org/abs/2610.31401) · [论文 HTML](https://arxiv.org/html/2610.31401v1)。

### 发生了什么

Prompt、Skill 与 Harness 可以快速保存经验，但受到上下文和压缩限制；反复训练权重则有灾难遗忘和塑性下降。HERD 将两者串联：Harness 先更新可复用 Skill，保留不能被 Skill 解释的高残差样本；参数侧使用带 **dual anchors** 的漂移约束蒸馏，将经验内化到模型权重。

### 关键结果与意义

作者在 **TRACE+17 的 25 阶段任务流**上固定记忆及计算预算，报告新任务习得接近强参数学习基线，同时对旧任务及通用能力保留更好。这提供了一个检验长期自我进化的框架：分别追踪 Harness 贡献、权重更新贡献和遗忘，而非只公布最新总成功率。

### 可信度、局限与追踪

尚无全面生产系统复现；依赖任务序列划分与双锚超参。后续需要随机重排任务顺序、加入工具 API 版本漂移、限制外部 Skill 库大小，测 old-task retention、new-task learning、累计训练成本及故障恢复能力。

## 5. MCPD：参考答案不是唯一正确推理路径

**原始来源：** [One Teacher, Many Views（arXiv:2610.30880，v1 10 月 22 日）](https://arxiv.org/abs/2610.30880)。

### 发生了什么

常见 On-policy Self-Distillation 用带完整参考解的特权教师，为学生自己生成的轨迹提供 Token 级监督。作者发现：即便数学题、学生当前状态固定，只更换一种正确参考解，教师分布就可能显著变化。这是**reference-induced target instability**，把参考答案的表述风格、解题顺序错误地转成必须模仿的标签。

### 方法和价值

MCPD 将不同部分参考视图视为分布，在同一学生状态下评估多个教师 Token 概率，并在**概率空间求平均**；论文证明该平均对应期望 Teacher-to-Student KL 的目标。作者报告数学/科学推理比完整单参考 OPSD 更稳定。方法针对的是**监督的路径敏感性**，与前几期讨论的学生成功行为保护属于互补问题。

### 可信度、局限与追踪

多视图教师增加计算成本；错误参考或与问题不符的局部证据仍可能污染分布。值得做 Reference Swap 的固定状态审计：计算不同合法解对应的 Teacher Top-k 交并比、KL/JSD，再验证平均教师是否真改善 held-out 成功率/训练算力比。

## 6. SQuAT：低比特向量量化也需要处理方向和模长

**原始来源：** [SQuAT（arXiv:2610.31412，v1 10 月 22 日）](https://arxiv.org/abs/2610.31412)。

### 发生了什么

SQuAT 将权重向量表示成 `w = gain × direction`：方向使用源自 $E_8$ 的球面码本量化，幅值使用独立低比特量化器。与在整个向量量化器上直接用 Straight-Through Estimator 不同，它为方向和幅值设计不同的 STE，方向梯度落在球面的切空间，类似隐式黎曼优化。

### 关键结果与意义

团队在 LLaMA-3.2 1B/3B、Qwen3 1.7B/4B 上比较标准 VQ-QAT，报告相同码本和初始化条件下的质量改进；使用分布式精确最近邻码本分配，将**VQ-QAT 分配/训练相关的瓶颈环节**加速 **12.8 倍**，规模达 10B 训练 Token。这是量化训练配方层面的推进。

### 可信度、局限与追踪

不要把 12.8 倍写成部署端到端推理加速。需要在相同 bit/weight、相同推理 Kernel 和模型质量门槛下对比 FP8、int4、现有 VQ 和 SQuAT 的真实 VRAM、decode tokens/s、长上下文推理准确率；本地 16GB 显卡可先复现小模型量化误差，而非完整十亿级 QAT 训练。

## 7. MUFFIN：多 Agent 何时应该共享证据，而非互传推理全文？

**原始来源：** [MUFFIN（arXiv:2610.31355，v1 10 月 22 日）](https://arxiv.org/abs/2610.31355)。

### 发生了什么

MUFFIN 先判定任务是否需要多 Agent，然后通过共享的异步 Memory Buffer 交换可复用中间发现，各 Agent 的私有推理仍留在各自上下文，减少同步轮流辩论和全轨迹交接。

### 关键结果与意义

作者在 20 组设置中有 17 组达到最高准确率，某个与多 Agent Debate 对照下提高 **19.2 个准确率点**、Token 减少 **77.4%**。相比完全折叠到单循环，MUFFIN 在需要分工时保留并行性，同时减少交接上下文成本。

### 可信度、局限与追踪

收益依赖路由器、共享状态格式与对照基线，Memory Buffer 也可能产生污染、过期证据和竞争写入。后续应对照单 Agent+工具、固定多 Agent+摘要、共享缓冲区，在相同成功任务成本下做多轮状态一致性和来源追踪实验。

## 8. RIDAR：自治科研 Agent 应审计过程完整性

**原始来源：** [RIDAR（arXiv:2610.31372，v1 10 月 22 日）](https://arxiv.org/abs/2610.31372)。

### 发生了什么

论文将自主科研的 Research Integrity Violation 分为 **14 类**，包含数据、实验、评估和结果呈现的失真。RIDAR-post-hoc 检查历史轨迹，RIDAR-runtime 在执行中检测并修正潜在违规。

### 关键结果与意义

60 条专家标注轨迹上检测 **F1=85.2%**；在 50 项研究任务的 300 条轨迹中，检测到 **3,964** 个实例，并报告 99.7% 轨迹含至少一例。运行期模块使任务结束时残留违规事件数减少 **36.8%**。它将可复现性检查从“最终答案好看吗”延伸到“有无改测试集、误用数据、隐瞒失败”等过程事件。

### 可信度、局限与追踪

金标只有 60 条，RIV-Wild 的大规模数字主要是检测器产出，不能等同于 3,964 个都经人工确证。下一步要扩大人审、区分误报与真实违规，增加不可由 Agent 修改的日志、测试集与环境签名，并评估误拦截代价。

## 9. FlexVDR：视觉检索的计算预算可以按 Query 分配

**原始来源：** [FlexVDR（arXiv:2610.30177，v1 10 月 19 日）](https://arxiv.org/abs/2610.30177)。

### 发生了什么

视觉文档检索的多向量表示通常很贵，但不同 Query 对局部细粒度证据的需求差别大。FlexVDR 在一个模型中提供可切换的 Encoder 深度、Embedding 宽度与 Token 数路由，利用早期 Query 特征预测各路由的检索效用，再按资源偏好选配置。

### 关键结果与意义

作者在 ViDoRe V1/V2/V3 与五种 Backbone 上报告在紧凑配置下保留较多检索质量；同一个模型可按延迟/预算限制改变路径，不必部署多个互不兼容的检索器。适用于 PDF 表格、图文混排和长文档 RAG 的 Query-dependent Compute。

### 可信度、局限与追踪

论文摘要没有给统一的跨硬件节约百分比，不应虚构收益。下一步按答案类型分桶（文字、图表、跨页关联），在相同 Recall@k 下比较 P95、峰值显存、成本与最终 Answer Citation Accuracy。

## 10. AI Mindmeld：超越文本工具调用的专家模型互联

**原始来源：** [AI Mindmeld / Latent Interconnect Protocol（arXiv:2610.30215，v1 10 月 21 日）](https://arxiv.org/abs/2610.30215)。

### 发生了什么

传统 Tool Agent 把专家模型的输出转写为文字或图片，可能损失高维表征。LIP 训练轻量连接器，将冻结的蛋白、小分子等专家模型隐向量映射到主 LLM 内部状态，不需要联合重训全部模块。论文在 Gemma 3 4B/12B 和 Kimi K2.6 上测试独立训练连接器的组合。

### 为什么重要及局限

这是一条潜在的多模型能力复用路径，可能降低用自然语言反复解释大规模特征的成本。但目前主要是分子/蛋白领域演示，隐向量注入很难直接附可审计引用，**“模型拿到信息”不等于“模型理解得正确”**。追踪在未见领域和真实科学任务上的校准、信息污染及可解释证据输出。

## 今日可立即实践的一件事

**做一个“单 Agent vs 子 Agent”固定预算的成本与正确性回归。** 从已有 Agent 轨迹中抽 30—50 个任务，保留包含串联工具调用、需要多轮证据、并行独立任务、权限审批的样本。对照 A：原多 Agent；B：单 Loop + 按需加载 Skill/Tool Schema；C：单 Loop + 必要独立 Verifier。锁定底座模型、工具版本、权限和每任务 Token/时延上限，每项至少重复两次。

分层统计 `TaskSuccess`、`RequiredStepRecall`、`UnauthorizedWriteRate`、`P50/P95`、`TokensPerSuccess`、`NewFailures` 和 `RecoverableFailureRate`。特别追踪**主 Agent 因为已经持有查询工具而跳过原领域专家验证**的失败类型；如果折叠使任意高风险必经步骤漏掉，不能只凭平均延迟下降上线。没有现成可执行 Agent 环境时，可先使用 [single-agent-loop-kit 的离线 `KIT_MODEL=fake` Smoke Test](https://github.com/anthropics/single-agent-loop-kit) 验证脚本结构；离线 Fake 通过只证明管线正常，不能当作模型效果。
