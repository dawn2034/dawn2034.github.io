1. VH-GPO：全失败 GRPO 组怎样变成学生真正学得会的轨迹？

原始论文 · 含算法与消融的 HTML 全文

发生了什么

普通 GRPO 依赖同一道题不同 Rollout 的组内 Reward 差异。若一组全部失败，组内 Advantage 近乎为零。VH-GPO 为这类样本寻找学生走到过的可恢复环境状态，让冻结 Teacher 从该处尝试纠错；只保留环境 Verifier 确认成功的修复轨迹，再搜索最早可把控制权交还 Student 且 Student 能独立完成的状态。最终训练样本由学生前缀、短教师桥接、验证成功的学生后缀组成；通常不需要推理期教师。

关键结果

Qwen2.5-1.5B 在 ALFWorld 从 59.38% 升至 94.79%，WebShop 从 71.62% 升至 77.34%。7B 学生在两者分别从 78.12%→95.57%、71.61%→79.69%。作者称 7B 实验中的额外教师和学生生成 Token分别是常规学生 Rollout 生成量的 1.77% 和 2.61%；这不等于完整 GPU 运行费用仅增加相同比例。

为什么重要

它保留了学生自身状态分布这一 On-policy 优点，同时从验证成功的教师行为中提供局部纠错信号。对 SQL Tool Agent、Web Agent 和多步购物 Agent，若支持环境 Snapshot/Replay，这比直接蒸馏整条教师成功轨迹更值得试验。

可信度与局限

论文给出任务、消融和算法细节，证据质量中等（受控第一方）。收益强烈依赖可回放状态、可验证终点及教师在失败状态能否恢复；不能直接迁移到外部 API 不可逆、时间敏感或 Verifier 不可信的任务。

最值得继续追踪

固定任务、Token 和工具调用预算，比较 DAPO 过滤、纯教师后缀蒸馏、最早验证 Handoff，以及随机 Handoff；单列零 Advantage 组被挽救的比例和每个成功任务的 GPU/工具成本。

2. PreSO：On-policy 自蒸馏应该传递哪一部分“特权信息”？

原始论文 · OPSD 先前基础方法

发生了什么

On-policy Self-Distillation（OPSD）让同一模型扮演学生和带特权答案的教师，向学生 Rollout 提供 Token-level 学习信号。但教师知道完整解答时，其表征变化可能包含学生推理时永远得不到的题目特异细节。PreSO 优先提供简短 Hint，收集跨题目的隐状态差异，估计主导低秩子空间，只蒸馏投影到该子空间的特权修正。

关键结果

五项竞赛级数学测评中，Qwen3-1.7B、4B、8B 对应平均准确率相对各自 Base 提高 6.8、9.0、10.0 个百分点，作者报告训练后期 Checkpoint 仍保留收益。论文强调 Hint 诱发的表示方向更集中、更跨题一致。

为什么重要

这是一个有价值的信息瓶颈假设：越完整的教师答案未必产生越适合蒸馏的中间表征。对 Agent RL，可把 Hint 换成工具 schema、局部诊断或有限专家反馈，研究能否把“可复用纠错规律”与“当前任务答案泄漏”分开。

可信度与局限

证据质量中等偏低（作者自测、数学任务集中）。主子空间是经验代理，不能证明投影后信息全部可迁移；特定层、Rank、题目家族、Hint 编写方式可能决定收益。还应检查 pass@k 多样性和 OOD 表现，避免蒸馏使模式塌缩。

最值得继续追踪

在相同生成 Token 预算下做四组消融：无教师、完整解答条件、短 Hint、短 Hint 加低秩投影；记录训练曲线尾部、跨题方向一致性及 OOD/pass@k。

3. DoSA：稀疏 Attention 的 Indexer 也能跳过大部分计算

原始论文 · 含性能设置的 HTML 全文

发生了什么

不少 Sparse Attention 在 Top-K 访问很少 Key 时，仍由多个 Indexer Head 对所有 Key 全量打分。DoSA 给候选分数构造安全的上下界证书：若某候选理论上界已经低于当前 Top-K 下界，可直接拒绝，无须补算所有 Head。它保持既定 Indexer Top-K 选择完全相同，属于 Indexer 结果意义上的 lossless screening；并不等于任何替换 Attention 都无损。

关键结果

在 128K—约 1M 上下文的英语、中文和代码测试中，完整 Indexer 相对 SGLang 最快 2.74×，相对 LiteTopK 最快 1.69×。在约 1M Token、TP8 的 GLM-5.2 / DeepSeek-V3.2 上，TTFT 相对 SGLang 分别 1.86× / 1.94×；测试将 Prefix Cache 在请求间清空。模型采用 Top-K=2,048，且有 32/64 个 Indexer Head。

为什么重要

这项研究提醒 Serving 工程师：稀疏算子的瓶颈可能转移到“决定哪些位置值得算”的索引步骤。证书剪枝与 Kernel 融合相比，可直接减少评分 FLOPs；长上下文时 Indexer 在 Prefill 时间中的占比上升，收益才放大。

可信度与局限

证据质量中等偏高（明确硬件、基线与消融，仍为第一方）。强依赖指定架构的 Indexer 和较长 Prompt；TP8 的最高 TTFT 收益不能照搬至 RTX 4080 16GB 或普通 Full Attention Model。

最值得继续追踪

检查不同 Prompt 长度下 Indexer 占比、真实 Token 选择的一致性、Indexing FLOPs、P95 TTFT 与 Prefix 命中情况。若落地模型没有类似 Top-K Indexer，先不要投入适配 DoSA Kernel。

4. GameSmith：可验证合成环境让 Self-play RL 真正扩规模

原始论文 · 含验证协议的 HTML 全文

发生了什么

GameSmith 从三类模板生成新双人零和文字游戏。关键是把 Reward、Observation 和隐藏信息传递保留在固定模板中；LLM 只生成游戏特定逻辑，随后使用种子配对重放和独立重实现的规则验证检查正确性，再扩展编码、规则和规模变体。研究还提出 CRAB，在不同游戏访问次数稀疏时，对位置预期回报使用带收缩的基线。

关键结果

作者从三个原有 SPIRAL 模板扩展到 29 个 Game Family（含 26 个新游戏）与 336 个验证变体。Qwen3-4B-Base 在 13 项推理 Benchmark 的平均 pass@1 由 45.5→62.5（先用 Qwen3-32B 自博弈蒸馏），随后自博弈 RL 达到 64.9。与只用三个手写游戏、相同训练预算的 60.6 相比，环境多样性显示额外收益。

为什么重要

这是“增加有效环境覆盖”与“训练更久”之间的分离实验。相对于让 Agent 自己写任意 Reward Function，保持评分器与环境规则独立，并对状态转移进行交叉验证，可以降低奖励投机和错误环境污染训练集的风险。

可信度与局限

证据质量中等（公开验证设计，仍需独立复现）。它依赖有明确定义输赢的零和游戏，不能自动推出开放式对话、推荐业务或非零和 Agent 的收益；蒸馏阶段使用 32B 教师，需把 Teacher Compute 纳入完整成本。

最值得继续追踪

固定总 Episode 和生成 Token，对照“3 个游戏更多 Rollout”与“更多游戏同预算”；分开测跨模板迁移、规则错误率、胜负之外的通用推理改进和对 OOD 游戏的泛化。

5. Predictive Self-Evolution：修改 Agent 前先预测改动的后果

原始论文 · 作者公开匿名代码 · HTML 全文

发生了什么

多数自进化 Agent 采取“修改代码→跑评测→看总分”的循环。该工作在 HyperAgents 上加入可编辑 Improvement Dynamics Model（IDM）：修改被实际测试前，预测它会如何影响各任务分数；只有风险/收益值得时追加一次候选修改。真实结果写回预测历史，更新 IDM 自身。

关键结果

编码任务 Polyglot 的 40 代实验中，匹配 Token 预算的最佳表现曲线面积（AUBC）中位数比 HyperAgents 高 10.9%。166 个 Held-out Coding Task 上，选出 Agent 相对相同初始版本的 Resolve Rate 改善中位数为 13.25pp，HyperAgents 为 5.42pp。但完整 40 代的平均 Token 花费在编码实验中约 170.22M（Selective IDM）对 49.45M（HyperAgents）；“更高预算效率”只在报告的匹配预算对照意义上成立。

为什么重要

系统可把失败经验从“某个 Patch 得了几分”提升为“何种修改在何类任务上通常改善/退化”。这对 Agent Harness 自动调参、工具路由与 Prompt/Memory Policy 演化有直接意义。

可信度与局限

证据质量中等（五次重复、Held-out 编码任务及真实 Token 统计）。预测器可能记住 Bench 结构，且全流程的 Token 数并不天然更少；论文中的“最高 46% 提升”是部分指标与设置，不能解释为普遍任务成功率提升 46%。

最值得继续追踪

在冻结的修改候选列表上预测每个 Patch 的 Delta Score，考察 Brier Loss、校准误差、误杀高收益 Patch 比例，并比较“预测器+选择性评测”与“把同样预算直接用于更多真实评测”。

6. LACRM：电商广告商竞争关系应建模为有方向的图

原始论文 · 实验与案例全文

发生了什么

同一商品类目的两个广告商并非对称竞争：品牌、价格带、渠道、促销周期和跨品类替代关系会造成方向性的影响。LACRM 通过 LLM 生成角色分离的商家画像，用多路非对称 ANN 检索发现现有和潜在对手，再通过与历史竞价行为对齐的 Listwise Ranker 学习有向、带权竞争边。

关键结果

作者报告两个独立在线试验：将竞争图用于自动出价，广告收入 +1.73%、每日预算目标达成率 +0.91 个百分点；用于固定补贴总额下的激励分配，广告收入 +1.14%，后者报告 $p<0.01$。这是两个不同业务场景，不可相加成 +2.87%。

为什么重要

推荐/广告中“相似 Item”与“互相争夺同一批用户或预算”的关系不同。把语义召回限定为候选生成，再通过行为数据和在线试验纠偏，有助于控制 LLM 的联想噪声，同时发现历史共竞价图里没有的潜在对手。

可信度与局限

证据质量中等偏高（含线上对照与统计方法，但仅单平台）。平台没有公开商家与补贴等敏感规则；实际收益可能来自广告生态结构、促销节奏和特定竞价系统，长期均衡效应尚不明确。

最值得继续追踪

在匿名竞价日志构建有向竞争候选后，先评测已实现对手 Recall、潜在替代的专家精度与关系方向稳定性；若上线，应以商家分组随机化做 Spillover-aware A/B，并单独监测广告主 ROI。

7. 多向量检索：压缩 ColBERT 后用线性修正找回多少排名质量？

原始论文 · HTML 全文

发生了什么

Late Interaction 的每篇文档保存多个 Token-level Vector，精排质量好但索引庞大。新研究在压缩后冻结 Encoder 与 Compressor，只学习一个很小的全局线性映射，用未压缩模型的候选分数分布作为蒸馏目标。该修正可在 Query 时施加，也可以离线投到文档向量侧。

关键结果

在 ColBERTv2、Jina v4、ColPali2 和 MS MARCO、BEIR、ViDoRe v3 上，作者研究了四类免训练压缩方法。在 160 个 BEIR 域内组合里，线性修正优于压缩基线 154 个；但从 MS MARCO 学得的映射迁移到其他 BEIR 域时表现不稳定。

为什么重要

该方案给 Agent Memory / RAG 的多向量索引提供了一种低成本质量补救：当在线查询难以承受上千个 Document Token Vector 时，可以先压缩，再用少量有标签的 Query–Doc Pair 蒸馏评分几何。

可信度与局限

证据质量中等（多 Encoder/数据集，跨域负结果如实披露）。154/160 表示优于已经压缩的 Baseline，不能理解为恢复了未压缩的全部质量；最重要的线上瓶颈可能仍是 ANN 候选查找和随机内存访问。

最值得继续追踪

在固定向量预算和 P95 延迟条件下测 BEIR NDCG@10、Recall@20、Index GB、CPU/GPU 内存及纠正矩阵的域间稳定性；优先做同域训练与异域测试的交叉验证。

8. PRIME：MoE 专家裁剪和合并应被联合决策

原始论文 · 可参考的公开对照实现：REAP

发生了什么

稀疏 MoE 在设备上部署时，权重占用未必随着单次激活专家数降低。PRIME 把 Expert Pruning 和 Merging 统一为频率加权优化，利用整数线性规划在全局选择“删掉、并入、保留为代表”的决策，而非先贪心删除再单独合并。高频 Expert 更容易作为合并中心，以降低路由不稳定性。

关键结果

论文在 Qwen3-30B-A3B 与 Qwen3.5-122B-A10B 上做知识、代码、数学、长上下文质量及 vLLM Serving 实验。摘要没有提供一个可在所有模型/压缩比下通用的“速度提高 X 倍”；本期仅将其作为值得复现实验的压缩策略，不虚构统一提升数值。

为什么重要

Expert 的使用频率与功能不可替代性可能不同。按频率做代表选择，再用真实激活及质量门槛验证压缩后的任务能力，比只按 Expert 参数相似度做合并更贴近部署目的。

可信度与局限

证据质量中等偏低（第一方、跨设置完整数字需读正文）。整数规划求解成本、校准集是否覆盖罕见 Expert、合并对 Routing Margin 的影响、长尾工具调用退化，都可能改变最终选择。与 REAP 的结论需在相同模型、压缩比和 Kernel 下比较。

最值得继续追踪

绘制压缩比例—任务成功率—CPU/GPU 总显存—Token/s 的 Pareto 曲线，单独测试低频但关键的 Code/Tool Call；不要以权重文件体积代替真实加载显存。

候选簇 1：Agent Harness 从循环迁移到图编排的边界

今日最值得花 30 分钟阅读的一项

VH-GPO：Verified Handoff for LLM Agent Reinforcement Learning。 这是最适合连接 GRPO、Agent Harness 和 Tool-Agent RL 的一篇。

前 10 分钟读 Section 1 与 3.1：明确全失败组为何没有组内监督。中间 12 分钟读 3.2—3.4，画出 Student Prefix → Teacher Bridge → Student Resume 三段，并标记哪些位置能独立环境验证。最后 8 分钟检查 ALFWorld 与 WebShop 实验和开销口径，尤其分清“额外生成 Token 很少”与“总体实验资源很少”。

带着一个问题结束阅读：要让失败轨迹产生学习信号，最少需要教师帮学生跨过哪一段不可独立完成的状态？

今日可立即实践的一件事

建立 Zero-Advantage Failure-to-Handoff 审计

从你已有的 SQL Tool Agent / Coding Agent Rollout 中抽取 50—100 个任务，每题 4—8 次采样，找出“所有结果相同且失败”的组。记录失败前最后一个可恢复的环境状态；如果涉及不可逆 API 或敏感线上操作，只做离线 Sandbox Replay。

在其中 10—20 个有确定 Verifier 的任务上，选择一个冻结的更强 Teacher 完成缺失步骤；每执行一个或少量动作就尝试让冻结 Student 接手，并独立运行到终点，寻找最早成功的交接点。保存 Teacher Bridge 长度、Student 自主成功次数、额外 Token/工具调用、验证失败与状态恢复失败原因。

无需当天训练模型，先完成数据质量审计即可。最后输出一张表：全失败组数量、可恢复比例、教师可救回比例、可提前交还学生比例，以及每条有效训练样本的总额外成本。这将决定是否值得实现 VH-GPO 式训练，避免直接为不可恢复的 API Agent 采购昂贵 Teacher Rollout。
