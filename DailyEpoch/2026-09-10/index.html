今日主线： Model–Harness Fit · Executable Test Critics · Test-Time RL · Procedural Memory · 100K Recommendation · Multimodal Disaggregation

截至今天早上，arXiv 最新常规公告批次为 2026 年 9 月 9 日：cs.AI 共 517 条，cs.IR 共 48 条。今天最值得连起来看的变化，是“模型能力”越来越难脱离其运行结构单独讨论：同一个弱模型在为它进化过的 Harness 中可以大幅变强，却会被强模型全轨迹模仿反向破坏；Coding Agent 的测试器如果质量不够，增加 executable feedback 甚至会降低修复率；无公开测试时，行为共识适合作为负信号，却不适合作为正确性证书；长程 Agent 的经验也开始从自然语言笔记升级成可验证、可演化的执行图。推荐与推理侧则继续把系统收益建立在“可复用中间状态”上：100K 用户历史要先变成可缓存 sketch，多模态 Serving 则要判断视觉编码是否已经成为独立瓶颈。

今日核心判断

  1. Harness 与 Policy 存在双向适配，强 Teacher 的完整轨迹并不天然是好训练数据。 Salesforce 的 Co-Evolving Harnesses 在 7 个企业任务上先把 Qwen3-Coder-30B-A3B 的平均成功率从 29.2% 提到 78.0%；随后用 Gemini 3.1 Pro 的成功轨迹做普通 imitation，结果反而在 7/7 任务上退化到 63.1%。原因主要不是知识没学到，而是完整模仿打乱了原先与 Harness 对齐的 planning style。只在 Student 自己失败轨迹上局部替换一个关键 turn 的 on-policy correction，则把 78.0% 提到 79.7%。

  2. “给 Coding Agent 加测试”不是单调收益，测试器本身也是必须训练和验证的 Agent。 ExecCritic 固定 Repair Agent 时，基础 35B Test Agent 生成的测试把 SWE-bench Verified resolved rate 从 61.2% 降到 57.3%，而 GPT-5.6-sol 生成的测试提高到 65.3%。单独训练 Test Agent 后，其 Base-to-Gold 测试成功率从 22.2% 提到 62.2%；再和训练后的 Repair Agent 组合，最终达到 72.6%。真正有价值的是“行为契约 → fail-closed 测试 → 独立修复”的结构，而不是无条件增加一个 critic。

  3. 没有可信测试时，行为共识更适合当“淘汰信号”，不适合当“奖励正确答案”的证书。 ERPO 为代码任务自动生成只有输入、没有标准输出的 probes，用多个候选程序的行为共识构造 PCR。PCR≤0.5 的候选超过 91% 会在隐藏测试失败，但即便 PCR=1.0，Qwen3-4B / 8B 仍有 44.2% / 51.9% 是错的。直接用 PCR 做 GRPO 会强化“大家一起错”的模式；只对低排名候选施加负向更新并约束熵，反而显著提升 pass@k。

  4. 长程 Agent Memory 正在从“记住过去”转向“显式保存怎么做、何时做、下一步能做什么”。 Procedural Graphs 用 (procedure, relation, procedure) 组织执行知识，并只检索当前 active node 周边的局部子图；离线 refiner 根据成功／失败轨迹修改图，只有 held-out validation 不退化才接受更新。132 个月 EnterpriseArena 中，Claude Sonnet 4.6 的完整存活率从 44% 提到 58%，Gemini 3.1 Pro 从 6% 提到 34%。不过局部图指导虽然减少 step，GDPval / ALFWorld 总 token 仍分别高 33.4% / 55.4%，因此它不是“免费压缩”。

  5. 100K 序列推荐的关键不只是长 Attention，而是把 user-only computation 变成跨候选、跨请求可复用资产。 Douyin 的 SequenceO1 先用 target-agnostic Sketch Attention 把最高 100K 历史压成约 1K prototype，再用 target-conditioned 分支结合最近 10K 行为。生产系统对 sketch 做版本化缓存：训练约 50% hit、Serving 约 60% hit。一个月线上 A/B 中，抖音主端 30-Day Activeness +0.1968%、Duration +1.4999%、Finish +2.3256%、Like +2.3617%，Dislike -6.9829%。论文已经部署到全流量，但其 49.9×/63.9× 只是 ultra-long branch 的 FLOP 对比，并非整个 ranker 的端到端加速。

  6. 多模态推理是否值得 EPD 解耦，取决于 runtime bottleneck，而不是“视觉模型就应该拆出去”。 NVIDIA 在 Dynamo 中把 Encode 与 Prefill/Decode 分离。图像重、输出中等的设置里，异构 encoder tier 在相同 latency SLO 下 goodput +70%；但固定 5 张图、把输出长度从 128 拉到 2048 时，异构 EPD 的端到端收益从 20.3% 缩到 5.2%，colocated EPD 甚至从 +11.8% 变成 -2.5%。4B→27B 时 colocated EPD goodput 比例从 2.62× 降到 0.65×，说明真正应该测的是 ViT / prefill / decode 的运行时间占比。

1. Co-Evolving Harnesses：强 Teacher 的完整模仿为什么会把弱模型教坏

原始来源： Co-Evolving Harnesses and Models: On-Policy Correction Helps Weaker Models Catch Up Where Imitation Fails

发生了什么

论文先固定 Qwen3-Coder-30B-A3B，在 payroll auditing、budget approval、stock alerts、IoT anomaly、browser automation、website management、code refactoring 七个可客观验证的企业任务上进化外部 Harness。Harness 的修改包括更适合该模型的提示、工具使用规则和任务结构；所有测试结果按三次运行平均。

仅改变 Harness，Qwen 的平均成功率就从 29.2% 提到 78.0%（+48.8 points）。更强的 Gemini 3.1 Pro Preview 在同一个进化 Harness 上达到 93.6%，而且比 Qwen 更充分地调用新加入的 Harness 能力。直觉上，下一步似乎应该把 Gemini 的完整成功轨迹直接蒸馏给 Qwen。

结果恰好相反：在进化 Harness 下，用 Teacher 成功轨迹做普通 SFT 后，Qwen 从 78.0% 降到 63.1%，七个任务全部退化，平均 -14.9 points。相同 imitation recipe 放回未进化的基础 Harness，却把 29.2% 提到 35.5%。

关键结果

条件Qwen 平均成功率
Base model + base harness29.2%
Base model + evolved harness78.0%
Expert imitation + evolved harness63.1%
Expert imitation + base harness35.5%
On-policy localized correction + evolved harness79.7%

失败分类进一步解释了机制：在进化 Harness 下，完整 imitation 后 planning failure 明显增加。论文的修复办法没有继续追求“更完整的专家示范”，而是从 Student 自己的失败 rollout 出发，只定位一个关键失败 turn，让 Expert 改写这个局部动作，其余规划轨迹保持 Student-native。这样平均成功率从 78.0% 提到 79.7%，五个任务提升，两个基本在噪声范围内。

为什么重要

这篇工作的核心不是“Prompt Engineering 比 Fine-tuning 更重要”，而是 Harness 与 Policy 共同形成一个闭环行为分布。Harness 如果是在 Student 的原生规划方式上进化出来的，那么换成 Teacher 的完整 action distribution，可能相当于把软件接口保留、却把调用协议换掉。

这也解释了为什么近期 OPD、Tool-Agent RL 越来越强调 student-state supervision：训练数据是否来自 Student 真正访问的状态，比 Teacher 本身有多强更重要。对于 Agent 系统，可以把数据优先级写成：

2
3
4

Student 自己的失败状态
→ 定位可验证的局部错误
→ Teacher 只修正必要动作
→ 保留其余已与 Harness 对齐的规划结构

可信度与局限

优点是任务有客观 verifier，而且作者同时报告了“模仿强模型反而更差”这一负结果，机制证据比只报最终 best score 更有价值。论文还在另一模型／环境上观察到类似 imitation regression，因此现象并非单一表格偶然。

但“planning fit”仍然是作者基于失败分类给出的解释，并非严格因果识别；Harness evolution 与模型行为存在共同设计。On-policy correction 的 +1.7 points 也远小于 Harness 本身的 +48.8 points，因此不能把它包装成新的万能后训练方法。

最值得继续追踪

最值得做的是固定 Harness 与总 Teacher-token 预算，比较 full-trajectory imitation、失败 turn correction、OPD token-level correction 与 executed counterfactual repair。若局部 correction 的优势能在 Coding、Browser、SQL Agent 上稳定复现，“Student-state locality”可能会成为 Agent post-training 的基础数据原则。

2. ExecCritic：测试器不是工具附件，而是需要单独训练的角色

原始来源： ExecCritic: Learn to Test, Test to Improve for Coding Agents
代码仓库： MSR-Orchard/execcritic

发生了什么

ExecCritic 把软件修复拆成两个独立角色：Test Agent 从 issue 与当前代码中生成 executable behavioral tests；Repair Agent 只能修改实现，不能修改已经通过 Harness qualification 的测试。测试采用 fail-closed 流程，最终仍由 SWE-bench 官方 evaluator 决定任务是否真正修复。

这解决了 Coding Agent 中一个经常被忽略的问题：自动生成的测试并不天然可靠。它可能覆盖错误行为、过拟合某个 patch，或者把本来正确的实现判错。如果 Repair Agent 又能修改测试，系统还会产生非常直接的 reward hacking 通道。

关键结果

固定基础 Repair Agent 时：

Test 来源SWE-bench Verified Resolved
不加 Test / Round 061.2%
Base-35B Test57.3%
GPT-5.6-sol Test65.3%
Oracle F2P69.4%

也就是说，一个质量不够的 Test Agent 会让系统 -3.9 points。论文随后对 Test 与 Repair 分角色 post-train：Test 的 Base-to-Gold success 从 22.2% 经训练提高到 62.2%，Repair 的无测试 Round-0 从 61.2% 提到 68.3%。两者组合后达到 72.6%，比原始无测试 baseline 高 11.4 points；评测阶段不再需要 GPT-5.6 或 Oracle feedback。

为什么重要

这项工作把“自动测试”从工具调用提升成一个可学习的监督角色。对于 SWE-RL，真正值得训练的可能不只有 patch policy，还包括：

2
3
4
5

issue / behavior contract
→ 构造能区分正确与错误实现的 test
→ Harness 冻结 test
→ Repair 根据 executable feedback 修改实现
→ 官方 evaluator 独立验收

这比让同一个 Coding Agent 写代码、写测试、再宣布自己通过更接近可靠的软件工程分工。

可信度与局限

论文明确承认，72.6% 的组合结果包含额外 test generation 和 revision 计算，不是 compute-matched improvement。因此不能把 +11.4 points 理解成“同样推理预算免费上涨”。

跨语言也不是均匀泛化：Test Agent 只用 Python post-training 后，在 Rust/C++ 的 Base-to-Gold 仍有 66.7% / 58.3%，但 C 只有 26.1%、Java 2.4%。这提醒我们，测试生成本身也严重依赖语言、构建系统和项目生态。

最值得继续追踪

生产 Coding Agent 最应该增加的是 Test precision / recall 与“错误测试造成的 Repair regression”指标，而不是只看最终 resolved rate。另一个关键方向是让 Test Agent 在不知道官方 hidden tests 的前提下学习 coverage、behavioral invariants 和 mutation sensitivity。

3. ERPO：没有 Gold Test 时，把共识当负信号，而不是正确性证书

原始来源： Entropy-Regularized Rank-Masked Policy Optimization for Test-Time Reinforcement Learning in Code Generation

发生了什么

Test-Time RL 希望针对当前任务现场适配模型，但代码生成通常没有公开标准输出。ERPO 从题面自动生成一组 output-free probe inputs，让多个候选程序在这些输入上执行，再用行为一致程度构造 Probe Consensus Reward（PCR）。

问题在于，共识具有明显的不对称性。低共识通常意味着程序不可靠；高共识却可能只是多个候选共享同一种 bug。LiveCodeBench 隐藏测试校准中，PCR 对正确性有一定判别力，但远达不到 verifier 的程度。

关键结果

  • PCR AUC：Qwen3-4B 为 0.790，Qwen3-8B 为 0.750；
  • PCR ≤ 0.5 的候选，隐藏测试失败率分别为 92.0% / 91.3%；
  • PCR = 1.0 的候选仍有 44.2% / 51.9% 失败。

直接把 PCR 当 reward 做 GRPO，Qwen3-4B 在 LiveCodeBench 的 P@16 从 Base 的 34.4% 降到 30.9%，说明模型会开始强化 consensus-friendly、但缺乏真实正确性保证的模式。

ERPO 的处理更保守：按 PCR 排序，只主要惩罚低排名的一半候选，不强行奖励高共识样本，并用 entropy regularization 控制策略塌缩。结果 Qwen3-4B 的 LCB P@1 / P@16 从 26.0 / 34.4 提到 36.7 / 46.3；Qwen3-8B 从 25.6 / 34.6 提到 35.1 / 50.9。在 CodeContests、CodeForces、TACO 三个 zero-shot transfer 上也有明显提升。

为什么重要

这篇论文提供了一个很实用的 weak-verifier 原则：

如果一个 proxy 对“错”很有把握、对“对”没把握，就只用它做 negative filtering / negative advantage，不要对称地把它当正奖励。

这个思想不只适用于代码。多 Agent 共识、RAG claim agreement、self-consistency、无标签 reranking 都可能有同样问题：大家不同意往往值得警惕，大家同意并不能证明事实正确。

可信度与局限

PCR 依赖自动生成 probe 的覆盖范围；边界 case 没被 probe 到时，多程序会形成非常稳定的共同错误。ERPO 也仍然需要为单个目标任务进行 test-time adaptation，带来额外采样、执行和更新成本，不是纯 inference-time reranking。

此外，结果来自程序可执行、输出可比较的任务。开放式 Agent 行为很难定义同样清晰的“behavioral consensus”，不能直接照搬。

最值得继续追踪

最值得测试的是把 PCR 与静态分析、mutation testing、symbolic constraints 或少量可信 public examples 组合，构建“负信号很强、正信号逐步增强”的分层 verifier，而不是继续追求一个单一 scalar reward。

4. Procedural Graphs：Agent Memory 开始保存“执行结构”，而不只是文本经验

原始来源： Procedural Graphs: Self-Evolving Execution Structures for LLM Agents

发生了什么

Procedural Graph（PG）把 Agent 的操作知识表示为 (procedure, relation, procedure) 三元组。在线时先定位当前 active node，只取局部 subgraph，再由 guidance model 转成当前情境下的执行建议；离线 refiner 则比较成功和失败轨迹，修改节点、边或条件。

更新不是自动永久写入。候选图必须在 held-out validation 上不低于当前版本才会被接受；被拒绝的修改还会作为 negative constraint 保留，防止后续 refiner 重复犯同一个错误。这让 Skill / Memory evolution 更像带验证门的程序版本迭代。

关键结果

在 132 个月、包含未预告危机的 EnterpriseArena 中：

模型Baseline 完整存活Procedural Graph
Claude Sonnet 4.644.0%58.0%
Gemini 3.1 Pro6.0%34.0%
Grok 4.1 Fast26.0%40.0%
Gemini 3.5 Flash0.0%0.0%，平均寿命 33.58→40.62 月

更有意思的是 tool-call 变化并不单向：Claude 和 Gemini 3.1 Pro 在 PG 下反而调用更多 forecast / market tools，但存活率提高。也就是说，收益来自更合适的调用顺序与条件，不是简单减少工具调用。

局部 guidance 在 GDPval 把 solver steps 从 28.20 降到 18.57，在 ALFWorld 从 21.84 降到 18.80；然而总 token 分别仍高 33.4% 和 55.4%。图的结构化信息降低了无效动作，却引入了额外 guidance token。

为什么重要

这类方法把 Agent Memory 从“检索一条过去经验”推进到“恢复一个局部执行状态机”。对于需要长期重复工作的 Agent，真正可复用的知识往往是：

1
2
3
4

什么条件下进入某个过程
→ 哪些步骤有依赖关系
→ 什么观察会改变下一步
→ 哪种失败需要切换分支

相比扁平 Skill 文档，图结构更容易表达 prerequisite、alternative、recovery 和 transition。

可信度与局限

EnterpriseArena 仍是模拟环境；一些评估依赖模型 Judge，且图构建、guidance 生成与 benchmark 处在同一研究 pipeline。更重要的是，PG 当前不是纯效率优化：step 下降不代表 token 或 wall-clock 一定下降。

自我演化还依赖 validation gate 的质量。如果 validation set 太窄，图同样可能把偶然成功固化成长期规则。因此“可演化 Memory”必须和独立评测、版本回滚一起设计。

最值得继续追踪

下一步最值得看跨任务 procedural graph transfer：同一张执行图能否被不同模型、不同工具栈复用；以及用程序化 verifier 替代 LLM Judge 后，长期自我演化是否仍能稳定单调改进。

5. SequenceO1：100K 行为序列真正的难题，是让长历史可复用

原始来源： SequenceO1: End-to-End Ultra-Long (100K) Sequence Modeling in Recommendation with Low-Rank Caching

发生了什么

Douyin 用户一年行为很容易达到 $10^5$ 量级，但把 100K 历史直接对每个 candidate 做 target-conditioned attention，训练样本、Host→Device 通信、显存和在线算力都会一起爆炸。

SequenceO1 把长历史拆成两条时间尺度：最近约 10K 行为继续保留 target-conditioned 分支；更长的 100K 历史先经过 target-agnostic Sketch Attention，压成固定约 1K 个 prototype，再与 candidate 做后续交互。因为 sketch 只依赖用户，不依赖当前候选，所以可以跨 target 和连续请求复用。

生产实现用 user id + model version + history timestamp + sketch config 作为 cache key。训练 3 小时 TTL 下有效 hit rate 约 0.5；Serving 1 小时 TTL 下约 0.6。cache miss 时只需要重新计算 user-only Sketch Attention，且可以与上游 retrieval 并行。

关键结果

100K truncation（平均实际长度约 85K）时，SequenceO1 相对轻量 STCA baseline 的 Finish AUC +1.07%，保留了直接把 STCA 扩到长序列所得 +1.29% 收益的 83%。

一个月线上 A/B 的 Overall 结果：

指标DouyinDouyin Lite
30-Day Activeness+0.1968%+0.2335%
Duration+1.4999%+1.6655%
Finish+2.3256%+3.4872%
Comment+3.5910%+8.6132%
Like+2.3617%+2.9399%
Dislike-6.9829%-5.9972%

论文还报告在观察到的复用率与 cache hit operating point 下，100K ultra-long branch 相比直接 STCA 的理论 FLOPs 在训练侧低 49.9×、Serving 侧低 63.9×。但作者明确说明，该比较没有计入共同的 recent-10K branch、dense ranker、embedding preprocessing 和 fusion，所以不能称为整个推荐系统快 50–64 倍。

为什么重要

超长序列推荐的 scalable pattern 越来越清楚：昂贵计算如果与 candidate 无关，就应尽量前移并缓存；真正需要 target interaction 的部分只在压缩后的固定状态上运行。

这和 LLM prefix/KV caching 有相同系统思想，但 SequenceO1 缓存的是长度固定的 user sketch，因此 cache footprint 不随 100K 原始历史线性增长。对于 Feed、广告、搜索 ranker，这比单纯把 Transformer context 拉长更接近真实生产约束。

可信度与局限

这是 RecSys 2026 Industry Track 工作，并给出一个月线上 A/B 和全量部署，证据强于纯离线推荐论文。但全部生产数据来自 Douyin，一方实验难以外部复现。

更关键的是 cache freshness：把用户历史压成固定 sketch 后，模型用 TTL 在成本与最新兴趣之间做交换。线上提升证明当前 operating point 有效，不等于 100K 越长越好，也不等于 sketch 对快速兴趣漂移没有损失。

最值得继续追踪

建议关注 cache hit × sketch staleness × user activity bucket × marginal AUC/lifetime gain。当历史继续扩到百万级时，真正决定收益的可能不是 Attention kernel，而是哪些状态值得重算、何时失效、如何增量更新。

6. NVIDIA EPD：视觉 Encoder 拆不拆，应该由瓶颈比例决定

原始来源： When to Use Encode-Prefill-Decode Disaggregation to Accelerate Multimodal Model Serving

发生了什么

传统 VLM Serving 会在同一 worker 上完成视觉 Encode、LLM Prefill 和 Decode。NVIDIA Dynamo 的 EPD 把 Encode 独立成 worker pool，再通过 NIXL 把视觉 embedding 传给 Prefill/Decode worker；还可以把 encoder 放到更便宜的 GPU tier，把昂贵 GPU 留给语言模型。

这种拆分是否有效，取决于视觉编码在完整请求中占多少比例。Encoder 很重时，它会阻塞文本／图像混合队列；Decode 很长时，即使把 Encoder 优化掉，整体请求仍被 autoregressive generation 支配。

关键结果

图像重的设置（10 张图、每图 256 visual tokens、OSL 1024）中，TTFT colocated EPD 下降 58%，heterogeneous EPD 下降 50%；后者在相同 latency SLO 下可以服务 70% 更多流量。

但把输出长度拉长会迅速稀释收益：固定 5 张图时，OSL 从 128→2048，heterogeneous EPD 端到端收益从 20.3% 降到 5.2%；colocated EPD 则从 +11.8% 变成 -2.5% regression，原因是新增 encoder workers 和 PD workers 争抢同一 GPU 资源。

模型大小也改变结论：Qwen3.5 4B / 9B / 27B 的 colocated EPD same-SLO goodput 相对 aggregated serving 分别为 2.62× / 1.50× / 0.65×。只把活跃语言模型权重量化到 NVFP4 时，EPD goodput gain 又从 BF16 条件下的 1.78× 提到 2.64×——语言模型变快以后，视觉 Encoder 再次成为更显著的瓶颈。

为什么重要

这篇工程文章最重要的不是一个 EPD 架构图，而是 Serving architecture 应跟随 bottleneck 迁移。量化、MoE、长输出、图片数量、混合流量都会改变 ViT / Prefill / Decode 的时间占比，因此同一套 disaggregation 在不同模型上可能从 2.62× 收益直接变成 0.65× 亏损。

对于多模态 Agent，另一个价值是消除 head-of-line blocking：文本请求不必排在重视觉编码任务后面。真正的容量规划因此应按请求类型分层，而不是只用“平均 token/s”。

可信度与局限

这是 NVIDIA 官方基准，硬件、Dynamo/NIXL 和模型设置都属于其优化栈，第三方仍需要在自己的网络拓扑和 GPU 成本下复现。Goodput 是在特定 SLO 下的系统吞吐，不等于单请求 latency 或 raw tokens/s。

异构 EPD 还增加 embedding transfer、网络依赖和额外 worker pool 运维；在轻图像、长 Decode 的 workload 里，这些固定成本可能比省掉的 Encode 更大。

最值得继续追踪

最值得建立一个简单的在线 router：根据 image count / visual tokens、预计 OSL、模型大小和当前各 pool utilization，动态选择 aggregated、colocated EPD 或 heterogeneous EPD，而不是为所有请求固定一种拓扑。

今日值得收藏的代码 / 学习资源

MSR-Orchard/execcritic 是今天最值得直接读代码的仓库。它把 behavior-contract test generation、test qualification、self-repair 与 SWE-RL 拆成清晰角色；尤其值得检查 Test Agent 的训练数据如何定义 Base-to-Gold，而不是只复制 Repair Agent 的训练框架。

Agentic ML Exploration (A-MLE) for Ads Ranking 来自 Meta，适合推荐算法团队精读其 Research Harness。系统把 hypothesis generation、exploration strategy、experiment execution、result analysis 和 shared substrate 串成五阶段，阶段边界保留人工 checkpoint。实验模型上，单一架构放大只带来 +0.44% relative offline regression-error reduction，多轮架构探索 +0.58%，组合 architecture + efficiency 的 multi-source exploration 达到 +2.56%，训练 QPS +0.42%。它没有公开线上 A/B，因此这些数字应理解成离线研究探索证据，而不是业务收益。

FastE: Readout-Triggered Token Compression for LLM Embedding Inference 值得做 embedding / RAG serving 的人收藏。它利用 embedding model 最终只读取少量 readout token 这一结构，在中间层动态压缩其他 token；论文报告 Qwen3-Embedding-0.6B / NarrativeQA 上 decoder-backbone FLOPs -40.11%，仍保留 99.53% 的 full-compute nDCG@10。这里的指标是 FLOPs，不应直接等价成 40% wall-clock latency 降低。

SkillAdam: Stable and Efficient Skill Evolution for Agents 继续推进 Skill 自进化：用类似 Adam 一阶／二阶状态的离散记忆分别记录历史修改方向与“哪些区域反复震荡”，再据此调整下一轮 skill edit scope。值得把它和 Procedural Graphs 放在一起看：前者更像优化器，后者更像可执行状态结构。代码仓库为 ruc-datalab/SkillAdam。

Closing the Consistency Gap 提醒 Agent benchmark 不要只看单次成功率。论文在 AppWorld 中观察到 GPT-4.1 ReAct 单次平均成功率约 77%，但同一任务连续五次都成功只有约 53%；只把不稳定步骤写入 episodic memory，可以明显缩小这个 consistency gap。对生产 Agent，P(success once) 和 P(success repeatedly) 应该被当成两种不同能力。

今日最值得花 30 分钟阅读的一项

首选 Co-Evolving Harnesses and Models。

这篇比一个新的 Agent leaderboard 更值得读，因为它给出了一个非常反直觉、又直接影响 Agent post-training 的负结果：Teacher 更强、示范更成功、Harness 使用更充分，完整模仿仍然可能让 Student 变差。

建议 30 分钟按这个顺序读：

  1. 先看 Harness evolution 如何让 Qwen 从 29.2% 提到 78.0%；
  2. 再看 Gemini 在同 Harness 上达到 93.6%，确认 Teacher 确实更强；
  3. 重点看 full-trajectory imitation 为什么让 7/7 任务一起退化到 63.1%；
  4. 看 failure taxonomy 中 planning failure 的增长；
  5. 最后看 localized on-policy correction 如何只修 Student 自己的失败 turn，并把成功率恢复到 79.7%。

最值得带走的判断是：

Agent 数据的“好坏”不能脱离 Student 当前 Policy 与 Harness 来定义。一个全局更优的 Teacher trajectory，可能是局部更差的训练目标。

这和近几周 OPD、student-state coverage、Tool RL 的多个结果正在形成同一条主线：后训练不仅要问 Teacher 是否强，还要问监督是否发生在 Student 真正访问的状态、是否保留已有的系统适配。

停止条件： 如果 full imitation 在 3 个 seed 上都不造成 planning regression，而且明显高于 local correction，就没有理由为了追热点改训练 pipeline；反过来，如果完整 Teacher 轨迹越强、Student 的系统性规划反而越不稳定，就应优先把训练数据生成改成 student-state、failure-localized correction，再考虑扩大 Teacher 规模。

这个实验直接回答一个很实用的问题：

你的 Agent 真正缺的是更好的完整示范，还是只需要在自己已经会走的路上纠正少数关键错误？
