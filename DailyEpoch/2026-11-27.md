## 一、推荐与检索

### 1. OneQuery：把多语言电商 Query 理解变成统一结构生成

**发生了什么：** 将语言识别、纠错、翻译、标签提取统一为受 schema 约束的生成任务；先训练单任务，再合成联合样本，最后通过多任务 RL 对齐。AliExpress 线上使用 14B 教师离线处理头部查询并缓存结果，0.3B 蒸馏学生实时处理尾部查询。作者报告列表到支付转化率提升 0.5%，人工并排相关性评价提升 0.8 点。

**为什么重要：** 多语言混合查询的语言判错可能导致后续翻译和属性识别全部出错。联合生成允许各字段共同利用原始查询；头尾分流则使大模型的收益不必对应每次请求的大模型成本。

**局限与追踪：** 线上收益来自整套部署，不能独立归因于 RL。下一步按语种、头尾、拼写噪声分桶，测字段一致性、Recall@K、缓存命中率和 P99，并固定候选库比较联合生成与流水线。

[论文（WSDM 2027 Findings）](https://arxiv.org/html/2611.33653v1)

### 2. MKGE：给多模态用户偏好建立共享语义坐标

**发生了什么：** 从商品图文归纳可复用的规范概念，把历史交互映射到用户—概念关系，并联合用户—商品路径与概念路径。作者在 ML-1M、Video Games、Beauty 三个公开数据集的六项指标上报告一致改善；低活跃用户对个性化概念图尤其敏感。

**为什么重要：** 多次购买中共同出现的风格、主题或材质可以跨商品聚合证据，并支持显式偏好修改，而不局限于难以定位的稠密向量。

**局限与追踪：** 点击不等价于喜欢商品的每个属性；概念归纳也可能合并不相关因素。重点检查概念同义归并、时间漂移、稀疏用户分桶和构图成本；用随机重连概念边作为负控，区分知识贡献与额外图容量。

[论文（WSDM 2027）](https://arxiv.org/html/2611.34436v1) · [代码与知识图](https://github.com/Garden1a-X/MKGE)

### 3. ConTra：让切片上下文同时服务召回与重排

**发生了什么：** 训练 2B 模型离线生成文档切片前缀，奖励来自冻结的 embedding 模型、reranker、事实核验及长度约束；将增强文本与向量一起入库。作者在 ConTEB 和 RealContextBench 上报告相对对照最高 3.15 点改善；短文档索引速度分别为提示式 9B 方案和 PPLX-4B 上下文编码器的 7.74 倍、2.15 倍。

**为什么重要：** 仅在 embedding 中编码上下文，无法让文本重排器直接读取该信息；显式前缀可以连接两阶段检索，并把生成成本转移到索引端。

**局限与追踪：** 奖励可能过拟合指定检索器；前缀可能引入错误事实，增大索引与重排输入。应检查换 embedding/reranker 后的迁移，逐项验证前缀事实、索引体积与更新成本，并报告答案正确率而非只测召回。

[论文](https://arxiv.org/html/2611.34366v1) · [实现](https://github.com/SStan1/ConTra)

## 二、架构、训练与 Agent 评测

### 4. GigaChat 4：混合线性注意力、MLA 与稀疏注意力的联合训练

**发生了什么：** 11 月 26 日发布 708B-A41B 和 37B-A4B 权重。旗舰采用 Gated DeltaNet、MLA 与 DeepSeek Sparse Attention，原生支持百万 token；SFT 后训练专长 RL 教师，再对学生自身采样进行多教师 on-policy distillation，统一 Reasoning 与 Instant 模式。官方报告旗舰 Terminal-Bench 2.0 分数分别为 71.26% 和 60.47%。报告还公开训练稳定性、FP8、异步后训练与投机解码的实现思路。

**为什么重要：** 线性状态层可以节省序列缓存，稀疏注意力减少长序列读取；多教师蒸馏适合研究如何在单模型保留不同专长。此处的百万上下文是能力上限，不能直接换算成吞吐。

**局限与追踪：** 作者跑分未独立验证；两个模型许可不同，708B 模型卡标注 MIT，37B 标注个人非商业许可。总权重规模决定存储需求，激活参数不能当作显存需求。建议固定框架版本测短长上下文、不同 batch 的 TTFT、TPOT、KV 内存与工具成功率，并对照基础及中间 checkpoint 检查能力形成过程。

[技术报告（11-26）](https://giga.chat/blog/en/posts/gigachat-4-tech-report) · [旗舰模型卡](https://huggingface.co/ai-sage/GigaChat4-708B-A41B) · [小模型卡](https://huggingface.co/ai-sage/GigaChat4-37B-A4B)

### 5. Mixture-of-Loops Transformer：把循环依赖从同位置状态迁移到 KV

**发生了什么：** MoLT 探索跨循环选择性读取 KV。MoLT-KV 每轮从 embedding 重启并读取先前循环的历史位置 KV，解除同位置跨循环依赖；U-MoLT 将记忆构造与预测读出拆开。作者在 400B-token 预训练中报告 700M 模型达到 1.7 倍验证交叉熵 token 效率，3B MoE 的十任务准确率提高 2.1 个百分点；约 113M 的延迟对照中达到与非循环模型相近的速度。

**为什么重要：** 循环层共享参数的瓶颈在串行状态依赖；若能让不同循环更充分复用历史信息，参数量、计算深度及解码延迟之间的折中可能改变。

**局限与追踪：** 小规模延迟实验不能证明旗舰规模服务同样高效；token 效率也不是 FLOPs 效率。追踪等训练算力的消融、缓存占用、长序列复杂度、超训练循环次数的外推与独立复现。

[论文摘要及实验概览](https://arxiv.org/abs/2611.34923) · [代码](https://github.com/hustvl/MoLT)

### 6. DRBench Pro：研究报告评测需要知识拓扑，而非仅有事实清单

**发生了什么：** 从 Wikipedia 局部知识结构生成研究问题和关系级 rubric；分别评价研究方向覆盖广度、知识链探索深度，再以几何均值形成总体分。144 个案例覆盖 24 个领域和 44,102 条 rubric；16 个 Agent 中最优总体覆盖为 57.04%，rubric 判断与人工标注的 Macro-F1 为 0.893。

**为什么重要：** 文档长、搜索次数多并不保证覆盖关键关系；广度与深度分开可以定位规划、检索、报告合成哪个环节不足。

**局限与追踪：** Wikipedia 的可组织知识不能代表全部专业研究，自动 rubric 也可能漏掉合理的新观点。下一步按领域和冻结检索环境比较，额外评估原始证据的可追溯性、事实错误率及单位新增覆盖成本。

[论文](https://arxiv.org/html/2611.34852v1) · [评测仓库](https://github.com/ZJU-REAL/DRBenchPro)

### 7. Agent Monitor 评测：测试样本分布会左右漏报率

**发生了什么：** 研究固定部署情境和 30 个控制任务，仅改变生成评测轨迹的策略。作者发现监控器漏报率对样本生成方式及优化程度显著敏感，部分设置达到 23%；因此单一测试集上的低漏报不足以支持真实部署安全结论。

**为什么重要：** 这与推荐模型的 OOD 评估类似：验证集抽样方式本身决定了风险估计能否迁移。监控评估需要独立生成策略和多种场景，而不仅是平均准确率。

**局限与追踪：** 模拟轨迹与真实故障分布不同，特定监控器的结果不适用于所有系统。应预注册威胁模型，报告分布外覆盖与置信区间，结合权限最小化、人工审批和独立审计；不将离线漏报率直接解释为线上事故概率。

[论文](https://arxiv.org/html/2611.34934v1)

## 今日最值得花 30 分钟阅读的一项

[OneQuery](https://arxiv.org/html/2611.33653v1)。前 10 分钟读联合字段生成和数据合成，中间 10 分钟研究多任务奖励及 KL 消融，最后 10 分钟研究头部缓存与尾部学生的部署设计。重点判断联合生成带来的错误耦合能否被 schema、独立字段验证与路由策略约束。

## 今日可立即实践的一件事

建立 60 条多语言电商 Query 的离线评测：分别覆盖混合语言、拼写噪声、型号、品牌、价格约束及长尾属性。冻结商品库和检索器，对比四阶段流水线、单次 schema 生成和单次生成加字段校验。对每条 Query 记录字段 exact match、关键属性保留率、Recall@20、nDCG@10、P95 与调用成本；人为注入错误语言标签，检查后续字段是否连锁失效。用配对 Bootstrap 估计检索增益区间。60 条用于诊断机制，不足以证明线上转化收益。
