## 1. ActionOPD：蒸馏 Agent 的「决策」而非复刻教师 Token

**日期与原始资料：** 论文 2026-10-14 首次提交。[原始论文](https://arxiv.org/abs/2610.19820) · [作者实现及训练说明](https://github.com/thu-nics/ActionOPD) · [项目页](https://thu-nics.github.io/ActionOPD/)。

### 发生了什么

传统离线模仿要求学生学习教师生成的 Token 序列；On-policy Distillation（OPD）改善了状态分布错配，但 Token-level OPD 往往需要教师 Token 概率且与 Tokenizer 兼容。ActionOPD 转而对齐**环境状态下的语义动作**：在学生实际到达的状态同时采样教师、学生动作，把合法工具调用或面向用户的最终行为是否一致作为局部奖励。教师可以是黑盒 API，学生也无需复制教师的思考文字。

作者公布的一个实现配方是在同一状态采样 **3 个教师动作与 4 个学生候选**，为语义一致性、教师动作出现频率和无效动作分别设置奖励项，再让最高奖励的动作推进一条环境轨迹。组内其他候选也用于 Policy Optimization。这里需要特别区分：动作一致性的教师代理奖励与最终任务成功率属于不同监督层级。

### 关键结果

在 **6,697 个 AWM/EnvScaler 训练任务、100 个训练 Step** 后，作者报告四项 OOD 平均得分：Qwen3-4B 从 30.8 到 35.9（Qwen3.7-Flash 教师）或 37.7（DeepSeek-V4-Flash 教师）；Qwen3-8B 从 35.7 到 39.0 / 40.0，对应约 **+3.3 到 +6.9 个百分点**。四项平均覆盖 BFCL、ToolSandbox、AppWorld 和 τ²-bench，各指标先归一到 0—100 再加权。作者明确指出，在 τ²-bench 上其 **pass⁴（四次全成功）低于离线蒸馏和 Token OPD 基线**，不能仅凭单次成功率宣布全面领先。

### 为什么重要

黑盒教师的输出格式、隐藏推理、Tokenization 与小模型常常不同。把对齐粒度上移到「做什么」后，能够训练一个保持自身内部推理习惯的学生。这对工具调用、搜索/推荐工具选择和跨厂商 Agent 蒸馏特别实用。可形式化把采样动作一致性记为局部 Reward：

$$
R(s,a)=\operatorname{Agreement}\!\left(a,\{a_T^{(1)},\ldots,a_T^{(m)}\}\right)-\lambda\,\mathbf{1}[a\text{ invalid}].
$$

这里的 Reward 是实现思路的抽象，具体频率修正和各权重以作者代码为准。

### 可信度与局限

代码、配方和若干训练入口已开放；但 Benchmark Runner、其他 KD/OPD 基线和 Self-ActionOPD 的部分消融脚本没有包含在同一仓库。环境状态对齐依赖可复现的工具上下文，语义评判器可能把表达等价错判为动作等价。最终性能也受教师动作自身错误率限制。完整训练仍要求多 GPU、环境服务与奖励评估，单卡 RTX 4080 更适合先复现局部打分器和小任务 Trace。

### 最值得继续追踪

对照 Token-OPD、Offline SFT、Outcome-GRPO 与 ActionOPD，在相同教师调用 Token、Rollout 成本下报告 **Task Success、pass¹、pass⁴、工具错误率与每个成功任务成本**。重点调查错误教师动作、等价 JSON 参数、工具调用顺序变化及长流程信用分配。

## 2. Agent-Reflex：把工具失败后的恢复行为训练成内生能力

**日期与原始资料：** 论文 2026-10-13 提交，仓库 10 月公布模型、代码与数据。[论文](https://arxiv.org/abs/2610.17953) · [完整代码与实验](https://github.com/RUC-NLPIR/Agent-Reflex) · [8B 模型](https://huggingface.co/dongguanting/Agent-Reflex-8B) · [54K SFT 数据](https://huggingface.co/datasets/dongguanting/Agent-Reflex-SFT-54K)。

### 发生了什么

很多 Agent 在干净的 Benchmark 中擅长调用工具，一旦遇到超时、权限拒绝、格式错乱或用户临时修正，就反复重试、忽略反馈或让错误状态传播。Agent-Reflex 把**发现异常—解释原因—修正计划—继续执行**当作可学习的技能。整体分三阶段：RSD 在真实失败类别的扰动环境中从成功/失败轨迹对提炼反思技能；ReSFT 将技能转成自反思、恢复与用户纠正数据；ORPO 在有噪声的 Agentic RL 中引入技能指导的同 Token On-policy Distillation。上线时无需额外显式技能提示。

### 关键结果

作者在 **557 个环境**中整理 **1,170 个反思元技能**，开放 54,663 条 ReSFT 轨迹与约 2,550 个 RL 任务。Qwen3-8B 在五个工具 Benchmark 的综合分数 **40.2→58.6（+18.4）**；在 AgentNoiseBench 上 **12.3→29.1**。相对文中 EnvScaler-8B 的综合分数 50.9，也有约 +7.7 的提升。这些分数来自多套 Benchmark 官方指标的综合，不能直接理解为统一的真实线上成功概率。

### 为什么重要

工程 Agent 的 Failure Recovery 经常依赖外层 Harness 的异常分支。把恢复策略部分内化到模型后，Agent 可能减少重复工具调用、避免把临时网络故障误判为业务事实。这种训练思路也适用于购物助手中缺货、价格 API 限流、订单工具超时、用户修订条件等状态。

### 可信度与局限

代码、权重、数据可核验是积极信号，但本轮未独立运行 Benchmark。噪声由设计的扰动类别产生；真实生产中的联合故障、延迟反馈、服务降级以及人为对抗未必同分布。技能数据可能与部分测试环境结构接近，应严查 Train/Test 隔离和异常恢复是否造成额外调用成本。

### 最值得继续追踪

在真实或回放的 Tool Trace 上按失败类型分桶，比较重试策略、错误检测 Precision/Recall、P95 恢复时间、额外工具调用和用户纠正后的任务成功率。加入**错误信息与成功信息语义冲突**的对抗测试。

## 3. 何时小模型反而更贵？按成功任务重新评估 Agent Router

**日期与原始资料：** 2026-10-14 提交。[原始论文：When Is Smaller Greener?](https://arxiv.org/abs/2610.19345)。

### 发生了什么

这篇工作指出，按单个 LLM Call 的费用、延迟或能耗选路，容易低估多步骤任务中的失败成本。论文以 **成功完成的任务** 为功能单位，比较小模型与大模型在不同任务长度下的总资源消耗，讨论重试次数和一条流程中多个步骤的联合成功概率。

### 关键结果

作者提出理想化分析：如果每步正确概率近似为 $p$，流程必须连续成功 $L$ 步，且每步资源花费约为 $c$，则一次流程成功率为 $p^L$，重复独立尝试下达到成功的期望资源可近似为：

$$
\mathbb{E}[C_{\mathrm{success}}]\approx\frac{Lc}{p^L}.
$$

理论上，小模型虽然 $c$ 低，但 $p$ 略低也会在长流程被指数放大。作者使用五家机构、**15 个 0.6B—27B 开放权重模型**、两类多步 Agent 任务和实测 GPU 能耗，对比不同任务长度的交叉点，发现最省能耗的模型会随任务长度及类型变化。

### 为什么重要

Agent Router 最终需要最小化 **Cost per Successful Task**，且要把失败重试、工具费用、人类介入和尾延迟计入。原本在每个 Token 上都昂贵的模型，可能在 30 步以上任务中因为错误更少而总成本更低。它也提醒我们：模型能力评测必须匹配实际流程长度分布。

### 可信度与局限

上述公式假设步骤成功事件和每步资源成本足够稳定。现实中的步骤错误高度相关，Agent 可以局部恢复、缩短任务或调用其他模型；试错结束规则也不同。因此论文的单交叉点结论需要用业务 Trace 验证。15 个模型、两类任务的 Pilot Study 提供初步证据，外推到复杂推荐/交易 Agent 仍需更广覆盖。

### 最值得继续追踪

按 1—5、6—15、16—30、30+ 步分桶，把 $p$ 从单步平均数替换为**历史条件成功概率**，联合比较单模型、动态升级 Router、失败局部修复三种策略。不要忽略不同模型引起的工具预算和 Task Decomposition 差异。

## 4. Ricoh LMM_35B-A3B：在 Qwen MoE 上进行领域 RL、课程训练与 NVFP4 部署

**日期与原始资料：** Ricoh 2026-10-15 官方发布。[原始新闻稿及指标表](https://jp.ricoh.com/release/2026/1015_1)。

### 发生了什么

Ricoh 以 Qwen3.6-35B-A3B 为基座，宣布针对日文图表文档、业务问答与工具调用进行强化学习、Curriculum Learning，并开发 Blackwell 平台用的 NVFP4 量化版本。总参数约 35B、激活约 3B，可支持约 256K Context、图像、视频与工具调用。厂商表示 NVFP4 版本可在单台 DGX Spark 运行，预计 11 月起整合至企业本地部署产品。

### 关键结果

在 Ricoh 自有的 JDocQA-Reasoning v2.0 上，模型从 Qwen3.6-35B-A3B 的 **0.816 提升至 0.841**；日语工具使用 j-τ-bench telecom 的任务正确率从 **62.4% 提升至 77.7%（+15.3pp）**。官方称其答复质量约等于 Qwen3.6-27B Dense 与 GPT-5.6 Sol 在所测日文文档任务的表现。对同模型 BF16 版本，NVFP4 的单问题响应时间约降低到 **1/3**，结合 MTP 约 **1/4**。

### 为什么重要

这是一个值得研究的**领域后训练 + MoE 权重保留 + 量化 Serving** 的闭环案例。泛化能力未必需要从头预训练；企业文档的表格/图形、遵循政策的多轮工具调用和无效长思维循环，都可以成为专门的后训练目标。活跃参数小不意味着权重存储仅需 3B 的显存，部署仍要考虑完整专家权重及 KV Cache。

### 可信度与局限

核心数据来自厂商公告，JDocQA 是自有评测，不具备统一 Harness 的独立横向认证；量化速度取决于硬件、Batch、输入/输出长度和 MTP Accept Rate。公告称将面向产品逐步提供，**本轮没有核验到可下载开放权重及完整训练配方**，因此不把它列为可立即复现的开源模型。

### 最值得继续追踪

关注权重/模型卡/技术报告是否发布，核对日文 Benchmark 的题目公开度、数据污染审计、工具调用 policy compliance，以及 NVFP4 在相同质量门槛下的 TTFT、TPOT、显存和失败重试成本。

## 5. FARL：自动设计 Observation、Reward 和 Solver，并记住失败实验的条件

**日期与原始资料：** 2026-10-11 提交，属于本期七天技术扩展观察。[原始论文与完整实验](https://arxiv.org/abs/2610.15691)。

### 发生了什么

传统 RL AutoML 往往只调整 Reward 或超参数，FARL 同时搜索**观察特征映射、Reward Program、学习算法、探索策略及训练预算**。搜索过程先用短试验检查能否运行与阶段性进步，再用更长训练验证；失败的设计不会被直接删除，而是连同验证条件写入 Scientific Memory，允许以后与不同 Solver 重新组合。

### 关键结果

在 Adroit Hand Relocate，FARL 报告 **97.11%±2.99%** 的成功率，同表中的 Eureka 和 LiMEN 为 0%、原生 PPO 约 1%；每个被选 Policy 的比较训练预算为 5M Steps。**关键成本陷阱：** 论文同时报告完整搜索过程涉及约 **408.4M 环境步**，Eureka 为约 110.4M，LiMEN 为 55.0M；因此不能把 5M 当作 FARL 的总训练算力。其 DoorKey、Ant、Door-Open 任务也有实验和消融，但不同任务的预算口径不完全相同。

### 为什么重要

自动改 Reward 时，最危险的是把错误训练收益当作真正行为改善。FARL 的关键贡献是将**可证伪诊断**融入实验：明确预期改善的行为、保持不变的参数、对照组和结果证据，再决定是否增加预算。这种方法能迁移到 Agent Reward Engineering、RLVR 训练数据构造和 Tool Agent Harness 自我改进。

### 可信度与局限

这是机器人控制和仿真环境中的第一方研究，不直接证明 LLM Agent 的训练配方能自动进化。巨大搜索步数、不同训练预算和模型采样成本，使它更适合评估自动实验框架的设计原则，而非马上用于小显卡实验。训练环境和评估器的权限隔离非常关键。

### 最值得继续追踪

比较「只改 Reward」「只改 Observation」「联合修改但无对照」「FARL 全机制」，在**固定完整搜索成本**下的真实任务提升及 Reward Hacking 率，特别审计 Scientific Memory 是否记录失败条件和可复现配置。

## 6. SAT-RL：利用符号求解器为 Tool-Agent RL 提供可验证反馈

**日期与原始资料：** 2026-10-09 提交，作为本期背景扩展；避免误称 10 月 15 日新论文。[原始论文](https://arxiv.org/abs/2610.14402) · [作者代码](https://github.com/sunjia72/SAT-RL)。

### 发生了什么

SAT-RL 将自然语言逻辑推理转化成可以使用 SMT/SAT Solver 的多轮 Tool Agent 过程。训练分为合成可验证问题、求解器辅助轨迹的 SFT Warm-up，以及包含工具反馈的 Solver-grounded RL。模型负责理解约束并提出求解步骤，符号求解器负责验证部分形式逻辑关系。

### 关键结果

论文报告在域内及域外逻辑任务中改善 Solver-augmented 推理，但本轮可核验摘要没有一致的可引用绝对提升数值，因此不制造虚假的百分点。这里更重要的是**奖励来源的可检查性**：对于公式合法性、约束满足性和最终结果，可由工具或求解器独立判定。

### 为什么重要

Tool-Agent RL 最常见的工程问题是终局奖励稀疏、Judge 评分容易受语言风格影响。通过 Z3 一类独立符号后端可以降低某些奖励歧义，适合 SQL Agent、配置生成、约束规划和代码检查。需要把「求解器反馈可靠」与「模型正确建模用户要求」分开验证。

### 可信度与局限

如果模型把自然语言约束转译错了，即使 SMT 返回 SAT，也可能高置信地给出错误业务答案。Solver 调用具有延迟和 Token 成本，且算法可能过拟合某个工具的调用格式。完整任务层面的独立 Verifier 仍不可省。

### 最值得继续追踪

在 Held-out 逻辑题中分别测量 NL→Formal Specification 一致性、Solver 执行成功率、最终答案准确率、平均 Solver 调用次数及故障恢复能力；引入 Solver Timeout 和错误 API 返回的消融。

## 7. 独立 Agent Evaluation：Anthropic 给予 METR 嵌入式访问权限

**日期与原始资料：** Anthropic 2026-10-15 发布。[官方说明](https://www.anthropic.com/news/an-update-on-independent-evaluators)。

### 发生了什么

Anthropic 宣布让 METR 的外部评估团队取得类似内部风险评估人员的设备、办公场所和部分内部工具访问权限，以独立测试前沿模型、Agent 行为与风险管理流程。公司表示 METR 可公开发布评估结果，无需一般性的发布预先批准；特定涉及客户数据、法律特权或模型架构细节的内容可要求有限删改。该安排属于其多层外部评估计划中访问程度最高的一层。

### 关键结果

这是一项**评估治理机制的改变**，不是新的模型能力 Benchmark，也没有证据足以断言它已经改善任何模型的可靠性。其增量在于评估者可以接近模型开发中的系统、内部 Trace 和风险流程，有机会发现仅从公共 API 或标准 Benchmark 无法识别的问题。

### 为什么重要

部署 Agent 时，独立评估最缺的是失败样本、工具权限、异常轨迹、过滤规则与真实系统上下文。给评估者更多可追溯的证据，理论上有助于审查与复现。对一般企业也有启发：可以把开发团队与验收团队的访问权限、修改权限及审计记录明确隔离。

### 可信度与局限

发布内容来自参与方自己的说明，评估独立性需要等待 METR 实际出具报告才能判断。即便不能一票否决报告，也仍可能通过样本、访问时间和敏感数据范围影响结论。外部评估不能替代生产环境的持续监测与责任追溯。

### 最值得继续追踪

METR 首份公开独立报告是否说明测试任务集、失败示例、统计不确定性、厂商删改请求及复核协议；这些比「获得办公权限」的新闻本身更有技术价值。

## 今日最值得花 30 分钟阅读的一项

### [ActionOPD：Distilling Decisions, Not Tokens](https://arxiv.org/abs/2610.19820)

前 8 分钟读 Problem Setting 和 Action-level Reward 目标，弄清为何在 Student-visited States 对齐语义动作。中间 12 分钟对照 [作者 GitHub](https://github.com/thu-nics/ActionOPD) 的三次教师采样、四次学生采样、动作打分及组内更新，判断哪些组件可以复用已有 Agent RL Harness。最后 10 分钟读**负面结果**：为什么 τ²-bench 的 pass⁴ 逊于 Token OPD/Offline KD，哪些任务需要轨迹级而非单步语义一致性。

读完应输出两项可以写进实验计划的结论：一个 Agent 动作等价判定函数如何实现；一个检验教师动作「看似一致但最终无效」的评价集如何构造。

## 今日可立即实践的一件事

### 使用 50 个真实 Tool Trace 评估 Action-level Teacher Agreement

从已有 Agent 的日志中取 50 个多轮任务，抽取每个任务的 1—3 个决策状态。固定同一上下文，收集学生的 4 个候选动作和教师的 3 个候选动作；如果没有真实教师 API，先用已经存在的高质量人工/历史正确轨迹作为有限替代，明确其不等价于黑盒教师采样。

针对工具调用，将动作规范化为 `(tool_name, canonical_json_arguments, side_effect_class)`；针对文本回复，用独立判定器加人工抽检定义等价。统计：`agreement@4`、非法工具调用率、参数错误率、等价判断误差和教师调用费用。在允许执行的沙盒环境里，把动作等价结果与真实后续任务成功率进行对照，找出「动作像教师、任务仍失败」的样本。

建议先避免正式训练，用轻量 Python 脚本完成状态抽样与一致性标注；4080 单卡可以用于本地小模型对照，完整 ActionOPD 训练需要更多显存、环境服务与可验证奖励。

> **最重要的决策：** 如果动作一致性与真实成功率相关性弱，就应先修正 Reward/Verifier，暂缓投入完整的 On-policy Distillation 训练。
