## 今日核心判断

1. **能力和学习能力是不同指标。** Agent Plasticity 用 Held-out Improvement 和学习成本衡量 Agent 将经验转化成可迁移能力的效率；终点能力较高的模型未必学得更快。[论文](https://arxiv.org/abs/2610.08902)
2. **Skill 相关性不是 Skill 效用。** 同一个 Skill 在不同 Model–Harness 配置间，在 **36.78%** 的测试任务上效用方向翻转；操作支持型重排使首选通过率提高 **4.35–5.80pp**。[论文](https://arxiv.org/abs/2610.08875)
3. **OPD 的监督应兼顾依赖图与分歧。** GraphOPD 发现只选教师—学生 Divergence 最大的步骤并不稳定优于随机选择；利用环境结构估计因果重要性后，在实验中最多超过最强基线 **5.8pp**。[论文](https://arxiv.org/abs/2610.08959)
4. **自我改进会制造 Winner's Curse。** 当每一轮反复使用 16 条选择题挑选最优改动时，最终选择集评分可比独立测试高 **13–20 points**；256 条选择题仍高 **1–5 points**。[论文](https://arxiv.org/abs/2610.09239)
5. **Agent RL 应训练实际部署时的 Harness。** Agent Lightning v1.0 以约 3500 行代码连接真实 Agent Loop 与 RL Trainer；第一方 SWE-bench Verified 流程用约 6000 条训练样本使 Qwen3.5-9B Pass@1 **41.8%→56.4%**。[Microsoft](https://www.microsoft.com/en-us/research/blog/agent-lightning-v1-0-a-3500-line-lightweight-agentic-rl-framework-for-training-agents-with-real-harnesses/)
6. **RTX 多卡 MoE 通信需要面向 PCIe / Host 重构。** CoMoE 报告 RTX 5090 环境下最高 **1.46×** 吞吐，相对 NVLink A800 方案的硬件成本约 **23.4%**。[论文](https://arxiv.org/abs/2610.09424)
7. **生成式推荐补进遗漏正样本可能破坏线上候选排序。** 在四组预注册 Amazon Video Games 设置中，取消训练专用 Target 与线上候选的 Softmax Competition，使 FT-NDCG 相对提高 **7.8%–22.2%**。[论文](https://arxiv.org/abs/2610.10124)

## 1. Agent Plasticity：从“会做题”转向“从经验中变强”

[原始论文：Agent Plasticity](https://arxiv.org/abs/2610.08902)

### 发生了什么

静态 Benchmark 衡量当前 Agent 能完成多少任务。Agent Plasticity 改为观察 Agent 在多个 Checkpoint 继承之前的 Artifact 后，未来 Held-out 环境表现是否改善，并将额外交互与学习成本纳入评价。作者区分三类问题：经验是否带来改善、改善的效率、改善在哪个环节中断。

### 关键结果

多个模型在类似学习机会下出现很不相同的提升曲线；内部训练环境的收益只能部分转移到 OOD 任务；最终分数最高者未必是学习效率最高者。低 Plasticity 系统常未能复用相关 Artifact；较强系统即使复用，也可能由于质量低、泛化失败或错误使用而没有受益。

### 为什么重要

长期 Coding、Research 和 Shopping Agent 的价值应同时衡量任务质量和积累经验的投资回报。一个便于讨论的工程指标是：

$$
\mathrm{plasticity}=\frac{Q_{\mathrm{heldout,after}}-Q_{\mathrm{heldout,before}}}{C_{\mathrm{learning}}}.
$$

此处是简化操作性表达，正式比较须遵循论文的成本与任务归一化口径。经验存储量多不意味着可塑性强。

### 可信度与局限

不同任务的性能上限不同，不能把各环境的原始差值机械平均。继承外部文件的学习也不同于更新模型权重；实验尚不足以证明生产环境中数月的持久收益。

### 最值得继续追踪

把失败拆成“相关 Artifact 未召回 → 已召回但质量不足 → 内容正确却错误应用 → 训练内成功但 OOD 失效”，分别测量漏斗转化率。

## 2. Agent Skills Utility：为什么“相关技能”可能是累赘？

[原始论文：An Empirical Study of Agent Skills' Downstream Utility](https://arxiv.org/abs/2610.08875)

### 发生了什么

研究使用同一任务、相同 Model–Harness 条件下 With-Skill 与 No-Skill 的通过率差定义真正的下游效用。评估覆盖 87 个 SkillsBench 任务、九种配置，并检索规模为 37,596 的 Skill 候选库。

### 关键结果

| 测试 | 结果 |
|---|---:|
| 同一 Skill 跨配置效用正负翻转 | **36.78%** 的任务 |
| 按所需操作支持程度重排候选 | 首选通过率 **+4.35–5.80pp** |
| 可操作 Skill 编写建议 | **17 条** |
| 多 Skill 的组织 | Stage Plan / Dependency DAG 优于仅按使用顺序 |

DAG 的额外收益主要集中于五到六个 Skill 的任务，这个条件值得保留。

### 为什么重要

Skill Marketplace 的语义相似度无法判断当前 Agent 是否真的缺这项能力。一个相关却重复的操作程序，可能增加 Tool Calls、阻碍恢复或违背当前任务的明确约束。更合理的排序目标是 **当前 Model–Harness–Task 下的增量执行效用**。

### 可信度与局限

实验来自 SkillsBench 与所选候选集，Pass Rate 差值存在采样方差。全局 Skill 分数会掩盖运行时差异，需要在真实部署配置上复测。

### 最值得继续追踪

建立 Skill 的适用 Harness 版本、执行前提、冲突规则、依赖 DAG、回归结果和撤销条件，而非仅保存描述与 Embedding。

## 3. GraphOPD：训练信用分配必须知道“哪一步影响了未来”

[原始论文：GraphOPD](https://arxiv.org/abs/2610.08959)

### 发生了什么

OPD 在 Student 自己走过的轨迹上，用 Teacher Distribution 提供密集监督。传统办法把 Teacher 与 Student 分歧大的步骤视为需要更多指导。但早期关键错误会改变未来环境，后续 Teacher 也只能在错误状态中继续评价；不重要的可互换动作却可能有很大 KL。

GraphOPD 从环境自己的状态变化记录建立步骤依赖图，计算随机游走平稳分布得到结构性信用，再与分歧信号联合产生 Rollout-relative Supervision Mask。

### 关键结果

只选择最大 Divergence 步骤，在实验中没有稳定超过随机选择。GraphOPD 在三档模型规模、11 个基线及 ALFWorld、WebShop、SearchQA 中最多超过最强基线 **5.8pp**；Executed Replay Audit 表明图信用分数与真实干预影响明显相关。

### 为什么重要

高 KL 是“模型不一致”的证据，环境依赖链补充了“这一步是否影响最终结果”的信息。对于 Shell / Coding Agent，读写文件、执行测试和生成 Artifact 的显式依赖可成为低成本信用分配骨架。

### 可信度与局限

依赖图难以覆盖思维改变、隐藏 API 状态和远程副作用；最高 5.8pp 是最佳实验增益，不能当成跨任务保证。图指标也不是完全可识别的因果效应。

### 最值得继续追踪

用依赖图筛出少数候选 Pivotal Step，再对这些步骤做 Counterfactual Replay，把昂贵的验证预算集中到高价值节点。

## 4. Winner's Curse：优化器刷高了成绩，还是刷熟了考题？

[原始论文：The Winner's Curse in LLM Self-Improvement Loops](https://arxiv.org/abs/2610.09239)

### 发生了什么

Prompt / Harness Optimizer 每一轮提出多个改动，再用相同小评测集选择最优版本；循环多轮后，最优值容易混入极值噪声和重复使用验证集造成的过拟合。作者让 Qwen 自行修改 Instruction，并对所有候选使用独立的 600 条未参与选择的测试题。

### 关键结果

| 选择集规模 | 报告分数相对独立测试的高估 |
|---|---:|
| 16 条 | **13–20 points** |
| 256 条 | **1–5 points** |
| 额外 64 条盲审计题 | 可消除平均偏差；单次估计仍有约 **6 points** 误差 |

大多数第一轮之后的改动在独立测试中反而有害；替代 Acceptance Rule 也未稳定战胜 Greedy Loop。选择集加大只在部分任务明显提高了真正的泛化收益。

### 为什么重要

“模型自我改进”需要独立测试、预先登记的接受门槛及不确定性区间。用同一批题反复筛选产生的学习曲线，即使一直上升，也无法区分真实能力与测量噪声。

### 可信度与局限

研究对象是 Instruction Self-rewriting；不能把它的 13–20 points 直接推成任何 AutoResearch 系统的错误幅度。候选之间相关，噪声模型的具体假设也值得审查。

### 最值得继续追踪

在固定 Evaluator 预算下比较：增加候选数、增加选择集大小、以及保留真正不可见的 Final Hold-out，哪种分配拥有最高的真实 OOD Gain？

## 5. Agent Lightning v1.0：Harnessed Agentic RL 进入可复用工具链

[Microsoft Research 官方技术文章](https://www.microsoft.com/en-us/research/blog/agent-lightning-v1-0-a-3500-line-lightweight-agentic-rl-framework-for-training-agents-with-real-harnesses/) · [GitHub](https://github.com/microsoft/agent-lightning)

### 发生了什么

10 月 7 日公布的 Agent Lightning v1.0 让真实部署时使用的 Agent Harness 保留 Tool Loop、Subagent、Context Compaction 和 Sandbox 逻辑，通过兼容 OpenAI 的 LLM Proxy 接入 RL Trainer。API Gateway、Rollout Controller、Custom Trainer 构成约 3500 行的核心控制面，支持本地流程和 Kubernetes Jobs。

### 关键结果

| 指标 | 官方结果 |
|---|---:|
| Qwen3.5-9B · SWE-bench Verified | **41.8% → 56.4%** Pass@1 |
| 训练集 | 约 **6000** 条样本 |
| Collocated Async RL vs 同步方案 | 约 **2×** 训练加速 |

### 为什么重要

真正的 Harness 会将一个任务拆成多次 LLM Request，并用 Summary 或 Subagent 进一步分裂 Sample。如果把 Advantage 与 Loss 按 Sample 平均，工具调用更多的任务会获得非预期的训练权重。**Rollout-level Advantage + Rollout-level Normalization** 因此是重要的算法细节。

### 可信度与局限

SWE-bench 提升来自完整训练 Pipeline，不能归因给代码行数或 Proxy 本身。Kubernetes 与 Sandbox 的可靠性、奖励作弊防护、模型一致性和 Training/Serving Retokenization 仍是生产瓶颈。

### 最值得继续追踪

比较“训练框架重写 Agent Loop”与“真实 Harness + API Proxy”在执行轨迹、Gradient Bias、成本和实际部署效果上的差异。

## 6. CoMoE：消费 GPU MoE 的关键在 Host-centric Routing

[原始论文：Democratizing MoE inference on commodity GPUs](https://arxiv.org/abs/2610.09424)

### 发生了什么

Expert Parallelism 往往依赖 NVLink 等高速 GPU P2P。多数消费级 RTX 多卡缺少同样的互联，跨卡 Token Dispatch 会产生重复传输，全局同步又放大慢 Expert 的延迟。

CoMoE 让 Host 成为主动路由中心，用 Host-backed Token Multicast 避免重复发送共享 Token，再以细粒度 Host Staging Buffer 做 Token-level Combine。

### 关键结果

RTX 5090 多 GPU 设置下报告最高 **1.46×** 吞吐提升；在其硬件比较中，性能接近 NVLink A800 配置，硬件采购成本约为 **23.4%**。

### 为什么重要

在没有高速 P2P 的拓扑上模拟数据中心的 All-to-all 不一定最佳。Host 路由、Expert Hot Set、CPU/RAM 分层和异步复用需要协同设计。

### 可信度与局限

硬件价格比不包含供电、主机、调试、维护和长期 TCO；最高吞吐增益也依赖工作负载。结论来自多 RTX 5090，不适合直接套到单 RTX 4080。

### 最值得继续追踪

检查 NUMA、PCIe Gen、Batch Size、并发 KV 占用和 P99 Tail Latency 的拐点。

## 7. 生成式推荐：Missed Target 补样本的 Softmax 陷阱

[原始论文](https://arxiv.org/abs/2610.10124)

### 发生了什么

Generative Recommender 生成的候选列表可能漏掉 Ground-truth Target。一种直觉是把这些漏召 Target 追加到 Reranker 训练列表中，而推理时仍然只排序真实召回的候选。

作者拆分三种改变：原本命中 Target 的监督权重、追加 Target 本身的监督、以及两个 Group 在同一个 Softmax 里的概率竞争。通过匹配损失权重，单独消融这种 Competition。

### 关键结果

四组预先指定的 Amazon Video Games 比较中，消除 Cross-group Competition 后，FT-NDCG **相对改善 7.8%–22.2%**；User Bootstrap 与三组 Training-run 置信区间支持了这一方向。简单的 Dev-set 决策规则有时应该补样本，有时应拒绝补样本，还避免了一次约 1.7% 的损失。

### 为什么重要

$$
\mathcal{C}_{train}=\mathcal{C}_{retrieved}\cup\mathcal{C}_{missed},
\qquad
\mathcal{C}_{serve}=\mathcal{C}_{retrieved}.
$$

训练阶段新加的正样本可以帮助学习，但让线上永远不会一起出现的候选竞争概率，可能改变真正候选之间的相对分数。**补监督与补竞争需要独立决策。**

### 可信度与局限

效果取决于 Generator Recall、候选数量与任务分布。7.8%–22.2% 是相对 FT-NDCG 增幅，不是绝对百分点；没有证据表明所有生成式推荐都应禁用追加 Target。

### 最值得继续追踪

按模型分别报告 Missed-target Rate、Returned-item NDCG、Full-target NDCG 与 Cross-group Normalization 的贡献，再制定训练策略。

## 今日值得收藏的代码 / 学习资源

**RSI-Forge：把科研论文转成可执行的自我改进环境。** 三个 Agent 负责构建、独立复现与审查；覆盖 18 个领域的 210 个环境，其中 90 个经独立专家评阅。120 个环境连续三次尝试中，84% 至少有一个模型在第一次之后变好，但专家对 Shortcut Resistance 与原论文忠实度提出质疑。[论文](https://arxiv.org/abs/2610.09426)。

**Q-PACE：Dynamic Mixed-precision QAT。** 用 Quantization Noise MSE × Layer Curvature 近似损失，周期性更新层级精度分配；对最多 4B 参数模型提供较好的质量—显存折中，跨模型规模外推仍待验证。[论文](https://arxiv.org/abs/2610.09183)。

**vLLM × DeepSeek-V4.1-Flash 工程复盘。** 官方称三周联合优化将低并发速度提高 **1.9×**，150 TPS 约束下 Agentic Throughput 提高约 **5.3×**；贡献来自 Bounded Replay、CUDA Graph、MegaAttention、Mega-mHC 与算子融合，不应归功于某一个单独 Kernel。[官方文章](https://vllm.ai/blog/2026-10-07-deepseek-v41-flash)。

**视觉检索的 VLM Teacher 应先消除假负样本。** 同样的 Student 和训练预算下，Teacher 审核挖掘出的 Hard Negative，使 ViDoRe v2 nDCG@5 从 55.2 提高到 62.6–63.0；论文附带 330 万 Teacher Judgment 和代码资源。[论文](https://arxiv.org/abs/2610.09177)。

**视觉文档 Embedding 也存在隐私边界。** Patch-level Multi-vector Index 可能泄漏原文；实验中从原始 Index 恢复 47% 词语、45% 敏感 Token，意味着托管向量库不能因存的“只是向量”就自动降低保护等级。[论文](https://arxiv.org/abs/2610.09920)。

## 今日最值得花 30 分钟阅读的一项

**[The Winner's Curse in LLM Self-Improvement Loops](https://arxiv.org/abs/2610.09239)**。

30 分钟重点看选择集样本数量对偏差的影响：16 条选题导致 13–20 points 夸大，256 条仍有 1–5 points；即使保留 64 条未见审计题，单次测量仍有约 6 points 误差。

> 真正的 Self-improvement 必须在**从未参与候选搜索的环境**中成立；训练内最高分持续创新高，不能单独证明能力进步。

## 今日可立即实践的一件事

对现有 Harness Optimizer / AutoResearch 执行 **Winner's Curse Audit**：保存最近 20–50 次 Proposal 的候选 ID、选择集、选中分数与接受决策。在彻底冻结 Proposal 后，只用一批未参与任何中间选择的 Hold-out 环境重新评估，画出 Selection Score 与 Held-out Score 的差距及其置信区间。

一个最简单的监控式是：

$$
\mathrm{selection\ gap}_t =
S_{\mathrm{selection}}(h_t)-S_{\mathrm{holdout}}(h_t).
$$

同时记录累积选中次数、每次候选数、Evaluator Cost、负向 OOD Flip Rate。如果选择集分数持续提高、真正 Hold-out 指标不动，就增加盲测试与验收门槛，暂停按微小分差自动接受 Patch。

**要回答的是：Agent 真的从经验中变强了，还是越来越熟悉不断复用的同一套考试题？**
