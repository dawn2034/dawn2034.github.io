1. Evolving Agent Teams：让团队结构随瓶颈改变

原始资料： 论文与完整实验 · 作者代码仓库 EAT。v1：10 月 27 日。

发生了什么

伯克利团队用 Supervisor 观察 Coding Agent 在 GPU Kernel 优化中遭遇的瓶颈，然后动态生成或重组 Profiler、Hardware Researcher、Planner、Implementer 等角色。持久化文件系统保存学习记录、演化历史和每个团队的实验产物。固定四角色团队无法在瓶颈变化时自动新增 Challenger 或 Knowledge Integrator，而自演化团队可以修改协作结构。

关键结果

论文报告扩展 Token 预算后，自生成的 MLA Paged Decode Kernel 相对生产 FlashInfer 均值 1.2×，在 47 个工作负载中 36 胜、11 负；其余 11 个为 0.86–0.99×。注意作者专门区分 plan() 开销包含与否：相对仅测 run() 的 FlashInfer 基线，该 Kernel 约为 0.96×，不能将 1.2× 误写为全面超过所有内核计算。匹配推理预算的多次实验显示团队结构演化优于静态团队，但报告中不同对照有不同运行次数。

为什么重要

Self-Evolving Agent 研究往往只更新 Prompt 或 Skill。这里将角色拓扑、分工与知识共享方式纳入可演化空间，尤其适合目标函数可精确测试的 Kernel / 编译器 / 数据库优化。

可信度与局限

测试以 GPU Kernel、固定 Benchmark 和昂贵的 Claude Code 执行器为主；最高成绩涉及额外预算和自动调优过程，不代表低成本 LLM 也能复现。严格区分编译正确性、Kernel 执行时间、编译/计划开销和研究花费。继续追踪： 固定总美元与工程时间，跨随机种子报告性能分布、回退频率、重复探索率与真实服务 P95。

2. PailitaoMMSearch2.0：图文到 Semantic ID 的端到端多意图生成式检索

原始资料： 论文全文。v1：10 月 27 日。

发生了什么

淘宝拍立淘团队让 VLM 接收原始图片与自由文本指令，直接生成商品三层 Semantic ID，无须在前端先将请求固定分类为“同款、属性修改、搭配”。系统按三个维度扩展：可组合数据清洗与标注工具；CPT + 多意图多预算 SFT + 统一 RL；按请求复杂度选择不同推理预算。其 Sample–Beam Rollout 先采样推理轨迹，再以 Beam 解码候选 SID，以贴近实际多候选服务。

关键结果

论文给出线上约 10% 实验流量、约 14 天的受控 A/B：商品详情页浏览 +17.90%、交易 +27.04%、GMV +8.94%，并报告 CTR +0.58 个百分点、转化率 +0.37 个百分点（作者称 p<0.05）。Sample–Beam RL 相对 SFT 的 Macro Excellent Rate 提高 5.97pp，这属于离线评判指标，不能等同 GMV 增幅。不同推理预算并非越大越好：2B 的 Macro ER 约 54.62%（No-think）、55.13%（Low-think）、55.00%（High-think）。

为什么重要

电商 AI 搜索中，Intent 路由、商品库语义、候选解码、在线成本和业务指标可以放进一个统一训练与服务配方。对购物 Agent，重点看多关系检索是否可以减少前置分类与工具链误差。

可信度与局限

工业 A/B 是强于纯离线 Recall 的证据，但完整部署配置同时变化，无法将 GMV 提升归因于 SID、RL、数据合成或推理预算中的某一项。自动 Judge 参与数据过滤与奖励，可能有相关性误差。作者只覆盖三类购物关系。继续追踪： 分意图和冷启动桶的长尾召回、增量上新、推理成本/每笔成交、流量漂移和线上消融。

3. Tessera：检索正确也可能因证据切块而答错

原始资料： 论文全文 · 作者代码。v1：10 月 27 日。

发生了什么

普通 RAG 将 Chunk 同时用作索引、排序和 Reader 的阅读单位，导致表格单元格丢失表头、Infobox 缺失实体名称、截图 Tile 缺少上下文。Tessera 保留现有索引和 Retriever，只对命中网页重建 Structure-Completed Evidence Units：为每块补足页面标题、章节路径、表头，再在不增加 Reader Token 预算的条件下筛选、排序和打包。

关键结果

在三项 QA 集合合计 7,851 道问题、3K Reader 证据 Token 的同预算比较中，Top-3 原始块汇总准确率 70.70%，Tessera 75.74%（约 +5.03pp），Query2doc + Tessera 达 76.65%。它对图像 Screenshot Pipeline 也有增益，说明丢失的不只有文本表格解析，还包括证据传递单位的选择。

为什么重要

企业 RAG 对网页、财报、制度表格的错误常发生在“已检索到正确页，但送入模型的信息不完整”。优先检查 Evidence Delivery，比盲目更换 Embedding 或增加上下文更具性价比。

可信度与局限

论文重点关注网页结构化内容，完整 HTML 可获得是前提。重新解析和单位重建有 CPU、缓存及新鲜度成本，报告的答题收益不能直接代表端到端 P95。继续追踪： 表格跨页、动态 DOM、PDF 结构复原、引用对齐、缓存失效和增量成本。

4. CEP/SCI：搜索图中的“连接多”会制造虚假证据权重

原始资料： 论文 · 完整方法与消融。v1：10 月 26 日。

发生了什么

跨文档证据图上的 Personalized PageRank 会将多个来源的传播质量累积到高连接度节点，造成背景 Hub 排名膨胀。CEP 使用最强单条证据路径，再用同图背景访问分布校准其得分；SCI 将文档与连接路径整理成供 Agent 阅读、验证、扩展的结构化 Map。

关键结果

作者在 BrowseComp-Plus、TREC-COVID 上报告答案准确率和 nDCG@10 改善。与任务表现最强的比较系统相比，工具调用数和生成成本的最大降幅分别超过 50% 和 40%。这些是特定设置的最大改善，不是所有问题上的平均降本。

为什么重要

Agentic Search 的下一步检索不该只沿着“热门、高引用、高连接”的文档扩展。保留可解释证据路径，能给 Agent 一个探索线索，也能检查 Citation 是否真的支撑结论。

可信度与局限

构图质量、实体消歧、扩边阈值和背景校准决定实际收益；在图很稀疏或错误连接较多时，路径机制可能误导。继续追踪： 合成高连接度干扰节点的鲁棒性、Evidence Recall、最终引用真实性及构图开销。

5. Refiner：推荐排序中的潜变量残差思考

原始资料： 论文与工业实验。v1：10 月 27 日，论文标注 CIKM 2026。

发生了什么

Refiner 在生成式排序模型上叠加多步隐空间推理，每一步预测对候选物品得分的残差修正，并通过 History Queries 压缩用户历史；LoRA 将推理适配成本控制在附加参数中。它避免要求非文本 ID 排序器生成冗长自然语言 CoT。

关键结果

工业离线 CTR GAUC 从 MTGR 的 0.6909→0.6920，CTCVR GAUC 0.7046→0.7061；线上使用一个推理步骤，在 1% 流量、7 天观察窗口中进行 A/B。这里引用离线 GAUC 的绝对数值，不把千分位提升误写成百分点级业务收益。

为什么重要

这是将 Test-time Compute 引入传统 Ranking 但仍保持批量候选评分形式的实用路线。额外推理层可改进排序，也可能吞噬在线 QPS、时延与成本预算。

可信度与局限

收益量级较小且依赖强工业底座，反事实偏置、候选构建、更新周期都影响测量。作者指出附加推理尚未进行完全 Serving 优化。继续追踪： 不同请求复杂度的自适应推理步数、A/B 置信区间、GAUC 对真实长期价值的预测性。

6. RuHarness：优化 Harness 时，评价标准也要迭代

原始资料： When the Critic Falls Behind，v1 在 10 月 28 日新公告出现。

发生了什么

静态评价 Rubric 会逐渐失去区分力：Harness 修复已知问题后，剩余失败变成新的瓶颈。RuHarness 从执行轨迹持续发现和重评行为准则，优先处理尚未解决的弱点，并针对性修改 Harness；终局任务目标仍保持固定。

关键结果

作者报告在不同 Agent 任务和底座模型上优于多项 Harness Evolution 对照，特别强调独立留出任务和长期迭代的稳定性；公开摘要缺少可用于统一比较的百分点，本期不臆造数值。

为什么重要

自动进化项目容易出现评估器落后、测试饱和，甚至自评标准被优化器钻空子。动态 Rubric 有助发现新错误模式，但终局 Verifier 和独立测试集必须与优化器隔离。

可信度与局限

自演化的 Rubric 仍会受到训练轨迹偏差与 Judge 相关错误影响。继续追踪： 固定外部任务标准、相同评测预算、未见任务、Rubric 漂移与真实能力增益的分离。

7. ConCal 与 Guided-RLVR：两种不同的 Agent RL 痛点

原始资料： ConCal · Guided-RLVR。均在 10 月 28 日新公告出现。

发生了什么

ConCal 针对长程 Agent 的信用分配：同一状态下动作优劣若只看一个后续采样轨迹，噪声很大；它匹配一个 Rollout Batch 中相同任务的状态-动作-后续状态转换，复用已有延续证据并向前回传校准后的价值，无需新增 Rollout。Guided-RLVR 则针对数学与代码强化学习的推理轨迹收缩，通过轻量控制器在关键位置注入有语义的 Steering Token，增加探索多样性。

关键结果

ConCal 使用 Qwen2.5-1.5B-Instruct，在 ALFWorld 与 WebShop 上分别较 GiGPO 提升 3.39pp / 5.86pp。Guided-RLVR 作者报告提升正确率与轨迹多样性，但当前摘要未给统一统计值；不能据此断言在 Agent 工具调用任务中已有相同改善。

为什么重要

两种机制应分开测：ConCal 降低动作价值估计噪声，Guided-RLVR 扩大探索支持集。把二者混成“增加 Rollout 数量”的结论会失去训练诊断价值。

可信度与局限

同状态匹配可能对开放环境不稳，Steering Token 则可能让轨迹多样却更慢。继续追踪： 等 Rollout、等 Token 下的 OOD 成功率、奖励方差、动作多样性及训练墙钟时间。

8. CRISP 与 RELAY：把计算预算放在真正有效的位置

原始资料： CRISP：MoE Pruning + Scheduling · RELAY：Sequential Recommendation。均见于 10 月 28 日新公告。

发生了什么

CRISP 不均匀保留和执行 MoE 专家：识别共同激活的专家组合，按热、温、冷路径区分容量，重排神经元并与权重搬运重叠执行。RELAY 使用一个学习到的 Query，一方面编码用户语义偏好，另一方面重用 Attention 作为历史事件、转移证据的路由权重，再对不同候选用门控校准两路记忆。

关键结果

CRISP 在 Mixtral-8x7B 和 DeepSeek-MoE-16B 上，相同内存预算下推理吞吐最高 2.1×，相对全宽推理精度损失控制在 3.6% 以内。RELAY 六组 Full-Catalog 测试中，Recall@5 / NDCG@5 相对所列最强对照平均提高 14.22% / 17.88%；预测器约 2.044M 参数、报告 1.75–1.79× 加速。

为什么重要

两者都强调在不等重要的路径上进行差异化计算分配：MoE 侧是专家组合与显存带宽，推荐侧是用户历史证据与候选条件化。

可信度与局限

CRISP 结果只覆盖指定 MoE 和边缘硬件；吞吐率不等于长上下文或多轮 Agent 的总成本。RELAY 的 Full-Catalog 结果不能直接推论工业曝光偏置与在线业务收益。继续追踪： 冷门专家与长尾 Item、缓存命中、P95、在线 Drift 以及质量固定后的真实服务成本。

今日最值得花 30 分钟阅读的一项

PailitaoMMSearch2.0：从多模态用户需求直接生成商品 SID。 这是本期最贴近电商 AI Agent / 推荐算法的工业研究。

前 8 分钟读系统的三类检索关系及统一 SID 解码；中间 12 分钟研究 Data Toolset、CPT/SFT/RL 与 Sample–Beam 的训练对齐；最后 10 分钟看第 7.5、7.6 节——注意 2B 上更多 Think Token 不一定提高 Macro ER，并分清 14 天线上整体收益和各组件的离线消融贡献。

读后应能回答：如果统一 Search Model 不再显式划分“找同款、改属性、找搭配”，如何构造多意图训练数据、保持长尾意图公平，并在固定 P95 和成本约束下选择合适推理预算？

今日可立即实践的一件事

构造 60 条图文购物查询的多关系检索评估集，并做成本约束的多策略重放。 将查询分成同款检索、指定属性修改、跨品类搭配三组，每组至少 20 条；为每条记录图像、自由文本、目标约束、若干可接受商品与不可接受商品。模型可先采用现有 VLM + 向量/关键词检索，无需在本地 16GB GPU 上训练大型 SID 生成器。

比较三条路径：A（意图分类 → 专门检索器）、B（单一文本/图像融合 Embedding → 统一召回）、C（VLM 生成结构化检索条件 → 检索 + 精排）；统一 Top-K 候选数与 P95 预算。分别按意图统计 Recall@20、NDCG@10、约束违反率、跨品类误召回、Token 与每成功请求成本；人工检查失败样本是否来自路由、候选缺失还是重排。只有在长尾关系的约束符合率不恶化、端到端质量和成本同时过线后，才继续投资 SID 端到端训练。
