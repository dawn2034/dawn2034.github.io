> **今日主线：** Multi-Agent RSI · Live-Commerce Agent RL · Productive Compute · Diffusion Plan Repair · Retrieval–Ranking Lifecycle · Skill Reranking · Decision Models

今天是周六，arXiv 不发布周末常规公告。最新常规公告为 **2026 年 10 月 9 日**：cs.AI 472 条、cs.LG 472 条、cs.CL 230 条、cs.IR 28 条，包含新稿、交叉收录和修订，分类之间有重叠，不能相加。[cs.AI](https://arxiv.org/list/cs.AI/new) · [cs.LG](https://arxiv.org/list/cs.LG/new) · [cs.CL](https://arxiv.org/list/cs.CL/new) · [cs.IR](https://arxiv.org/list/cs.IR/new)。

本期最值得连起来看的问题是：**Agent 如何在真实动态环境中分配计算、积累经验并改善决策？** 最近论文开始把“会停止”和“会有效利用时间”区分开，也开始把多 Agent 计算图、任务合成器、局部计划修复、Skill 选择和推荐系统生命周期表示作为新的优化对象。工业模型发布方面，限定候选打分的 Decision Model 进一步进入实际应用。

## 今日核心判断

1. **多 Agent 工作流可以产生自蒸馏监督。** MASS 交替执行多 Agent Workflow Evolution 与轨迹 SFT；Qwen3.6-27B 两轮之后，在四个开放式基准的单位输出 Token 表现提高约 1.2–1.6 倍。只证明有限循环内有收益。
2. **动态电商运营揭示 Agent 的长期决策缺口。** StoreBench 中最强受测模型只通过 49% 的任务–随机种子组合，人工编写的 smart-triage 策略达到 97%；Qwen3.5-27B 经 GRPO 在 held-out 任务上的 composite 从 0.136 提升到 0.373。
3. **遵守预算和善用预算是两个目标。** On the Clock 表明 Harness 时间反馈能改善守时；RL Agent 也可以学会停止，但额外时间常被重复动作消耗，多预算训练甚至会向最短预算策略坍缩。
4. **局部计划修改适合 Diffusion Planner。** Plan-and-Patch 在 Natural Plan 未专门训练时的修补成功率为 53.7%，自回归基线为 27.0%；任务训练后平均计划生成延迟减少 39%–46%。
5. **统一检索与排序要保留时点语义。** LIFT 将交互分成 Request、Item、Context、Action 状态，让不同阶段只访问各自可用的表示。ML-20M / Taobao 的 Joint Score 相对强基线 +4.9% / +3.6%。
6. **Skill 的差异性条款可能比共享文本更重要。** SkillContrast 选取相似 Skill 之间的差异文本供 Reranker 比较，低成本改善“选中好 Skill 且避开风险同胞”的 clean hit 指标。
7. **限定候选决策层进入新的竞争阶段。** Microsoft 10 月 9 日发布 Microsoft-Decision-1，基于 Qwen3.5-9B 做单次结构化打分；其质量、速度和校准主张目前仍以第一方资料为主。

## 1. MASS：多 Agent 编排与模型权重能否交替自我改善？

[论文：Recursive Self-Improvement through Multi-Agent Self-Supervision](https://arxiv.org/abs/2610.12176)

### 发生了什么

MASS 使用同一基础模型提出、执行和评价多 Agent Workflow。它搜索角色、依赖关系以及 Agent 间的信息路由，用结构化约束限制不合理的 Workflow。之后将执行出来的多 Agent 轨迹作为监督数据做 SFT，使更新后的模型成为下一轮更强的 Workflow Optimizer 和 Evaluator。

### 关键结果

| 项目 | 论文报告 |
|---|---|
| 基础模型 | Qwen3.6-27B |
| 自我改进轮数 | 2 |
| 测评 | 4 个开放式 Benchmark |
| 单位输出 Token 表现 | 1.2–1.6 倍 |
| 多 Agent 轨迹训练效率 | 超过使用 1.4 倍训练 Token 的单 Agent Student |

### 为什么重要

多数系统要么固定权重修改 Harness，要么固定 Harness 更新权重。MASS 将两者联系起来：更好的 Orchestration 生成更丰富的训练轨迹，模型改进又使下一轮 Orchestration Search 更有效。关键的待检验对象是模型、编排和训练数据三者的联合贡献。

### 可信度与局限

提出候选、执行和自评共享模型体系，可能产生同源盲点。两轮迭代不是开放式递归增长的证据；“每输出 Token”也没有覆盖 Tool Calls、长 Context Prefill 和多 Agent 协调开销。

### 最值得继续追踪

分离仅 SFT、仅 Workflow Evolution 和二者交替的消融；增加始终未参与选择的 OOD Holdout，并以 **verified improvement per total dollar** 衡量真实收益。

## 2. StoreBench：动态世界中的经济性 Agent RL

[论文：StoreBench](https://arxiv.org/abs/2610.10942)

### 发生了什么

StoreBench 将长程运营任务放到模拟的线上服装商店：客户持续购买，供应商会重新定价或失约，市场冲击可能无预警出现。Agent 调用 29 种商家工具，并在窗口化操作预算中推进模拟时间；环境支持相同动作序列的确定性重放。奖励门槛参考脚本化 Anchor Policy 设定，并设置了 Reward-hacking 防护。

### 关键结果

| 指标 | 报告值 |
|---|---:|
| Frontier Models / 场景数 | 7 / 11 |
| DeepSeek-V4-Pro task-seed pass | 49% |
| Smart-triage 脚本策略 pass | 97% |
| 人类专家 mean composite | 0.708 |
| 最佳受测模型对应 composite | 0.700 |
| Qwen3.5-27B held-out：GRPO 前 | 0.136 |
| Qwen3.5-27B held-out：GRPO 后 | 0.373 |

任务包括 30–45 天的多个场景及完整模拟年。GRPO 使用五个与测试分离的任务。

### 为什么重要

许多 Agent Benchmark 中世界只在 Agent 操作时变化，未行动基本没有代价。真实商家和企业流程里，**不行动也会改变库存、价格和顾客体验**。这让长期效果、不可逆副作用和对外部变化的反应成为 Agent 能力的组成部分。

### 可信度与局限

环境建设者也是评价者，完整测试环境为防污染而保留。模型与 Scripted Policy 的差距不能直接推算真实业务 GMV；模拟经济规律、顾客策略和 Reward 权重都可能影响排序。Qwen GRPO 的收益同样不等价于线上 A/B。

### 最值得继续追踪

增加长期成本、缺货率、顾客损失和库存周转等多目标的 Counterfactual Audit；检查 Agent 是否为了优化单一 Reward 牺牲其他实际目标。

## 3. On the Clock：截止时间遵守率提高，为何任务仍不变好？

[论文：On the Clock](https://arxiv.org/abs/2610.10833)

### 发生了什么

研究者要求小型 LLM Agent 在明确 Wall-clock Budget 内完成 MLE-Bench Lite 或 Zork I 等任务，比较直接在 Prompt 写预算、由 Harness 注入时间状态、强制 Deadline Hook，以及用 Budget-aware Reward 训练 GRPO。

### 关键结果

Harness 提供实时计时信息后，Qwen3.6-27B 的预算遵守率明显改善，论文报告没有可测的质量损失。GRPO 在 Zork I 上接近完全守时，并能泛化到未见过的预算值。不过，它在 MLE-Bench 上没有提高相对未训练 Harness 的任务表现；额外时间经常被重复行动填充，多预算训练还可能坍缩到最短预算的策略。

### 为什么重要

三种能力必须分开报告：知道剩余时间、能在截止时间前停止、以及知道下一分钟最值得执行什么操作。第三者对应 Value of Computation：

$$
\mathrm{EVC}(a\mid s)=
\frac{\mathbb E[\Delta Q\mid a,s]}
{\mathbb E[T(a)\mid s]}.
$$

仅提高 Stop Accuracy 无法保证成功率随预算增加。

### 可信度与局限

真实线上工具延迟和排队负载存在非平稳性，论文测试不代表所有部署。模型重复行动的程度还取决于奖励、任务集与 Harness；额外 Thinking Tokens 也不保证产生新增有效证据。

### 最值得继续追踪

结合成功率、重复 Tool Call、有效证据增量和 Cost per Successful Task，报告不同时间预算下的 Quality–Time Frontier，并区分“停止得准”与“探索得值”。

## 4. Plan-and-Patch：Diffusion Planner 处理局部计划损坏

[论文：Plan-and-Patch](https://arxiv.org/abs/2610.10786)

### 发生了什么

多轮 Agent 计划常只有一个中间步骤被工具反馈推翻。自回归 Planner 重新输出整份计划可能改变原本正确的步骤。Plan-and-Patch 使用 Diffusion Language Model 生成结构化程序式计划，对受影响区域重新 Mask，并在保留前后步骤的条件下完成局部补全。

### 关键结果

| 实验 | Diffusion | Autoregressive |
|---|---:|---:|
| Natural Plan，无任务专门训练：修补成功 | 53.7% | 27.0% |
| ALFWorld / TextCraft 任务训练后 | 计划生成成功接近 | 计划生成成功接近 |
| 任务训练后平均计划生成延迟 | 相对 AR 减少 39%–46% | 基线 |

### 为什么重要

真实工具失败具有局部性。修正一个网页操作、API 调用或中间文件步骤时，理想更新应尽量保留不受影响的计划状态：

$$
P'_{\bar M}=P_{\bar M},\qquad
P'_M\sim p_\theta(P_M\mid P_{\bar M},o).
$$

这里 $M$ 是待修改步骤集合。

### 可信度与局限

局部编辑未必保持全局约束，计划修补成功也不等于最终任务成功；Diffusion 的延迟优势依赖采样轮数、硬件和批处理方式。

### 最值得继续追踪

使用执行依赖图自动决定 Patch Scope，并在局部修复后对整个计划做约束与可执行性验证。

## 5. LIFT：把交互阶段信息显式写进推荐序列

[论文：LIFT](https://arxiv.org/abs/2610.10556)

### 发生了什么

Retrieval 与 Ranking 共享用户行为历史，但可用信息的时点不同。LIFT 将每次交互拆成 Request、Item、Context、Action 状态序列；Retrieval 使用 Request State，Ranking 使用 Context State，利用 Role-Conditioned Attention 和 Pre-LN Bias 在参数共享的同时保持阶段语义。

### 关键结果

| 数据集 | 相对最强受测联合模型的 Joint Score |
|---|---:|
| MovieLens-20M | +4.9% |
| Taobao | +3.6% |

论文还通过 Loss Weight Sweep、消融和容量比较研究 Retrieval/Ranking 之间的权衡。

### 为什么重要

将相同特征表无条件提供给两个阶段可能引入 Point-in-time Leakage：部分曝光后、排序后或行动后才出现的信息，在线检索时根本不可用。生命周期分解让这些差别直接成为模型结构。

### 可信度与局限

Joint Score 是论文定义的综合指标，不能解释为两个任务都分别得到 4.9% 或 3.6% 的提升。结果仍来自离线数据与第一方实验，缺少真实大规模线上 A/B 和 Serving 成本比较。

### 最值得继续追踪

严格设置特征可见时间，在相同预算下分别比较 Retrieval Recall、Ranking NDCG、Latency、状态更新和在线一致性。

## 6. SkillContrast：为何相似 Skill 的不同之处更有信息量？

[论文：SkillContrast](https://arxiv.org/abs/2610.11650)

### 发生了什么

多个 Skill 经常共享相同操作模板，但适用版本、输入前提、工具权限或禁止项不同。只根据 Query 相似度截取片段，容易保留无差别的常规说明、删除真正决定正确选择的差异条件。SkillContrast 对候选 Skill 进行相互比较，保留差异文本及上下文交给现成 Reranker，无需重新训练检索模型。

### 关键结果

| 指标 | 结果 |
|---|---|
| SameCapRisk-Bench 请求 | 1,235 |
| 相对 TF-IDF Query Selection 的 clean hits | +54 至 +72 |
| 相对完整 Skill 文本的 Token 节省 | 51.1%–58.8% |
| 使用 0.6B Reranker | 较完整正文少 10–18 个 clean hits |
| 使用 4B Reranker | 与完整正文相当或更好 |

Clean hit 是选中有益 Skill 且未选中已标记危险的相似 Skill。

### 为什么重要

Skill Reranking 更接近比较问题：候选共有信息已经无法帮助区分，最有价值的往往是边界条件。它也补充了近期 Skill Utility 的警告——语义相关度不等于实际使用后的增量效用。

### 可信度与局限

测试集专门设计了相似且有风险的 Skill Pair；clean hit 不等于真实 Agent Task Success。压缩过度仍可能丢失共享但重要的执行约束，小模型的负结果说明 Selector 与 Reranker 容量存在交互。

### 最值得继续追踪

联合建模 Query Match、Skill 差异条款、Harness 适配性和 Counterfactual Utility，并在真实执行轨迹上复评。

## 7. SynCo：生成训练任务的 Agent 也需要接受 RL

[论文：SynCo](https://arxiv.org/abs/2610.11345)

### 发生了什么

固定 Generator 长期提供题目时，已学会的题目逐渐失去梯度价值，过难题目又缺少有效监督。SynCo 独立训练 Synthesizer 与 Reasoner：合成任务触发多个 Solver Rollout，解题正确性更新 Reasoner；任务质量、答案可靠性和可教学性更新 Synthesizer，然后用更新后的能力状态生成下一批样本。

### 关键结果

作者报告在八个数学推理基准上优于受测的静态合成与受控方案，主要增益来自此前尚未解出的题目。公开摘要未给出统一可直接引用的百分比 headline，因此不自行添加具体幅度。

### 为什么重要

合成任务的目标可以是 Expected Learning Progress，而非只提高难度。一个任务的价值既取决于是否有效，也取决于它是否处于当前 Learner 可以从反馈中改善的区间。

### 可信度与局限

数学任务拥有相对成熟的自动 Verifier；开放式研究和真实 Tool Use 的 Reward 更容易被利用。Synthesizer 与 Reasoner 联训也可能共同适应固定验证规则。

### 最值得继续追踪

引入 OOD Holdout、生成题目多样性、Verifier Exploit Rate，并报告 Generator + Solver + Verifier 的联合训练成本。

## 今日值得收藏的代码 / 学习资源

### Microsoft-Decision-1：固定候选决策独立成服务层

[微软 10 月 9 日发布](https://commandline.microsoft.com/microsoft-decision-1-model-foundry/)

微软将 Qwen3.5-9B 后训练为单次结构化决策评分模型，支持 Yes/No、Multiple-choice、Rating、Rubric Grading 与 Tool/Model Routing。官方报告它在 36 项测试、近 15 万问题的第一方比较中准确率最高，延迟比 H2O-Lightning-4B v1.1 快 2.5 倍，八种无害输入扰动下平均决策翻转率为 1.3%。这是厂商测试，不保证异构服务的同条件比较，也不能替代 Missing-candidate Detection 和校准审计。

最值得深读官方文章中的 **鲁棒性、概率校准与真实 Harness 控制用途**，然后与 Jev、Clef、Strands Decider 对照。

### EmbeddingGemma 2：740M 多模态向量模型进入本地 RAG

[Google 原始发布](https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2/)

10 月 6 日 Google 发布的 EmbeddingGemma 2 将文本、代码、图像、音频和视频映射到共同嵌入空间。文本组件约 270M 参数，加视觉约 170M、音频约 300M；MRL 支持从 768 维截到 512/256/128 维，向量存储理论上最多降低 6 倍。官方报告量化后 Pixel 11 Pro 文本模式约需 191MB 活跃内存、完整多模态约 567MB；MTEB Code 从 68.76 提升到 78.68。所有数字均应在目标设备与数据集上独立复现。

适合建立本地论文截图、代码片段、录音和教学视频的跨模态检索系统；需重点验证混合语料中的文本偏好和截断维度后的 Recall。

### Agentic-TTT：让模型判断何时更新自己

[论文：Agentic-TTT](https://arxiv.org/abs/2610.12002)

将 Test-time Training 方法封装成 Tool，Agent 决定当前任务是否值得适应、采用哪个算法以及是否可以复用历史 Skill。论文在自有 Benchmark 上报告 Utility 近乎翻倍，也能学习计算成本的权衡。生产落地必须隔离 Adapter、限制参数写入、保留回滚与独立验收，避免一次部署任务污染后续请求。

### Project Greenhouse / Gaggle：不依赖第三方底座的开放 Search

[论文：Project Greenhouse](https://arxiv.org/abs/2610.11922)

Jimmy Lin 等提出从零预训练 + SFT 的 Pointwise Decoder Reranker，并公开数据、配置、代码与 Gaggle Checkpoint，目标是端到端可审计的 Agentic Search 组件。这条路线最有价值的问题是：相同数据、计算与延迟预算下，从零训练的专用 Ranker 能否超过在通用 Backbone 上微调的版本？

### Agent-controlled Forgetting：可恢复的 Context 压缩

[论文：Agent-Controlled Forgetting](https://arxiv.org/abs/2610.10590)

Agent 将低价值 Tool Observation 原文放进外部 Archive，在原位置留下简短注记，必要时可取回。一个 OpenTelemetry 调试案例中 Provider-reported Prompt Tokens 从 912,492 变为 231,951，累计 Input Tokens 减少约一半，API 成本估计从约 4.38 美元降至 1.28–1.44 美元；但调用更多、耗时长 17%，另一组开发任务没有节省。**这是样本很小、工作负载敏感的机制实验**，值得学习可逆设计，不适合当作通用节约比例。

## 今日最值得花 30 分钟阅读的一项

**首选 [On the Clock: Towards Punctual and Productive Time-Budgeted AI Agents](https://arxiv.org/abs/2610.10833)。**

建议依次看 Harness 注入时间反馈的收益、GRPO 对 Stop Behavior 的影响、多预算训练向最短预算策略坍缩的现象，以及关键负结果：**Agent 可以学会按时停止，却仍不知道怎样把额外时间转变成有效任务进展。**

这一结论对 Coding Agent、AutoResearch、Search Agent 和动态 Test-time Compute 都直接适用。增加思考预算之前，应优先判断下一次工具调用的预期收益。

## 今日可立即实践的一件事

给现有 Agent 做一次 **Productive Compute Audit**。选 30–50 条长程真实任务，用相同 Sandbox、Seed、工具版本和输入分别运行 2/5/10 分钟 Budget；每个 Budget 至少重复两次。Harness 显式提供 \`remaining_seconds\` 与 \`deadline\`。

每条轨迹至少记录 Task Success、Deadline Miss、有效新证据、重复 Tool Calls、Verifier Improvement、Wall-time、P95 Latency、Cost per Successful Task。比较新增预算区间的边际收益：

$$
\mathrm{MarginalValue}(t_1,t_2)
=
\frac{Q(t_2)-Q(t_1)}{C(t_2)-C(t_1)}.
$$

$Q$ 使用独立 Verifier 的质量分数，$C$ 使用同一种时间或费用单位；不要混用。若追加时间使 Token / Tool Call 不断增加，而 $Q$ 不再提高，优先优化停止与升级策略。

> **你的 Agent 得到更多时间后，究竟产生了新证据、新策略和更可靠的结论，还是只执行了更多动作？**
