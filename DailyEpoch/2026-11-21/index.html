今日主线： Agent 系统正在把「每一步都调用大模型」拆成可校准的轻量决策、可复用的预测与可审计的记忆；与此同时，长上下文推理的瓶颈正下沉到 KV Cache 的位置与生命周期。新结果令人期待，但系统级收益必须同时核算失败恢复、约束违规和尾延迟。

归档日期： 2026-11-21（北京时间，周六）。主观察窗口： 2026-11-20 07:35—2026-11-21 07:35（Asia/Shanghai）。考虑到 arXiv 论文索引延迟，研究核验扩展至最近 72 小时；专门标为「七日持续追踪」的项目不视为当天新论文。来源的首次发布日与本期归档日分别注明。所有实验指标均为原作者自报，未获得独立复现实验确认。

一、值得优先阅读的论文与技术进展

1. WeMM-Video：视觉、原声与语言统一建模，11 月 20 日开放权重

发生了什么。 腾讯微信视觉团队于 11 月 19 日提交技术报告 WeMM-Video，11 月 20 日发布 官方代码与模型说明。系列包括 2B、4B、9B 稠密模型及 35B-A3B MoE，支持文本、图像、音频和带原声视频联合理解，区分快速 Instruct 与显式 Thinking 模式。论文描述约 1.2T 多模态训练 token，以及多教师 On-Policy Distillation、MrDPO 与任务专门化 RL。作者报告评测涉及 120 多项基准。

为什么重要。 对短视频、广告推荐和多模态搜索而言，静音帧采样会丢失解说、音乐、说话人和声画不一致等关键证据。融合原声的视频理解模型有望用于检索预标注、视频内容安全和多模态相关性蒸馏。对于推荐场景，可用它生成可审计的事件标签，再与原始音视频及人工标签对齐。

可信度与局限。 论文、代码和权重发布可交叉核验；「开源领先」的对比仍是团队自报，且长视频信息保留、吞吐、GPU 显存及不同语言视频表现需要独立测试。不能把模型大小中的 35B-A3B 误认为每次仅占 3B 权重显存，也不能把该模型说成视频生成器。

最值得继续追踪。 基于相同采样帧率、音频质量和视频时长，对 4B/9B 与其他开源视觉语言模型测量 QA 准确率、跨模态幻觉率、TTFT、峰值显存和每小时视频推理成本。

2. Seer：用离线训练的环境模拟器和价值模型指导小型 Deep Research Agent

发生了什么。 Seer 于 11 月 19 日 17:03 UTC 首次提交，属于 72 小时扩展窗口。框架先在真实研究轨迹上训练两类可跨 Agent 复用的模型：工具响应模拟器和根据历史估计终局正确率的 Value Estimator。推理时，对候选下一步做「想象中的后果评估」，只实际执行被选中的一条操作；丢弃候选的模拟响应不会写入真实会话历史。作者报告 GAIA 上 Qwen3.5-4B 从 13.6% 到 41.7%、Qwen3.5-9B 从 22.3% 到 50.5%。

为什么重要。 它把搜索动作选择问题从更长的逐步 Chain-of-Thought 转为近似模型预测控制：候选动作生成、环境近似、价值比较与真实执行解耦。对成本敏感的 Agentic Search 可尝试在「搜索词改写 / 点击 / 阅读 / 停止」节点做本地批量候选评估。

可信度与局限。 数字来自论文摘要，尚不能解释不同 GAIA 题型的收益分布。模拟器可能产生错误搜索结果、价值模型可能偏好熟悉行为，扩大搜索宽度也会放大评分误差；需要同时报告真实工具调用数、模拟器开销与端到端成功任务成本。

最值得继续追踪。 冻结候选动作与工具回放数据，做 Oracle Ranker、Random Ranker、Value-only、Simulator+Value 消融，分析选择优势是否来自模拟器本身。

3. TripleKV：在工具执行间隙预取长上下文 KV Cache

发生了什么。 11 月 18 日提交的 TripleKV 把 Agent 推理—工具调用—再推理的间歇视作存储预取机会。在 GPU、主机 DRAM 和 SSD 三层之间管理 KV，预测工具何时返回，将下一轮可能重用的 KV Block 从 SSD 提前搬到 DRAM，并通过去重与 Victim Cache 减少空间浪费。论文报告关键路径 SSD 读取请求占比由 45%—76% 降至低于 10%，P95 TTFT 最多降低 49%（相对于带 DRAM/SSD 层的 vLLM 基线）。

为什么重要。 Agent 负载的瓶颈不只是算子 FLOPs。大量会话会在等待网络与工具响应时闲置显存，回到模型时又需要完整 Prefix。这个系统可与 Prefix-aware Routing、Disaggregated Prefill、Paged KV 互补，提示推理平台应将工具回调时延纳入缓存调度。

可信度与局限。 性能提升依赖工具耗时可预测、SSD 带宽、会话复用率及并发形态。对于短上下文、低并发或工具调用极不稳定的场景，预测/预取可能徒增流量；不能把「P95 TTFT 最多 49%」泛化为整体 Agent 任务提速 49%。

最值得继续追踪。 把常见 Agent 轨迹回放到 Prefix Cache 服务器，分别统计 Cache Hit、Host-to-GPU 与 SSD-to-DRAM 流量、P50/P95 TTFT、GPU 显存峰值。

4. AnyS1：将 Procedural Skills 编译为跨任务复用的 System-1 决策点

发生了什么。 Thinking Fast, Anywhere / AnyS1 于 11 月 18 日提交，代码开放于 middle-chunjie/AnyS1。作者从 1,000 多个公开 Skill 中抽取可枚举选择节点，在容器中收集执行态训练 4B 指针模型；低置信度交还给 System-2。论文报告三种未见基准上 Episode Cost 下降 75%—91%、模型调用耗时下降 63%—92%，保持原系统的任务可靠性。

为什么重要。 对推荐与金融 Agent，大量动作实际是有限候选选择，例如工具路由、标准化筛选、异常类型识别。将这些节点从生成式推理转成可校准分类器，既可能降低推理成本，也便于用 Choice-level 的 Accuracy、ECE 与拒判率做质量控制。

可信度与局限。 论文的主要前提是决策候选集合可枚举。真实环境遇到候选缺失、过期 Skill、工具 Schema 漂移时，System-2 回退比例会升高。开源项目的讨论已提出「候选可枚举覆盖率」以及错误 System-1 决策能否恢复的问题，值得在生产轨迹而非示例任务中验证。

最值得继续追踪。 建立四组数据：已知且正确、已知但相似、候选集合缺项、工具返回异常；画出阈值—成功率—成本—回退率曲线。

5. Piccolo：以数据与模型双向演化训练快速决策模型

发生了什么。 11 月 18 日提交的 Piccolo 公开了 0.8B—27B 多模态决策模型系列及 AgentScope 相关代码。研究 Agent 执行行为分析、数据生成、训练实验与评价，并通过语义切片和共享研究记忆继续调整数据配方。论文报告 27B 模型在 Decision Index Vision Full 得分 75.59，并强调更低连续损失未必带来更高离散决策准确率。

为什么重要。 这与推荐系统高度同构：训练目标的 log loss 下降，未必改善 Top-K 决策、约束满足和在线收益。Agent 的自进化也必须明确候选策略如何晋级，不能只看自我打分或单一验证集提升。

可信度与局限。 模型和代码可取，但榜单领先、递归自改进的贡献、训练集独立性仍要通过冻结测试集与横向评估证实。应警惕多轮探索对固定基准形成隐性过拟合。

最值得继续追踪。 固定 Choice/Score/Yes-No 三类任务的训练与验证划分；比较模型规模、定向数据增强、随机数据增强和人工难例的边际收益。

6. FlashMorph2：混合注意力层筛选回到真实离散模型的 On-policy 分布

发生了什么。 On-Policy Morphing into Hybrid Attention Models 于 11 月 18 日提交。论文指出，基于连续插值、教师强制隐状态进行层筛选，会与实际部署时「离散 Hybrid Attention + 参数恢复训练」的分布不一致。FlashMorph2 直接用样本化的离散架构自身的隐状态评测，联合优化保留 Full Attention 的选择分数与模型权重。作者报告相对 FlashMorph：RULER +2.42 分、LongBench +1.08 分，并给出 0.6B—8B 模型层选择的 GPU 小时成本。

为什么重要。 长上下文模型部署从「统一改算子」推进到「哪些层必须保留完整注意力」的预算分配。它也提示 LLM 压缩评估需检查训练/恢复过程的分布漂移，不能仅比较转换前离线代理指标。

可信度与局限。 表现仍依赖 Qwen3 尺度、具体线性注意力变体与评测任务；小量平均分提升不等于线上跨语言检索稳健改善。强结构化召回与长文证据定位要单独测。

最值得继续追踪。 在 32K/64K/128K 长度和跨文档多跳检索中测准确率、真实 Decode Latency、峰值 KV 占用和层选择可迁移性。

7. Late Entry：Looped LM 利用深度 Context Cache 来跳过早期循环

发生了什么。 Late Entry in Looped Language Models 于 11 月 18 日提交。对共享层堆叠循环 T 次的 Looped LM，论文提出新 Token 直接进入最后 K 次循环，利用已完成深层循环的历史 token Cache；后台继续补完历史 token 的剩余循环，并设计 Wake Verification。作者在 Ouro 与 Huginn 模型上报告不同容忍阈值下明显的解码速度提升。

为什么重要。 这是一种利用「历史 token 深度状态可复用」的计算不对称，与传统早退只砍当前 token 计算不同。对动态推理预算尤其值得关注，因为复用过去的计算深度可能比增加当前的推理 token 更便宜。

可信度与局限。 tau=0 的近似精确边界和 tau=∞ 的允许近似行为必须分开读；速度比对特定 CUDA Graph、Batch Size、基模型及循环次数敏感，不能跨架构直接外推。任务质量和回滚分布比单一 TPS 更重要。

最值得继续追踪。 观察批量服务、不同 Sequence Length 与非贪婪解码是否保留收益，并检查 wake 验证失败的分布。

8. PIPETTE：攻防演练的目标应该是防御者真正变强

发生了什么。 PIPETTE 于 11 月 18 日提交。作者发现自动化 Prompt Injection Red-Team 可通过反复搜索同一类高成功率攻击陷入模式坍缩，攻击成功率上升却没有带来新的鲁棒性训练收益。框架使用基于字典学习的奖励促进攻击策略覆盖，并用 On-policy 对抗训练改善 AgentDojo、ASB 场景中的防御表现。

为什么重要。 安全评测应估计攻击分布覆盖以及训练后的独立攻击集，并同时验证正常工具任务的效用；简单提升攻击样本数量或单一 Attack Success Rate 容易误导优化。

可信度与局限。 论文主张的接近零静态攻击成功率源自特定基准和攻击库。自适应攻击者、跨工具迁移、不同安全策略及真实业务权限边界仍需外部复核。

最值得继续追踪。 固定 Holdout Attack Families 与业务正常样本，分别报告 ASR、Defender Utility、攻击策略多样性和攻击生成计算预算。

9. 七日持续追踪：BRIDGE 提醒 Agent Memory 应评估「会不会用」而非「找不找得到」

发生了什么。 11 月 17 日提交的 RAG in a Trenchcoat 提出极简 BRIDGE：链式 Observation Notes、BM25 + Cosine Hybrid Retrieval、时间顺序拼装。作者发现它在 LongMemEval-S 与 BEAM 与复杂记忆方法在 Bootstrap 置信区间内接近，并在 EverMemBench 取得 5.7—6.3 分领先；然而在必须应用隐含规则/程序模式的对抗性任务里，不同记忆结构各有优势。官方 代码和数据 已开放。

为什么重要。 对多轮购物 Agent，检索对的历史偏好并不保证下一步把「预算、品牌排除、替代条件」正确施加到候选集合。衡量 Retrieved evidence contains constraint 与 Action obeys constraint 两个阶段，能更直接定位失败。

可信度与局限。 基准与检索器的设置影响很大；论文说明无统一赢家，不能总结为「复杂记忆都是浪费」。对真实用户偏好遗忘、冲突规则和数据修订，仍需要扩展评测。

最值得继续追踪。 在固定 Reader 下做 BM25+Vector、结构化事实记忆和程序规则记忆对比，同时量化存储、读取和错误执行成本。

10. 工程落地观察：SageMaker KV Cache-aware Routing

发生了什么。 AWS 在 11 月 16 日发布 SageMaker KV cache-aware routing 官方说明。推理容器报告 KV Block 的缓存与驱逐状况，路由器尽量把请求发往保留最长匹配前缀的实例，查询超时或无命中时退化为 Load-aware Routing。

为什么重要。 与 TripleKV 的存储预取组成互补设计：前者解决跨副本的命中位置，后者处理跨 GPU/DRAM/SSD 的缓存层级。对共享 System Prompt 与较长工具轨迹，这类优化经常比 Token-level 小模型调参更直接。

可信度与局限。 这是产品能力公告，不是独立基准。不能自动推断任何团队的部署都获得加速；需要同时观测负载均衡热点、缓存同步与容错成本。

最值得继续追踪。 采用固定 Prefix 重用率与混合负载，在 Round-robin、Least-load 与 KV-aware 之间对比 TTFT 和公平性。
