今日主线： Agent 系统正在从“只调模型参数”转向联合设计执行支架、可验证计划和决策预算。推荐侧同时出现两个互补方向：将长期行为压缩成常量大小的状态，以及按排序不确定性动态分配模型计算。值得警惕的是，论文中的效率数字往往使用不同的预算、准确率口径和硬件，不能直接横向排名。

二、Agent 与强化学习：执行支架成为可学习的对象

1. Soteria：安全代理不应只会“拒绝”，还应该知道如何恢复

发生了什么。 论文将 Agent 计划表示成可以验证的层级状态转换结构；工具调用前验证时间顺序、数据流和领域约束，执行时以 Runtime Monitor 拦截不符合规范的动作，并通过已验证计划指导恢复。11 月 13 日首次提交，作者标注 NeurIPS 2026 Oral。

关键结果。 作者报告，多个工具使用基准的平均任务成功率约为最优对照的 1.7 倍，所定义的策略规范违规次数为零。零违规是相对于形式化规范和指定测试集合，并非证明现实世界绝对安全。

为什么重要。 在支付、交易、商品下单与文件写入场景中，“Plan 通过验证”与“每一步执行符合真实工具前置条件”应是两道独立门槛；规则阻断后若能沿合法路径继续，才能避免安全措施使任务成功率坍塌。

可信度与局限。 有论文中的完整机制和对照，但形式化规范需要半自动生成及人工审查；Tool Contract 若与真实接口偏离，形式化证明无法兜底；验证器对部分一阶逻辑可能超时。继续追踪： 计划缓存、规范维护的人力成本、Tool Schema 变更、P95 延迟和未建模风险。来源：论文。

2. ModHarness-RL：Harness 的 Compression 和 Steering 可随策略共同演化

发生了什么。 不再固定人工写好的执行支架：训练轨迹首先保存为类型化状态块，然后由两个程序决定哪些历史进入上下文（Compression）和何时追加行为纠正（Steering）；候选程序从近期失败轨迹提出、执行验证，再回放到历史轨迹上。研究覆盖 CodeSearch、ALFWorld、BIRD SQL 和 1.5B—8B 模型。

关键结果。 在 CodeSearch 的已报告设置中，Qwen3-8B、1,024-token 历史预算时 Overall F1 由 0.333 增至 0.412；论文整体称多数设置优于固定 Harness。这个实验不证明任意 Agent 都会随自动改写稳定提升。

为什么重要。 Harness 不只是包装 Prompt：何时摘要工具结果、何时警告模型偏航，直接决定观测分布与 RL Credit Assignment。对 Shopping Agent 而言，库存、价格和商品 ID 等硬约束不能被通用摘要随意丢弃。

可信度与局限。 必须把 Harness 搜索成本计入总 GPU-hours/Token，区分“策略变强”与“推理时有更多脚手架帮助”；程序演化还会带来可复现性和权限风险。继续追踪： 固定总预算、跨任务迁移、执行环境版本锁定、失败轨迹的过拟合。来源：论文。

3. ARCHER：训练小模型生成“可执行推理记录”，而非好看的 CoT

发生了什么。 第一阶段把自由文本 CoT 编译成带类型的计算器调用、运行时返回与验证动作；第二阶段通过分组、条件触发的层级 RL 奖励，联合鼓励答案正确、工具接地和轨迹纪律。

关键结果。 作者报告在五种 10B 以下基础模型上，相对最强工具增强对照的基准宏平均准确率提升 5.51 个百分点；MATH-500 提升 8.95 个百分点。这里是百分点而非倍数。

为什么重要。 可执行 Trace 让“思考得对不对”变成“操作过程能否重放、核对”；适合财务计算、数值规划、价格比较及需要审计的工具 Agent。

可信度与局限。 数学工具链通常有精确 Oracle，开放式购物和网页任务缺乏同等完备的验证器。继续追踪： Reward Hacking、计算器使用比例、额外 Token 与工具调用成本、跨域迁移。来源：论文。

三、推荐系统：固定状态与动态容量分配

4. RecMem：长期用户行为序列能否收敛成固定容量的可更新状态？

发生了什么。 RecMem 将历史片段压缩到固定数量的 Memory Slots，通过 Forget Gate 递推更新；Stream-consistency Training 尝试让分段流式处理与一次性打包处理的预测一致。论文还分析了近似半群一致性与收缩条件下的状态误差界。

关键结果。 在 MerRec 上，作者用 16 个 Memory Slots + 216 个 Decoder Tokens 对比 HSTU-1200 的 1,200 Tokens，保留其 87.9% Recall@10、97.0% Recall@200。注意这不是“准确率提升”，而是用压缩交换部分 Recall@10。

为什么重要。 用户记忆存储从“每次重新 Encoder 全序列”转为增量 State Update；非常适合长期消费、内容序列及跨会话推荐。更重要的是，Recall@10 与 Recall@200 保真差距提醒我们：压缩后宽候选召回尚可，不意味着精排前列不受损。

可信度与局限。 理论界依赖状态收缩等假设；兴趣突然变化、旧偏好撤销、用户冷启动与线上长期漂移需要独立测试。继续追踪： 状态更新延迟、跨设备一致性、兴趣反转后的恢复速度及 Recall–Memory–Latency 三维 Pareto 曲线。来源：论文。

5. RACE：给复杂用户分配更大的推理容量，而不是所有人等比压缩

发生了什么。 RACE 从 Top-K 排名分布稳定性定义 List-wise Ranking Uncertainty，以轻量早层预测器估计困难程度，再联合决定通道裁剪与行为序列筛选强度。不是简单用历史长度代替任务难度。

关键结果。 论文报告四个公开序列推荐数据集上准确率与效率兼顾，但摘要没有足够信息形成统一的线上提速倍数；此处不制造具体收益。

为什么重要。 推荐系统里的容量调度应按实例难度，而不只按设备型号或全局 QPS。对不确定性高的用户与候选集增加计算，可能比全面升级大模型更划算。

可信度与局限。 不确定性代理可能和群体特征、长尾流量相关，导致对难例系统性分配不足；提前预测本身也有开销。继续追踪： 对长尾用户的 Recall@K、分组公平性、校准误差，以及固定 P95 下的效益。来源：论文。

四、推理、RAG 与模型可编辑性

6. MMFlash：视觉依赖度决定 Speculative Decoding 的接受率

发生了什么。 作者通过去掉视觉输入前后的 Next-token 分布 KL 散度估计 Token 的视觉依赖性，发现高视觉依赖的 Token 更容易被 Drafter 猜错，因此针对性强化这部分训练；长视频再用稀疏 Attention 降低 Draft 成本。

关键结果。 作者报告最低视觉依赖四分位的接受率约 46%、最高四分位约 22%；多模态测试中最高获得 3.58 倍无损解码加速。最高值不是跨模型、跨硬件的稳态平均值。

为什么重要。 商品图像问答、屏幕操作与视频 Agent 的 Draft 不应复用只看文本概率的难度估计。可信度与局限。 必须同时计入图片预处理、视觉 Encoder、Draft 与 Verify 的端到端成本；高视觉依赖不等于“语义很重要”。继续追踪： 图像数量、视频长度、Batch Size 与真实 Token Acceptance 的关系。来源：论文。

7. WeightBench：权重空间编程的能力边界首次得到系统化量测

发生了什么。 官方仓库提供 42 项、5 条赛道：读权重、修复权重、直接编写权重、识别不可能的修改、无数据压缩；配备 OS 级沙箱、计量 Forward Pass 和哈希链式审计账本。目标网络从 2K 参数控制器到 7B 参数语言模型。

关键结果。 作者的 v0.1 榜单中，Claude Opus 5.5 在 42 题宏得分 0.535；GPT-6.1-sol 在仅运行的 38 题得分 0.568，同 38 题 Opus 得分 0.546。两者不能拿 0.568 与 0.535 直接做完整榜单排名：题量不同，部分任务调用方式不同，样本数也不完全相同。

为什么重要。 这把“LLM 是否能替代优化器直接修改神经网络”拆成可量化能力，而非看几段 Demo。当前较可信的结论是小模型权重诊断/合成有可测能力，语言模型修复、零数据压缩以及不可行性判断仍很弱。

可信度与局限。 已读取官方 README，榜单明确标注 preliminary，未审查的隔离任务与不同运行预算会影响分数。继续追踪： 多 Seed、统一 Agent Harness、独立验证、模型族外分布及实际修复后的泛化。来源：论文 · 官方仓库与运行指南。

8. RAG-FGO：检索 Query Rewrite 的搜索空间不止 Prompt 字符串

发生了什么。 RAG-FGO 将检索 Query Rewrite 表述为离散 Prompt 模板与连续解码参数组成的黑箱优化，组合全局搜索、局部扰动和精英记忆池，以减轻带噪检索反馈导致的不稳定选择。

为什么重要。 很多 RAG 优化只调 Query Prompt，但 Temperature、采样控制与候选策略也影响结果。更重要的是，Rewrite 目标函数应评估检索到正确证据，而非仅优化答案 Judge 分数，否则可能奖励更长但不精确的搜索路径。

可信度与局限。 目前核验到论文与摘要中的机制，未确认可复现的正式仓库或生产级成本数据；不能宣称生产环境已经优于学习式 Rewrite。继续追踪： 每次优化耗费的检索调用数、OOD Query、Hard Negative 召回、Query Drift 和离线/在线反馈不一致。来源：论文。

今日最值得花 30 分钟阅读的一项

Soteria：Formally Verified Planning with Runtime Enforcement for Safe LLM Agents。 建议先用 8 分钟读“形式化规范与计划表示”；再用 8 分钟看静态验证、运行时监控与失败恢复的状态转换；接着用 9 分钟看成功率与规范零违规的评价口径；最后 5 分钟用自己的一个有不可逆工具动作的 Agent 场景检验：违规阻断之后是否存在安全恢复路径。真正值得复制的是可复核的约束执行与恢复机制，而不是论文中的 1.7 倍单一指标。

今日可立即实践的一件事

为 ShoppingAgentLab 增加一组“硬约束阻断后可恢复”回归测试（约 45 分钟，不用重训）。 固定 20—30 条包含缺货、预算超限、商家不可售、重复下单、错误商品 ID 的任务轨迹；在 Tool Call 前做确定性校验，令 Agent 在阻断后重新查询候选或终止。对比 H0=直接执行、H1=只阻断、H2=阻断+合法恢复，保持工具调用预算相同。联合测量 Task Success、Hard Constraint Violation、Recovery Success、P95、平均 Tool Calls 和单位成功任务成本。特别记录因状态陈旧造成的假阻断，否则零违规可能只是把所有难题都拒绝了。
