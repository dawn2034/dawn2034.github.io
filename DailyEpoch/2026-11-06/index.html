今日主线： 生成式推荐正在补齐实时供给、用户偏好和有效归因三块短板；Agent 自进化的评测逐步从“完成任务”转向“交付可验证的模型与服务系统”；长上下文、低比特与专用推理架构的收益，需要在真实负载和明确计费边界下比较。

归档日期： 2026-11-06（Asia/Shanghai），执行开始时间 2026-11-06 07:55:06 +08:00。常规观察窗口： 2026-11-05 07:55—11-06 07:55（北京时间）。扩展窗口： 2026-11-03 07:55—11-06 07:55（72 小时）；主要论文在 11 月 4 日 UTC 提交，11 月 5 日进入新论文索引。下文区分论文首次提交、模型仓库更新与本期归档日期。数值如无特别说明，均为作者自报结果，非独立复现。

一、前沿论文与技术进展

1. WISE：从指标报警走向搜索整页质量归因（Search / Agent）

发生了什么： WISE 将搜索质量诊断定义为 System Quality Diagnosis：同时读取用户看到的多模态页面和内部召回、排序等链路轨迹，用 ReTrace 构造证据一致的诊断轨迹，再用 Adaptive Harness-Policy Optimization（AHPO）联合改善执行流程与模型策略。关键结果： 作者报告 Qwen3.5-35B-A3B 上端到端归因准确率 75.20%，并发布 WISE-BENCH。为什么重要： “线上指标健康”不等于“用户看到的是好结果”；诊断 Agent 需要能定位哪个阶段把一个可解释的需求转化为错误曝光。可信度与局限： 论文提供真实业务场景，但标签由专家诊断、内部链路对外不可直接复现，且 75.20% 不等于真实业务缺陷的全覆盖召回。追踪： 跨页面样式迁移、反事实修复后的指标增益、根因定位校准和诊断人工成本。来源：WISE 论文（11 月 4 日 UTC 首次提交）。

2. RTP-LLM：生成式召回的请求级可售约束（电商 / Local Commerce）

发生了什么： 商家 Semantic ID 即便存在于目录，也不代表用户当前位置、时段和供给状态可履约。RTP-LLM 在请求时把可售 ID 编译为 CSR 前缀索引，CPU 准备与 LLM Prefill 重叠，多个 Beam 共享约束状态，合法扩展仍使用原始模型 Log Probability。关键结果： 一组相同 Beam 的日级约束比较中，需后过滤的商家由 170/299 降到 29/299；另一硬件边界的服务端附加延迟为 0.6ms。为什么重要： 约束应在生成搜索空间时生效，不能用“生成后删掉不合法候选”浪费有限 Beam。局限： 两个数字来自不同实验条件；论文明确没有证明在相同召回质量下节省 GPU 计算，0.6ms 也不包含完整客户端成本。追踪： 实时库存过期率、候选供给抖动、合法 Recall@K、P95 与 Beam 大小的联合曲线。来源：RTP-LLM。

3. FocalSwap：搜索增强推荐真的使用了“最新一次搜索”吗？

发生了什么： FocalSwap 对目标、候选、历史与评分器保持不变，分别用中性掩码和同类真实搜索记录替换最新 Search Episode，检查排序变化与目标相对倒数排名。关键结果： 三组 UniSAR Checkpoint、66,139 条样本中，掩码引发 59.7%—61.7% 的排名变化，匹配替换仅引发 44.1%—44.8%；作者没有建立 SESRec/UniSAR 在主要对照下对最新搜索槽的正向贡献。为什么重要： “删掉字段性能下降”可能只是 OOD Mask 破坏输入分布，不能证明模型理解了最新意图。局限： 数据集、检查点和匹配供体定义决定外推范围，不等于所有搜索增强推荐都无效。追踪： 真实 Query 改写、线上短期意图、匹配负对照、不同供体采样下的敏感性。来源：论文 · 作者代码。

4. PMRecBench：图像相似，未必符合用户偏好

发生了什么： 一个包含 510 个图文查询并连接真实用户历史的个性化多模态推荐基准，观察到图像相似性可能压倒用户长期喜好；加入查询语句改善内容匹配却不一定改善偏好遵循。为什么重要： 购物 Agent 常能“找像”，却未必能“找适合这个用户”；必须分别测量视觉匹配、明确约束与个性化。可信度与局限： 样本规模小、商品领域有限，不能代表线上 GMV；用户历史的构造方式亦影响判断。追踪： 可控冲突负样本、多轮偏好修改、个性化增益与群体公平性。来源：PMRecBench。

5. DESRec 与 CAP-Mix：序列推荐的可变计算和连续物品表征

发生了什么： DESRec 为不同用户历史分配不同数量的潜在推理步，并以训练期 Self-distillation 学习适合自己的思考深度；CAP-Mix 用共享原型与物品专属向量的软混合表示，替代硬性离散 Semantic ID。关键结果： CAP-Mix 作者报告六个基准平均 HR@5 +6.9%、NDCG@5 +13.6%；DESRec 报告跨六数据集、四骨干的改进，但摘要没有可核对的统一幅度。为什么重要： 生成式推荐不能只在 Token 生成算法上创新，用户状态计算预算和 SID 表示瓶颈同样重要。局限： 软表示的高速对比依赖选择的离散基线，尚不等于生产吞吐优势；动态推理步是否产生因果增益需等 FLOPs 对照。追踪： 固定 FLOPs、固定嵌入容量、长尾与冷启动、训练/推理一致性。

6. Optimal Re-Ranking Depth：每个 Query 需要重排多少候选？

发生了什么： 以查询难度预测值得进入昂贵 Reranker 的深度，不再固定 Top-100/Top-200。关键结果： 在论文的 LLM 判定排序指标设置下，作者报告文档重排数最多减少约 3 倍，同时维持效果；Oracle 上界的结论不能当部署模型表现。为什么重要： Agentic Search 的候选量受查询难度、文档歧义和推理成本共同决定。局限： Judge/训练数据泄漏、异常长尾、额外路由开销都可能吃掉节省。追踪： 同 P95 预算下 Recall/NDCG、置信区间及尾部分布。来源：论文。

7. Weaver：个性化 RAG 不应忽略偏好冲突与时间范围

发生了什么： Weaver 把用户意图拆成依赖图，以记忆条件化检索逐步补足证据，同时显式处理时间及作用域不同的偏好。为什么重要： “我不吃辣”和“这周可以尝试微辣”不应被粗糙摘要覆盖为永久冲突；Agent 需要可回溯的 Preference Provenance。可信度与局限： 作者在 PersonaMem 等基准报告证据完整度和答案表现改善，尚不证明生产多租户环境的时效、删除与隐私安全。追踪： 偏好撤销、跨会话污染、引用可证伪率和 Token 成本。来源：Weaver。

8. Turn-Level Best-of-N：多轮 Agent 的测试时选择

发生了什么： 每个 Agent Turn 生成多个行动候选，用选择器选出下一步，不只对最终答案采样。关键结果： 作者在长时程任务报告 5%—10% 的正确率与一致性增益。为什么重要： 将额外推理预算投入高风险步骤，可能比全轨迹回滚更低成本。局限： 候选相关性很强时 N 倍采样未必产生独立信息；选择器偏差、工具副作用、严格同预算比较均需检查。追踪： 失败 Turn 选择性扩展、相同 Token/工具预算下成功率、重试幂等。来源：论文。

9. CompressionBench：让 Coding Agent 直接提交可验证的量化模型

发生了什么： 给 Agent 原始权重、存储预算、推理环境与时间上限，要求它自主寻找压缩策略并交付权重加可执行推理。关键结果： 六类 Agent × 六配置共 36 次提交有 29 次通过验证；最优困惑度方案平均相对 BF16 PPL 上升 3.4%，下游准确率 77.33% 对 BF16 的 79.56%；79 次局部排序有 17 次在整模型反馈下发生逆转。为什么重要： 量化不能只看 PPL，必须把可运行性、生成行为、下游能力与端到端评测设为最终目标。局限： “自治发现”仍依赖既定预算、验证器及搜索空间，不是一般性自改进能力。追踪： 4-bit/2-bit 混合精度、推理 Kernel、Agent 试验预算与独立复现。来源：CompressionBench。

10. ServerBench：Agent 能否自主重构 LLM Serving？

发生了什么： Agent 在保持 Session 依赖和正确性的前提下自主修改服务栈，由独立 Replay 校验，优化延迟合格的 Token 价值/GPU 成本。关键结果： 作者报告 33 次中 22 次系统通过验证、13 次胜过最强基线；特定 Gemma E4B 任务中最高方案的论文目标指标为 vLLM 参考的 4.87 倍。为什么重要： 系统优化从 Kernel Tuning 扩展到批处理、负载选择、缓存与隔离策略的联合搜索。局限： 4.87× 是特定工作负载、专用目标函数与基线下的相对值，绝不能写成“通用 vLLM 速度提升 4.87 倍”。追踪： 跨硬件泛化、长短混合负载、冷启动、服务可靠性与交叉 Benchmark。来源：ServerBench。

11. Systolic Linear Attention：把门控 Delta Attention 映射到 TPU 矩阵阵列

发生了什么： SLA 重排线性注意力的数据流，适配 TPU v7x 的 256×256 Systolic Array。关键结果： 作者相对 Tokamax KDA 的相应层报告 1.6—2.5 倍加速，在 2,048 TPU 芯片上训练 6.5B—63.1B MoE，端到端速度改善约 11%—24% 且困惑度接近。为什么重要： O(N) 理论复杂度并不自动转化为硬件加速，内存布局和矩阵指令形态才是可部署的关键。局限： 属于 TPU v7x 特定实现，不能外推到 NVIDIA GPU，也不能把单层峰值等同整模型收益。追踪： A100/H100/B200 Kernel 可迁移性、长上下文吞吐与精度。来源：SLA。

12. ERNIE-5.5-Flash-Base：280B 总参 / 14B 激活的开源基座

发生了什么： 百度公开 ERNIE-5.5-Flash-Base 模型卡与 FP8/BF16 权重，MoE 标称约 280B 总参数、14B 激活，训练上下文 128K，并披露混合注意力设计与预训练规模。为什么重要： 为研究大型 MoE 的质量、实际激活计算与 FP8 部署提供权重和明确配置。可信度与局限： 模型卡与权重是可核验事实；卡片自报 Benchmark 未独立复现，声称可微调/推理至 1M 上下文也不等于该长度上的可靠检索与推理。许可证提醒： 使用自定义 ernie-5.5-flash-base-model-license-v1.0，不能擅自视作 Apache-2.0。追踪： Long-context Lost-in-the-middle、KV 需求、Tensor/Expert Parallel、真实 Token/美元 成本。来源：FP8 模型卡 · BF16 权重。

二、横向技术判断

推荐与搜索： 有效系统不是简单堆更大的生成模型，而是同时解决候选合法性（RTP-LLM）、真实使用意图的证据（FocalSwap）、偏好遵循（PMRecBench）和整页故障归因（WISE）。对购物 Agent 优先做可控消融：固定候选和用户历史，只改变一个信息源，配 OOD Mask 与真实供体双对照。

Agent 自进化： CompressionBench 与 ServerBench 说明“让 Agent 优化自己依赖的模型/系统”具有可测的工程价值；不过可运行提交率、独立验证和总预算，比单条最高性能数字更有解释力。

基础设施： SLA 与大型 MoE 模型卡提醒：关注芯片支持、Batch、Attention 状态形态和服务边界，不要跨 GPU/TPU 或不同测试负载生搬吞吐倍数。

今日最值得花 30 分钟阅读的一项

FocalSwap：Do Search-Augmented Recommenders Use the Latest Search Episode?（结合官方代码）。推荐将 30 分钟分为：10 分钟理解 neutral mask vs matched donor 的因果问题；10 分钟检查 66,139 条样本与三 Checkpoint 的 RR / Rank Flip 统计；10 分钟把实验改写成自己的 Search-to-Recommendation 消融计划。它比“又一个排序模型涨点”更值得立即吸收，因为它直接检验模型是否真正使用了宣称有效的输入。

今日可立即实践的一件事

在 ShoppingAgentLab 实施一个「最新用户意图」反事实输入审计（60—120 分钟可搭好首版）。 固定 100—300 条已有图文购物请求、用户历史、候选集合与打分器，对每条分别跑：原始最新 Query、直接 Mask、同品类/相似语义真实 Query 替换、与历史冲突的最新明确约束。输出 NDCG@10、候选排序翻转率、明确约束满足率、配对差值及 Bootstrap 95% CI；记录是否仍存在依赖错误输入分布的伪增益。止损判据： 如果 Mask 影响显著但匹配供体替换影响很小，先停止宣称“模型会主动利用最新搜索意图”，转而检查特征门控、训练目标与 OOD 测试设计。
